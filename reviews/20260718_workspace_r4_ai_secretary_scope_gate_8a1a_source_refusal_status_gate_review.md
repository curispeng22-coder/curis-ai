## 结论

拒绝码矩阵、单一返回和优先级定义成立，但“固定响应不泄露实体差异”只有原则声明，没有可执行、可比对的固定响应体契约，无法独立证明不同来源类型、ID、存在性和状态不会通过错误文案或字段泄露差异。因此本 Gate 不通过，不得推进 `8a.1b`。

## 已通过核对

| 优先级 | HTTP | 命中条件 | 终止边界 |
| --- | --- | --- | --- |
| 1 | `401` | 缺 tenant 或 access context | 鉴权前置终止，不进入来源查询 |
| 2 | `400` | 必填参数缺失/空白、字段类型错误、非法 null | 参数校验终止，不进入关联查询 |
| 3 | `403` | tenant/project/company/department/task/workflow 关联不一致或跨域读取 | 命中后立即终止，不继续查关联表 |
| 4 | `404` | 来源对象不存在、状态不可读、父对象缺失导致子对象不可承接 | 命中后立即终止，不返回部分集合 |

- 多条件同时命中时，优先级明确为 `401 > 400 > 403 > 404`。
- 每次请求最多一个 HTTP 状态码；拒绝后不返回部分对象。
- 主对象已拒绝时，不得继续读取或透传其子对象。

## 唯一阻塞

Issue 未固定实际错误响应体，例如稳定的 `error_code`、固定 `message/detail`、允许字段集合，以及对四种来源类型和“存在/不存在/状态不可读/作用域失配”是否必须字节级一致。当前只有“统一失败响应、不可区分实体差异”的原则，无法形成可重复验收，也无法排除实现把对象类型、ID、状态或命中字段写入响应。

最小修复：在本 Issue 内补一张固定响应契约表，明确每个 HTTP 状态的 exact body、允许字段和禁止字段，并声明同一失败类别不因来源类型、实体 ID、存在性或状态值改变；随后只需静态重审本 Gate。
