# Evidence 05 — 平台服务条款与合规红线（中文平台）

Authority Class: EVIDENCE
Collected: 2026-09-18
**性质**：本条为**产品可行性硬约束**，不是技术偏好。必须在 Capability 定义阶段登记。

---

## 1. 抖音《用户服务协议》第 5.1 条（原文）

Source: `https://sf3-cdn-tos.douyinstatic.com/obj/ies-hotsoon-draft/douyin_agreement/agreements.html`

> **5.1 您不得使用任何插件、外挂、系统或第三方工具对抖音的正常运行进行干扰、破坏、修改或施加其他影响，包括但不限于使用任何自动化程序、软件或类似工具接入抖音，收集或处理其中信息、内容。**

第 5.2 条另有列举，含"使用未经许可的数据或进入未经许可的服务器或账号"等。

**判定**：条文表述为"任何自动化程序、软件或类似工具接入抖音，收集或处理其中信息、内容"，覆盖范围**极广**，并未区分"爬取他人数据"与"用户读取自己的经营数据"。→ **抖音场景的端到端自动采集处于协议风险区。**

## 2. 小红书

Source: `https://guancyxx.cn/zh/blog/xiaohongshu-automation-agent-skill-survey`（第三方调研，非官方，仅作背景）
- 小红书**无公开 API**；其《用户协议》**明确禁止自动化抓取**。
- 引用风险层级：反爬条款违规（民事）→ 刑法第 285 条"非法获取计算机信息系统数据罪"（大规模用户数据）→ 《个人信息保护法》PIPL（含个人信息内容即便公开可见，批量采集仍需同意）→ 封号（设备指纹+行为分析+风控模型，封禁率极高，且**关联设备可能被永久拉黑**）。
- 该文所述头部开源项目 `NanmiCoder/MediaCrawler`（约 18k stars，Apache-2.0）已在首页加免责声明——**License 宽松 ≠ 使用合规**。

## 3. 抖音开放平台《开发者服务协议》要点（二手转述，需官方复核）
Source: `https://blog.csdn.net/gitblog_00188/article/details/157754256`
- 禁止未经授权的 API 调用、**模拟登录**及批量数据爬取；违规账号面临封禁。
- 数据使用范围：不得用于与平台竞争业务；用户数据需在获取后 72 小时内删除或匿名化；禁止提供给第三方或用于机器学习训练。
- 频率限制：普通应用 100 次/分钟；企业认证 500 次/分钟。

## 4. 抖音电商《【不当获取/使用信息】细则》（官方公示）
Source: `https://school.jinritemai.com/doudian/web/article/aJijoYGzDLJ5`
- 违规定义含"通过租借/共享账号、协助第三方扫描系统、**违规使用工具**、泄露/出售信息等方式，不当获取、使用、传播、出售平台商业信息或他人信息"。
- 规则于 2026-05-12 生效。处置含公示警告、停业整顿、扣除违约金、店铺清退；创作者侧可提高保证金至 2000 元。

## 5. 各平台官方数据通道可行性（第三方汇总，需官方逐项复核）

Source: `https://blog.csdn.net/teacherchen90/article/details/163481231`

| 平台 | 官方 API 可行性 | 说明 |
|---|---|---|
| 微信公众号 | ✅ `datacube` 系列已认证号即可 | **唯一完全干净的通道**；官方文档本身建议每日定时拉取入库（`getusersummary` / `getusercumulate` / `getarticlesummary` / `getuserread` / `getarticletotal`） |
| 抖音 | ⚠️ 开放平台数据接口 | 需实名 + 应用审核；**个人自媒体场景过审率不高** |
| 快手 | ⚠️ `open.kuaishou.com` | 需应用过审 |
| 哔哩哔哩 | ❌ 无官方创作者 API | 仅创作中心内部接口 |
| 小红书 | ❌ 开放平台仅面向商家/电商 | 创作者数据接口不在其中 |
| 微信视频号 | ❌ 完全没有 | 仅助手后台 |

> 该文同时给出实践方案："官方 API 优先，剩下的走**浏览器登录态复用**"——即承认了登录态复用路线的现实性，但**未处理平台协议风险**。本轮研究必须补上这一环。

## 6. 与 Curis 既有结论的一致性

本证据与此前 PHASE 2 Provider Feasibility 的既有结论一致并**进一步加强**：
> "⚠️ 中文平台合规红线：微信 2026-03-27/04-09 明确禁止 AI/脚本替代真人创作发布 → 端到端无人自动发布被规则禁止，止步「草稿+质检」"

本轮新增维度：**不仅"发布"受限，"读取/采集"同样受限**（抖音 5.1 覆盖"收集或处理其中信息、内容"）。

## 7. 对 Capability 定义的强制要求（推导）

"内置浏览器"**不能**被定义为"绕过平台无 API 限制的通用采集器"。它必须被定义为：
1. **用户在自身授权范围内、针对自身账号的经营数据读取**，且
2. **默认停在 Draft/Review Gate**，而非端到端无人发布，且
3. **明确登记平台协议风险为已接受的产品风险**（由总控决策席裁定），且
4. **优先官方 API 通道**（如微信公众号 datacube），浏览器路径是**次选而非首选**。
