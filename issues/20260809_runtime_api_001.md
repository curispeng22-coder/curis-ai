Runtime Foundation 与 RD / XHS / TTK Backend Simulation 已通过。当前前端仍无法消费目标 Runtime，因为 Foundation 尚未有稳定的 tenant-scoped API 入口。本 Issue 只增加薄 API Adapter，不修改产品对象、状态机或旧执行链。

## 1. 目标

为后续 CEO Desk、Workspace Portal、First Arrival 与三业务 Workspace UI 提供最小、可审计、租户隔离的 Runtime API：

- Company / CEO Assistant / AI Organization / Workspace 运行快照；
- FoundingRun 创建与恢复；
- SimulationRun 查询与失败 / 失效状态投影；
- CEO 明确确认的受控状态转换；
- 不返回 prompt、密钥、原始事件 payload 或隐藏思维链。

## 3. API 边界

建议最小接口：

```text
GET  /api/workspace/runtime/foundation/companies/{company_id}
GET  /api/workspace/runtime/foundation/companies/{company_id}/workspaces/{workspace_id}/simulations
POST /api/workspace/runtime/foundation/founding-runs
GET  /api/workspace/runtime/foundation/founding-runs/{founding_run_id}
POST /api/workspace/runtime/foundation/entities/{entity_id}/transition
```

要求：

- 所有查询必须通过当前 `TenantContext`，Company / Workspace 不匹配时 fail-closed；
- 状态转换只能经过 `RuntimeFoundation.transition()` / `SimulationRuntime.transition()`，不得直接更新数据库 `status`；
- Actor、trigger、reason、evidenceRefs、nextCheckAt 必须进入审计；
- CEO 确认、外部回执、手动反馈和失败恢复必须保留来源；
- 旧 Project / Task / Workflow 只能作为 `executionRef`，不能成为 API 的目标事实源；
- API 错误必须返回可操作的中文错误，不泄漏数据库、密钥或内部堆栈。

## 4. 禁止范围

- `frontend/`、`curis-ui-prototype/`、`desktop/`；
- 活动数据库、真实小红书 / 抖音 / TikTok API 与外部消息；
- 旧业务路由重写、旧表迁移、历史数据回填；
- 新的 Assistant / Agent / Task 系统；
- 清单外任何文件；不得 reset、checkout 或删除既有 dirty diff。

## 5. 必须证明

1. API fresh / restart 后可读到同一 Runtime 对象和 SimulationRun；
2. Tenant、Company、Workspace 隔离；跨作用域读取 / 转换返回安全错误；
3. 非法 Actor / 状态转换 / 自动批准 `WAITING_CEO` 被拒；
4. API 只读当前 Runtime 对象，不能把旧 Project / Task 聚合伪装成目标 Runtime；
5. 原有 Backend 聚焦回归、三业务 Simulation 回归和既有基线失败数量不变；
6. `main.py` 只保留新 Router 注册 diff，pre-existing dirty diff 可分离。
