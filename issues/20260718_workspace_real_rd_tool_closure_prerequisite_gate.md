## 唯一主目标

在不做前端、不实现 115 个 Tool 的前提下，建立一个最小真实研发工具闭环：项目文件读取/搜索 → 受控代码修改 → 测试或 Build → Git Diff 与成果输出 → Tool 审计、Token/成本。

本 Gate 不实现工具。三项前置证据全部完成后，才允许建立最小研发工具集实施 Issue。

## 严格顺序

1. **质量全量回归**：固定当前 SHA，记录通过/失败/跳过与失败归因；先判断是否存在阻断最小研发工具集的新增回归。
2. **R4 代码审计**：仅在第 1 步完成后，核对 R4 每项是实际代码、只读投影、测试/契约，还是空壳；不得把契约文档写成运行实现。
3. **Shared 状态同步**：仅在第 2 步完成后，经 `issues/shared/` 向 WorkBuddy / Admin 发送当前真实状态、可消费资产与未闭合依赖。

每一步必须有独立 Review / 证据并由产品规划席确认后，才可进入下一步。

## 禁止范围

- 不实现、批量启用或宣称 115 个 Tool；不做前端、Secretary、Connector、Billing 或新公司包。
- provenance Step1 Gate 保持 `PAUSED_BY_NEW_PRIORITY`：不注 Key、不启动、不调用。
- 前端和所有 L2 继续冻结；不创建模型调用、外部服务或实体迁移。
