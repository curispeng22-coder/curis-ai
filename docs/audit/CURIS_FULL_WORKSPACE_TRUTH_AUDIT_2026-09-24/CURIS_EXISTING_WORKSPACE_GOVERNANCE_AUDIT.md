## Conflicts and boundary findings

- `AGENTS.md` gives the current product authority chain and allows creation/changes only within stated scope; root `AGENT.md` is a second task-routing entry. Both exist. `AGENT.md` is a one-line legacy pointer and does not state precedence.
- `DOCUMENT_STATUS_RULES.md` allows Draft / Review / Frozen / Deprecated. `docs/standards/documentation-standard.md` defines Draft / Approved / Superseded. `Documentation_Governance_Final_Report.md` says `CURRENT_STATE.md` is the only current fact entry, while current `AGENTS.md` makes Product Blueprint the sole Product Authority and `CURRENT_STATE.md` the implementation route. Scope and status vocabulary need explicit reconciliation.
- `docs/standards/directory-structure.md` describes a Tool System v1.5 layout and does not match this repository's current V1 layout. `docs/ai-development-organization/README.md` still declares Sprint 1A / Tool System v1.6 as the current project state. These documents are historical, but they are not clearly marked Deprecated.
- The 2026-07-30 Document Inventory says it scanned 1,404 selected documents/assets. The full workspace manifest now records 349,311 files and 57,394 directories; the earlier inventory is a scoped documentation inventory, not whole-workspace governance coverage.

## Why rules did not prevent workspace drift

1. **Truth routing and filesystem routing are different.** The Pointer tells an Agent what truth to read. It does not pick a write destination or prohibit `mkdir` for every task.
2. **Issue boundaries are mostly file-scoped.** Formal business-code work needs Allowed Files, but the task contract lacks Allowed Directories, create-file/create-directory switches, HTML/screenshot switches and an owned Task Workspace.
3. **No closeout disposition is required.** The current task/report discipline does not require a complete created/modified/temp/evidence manifest with `PROMOTE`, `ARCHIVE` or `DELETE` for every output. A finished exploration can remain as an apparently reusable folder.
4. **One-time cleanup was mistaken for prevention.** Governance v1.0 documents finite 2026-07 migration/delete cohorts; it defines archive safety but not recurring intake, retention or task-close checks.
5. **Candidates and authorities share the same search surface.** The repository has many named exploration/review trees beside `docs/`; status and Pointer reduce semantic risk only when agents check them. Directory/filename tokens such as Final, Master, Current and Frozen are not gated.
6. **No retention contract for visual evidence.** Screenshot naming and CEO captures vary by task; neither minimum evidence retention nor expiry is required.
7. **Backlog is not a controlled promotion.** The current Pointer names canonical UI and execution backlogs, but `Next Step` / `TODO` in review and research files can look active; no explicit promotion step is required by every task.
8. **No creation-time failure gate.** The rules rely on the human/agent rereading static Markdown. No template or automated check refuses an unlisted output directory, unapproved file class, or missing disposition.
9. **Parallel governance sets aged in place.** A frozen instruction set, prior AI Development Organization set, one-line `AGENT.md`, old status docs and archive campaigns coexist without a single explicit succession map.

## Assessment

The main failure is **governance is descriptive, while artifact creation is unconstrained at task start and task close**. “Agent did not follow” is an incomplete cause: the system lacked a universal task envelope that named the only writable paths, denied unapproved directory creation, captured outputs, and forced a final disposition. Proposed remediations are in the four proposal files in this directory. They are Review-only and require CEO approval before becoming policy.
