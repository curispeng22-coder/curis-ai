# 专业工作台产品模型 — CEO 决策单

**状态：** 待 CEO 决定

**本轮只决定产品原则，不改文档、不改界面、不开发。**

请确认我们以后是否这样做：

1. **一个业务工作台是一整套持续经营业务的专业环境，而不是一张页面。**

2. **同一个业务工作台可以有多个专业工作区，例如经营概览、研究洞察、内容运营和数据增长。**

3. **一支业务团队贯穿整个工作台，而不是每个专业工作区各配一支团队。**

4. **专业工作区只说明需要哪类责任，不直接绑定某个员工；换员工不需要改工作台。**

5. **同一个员工可以在多个专业工作区承担工作，但始终保持同一个员工身份。**

6. **业务内部导航放在当前业务的 Context；Main 显示当前专业工作区；详情、编辑和证据按需展开。四者是职责分工，不是固定四栏。**

7. **团队、资料、成果和证据复用公司统一系统，不为小红书、研发等业务另建一套。**

8. **不同业务由自己的 Workspace Package 声明需要哪些专业工作区、业务对象、责任和能力；本轮不决定技术格式。**

9. **小红书“AI 科技”以后以经营概览作为候选默认入口；日历归入内容运营，商业化按阶段选用；其他菜单细节暂不冻结。**

10. **禁止新增 Surface Runtime、Surface Agent、Surface Cycle、Surface Result 或 Surface Session；继续复用现有工作、责任、员工、交接、结果、证据和经营周期。**

## 建议决定

**整体接受以上 10 项，作为后续 Authority Reconciliation 的输入。**

接受不代表已经实现，也不授权设计、开发或迁移。
