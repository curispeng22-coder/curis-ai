## B. Resolution Order Correction

统一解析顺序为：

`Business Intent → Read Current Company Truth → Recognize Domain / Scope / Risk → Search Verified Match → Instance Configuration → Maintained Derived → Safe Composition → determine whether Domain Truth supports Generic → bounded Domain / Risk Research when needed → Generic / Derived / Composed / Professional Candidate decision → Generation only when necessary`

这是一条产品解析与验收顺序，不是所有业务必须经过的固定 Workflow。已有成熟结构可以跳过重复研究；研究只在真实 Truth / Domain / Risk Gap 出现时插入。

## C. Product Promise

Curis 的承诺是：为常见高价值业务提供可信的专业工作环境；对近似业务优先复用和适配；对未知业务提供诚实的 Generic 起点、能力缺口、验证状态与升级路径。Curis 不承诺“任何行业一句话生成专业级软件”。

## D. Professional vs Generic

| Product Form | 语义 | 当前产品责任 |
| --- | --- | --- |
| Professional | 面向稳定专业问题、对象、动作、节奏和结果的深度工作环境 | 由 Curis / 合作方维护并以证据验证 |
| Generic | 对未知、早期或缺少 Domain Truth 的业务提供可运行的通用起点 | 保留身份、团队、工作、结果、证据和历史，透明暴露缺口并可安全升级 |

Professional / Generic 是产品形态，不等于 Verified / Candidate。

## E. Business Configuration Repositioning

Business 页面承载：身份 / 定位、Goal、Rules / Preferences、Team / Responsibility coverage、Capability / Connector 选择与授权、automation boundary、optional module、notification 与 operating cadence。它回答“这个业务怎么经营”，不要求 CEO 设计专业 IA、导航、Handoff、DAG、Router 或行业 Evaluation。

## F. Simplicity / User Responsibility Boundary

普通 CEO 主要表达意图、确认边界、查看提案、授权能力、做必要 Gate 与查看结果。系统 / Assistant / Leader 负责读取 Company Truth、发现匹配、研究、组织提案和跟进；不得把技术配置、Workflow 图或专业方法编排责任推回 CEO。

## G. Workspace Engineering New Role

Workspace Engineering 是 resolution-first 的发现、匹配、配置、组合、安装、验证、迁移和演进能力。其顺序是：读取 Company Truth → 识别 Domain / Scope / Risk → 发现 Verified Match → Instance Configuration / Maintained Derived / Safe Composition → 必要时 bounded Research → Candidate 验证。它不是默认从零生成器。

## H. Verified Model

Verified 不是视觉标签或目录存在状态。Verified metadata 至少需要 version、scope、evidence、maintainer、required connections、provider boundaries、known gaps 与 migration / support policy。缺一项不得把 Official、Professional 或 Generated 冒充 Verified。

## I. Quality Model

质量沿三个正交轴记录：

1. Product Form：Professional / Generic；
2. Provenance：Curis Official / Partner / Community / User-or-AI Generated；
3. Assurance：Verified / Candidate / Unverified / Deprecated。

不得把 Official = Verified、Professional = Verified 或 Generated = Verified。

## J. Professional UX as Package Asset

Package 可声明 Professional Surface、View、Detail、Editor、Tool、对象 / 动作投影与响应式行为。声明必须受限、可验证、可版本化；不得允许 arbitrary HTML / React / JS。所有 Package 与 Generic 仍复用相同 Company OS / Core / Runtime。

## K. Professional Module Direction

Professional Module 是 Approved Product / Architecture Direction Candidate，用于组织深度专业环境的可复用形态；本轮不创建 Module Runtime、Registry 实现或新 Schema。

## L. Official Library Direction

Curis 长期维护小而深的 Official Professional Workspace Library，而非承诺数量庞大的模板市场。Library、Verified Registry 和第三方 Package ecosystem 是后续方向，不是当前实现事实。

## M. Derived / Composed / Generated

- Instance Configuration：在 Verified 结构上适配当前 Business / Workspace。
- Maintained Derived：从受维护的专业基线派生并保留 provenance / version。
- Safe Composition：组合多个可信能力或 Package，并重新验证边界。
- Generated：仅在缺少更好路径时产生 Candidate；默认不是 Verified。

## N. Upgrade Path

Generic / Generated 应尽量保留 Business、Workspace、Team、Work、Result、Evidence、History 与 identity，在安全时原地升级。无法安全原地升级时，使用 sibling Workspace + controlled Handoff；不得静默复制身份、凭证、历史或 Runtime state。

## O. Autonomous Relation

Autonomous Operating V1 继续复用同一 Core / Runtime 与既有 Operating Lifecycle；本策略只决定 Workspace 形态解析和能力来源，不扩大 V1 Scope、Start Gate 或 Runtime primitive。专业方法仍由 Employee Operating Layer / Package / Skill / Knowledge 消费。

## P. Domain Capability

Domain Capability 是候选语义，用于表达一组面向专业 Domain 的能力需求；执行仍由既有 Capability、Provider、Tool、Agent、Connector 完成，不创建第二套执行 Runtime。XHS、RD、电商等仅为验证案例。

## Q. Ecosystem Direction

第三方 Package、Partner / Community provenance 与后续 Marketplace 是生态方向。任何外部资源进入 Company OS 前仍须经过 identity、permission、quality、evidence 与生命周期边界；本轮不授权 Marketplace 或自动安装。

## R. XHS / RD / E-commerce Implication

小红书、研发、电商、抖音等是 Professional Workspace 形态示例 / Validation Cases，不是 Curis 固定业务类型、默认模板、Core Domain enum 或用户必选路径。任何案例都必须服从通用 Company → Department → Business → Workspace 与责任、结果、证据和恢复合同。

## S. Current Implementation Gaps

- Verified Registry、Professional UX declaration / finite registry productization；
