## 2. Product Positioning

Curis 是面向一人公司创业者的 AI 公司经营系统：一位真实 CEO 经营一家公司，
多个 AI 员工承担责任、执行业务并提供证据。Curis 帮助 CEO 从零创建公司、
选择或设计业务、配置能力、运行 Workspace、获得真实世界结果，并持续经营、
优化和扩展。它不是任务管理器、AI 工作流平台、Agent 集合、BI 仪表盘、CRM、
ERP 或通用聊天机器人。

当前产品以 Local Desktop、单 Owner 使用为主要交付形态，同时保留未来
Platform/Admin 与 Company Runtime 的逻辑边界。计费、租户、模板市场和物理
拆分属于未来商业化，不得描述为已经交付。

Local Desktop 只约束部署方式，不约束 CEO 需要的产品能力。当前用户仍必须能够添加和验证
模型、Skill、Tool、知识与外部连接，将能力分配给 AI 员工和 Workspace，并完成运行、结果
反馈、验收和经营调整；没有云端 API 时允许本地能力或 CEO 手动反馈，但不能以“单机自用”为由省略产品形态。
这里的“必须能够”是产品完整性要求，不等于这些能力必须在同一阶段交付：模型数量、Skill
接入、Tool / Connector、权限、成本、AI 员工供给和 Workspace 运行都必须进入完整产品规划，
只能通过开发顺序分阶段实现。可以延后的仅是多租户、计费、模板市场和 Platform / Admin
商业化包装。

目标产品结构：

```text
CEO
→ Company
→ Company OS（固定经营语义）
→ Business / Outcome / Commitment
→ Cycle 或 Workspace（开放业务运行空间）
→ Evidence / Acceptance
→ Decision / Company Change
```

Company OS 的 CEO 入口是经营、业务、公司、工作空间；已建立公司的默认 CEO 体验是
CEO Operating Day，CEO Assistant 是第一位 AI 员工；Truth、Decision、Assistant
和 Change 是跨切运行面。Workspace 允许不同布局、组件、Agent、Tool、Knowledge、
Capability、Workflow 与 Resource。Task 是内部执行事实，不是产品入口。

全局视觉方向已冻结为 Calm Executive Workspace：中性纯色表面、低对比边界、内容优先
和对话流；禁止把 Curis 设计成多彩 Dashboard 或后台控制台。主题只提供系统、浅色、深色
三种模式，深色使用深灰而非纯黑。主按钮在深色主题使用品牌绿，在浅色主题使用深色；
蓝色仅保留给决策 / 信息语义。

该目标定义由 ADR-0040 冻结；Business Runtime 完成标准由 ADR-0041 冻结。
当前代码仍保留 Project/Task-first 兼容基线；但 First Arrival、Company OS 首批页面、Workspace
Portal、Studio、三业务 Runtime 与首个运行对象已经接入 Runtime；`DESKTOP-RUNTIME-EXECUTION-001`
又增加了显式 `workflow_run:<id>` 执行桥、非伪造 Evidence 和 CEO Review 命令。完整旧链迁移、
三业务 Simulation 创建 / 启动 / 刷新恢复已通过本地浏览器门禁；Studio 候选组织物化、隔离
`ORG-001`、Capability Supply Resource Check、CEO `APPROVE / MODIFY / REJECT`、原子激活和
14 天安全回滚也已通过源码浏览器验收。研发 Operating Cycle 的责任交接、显式执行引用、
Evidence、CEO Acceptance、复盘 Decision 与关闭链现已通过源码浏览器验收；但生产旧 Workflow
真实子执行、新鲜打包 Desktop 复核、外部平台结果、内容业务验收、失败恢复 Simulation 和
Blueprint Revision 仍未完成，不能把 Blueprint 目标态描述为全部已交付。

- 当前 Workspace API 位于 `backend/app/`
- 主要组合入口：`backend/app/main.py`
- 核心运行模块包括 Company/Project Runtime、Employee、Capability Registry、

  Workspace、挂起员工、撤销 Binding 并保留完整决定与转换历史
- Workspace Operating Cycle 在单一事务核对当前 Operating Version 与已激活团队，生成输入 / 输出
  Handoff、非 fixture Evidence、Acceptance 和 DecisionPacket；显式 `workflow_run:<id>` 只作为子执行
  引用，成功等待 CEO 验收，失败原子暂停并降级员工，接受后需明确复盘才能关闭，拒绝保留证据
