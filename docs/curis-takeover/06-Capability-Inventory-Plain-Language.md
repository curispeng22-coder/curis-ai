# Curis 产品「已实现能力 vs 缺口」白话盘点

Status: Deprecated

> 本文是早期接管盘点，不是当前产品或开发依据。当前事实以 `docs/00_Context/CURRENT_STATE.md`、唯一 Product Blueprint 4.12 和 Business Runtime v1.0 为准。

> **历史依据（2026-08-03）**：当时产品蓝图 `docs/01_Product/Curis_Product_Blueprint.html`（v4.4，Status: Review）+ UI 界面蓝图 `Curis_Product_UI_Blueprint_v1.0.html` + 设计系统 `docs/03_Design/Curis_Design_System.md`（Frozen）+ 当前事实入口 `docs/00_Context/CURRENT_STATE.md`（Frozen）+ `Business_Runtime_Gap_Report_2026-07-31.md`。当前依据见本文顶部说明。
>
> **一句话定调**：今天 Curis 已经把「底层零件」造齐了（公司、员工、项目、任务、能力、知识、记忆、AI 助手都能真跑）；但按最新蓝图，它要长成的那个「一人 AI 公司操作系统」还停在**图纸 + 局部验证**阶段——尤其是每个核心模块的「完整经营生命周期」还没定义完，所以**代码层面的产品重塑目前是被冻结的，不能动**。
>
> 下面用大白话讲清楚：现在能用什么、蓝图要它变成什么、中间差在哪。

---

## 一、先给结论

| 维度 | 今天的状态 | 蓝图的样子 |
|---|---|---|
| 产品定位 | 一个能创建公司、管员工、派任务、跑执行、存知识记忆的**本地桌面 AI 工作台** | 一个**一人 AI 公司操作系统**：一位真 CEO + 一群能担责的 AI 员工，靠「业务→承诺→证据→决策」循环持续经营 |
| 入口模型 | 项目 / 任务优先（Project/Task-first） | 公司 OS 固定 + Workspace 开放（Company OS / Workspace-first） |
| 导航 | 「CEO Office + 项目/员工/能力/执行…」老一套 | 「公司→经营→业务→AI 团队→工作空间 + 会议/决策室」新骨架 |
| 完成度 | 14 个底层模块已交付（见第二节） | 10 个核心模块的「业务运行时」一个都没完整定义完（见第四节） |

**白话总结**：地基和零件是好的、能用的；但「按蓝图把零件组装成完整公司 OS」这一步，被一道门（Business Runtime 蓝图 + 仿真评审）挡着，还没解锁。

## 二、今天已经能用的（已实现能力，白话版）

以下都是 `CURRENT_STATE.md` 标注 **Completed** 的真实交付，不是设计稿：

1. **桌面壳与登录**：本地桌面一键启动，Owner 登录、Session、首次引导都通了；只有一个前端（`frontend/`）、一个数据库（`data/curis.sqlite`）。
2. **公司 / 业务部门**：能建公司、建部门，数据和页面闭环跑通。
3. **AI 员工（Employee）**：能创建、编辑、软删除员工，配「能力档案（Capability Profile）」，并把员工挂到部门/项目上。
4. **项目（Project）**：能建项目、指定负责人、归属业务部门。
5. **任务与执行（Task / Workflow）**：项目里能建任务，异步执行，看状态、结果、失败；工作流步骤、控制状态、断点恢复都在。
6. **成果（Artifact）**：任务产出的真实成果会被存下来，且强制关联回任务。
7. **能力中心（Capability）**：六类能力（Model / Skill / Tool 等）能注册、看详情、启停、绑给员工——这是蓝图里「Capability = 公司资源」的雏形。
8. **模型网关（Model Gateway）**：能人工选模型、单次回退，调用量/成本（AI Usage）有统一计量。
9. **知识（Knowledge）**：能导入资料、手工建资料、检索、看来源。
10. **记忆（Memory）**：能写记忆、更新、检索、沉淀经验，并打成「上下文包」给下次任务复用。
11. **数字员工执行链路**：AI 员工执行有时间线，支持等待补充、人工接管、转派、恢复、取消。
12. **全局 AI 助手（Global Assistant Runtime）**：有身份、快照、通知、问答、命令能力；真能调模型、记用量、出成果——它是跨页面的基础设施（注意：不是旧版那种固定在 CEO Office 的秘书栏）。

> 白话翻译：你今天打开 Curis，能「开公司 → 招 AI 员工 → 派项目任务 → 看它真跑 → 收成果 → 喂知识记忆」，这条线是可用的。

## 三、蓝图里描绘的「完整 Curis」长什么样（UI 交互逻辑视角）

按 UI 界面蓝图，目标产品是这样工作的（这是「缺口」的对照物）：

- **首次到达**：不进空 Dashboard、不给功能导览，而是一间「空白但不空旷」的 CEO 办公室。AI 助手先自我介绍，陪你把意图一步步变成：公司牌匾 → 业务区域 → AI 员工 → 部门办公室。每完成一步，空间里就长出一个可见对象。
- **CEO 工作台 / 今日经营（CEO Operating Day）**：进产品后的主工作面。由「简报头 + 助手简报 + 待办事项 + 经营时间线 + 公司脉搏 + 交接收束」六块组成，由一个「第一位 AI 员工（Chief of Staff）」推动每天的公司运转。
- **经营页面**：六维经营脉搏（信号/趋势/风险/健康…），不是花花绿绿的仪表盘。
- **业务页面**：你的「业务版图」——每条业务有阶段、负责人、目标、关联工作空间。
- **公司页面 + AI Workforce Map**：看全公司 AI 团队分布和每位员工详情。
- **AI 组织控制面**：明确「CEO 治理助手 → 助手协调专业 AI → 专业 AI 出结果 → Workspace AI 在具体空间执行」四层关系，不是平级 Agent 列表。
- **工作空间（Workspace）**：业务真正跑起来的地方，可在「Workspace Studio」里装修、模拟、交付后再运行；不同业务可以有不同长相（研发像 IDE、财经像终端、内容像创作台），但都共用同一套身份/安全/语义。
- **会议工作台 + 决策室**：会议从草稿到归档有完整生命周期，产出「决策包（Decision Packet）」回写公司经营。
- **视觉语言**：「安静的 CEO 工作空间」——中性纯色、低对比边界、内容优先、对话流；深色用深灰不用纯黑；主按钮深色主题用品牌绿、浅色主题用深色；**严禁做成多彩 Dashboard / 后台控制台 / 聊天机器人**。

## 四、缺口在哪（白话版，三层）

### 第 1 层：产品模型缺口（最大的一道坎）
- 当前代码还是 **Project/Task 优先**的旧模型；蓝图要的是 **Company OS 固定 + Workspace 开放** 的新模型。
- 这个迁移被状态 `BLOCKED_PENDING_BUSINESS_RUNTIME_BLUEPRINT` 冻住——**还没有任何页面、路由、组件、Schema 或业务代码开始迁移**。蓝图目标是「未来态」，不能当成「已交付」。

### 第 2 层：业务运行时缺口（10 个核心模块都没「活」起来）
蓝图要求每个核心模块都有完整「经营生命周期 + 状态机 + 输入产出 + 负责人 + 反馈 + 关闭 + 仿真」。缺口报告逐个数了一遍，结论很直白：

| 模块 | 今天到哪步 | 缺什么 |
|---|---|---|
| CEO Office / 今日经营 | 只有页面布局和指标 | 没有从「信号到达→CEO 决策→派发→监控→关闭」的生命周期 |
| 业务（Business） | 有业务版图概念 | 没有「提议→验证→批准→运营→扩张/暂停→关闭」全生命周期 |
| 组织（Organization） | 有结构/部门/员工视图 | 没有招聘/入职/在岗/转岗/离职 lifecycle |
| 工作空间（Workspace） | 有 Portal + 4 种 UI 模型示意 | **完全未实现**；缺申请→设计→审批→开通→配置→仿真→运营→归档 |
| 会议（Meeting） | 有公司/空间拆分 + 短 happy path | 没有草稿到归档的完整生命周期、讨论轮次、执行计划回写 |
| 能力（Capability） | 有资源定义 + 可用/受限等标签 | 没有「需求→评估→采购→授权→绑定→监控→退役」全生命周期 |
| 经营雷达（Insight） | 有信号/趋势/预警页 | 没有信号→确认→分派→解决生命周期 |
| 经营分析（Analysis） | 有委托/证据/建议概念 | 没有委托→分析→建议→CEO 决策→执行跟进生命周期 |
| 知识 & IP | 有归档/展示区 | 没有采集→审阅→发布→复用→废止生命周期 |
| Workspace Portal 组合视图 | 无 | 缺注册/可用/需关注/暂停/归档的组合运行时 |

> 白话：现在每个模块「页面有了、按钮有了」，但**没有把「一件事从生到死怎么流转、谁来负责、卡住怎么办」写清楚**。蓝图把这套规则叫「Business Runtime」，目前一个都没定义完整，所以验收不出来，也就不能宣布任何模块「完成」。

### 第 3 层：UI / 导航缺口
- 当前前端仍是 **Project/Task-first 的老壳**（CEO Office 旧版、项目中心、能力中心旧版等），与蓝图新的「公司→经营→业务→AI 团队→工作空间 + 会议/决策室」导航骨架不一致。
- 设计系统（Calm Executive 视觉语言、三主题、组件规则、助手 UI 规则）**已冻结可用**，但前端还没按它整体翻新；旧 UI V1/V2/V3、静态原型、图片导出都**不算当前实现**。
- 设计系统明确禁止的反模式（多彩卡片、后台控制台、第二套聊天页）在旧界面里仍可能存在，需要按蓝图重构时清理。

### 被明确冻结、暂时不能碰的
- **Project 物理删除**：`BLOCKED_PENDING_CONTRACT`——现在只能软删，不能真删，等独立契约。
- **产品重置迁移**：等 Business Runtime 蓝图 + 仿真评审全过，再开 Issue 才能动。
- **未来扩展**（Web 部署、Mobile、Workspace/Admin 物理拆分、计费/市场/商业后台）：都是「以后」，不是现在的能力。

---

## 五、一句话收尾 + 下一步

**今天 Curis = 可用的「AI 项目执行工作台」；蓝图里的 Curis = 待组装的「一人 AI 公司操作系统」。** 零件齐、底层通，但「每个业务模块的完整生命周期」这道门没过，产品重塑就还不能开工。

下一步要解锁开发，必须先完成：10 个模块的 Business Runtime 蓝图定义 → 独立 Review 通过 → 每个模块跑通 Runtime Simulation → 再开有范围的业务代码 Issue。在那之前，任何「页面完成、按钮完成、接口完成」都不算产品完成。

> 备注：本文只做盘点与白话介绍，不包含任何代码改动；所有「已实现」以 `CURRENT_STATE.md` 为准，所有「目标态」以产品蓝图为准，冲突时已实现事实优先。
