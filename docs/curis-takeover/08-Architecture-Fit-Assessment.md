# Curis 架构承载力评估：现有后端能不能撑起新产品规划

Status: Deprecated

> 本文是 2026-08-03 的历史架构评估。当前运行事实以 `CURRENT_STATE.md`、Business Runtime v1.0 与 Runtime Review 为准。

> 日期：2026-08-03
> 问题：产品架构 + 已实现的后端运行逻辑，能不能满足当前产品规划？还缺哪些基础架构？
> 对照物（历史快照）：`curis-ui-prototype/`（18 页 + 7036 行原型 JS，8/2）× `backend/app/`（98 文件）× 当时蓝图 v4.4 / ADR-0040 / ADR-0041
> 说明：不看视觉，只看**运行逻辑**。前端未接入是已知事实，不在本次讨论范围。

---

## 一、一句话结论

**不能。**

后端不是"没做完"，是**做的是另一个东西**。

现有后端是一台**任务执行机器**（给它一个目标，它能拆图、派活、调模型、验收、失败换招、卡住上抛人）——这台机器是真的，质量也不差。

但新产品规划要的是一台**公司经营机器**（CEO 定方向 → 承诺落到部门 → 按周期自动跑 → 结果回流 → 算账归因 → 沉淀复用）。

这两台机器的**核心名词完全不重叠**。UI 原型里跳动的十几个核心对象，后端数据层**一张表都没有**。

---

## 二、UI 原型到底承诺了什么

先把话说清楚：这套原型**不是效果图**。7036 行 JS 里跑着真实的状态流转、并发排队、成本记账、证据归因。它是一份**用界面写成的需求规格书**。

它承诺的不是"页面长这样"，而是"系统会这样运转"：

### 承诺 1：公司会自己按节奏干活
默认就带三条自动节奏：小红书每天 08:00 研究、抖音每天 18:00 数据回流、公司每周一 09:00 经营简报。CEO 不点，它也到点跑。

### 承诺 2：跑不过来会自己排队
每条业务线有并发上限（默认 3）。超了自动进 `queued`，前面跑完自动按先进先出提上来。CEO 不用管调度。

### 承诺 3：需要你拍板时会自己找你
任务文案里出现"CEO / 授权 / 回传 / 失败 / 异常 / 确认"，跑完自动落 `waiting_ceo` 并推到助理提醒。而且埋了两个时间指标：**你多久才回应**、**你多久才处理完**——这是在量化"CEO 是不是瓶颈"。

### 承诺 4：花的每一分钱都挂在具体的人和模型上
每次运行按预估成本自动记账，带上是哪个模型、哪个 AI 员工、哪条业务线、哪个 runId。

### 承诺 5：成果要有证据，价值要能分账
外部数据（阅读/点赞/线索/订单）回流后，系统自动把关联的多条运行记录收束成一个"成果"，标注证据类型和可信度，再按贡献度给参与的 AI 员工分权重（合计必须 100%）。

### 承诺 6：新业务是"装修"出来的，不是配置出来的
Studio 有七步：Discover → Compose → Bind → Staff → Simulate → Approve → Operate。而且立了**三道硬门禁**——配置问题没修完不许过、模拟没跑通不许过、外部 Agent 没审阅不许过。

### 承诺 7：没有真实数据时，界面不许编
`.audit/` 里 34 张验收截图，专门有一组叫 `*-truth-empty`：business / calendar / shortvideo / workspace-portal 的空态。团队反复验证的是"宁可空着，不许假装有数据"。

**能自洽跑完这七条的完整状态机，UI 已经写完了。**

## 三、后端实际能跑什么

也别低估后端，它有真东西：

| 能力 | 状态 | 说明 |
|---|---|---|
| DAG 任务图 | ✅ 真实 | 依赖判定、拓扑排序、成环检测并拒绝 |
| 常驻调度循环 | ✅ 真实 | 真守护线程轮询，扫就绪节点派发 |
| 失败自愈四级 | ✅ 真实 | 重试 → 换能力 → 重规划 → 升级 CEO |
| 能力降级探活 | ✅ 真实 | 真发探测请求，挂了就换下一个 |
| 真实模型调用 | ✅ 真实 | 含 429 分类、密钥脱敏 |
| 真实研发执行 | ✅ 真实 | 真跑 pytest、真取 git diff、失败真回滚 |
| 人工介入（HITL） | ✅ 真实 | 7 个控制动作，暂停/接管/改派/补输入/恢复 |
| 执行占锁 + 会话恢复 | ✅ 真实 | 心跳续租、超时回收、断点重放 |
| 租户隔离 | ✅ 真实 | 中间件 + 上下文 + 资源策略三层，越权返 404 |

**这九项是资产，不该推倒。** 尤其"失败自愈四级"和"真实研发执行"，是很多团队做半年做不出来的东西。

但问题也在这儿：**这台机器的输入是"一个任务目标"，输出是"一个执行结果"。它不知道什么叫公司、什么叫承诺、什么叫这周该交什么。**

## 四、正面对照：UI 要的 vs 后端有的

| UI 承诺 | 后端现状 | 判定 |
|---|---|---|
| ScheduledRun 九态生命周期（queued→running→waiting_ceo→acknowledged→resolved） | 无此对象。DAG 节点只有 pending/running/done/failed 四态 | ❌ 缺 |
| 定时自动跑（每天 08:00 / 每周一） | `TriggerSpec.scheduled` 存在但**只驱动 DAG，不驱动业务流程**；且 event/condition 两种触发**直接 return True**（形同虚设） | ⚠️ 半 |
| 并发契约 + 自动排队提升 | 无并发契约概念，无队列 | ❌ 缺 |
| 自动升级 CEO + 响应耗时埋点 | 升级机制有（escalations + PendingDecision），**但无耗时埋点** | ⚠️ 半 |
| Commitment（承诺）全生命周期 | **零表**。无 Commitment、无 Goal、无 Objective | ❌ 缺 |
| Workspace（可装修工作空间） | **零表**。`/api/workspace/*` 74 个路由只是 URL 前缀，不是对象 | ❌ 缺 |
| Studio 七步 + 三道门禁 | 无。无 blueprint、无 simulation、无审批门 | ❌ 缺 |
| Cycle（运行周期） | **零表**。无 deadline 驱动 | ❌ 缺 |
| Business（业务方向）+ 价值/执行双健康度 | **零表**。`billing_*` 是平台向租户收费，不是公司自己的经营账 | ❌ 缺 |
| 经营账（收入/成本/AI 产出） | 只有 `ai_usage_records` + `billing_events`（平台计费视角） | ⚠️ 错位 |
| OutcomeAttribution（成果归因 + 贡献分配） | `artifacts` 表只有 generated/accepted/archived，无证据链、无多 run 收束、无权重分配 | ❌ 缺 |
| Meeting（会议 → 决议包 → 跟进） | **零表** | ❌ 缺 |
| 业务决策（approve/defer/revise/reject） | 只有 `b_layer_pending_decisions`（技术卡点）和 `evolution_decisions`（技术演化），**不是业务决策** | ❌ 缺 |
| AI 员工状态（暂停/调配/容量） | `employee_instances` 只有 `enabled` 布尔，**无状态机、无容量、无调配** | ⚠️ 半 |
| CEO 办公桌聚合视图 | `/api/ceo/evidence` 有 7 个端点：overview / timeline / org-tree / execution / budget / pending-decisions | ✅ 有（只读） |

**统计：14 项核心承诺，完整支撑 1 项，半支撑 4 项，完全缺失 9 项。**

而且要注意——唯一"✅ 有"的那项是**只读**的。CEO 能看，不能做。

## 五、一个必须说的发现：这些不是"还没做"，是"做过，废了"

`backend/app/database.py` 第 22–53 行有一份 `_RETIRED_EMPTY_TABLES` 清单，31 张表，被明确标记为"早期原型残留，迁移时若为空则删除"。

里面躺着：

```
workspace_goals                    ← 工作空间目标
goal_achievement_confirmations     ← 目标达成确认
goal_criterion_evidence            ← 目标证据
goal_progress_snapshots            ← 目标进度快照
decision_records / decision_drafts / decision_audit_events   ← 决策三件套
content_routines                   ← 内容自动节奏
content_routine_runs               ← 自动节奏运行记录
secretary_profiles / conversations / messages / suggestions / mode_preferences  ← AI 秘书五件套
employee_sessions + 6 张员工会话/记忆表
```

**看清楚：`content_routines` + `content_routine_runs`，正是 UI 原型里"自动节奏 + 运行记录"的对应物。做过，空了，进了退役名单。**

`goal_*` 四张表，正是"承诺"的前身。也废了。

`secretary_*` 五张表，正是"AI 助理"的前身。也废了。

这说明什么？**不是团队没想到，是之前那版实现方式没跑通，被主动清掉了。**

所以这次重建，不能当成"补几张表"来做。必须先回答上次为什么废——我的判断是：上次是**先建表再想语义**（表建出来一直是空的，说明没有任何真实流程往里写数据）。这次必须**先定义生命周期，再落表**。

这也正是 ADR-0041 要求"每个模块必须定义完整 Business Runtime 才算完成"的原因——那条 ADR 就是上次翻车的补丁。

## 六、缺的基础架构清单

分两类。**A 类是地基，B 类是房间。地基不修，房间盖起来还会塌。**

### A 类：运行时地基（5 项，全部缺失）

**A1. 统一状态机引擎**
- 现状：全后端只有 2 个 Python Enum，其余状态**全是裸字符串**，散落 12 套，无集中定义、无流转校验。
- 已出事：`workflow_runtime` 代码写 `'succeeded'`，而数据库 CHECK 约束写的是 `'completed'`——**枚举值和约束对不上，属于随时会炸的漏洞**。
- 要什么：状态定义集中化 + 合法流转表 + 非法流转直接拒绝 + 流转事件自动落审计。
- 为什么最优先：UI 承诺了至少 10 套状态机（ScheduledRun 九态、Commitment 六态、Workspace 四态、决策四选一…）。没有引擎，就是再写 10 套裸字符串，重演一遍今天的混乱。

**A2. 持久化任务队列 + 后台 Worker**
- 现状：全项目 grep `celery|redis|rq|apscheduler` → **0 命中**。调度器状态**纯内存**（进程级字典），**重启 = 所有在跑的东西全丢**。后台并发只有 3 处裸线程。
- 要什么：任务持久化落库、worker 独立进程、重启可恢复、失败可重投、可观测。
- 为什么必须：UI 承诺"每天 08:00 自动跑"。内存态调度器意味着——你晚上重启一次服务，第二天早上什么都不会发生，而且**没人知道它没跑**。

**A3. 事件总线**
- 现状：模块间靠**构造函数注入 + 硬调用**耦合，无 publish/subscribe。
- 要什么：领域事件（运行完成、承诺变更、结果回流、决策裁定）广播，下游订阅。
- 为什么必须：UI 里"外部数据回流 → 自动收束多条运行 → 自动推进内容阶段 → 自动写账 → 自动更新业务健康度"是**一条五级连锁反应**。硬调用写这个，就是五个模块互相 import，改一处崩一片。

**A4. 异步化 + 并发契约**
- 现状：169 个路由里 **164 个是同步 `def`**，模型调用用同步 urllib/httpx。一次 LLM 调用**占死一个线程池 worker**直到超时。
- 要什么：IO 密集路径异步化 + 按业务线的并发额度控制（UI 明确要求 `maxConcurrent`）。
- 为什么必须：UI 承诺"超限自动排队"。没有并发契约，这个承诺无处落地；不异步化，并发上限就是线程池大小，几个慢请求就能拖垮整个服务。

**A5. 拆分单体 + 统一响应契约**
- 现状：`main.py` **4677 行内联 169 个路由**；`routers/` 目录**只有一个 87 行的 home.py**（拆分覆盖率 <1%）；**无全局异常处理器**，错误结构每个 handler 自己编。
- 附带：`database.py` 是个 6132 行 / 160 方法的 God Class，DDL、迁移、37 个 seed、全部 DAO 挤一起；另有 **5 张旁路表散在独立 sqlite 文件**里，无跨库事务。
- 为什么必须：前端马上要接。**接口结构不统一，前端要为每个接口写一套错误处理**，这个债越晚还越贵。

### B 类：领域模型（6 组，全部零表）

| 组 | 缺什么 | 依赖 |
|---|---|---|
| B1 **Commitment** | 承诺对象 + 六态生命周期（pending→active→pending_revision/paused）+ 周期计数 + 与部门/业务的绑定 | A1 |
| B2 **Workspace / Blueprint** | 工作空间对象 + 装修蓝图 + 模块组合 + 外部 Agent 导入审阅 + 模拟结果 + 三道审批门 | A1 |
| B3 **Cycle / Routine / Run** | 自动节奏定义 + 运行实例九态 + 并发契约 + 排队提升 + 耗时埋点（含 CEO 响应/处理时长） | A1 A2 A4 |
| B4 **Business / 经营账** | 业务方向 + 价值/执行双健康度 + 公司自己的收入成本（区别于平台计费）+ 扩容/暂停/关闭决策链 | A1 A3 |
| B5 **Outcome / Evidence / Attribution** | 成果归因 + 证据链（类型/引用/可信度/采用状态）+ 多 run 收束 + 贡献权重分配 | A3 |
| B6 **Meeting / Decision** | 会议 + 发言分类（事实/观点/未知）+ 决议包 + 会后跟进；业务决策四选一（approve/defer/revise/reject） | A1 A3 |

另外两个**不是缺表、是缺语义**的：
- **AI 员工状态机**：`employee_instances` 现在只有 `enabled` 布尔。UI 要暂停/调配/容量/职责/交接——这是从"开关"升级成"责任主体"，对应 ADR 里"AI 员工是责任主体不是聊天角色"。
- **两条执行栈合流**：现在 `Scheduler+TaskGraph+PipelineRuntime`（有自动化，无组织语义）和 `WorkflowRuntime`（有组织语义，无自动化）**完全不通**。UI 要的是"AI 员工按节奏自动干活"——**恰好需要两者的交集，而这个交集现在不存在**。这是最隐蔽也最致命的一条。

## 七、还有两个坑

**坑 1：能力目录里的东西，运行时是假的。**

`database.py:1573` 的注释自己写着：工具模板 `executable` 默认 0、`mock_or_stub` 默认 1，"当前全库默认目录可见 + Mock/Stub、未配置未执行"。连接器 `current_connector_mode()` 缺省也是 `MOCK`。

也就是说——能力中心里琳琅满目，点下去大部分不会真的执行。UI 原型对此其实是诚实的（到处留了"CEO 手动补录窗口"兜底），但这个缺口必须写进计划，不能默认它会自己变真。

**坑 2：Business Runtime 定义还没开始写。**

ADR-0041 立了规矩：10 个模块每个都要定义完整业务运行时才算完成。但 `docs/01_Product/` 里目前只有一份 7/31 的 Gap Report，**10 个模块的 Runtime 定义文件一个都还没有**。

按 ADR-0041 的口径，现在**开发是被自己的规矩锁着的**。

## 八、建议怎么走

**先说不建议的：不要现在接前端。**

现在把原型接上后端，只会得到一个"点了没反应"的壳——因为它要调的接口，对应的对象在数据库里根本不存在。接完还得再拆一遍，纯亏。

**建议三步：**

### 第 0 步（前置，不写代码）
把原型 JS 里已经写好的状态机**逐条抄成 Business Runtime 定义**。

这件事的价值被严重低估了：**UI 原型已经把 ADR-0041 要求的东西写了七八成**，只是写在 JS 里，不在文档里。ScheduledRun 九态、Commitment 六态、Studio 三门禁——都是现成的，翻译一下就是定义。

先做这步，能同时解锁 ADR-0041 的门，还能避免"文档和原型两套语义"。

### 第 1 步：修地基（A1 → A2 → A4/A3 → A5）
顺序有讲究：
- **A1 状态机引擎最先**，因为 B 类六组全依赖它。先修它，后面六组是"填配置"；不修它，后面六组是"再写六套裸字符串"。
- **A2 队列紧随**，它决定"自动运行"这个核心卖点能不能成立。
- A4、A3 可并行。
- **A5 拆单体可以边走边拆**，但"统一响应契约"要在前端接入前定死。

### 第 2 步：按 CEO 的一天铺 B 类
不按模块铺，按 ADR-0041 的"CEO 的一天"铺。第一条闭环建议就选 UI 里最完整的那条：

> 定一条自动节奏 → 到点自动跑 → 需要拍板时找到 CEO → CEO 处理 → 外部数据回流 → 收束成果 → 记账归因

这条打通，B1/B3/B5 一起活，而且是**可演示的真实经营闭环**。剩下的 B2/B4/B6 再逐条补。

### 第 3 步：再接前端
地基和第一条闭环都通了，前端接入才是"通电"，不是"补丁"。

---

## 九、最后一句

后端的**执行能力**是资产，别推倒；后端的**经营语义**是空白，得从零建；中间隔着五项地基，一项都跳不过去。

原型不是负担，它是目前**质量最高的一份需求规格**。当务之急不是接它，是**把它翻译成定义**。
