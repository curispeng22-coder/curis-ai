# Documentation Standard

## Document Quality Bar

Documentation must be:

- Clear enough for a new AI agent or human teammate to act on
- Specific about ownership, scope, and gates
- Updated when the underlying process changes
- Short enough to remain reviewable

## Required Sections

Use these sections when relevant:

- Purpose
- Scope
- Owner
- Rules
- Workflow
- Review checklist
- Related documents

## Writing Rules

- Prefer direct instructions over narrative.
- Use lists for operational rules.
- Define approval gates explicitly.
- Avoid placeholders such as `TBD` and `TODO` in approved documents.
- Link to source-of-truth documents instead of duplicating large sections.

## Document Lifecycle

- Draft: Proposed, not yet binding.
- Approved: Binding standard for future work.
- Superseded: Replaced by a newer document or ADR.

Sprint 0 documents are drafts until organization review is approved.
