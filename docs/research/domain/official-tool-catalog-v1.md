## 一、扫描来源与方法

本 v1 工具来源于**主理人主动扫描下列公开生态**（已在每个工具的 `来源` 字段如实标注），经 AI 评估 → 分类 → 生成 Tool Draft → 安全检查后入册。

- **MCP Registry / 官方服务器**（modelcontextprotocol.io/examples、registry.modelcontextprotocol.io）：filesystem / git / github / gitlab / postgres / sqlite / fetch / memory / sequential-thinking / puppeteer / brave-search / slack / google-drive / notion / linear / figma / sentry / playwright / docker 等。
- **社区 MCP 目录**（wong2/awesome-mcp-servers、mcp-awesome.com、punkpeye/awesome-mcp-servers、chatforest workflow-automation MCP）：Zapier / n8n / Pipedream / Activepieces / Make / Supabase / HubSpot 等 MCP 形态。
- **GitHub Trending（2026-07）**：agency-agents、superpowers、agent-skills（addyosmani）、DesktopCommanderMCP、TencentDB-Agent-Memory、CubeSandbox、OfficeCLI、strix、OpenClaw 等 AI Agent / 工具框架。
- **企业 AI 工具分职能榜**（Sales/Marketing/Support/Finance/Data/Dev）：Salesforce Einstein、Apollo、Amplemarket、Jasper、Surfer、Semrush、Intercom Fin、Zendesk AI、OCTA、Ramp、Power BI Copilot、Tableau Pulse、GitHub Copilot、Cursor、Claude Code 等。
- **API / 连接器生态**（Zapier、Make、n8n、Pipedream、Activepieces、Workato、MuleSoft、Power Automate、AWS AppFlow）：连接器型与 code-first 自动化平台。

**提取方法**：对每个工具，先确认其真实能力、认证方式与所需权限（避免凭空编造），再按 Curis 的部门/员工模型映射，最后做安全分级。凡涉及具体私有实现的细节一律抽象为能力描述。

## 二、工具编目规范（字段定义）

每个工具 Draft 必须包含以下字段（单一真相源为本文件；DB `tool_templates` 仅存核心列 `name/description/tool_type/source/version`，富字段以本文件为准）：

| 字段 | 含义 |
|------|------|
| Tool ID | `tl_<name>`，DB 主键 |
| 名称 | 工具中文/官方名 |
| 能力 | 一句话能力描述 |
| 类型 | 代码管理 / 数据库 / 通信 / 知识 / 设计 / 自动化 / 监控 / 搜索 / CRM / 营销 / 支持 / BI / 安全 等 |
| 来源 | 扫描自哪个生态（MCP Registry / 社区 MCP / GitHub Trending / API Marketplace / 开源 Connector） |
| 适用部门 | 公司部门 |
| 适用员工 | 可绑定的 AI 员工角色 |
| 需要权限 | 运行该工具所需的权限范围 |
| 认证方式 | OAuth / PAT / API Key / Service Account / 无 |
| 安全等级 | 高 / 中 / 低（见第三节） |
| 版本 | 编目版本（MCP server 或 SaaS 最新稳定态） |
| 风险评估 | 安全检查结论与缓释建议 |
| 收录状态 | active（已入 DB）/ candidate（仅目录，待二轮评估） |

## 三、安全分级标准

- **高**：拥有对外写能力 / 可发送消息 / 可改生产数据 / 接触凭证或财务 / 可触发大量外部动作。→ 默认最小权限（读写优先降级为只读）、凭证走保管不落盘、建议沙箱内执行、需人工审批开通。
- **中**：只读外部数据或受控读写，认证明确，数据含部分敏感（客户/通话）。→ 明确 scope、限定数据范围、审计日志。
- **低**：本地/沙箱执行，不接触外部凭证或仅本地文件，无对外发送。→ 默认可用，仍需访问控制。

> 红线：本目录**只编目元数据**，不接入任何真实凭证、不建立对外 Marketplace、不做真实 instantiation。认证方式仅作"该工具需要什么"的记录。
