## 3. HTML会话可消费的边界

必须遵守产品合同，但本轮不执行：

- 四种Scope传递和保留必要Context，Owner与sender真实；无Owner不伪造。
- 修复Review定位的conv-open缺处理、Work找错人、Account/对象丢失、硬编码目标/旧Work、异步串会话。
- 制作总览保队列，可按方法分组；具体Work仅显示适用步骤和产物，必要规格不推迟到发布前。
- 同Proposal多交付保关联；Work/Variant按执行边界拆分，不能一账号固定一Work。
- 制作结果回原Artifact/Work，并交接发布；发布/复盘回Account经营，不因本轮变成独立生产工具。

UI自由：团队入口具体形态、员工入口位置、产线分组视觉、流程列表/时间线、Artifact预览方式、对话承载布局。自由不包括隐藏当前Owner、让用户猜接收人、丢输入版本或用固定12 Tabs替代适用流程。

## 4. 反证与定向验收

| 场景 | 必须通过的产品判断 |
|---|---|
| Team Owner A、Work Owner B、Step承担人C | 三种入口分别找到合法接收人；指定A咨询C负责步骤时区分交流对象与执行责任 |
| 一位员工同时做三个Work | 讨论一个不暂停其它；异步回复回原Work/会话 |
| 指定人离岗/无Assignment | 说明缺口/合法范围，原历史保留；不得静默冒用新身份 |
| 图文Work | 无无关数字人/视频环节；必要视觉/排版/QA按实际方法显示 |
| 数字人口播 | 资产许可/版本、脚本、方法能力、合成/剪辑/字幕/QA依赖明确 |
| 同选题三种形式 | 共享Proposal与来源，独立方法可拆Work；每个目标只有合法交付，不生成无需求组合 |
| 相同方法仅账号语气不同 | 可同Work多账号Variant，不强制拆Work |
| 修改Script v2且下游已用v1 | 保v1历史，说明受影响合成/字幕/QA，未受影响工作可继续 |
| 发布权限不足 | 不自动删Target；已合法制作可保留，发布等待，不能假装交付已有经营效果 |
| Envelope允许自动经营 | 系统形成明确交付即自主推进，不每轮强制CEO表单 |
| 方法未知或能力不可用 | 允许准备/可行性Work，正式制作诚实Blocked；不让HTML作者发明支持能力 |
| 节点只是一条Tool调用 | 不强制新Employee/Work/Runtime，用已有步骤事实表达 |

这些为后续验收条件，本轮未执行HTML操作，不能写成运行测试通过。
