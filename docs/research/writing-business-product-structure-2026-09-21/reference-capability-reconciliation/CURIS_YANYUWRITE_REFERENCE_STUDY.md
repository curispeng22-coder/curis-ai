## 1. 小说工作流：作者先决定什么

侧栏十步依次为：创作方向→搭建框架→世界观细化→角色设定→主线剧情→分卷及亮点→锁定框架→章节大纲→确认大纲→正文写作。后九步在初始态禁用。

创作方向实际有：书名、故事灵感、目标读者、人称、可搜索的多选题材、故事内核、篇幅、文风基调、平台行文风格、爽点及避雷要求。选择悬疑推理后出现相应平台风格推荐。确认进入框架会先选择精简/完整生成模式；此后触发会员门槛，未看到生成框架。

**价值（INFERENCE）**：把开书决定具体化，减少“空白正文＋问AI”的起步负担；世界、角色、主线、卷纲在正文前明确存在，正好反证不能把作品页压成章节列表。

**不直接照搬**：不强制每本书走十步，不把读者分区等同人物性别或题材；平台风格是该站概括，不是平台官方规范；默认大批标签平铺、重复出现文风/爽点，并不一定适合Curis。需要保持先写、先人物、先结局等自由进入方式。

## 2. 工具如何表达专业工作

以下是实际可见分类与入口，不是成功生成验收。完整观察文本在同目录JSON证据中。

| 工作 | 观察到的具体任务 | 可转化给Curis的价值 |
|---|---|---|
| 构思 | 命名、概念发散、简介、开篇、章末钩子、标签、开篇检查 | 作为定位/章节上的编辑请求，不另建七个应用 |
| 世界与角色 | 世界、人物、人物关系、时间线；角色一致性和行为口癖 | 不只填姓名背景，要有动机/成长/关系和当时状态 |
| 体系与道具 | 等级、势力、道具、能力规则及平衡检查 | 世界条目按题材启用相关字段，不强迫都市小说填修炼等级 |
| 框架 | 总纲细纲、冲突、伏笔、情绪节拍、反转、支线、结局、伏笔回收 | 作者在当前情节上直接讨论并确认可用计划；不能只创建“研究任务” |
| 正文 | 对话、场景、神态、卡文方向、动作戏、心理、扩写/精简 | 选段＋当前人物/场景→专项目的→局部候选；不把每个方法变Employee |
| 审查 | 多维审稿、人物一致性、开篇、文风、逻辑 | 分开写作质量和平台声明；返回具体证据与可修改位置 |
| 投稿 | 排版、投稿梗概、断章、字数和风险自查 | 出稿不止“发布”：作者也需要可检查、可导出的作品文件 |

伏笔助手实际表单：故事线索、题材、模型、模板插入和生成入口。尚未看到直接选本书/章节/伏笔档案的控制，因此不能声称它自动维护长期伏笔状态。

小说拆解助手实际表单支持粘贴文本或文件入口，文字说明上限10,000字，并说明输入与输出计量。页面称文件先在浏览器解析，不等于后续AI分析不传文本；本轮未上传用户资料、未执行拆解。免费标签与计费声明须分别读，不能推断零成本。

## 3. 素材如何进入工作

[素材库](https://yanyuwrite.com/prompts)有搜索、平台/标签/框架筛选，区分系统与个人库、模板与提示词。我们搜索“角色冲突弧设计”→去创作，实际进入模板编辑和生成结果页，页面说明结果可复制或发送智能顾问。

**已证实**：资源发现→调用的入口存在。
**未证实**：结果自动成为当前Book角色弧线、作者确认后更新Canon、章节依据随之变化。

Curis应吸收“方法可发现、就地可调用”，但以既有Book/人物/章/选段为目标，结果成为该对象候选；不是把模板全文复制给用户再让用户搬运。更不需要复刻数千提示词库存。

## 4. 导出与长期归属

测试草稿在“我的作品”显示为定方向阶段，有搜索/阶段/状态/题材筛选以及进入创作、导出。

实际导出动线：作品→快速全文或自定义范围→全部/按卷/选章→标题和分隔线选项→排版规范→格式。空测试书0章，立即导出禁用。未成功导出文件，不能声称文件内容正确。平台排版项有会员标记；它们不代表平台官方认可或自动发布。

这提醒Curis补齐独立成书导出；不能把“连载发布包”当全部导出能力。

## 5. 不能照抄的承诺

- 去AI味相关页面强调降低识别分值等；Curis继续以原创表达、人物声纹、重复句式、逻辑与作者质量要求为目标，不采用检测规避指标。
- “平台评分”“黄金三章留存”“爆款”等是工具定位，不能变成真实平台结果保证。
- 素材数量及工具数量是页面显示值，首页与工作台数量措辞不同；数量不能作为成熟度评分。
- 十步引导、模板调用并未证明百万字记忆、伏笔保护、版本恢复或正式稿不被改坏。

## 6. 对Curis的最小补充

优先不是增加功能列表，而是四条实际链：

1. 作品定位→世界/人物/主支线/结局→卷章/场景→本次写作依据。
2. 关系/事件/伏笔的编辑与证据→作者确认→下章按当时状态读取。
3. 文本上的专项编辑/审查→可读局部候选→部分采纳→新版本复查。
4. 正式正文→全书/卷/章节导出；候选与私人研究材料默认不混入。

上述许多能力原始三份研究已提出。妍语网补的是专业动作语言和前后顺序的直观证据，不是证明我们需要第四套Writing产品模型。

### 需要修正此前对分类的理解

这些选择不是仅用于作品列表的筛选标签，而是**作者对生成方向的结构化控制**。页面明确说明使用全部设定形成创作方向；其内部怎样拼接提示词、实际模型怎样遵循，尚未验证。产品层可以确认其意图，不能声称读取到内部提示词。

| 控制维度 | 作者决定的内容 | 应影响什么（Curis候选，不是已验证妍语内部实现） |
|---|---|---|
| 灵感与核心设定 | 本书独特前提、想探索的问题 | 主冲突、角色处境与故事方案 |
| 目标读者 | 阅读期待与受众 | 解释密度、情感关注、叙事承诺；不能机械按性别决定剧情 |
| 题材 | 故事世界与类型约定 | 必要设定、规则、冲突与专业词汇 |
| 故事内核 | 复仇、成长、探险等驱动 | 主支线推进与转折逻辑 |
| 叙事人称 | 谁在讲、谁能知道什么 | 当前视角和信息边界；第三人称不必等于全知 |
| 文风基调 | 克制、幽默、阴郁等表达意图 | 句法、描写、节奏及作者样例选择 |
| 篇幅 | 短篇、长篇、连载等规模 | 卷章规划与展开程度，允许后改 |
| 平台行文参考 | 对目标阅读环境的偏好 | 可选建议，不等于官方标准、签约保证或必须套用套路 |
| 避雷/保留要求 | 不想发生和必须保留的内容 | 生成约束及审稿标准 |

Curis应把这些选择保存为本书可编辑的创作方向，允许与Employee讨论形成候选；当前章可以明确继承或局部覆盖。改动后说明影响未来哪些章/计划，不静默重写已确认正文。后续的框架、人物、场景、正文和审校都应该消费适用的方向，而不是生成前重新询问或丢失。

正确采用标准不是“增加一排分类按钮”，而是能够演示：选择/讨论→确认方向→下游显示使用依据→生成相应候选→作者检查→以后可修订。同一素材换题材/文风的效果对比仍需真实生成验证。

本次结论：方向控制的产品价值明确；**完整十步实操仍未完成**，具体阻塞为当前账号的生成权限。已请用户自行开通权限或指出已使用过的免费推进入口，恢复时从研究草稿继续，不重建项目。
