## 3. 冲突登记：只记录，不执行扩展

### C1 — 视觉主位与Evidence宿主

- 候选诉求：Main可由Evidence占主位。
- Current：Shell首部Consolidation明确“Evidence→Utility”“Result→Reading Utility/maximized Reading”；Blueprint/UI Blueprint维持selected Professional Surface＋Shared Work Area。
- 判定：**若把诉求解释为完整Evidence直接改宿主到Main，则CONFLICT；本轮停止该扩展。**不是Current文件之间的冲突。
- 本轮保留：Evidence可通过Utility最大化获得主要阅读空间；Main可显示判断所需的证据摘要/引用。视觉焦点不等于改变Pane所有权。
- Owner：CEO / Product / Shell Authority。恢复入口：明确裁定是否需要直接Main Evidence，以及返回/工作连续性；Next Gate：独立窄幅产品/宿主Review。本轮不修改Shell。

### C2 — Choice快速采纳与既有P7

- 候选：正常创作选择用中性比较，不一律告警或升级CEO。
- Current：Visual §13“Decision is elevated only when the CEO must make a real judgment”；P7继续规定需审批事项的内容层级与证据。
- 判定：中性表达是REFINE，**若把Choice改名当成免审批、Layer-0直接批准所有变化或扩大决定者权限，则CONFLICT**。
- 本轮保留：按既有授权和风险选表达目的；“不异常”不等于“无需确认”。作者与授权Leader的关系来自已接受产品语言，但不据此自行改P7。
- Owner：CEO / Product。恢复入口：在后续具体Choice设计中核对既有权限/确认范围；需改变P7时单独提交。本轮无审批机制改动。

## 4. 简短反证结论

Content Growth需要交接/队列与参考，RD需要变化审阅，Writing需要连续正文，Music需要试听比较。统一容器、同样导航或固定面积都会破坏至少一个业务，因此已删除/降级固定布局规则。保留：对象/责任/产物连续、可判断状态、可返回的检查、合适媒介空间。
