## 三、完整产品必须补充的部分

### 1. 正式组织主线

```text
CEO
→ 公司
→ 部门
→ 项目
→ 项目负责人
```

项目必须位于部门之下。

项目负责人是 CEO 的主要沟通对象，并对最终结果负责。

### 2. 项目负责人主控循环

```text
CEO提出目标
→ 项目负责人澄清
→ 生成计划与验收标准
→ CEO确认
→ 拆解任务
→ 调用能力
→ 跟踪执行
→ 自动验收
→ 失败返工或重新规划
→ 最终汇报CEO
```

### 3. 统一能力层

需要明确：

```text
员工
外部Agent
模型
Skill
Tool
MCP
API
CLI
Connector
Workflow
```

全部都是项目负责人和员工可动态调用、可替换的能力。

不得把业务逻辑写死到 Codex、WorkBuddy 或某一个模型。

### 4. 三种执行模式

- Agent 模式：研究、创意、开放问题；
- Workflow 模式：稳定、重复、可审计过程；
- 混合模式：Agent 规划，Workflow / Tool 执行。

默认方向为混合模式。

### 5. 项目级上下文与 Session

```text
员工长期身份
+
项目独立Session
+
任务短期上下文
+
项目记忆
+
经验压缩
```

同一员工可以参加多个项目，但不同项目上下文必须隔离。

### 6. 自动调度与任务队列

需要加入：

- 动态任务图；
- Queue；
- 自动领取；
- 优先级；
- 并行项目；
- 定时 / 事件 / 条件触发；
- 超时；
- 重试；
- 暂停；
- 人工接管；
- 换Agent / 换模型；
- 失败升级。

### 7. 成果中心

成果不能只叫 Result，需要统一管理：

- 代码；
- Git Diff；
- 测试结果；
- 文档；
- Demo；
- 网站；
- 图片；
- 视频；
- 数据报告；
- 发布包。

成果必须关联：

```text
公司
→ 部门
→ 项目
→ 任务
→ 执行者
→ Token与成本
```

### 8. 能力中心与前端配置

用户需要在前端直接配置：

- 模型；
- Agent；
- Skill；
- Tool；
- Connector；
- 凭证。

例如新增模型：

```text
填写名称、服务商、模型ID、API地址和Key
→ 测试连接
→ 保存
→ Key进入凭证库
→ 模型状态显示可用
→ 项目负责人可选择调用
```

正常操作不能依赖终端、curl、环境变量或直接改数据库。

### 9. Admin 与 Workspace 关系

```text
Admin
→ 生产官方模板、官方能力和公司包

Workspace
→ 用户创建自己的公司、部门、项目、员工和私有能力
```

官方资产进入 Workspace 后形成用户自己的实例。

### 10. 自演进降级为内部能力

Execution Learning、Meta Development、Evolution Governor、Architecture Lock 可以保留，但只能放在内部治理层。

它们不能继续成为产品主线，也不能阻塞前端交互和用户真实成果。

## 五、原 8 张图分别怎么改

### 图1：产品功能结构图

改为 6 个主要领域：

1. 用户交互层；
2. 公司组织层；
3. 项目负责人和自动任务流层；
4. 能力调度层；
5. 执行与治理层；
6. 成果、记忆和经营数据层。

Admin 资产工厂单独画在右侧，不与 Workspace 运行层混在一起。

### 图2：信息与数据结构图

不要再把 Task 作为唯一产品聚合根。

调整为：

```text
产品聚合根：Project
执行聚合根：Task / Run
```

Project 应包含：

- Goal；
- Project Owner；
- Plan；
- Task Graph；
- Decision；
- Artifact；
- Metrics；
- Cost；
- Project Memory。

Task / Run 应包含：

- Assignment；
- Agent Session；
- Workflow Run；
- Tool Call；
- Trace；
- Result；
- Review / Rework。

### 图3：产品架构图

增加：

- Admin / Workspace 双产品；
- 项目负责人运行时；
- Queue / Scheduler；
- Capability Router；
- Agent Adapter；
- Credential Vault；
- Session / Context / Memory；
- Artifact Store；
- Token / Budget / Audit。

自演进能力放到底部，标注“内部可选”。

### 图4：业务流程泳道图

泳道改为：

```text
CEO
项目负责人
计划与任务调度器
能力路由器
员工 / 外部Agent
执行与验收
成果与项目记忆
```

重点体现项目负责人负责到底，不再固定所有席位轮转。

### 图5：页面流程图

改为：

```text
CEO办公室
→ 公司
→ 部门
→ 项目列表
→ 项目运行工作台
→ 能力中心
→ 成果中心
→ 设置
```

项目运行工作台必须包含：

- 项目负责人对话；
- 目标与计划；
- 任务进度；
- 待决策事项；
- 成果；
- 成本；
- 批准 / 返工 / 暂停 / 修改目标。

### 图6：状态机图

除 Task 状态外，增加项目状态。

项目状态：

```text
规划中
→ 待确认
→ 运行中
→ 等待决策
→ 暂停
→ 已完成
→ 已关闭
```

任务状态：

```text
待执行
→ 已分配
→ 执行中
→ 验证中
→ 返工中
→ 已完成
→ 失败
→ 已取消
```

补充：

- 重新规划；
- 重试中；
- 等待CEO决策；
- 阻塞；
- 人工接管。

### 图7：原型图

从“任务输入台”改为“项目运行工作台”。

推荐布局：

- 左侧：公司、部门、项目导航；
- 中间：项目负责人对话、目标、计划、任务进度；
- 右侧：待决策、执行者、成本和风险；
- 底部：代码、Diff、测试、文档、Demo等成果。

### 图8：交互说明图

更新为：

```text
CEO输入目标
→ 项目负责人澄清
→ 生成计划
→ CEO确认
→ 任务进入队列
→ 动态选择员工 / Agent / 模型 / Skill / Tool
→ 执行
→ 自动验收
→ 不通过自动返工
→ 成果进入成果中心
→ 项目负责人向CEO汇报
```
