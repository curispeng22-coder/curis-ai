# 共享产品开发规范（产品开发汇报标准）

> 本文档为 AI Company Asset Factory 开发团队与所产出的 AI 员工的统一汇报约定。
> 立项日期：2026-07-11，由总控（CEO）裁定生效。

## 一、为什么要有这条规范

CEO 不会每天看 20 页技术文档。他需要的只有两件事：

- **30 秒**知道发生了什么；
- **5 分钟**做出决策。

所以所有汇报必须短、必须直给结论、必须能直接触发下一步动作。

## 二、适用范围

1. 本软件开发团队（主理人 + 产品 / 架构 / 工程 / QA）的**所有阶段汇报**。
2. 正在开发的 **AI 员工（产品）** 对外汇报，同样遵守本规范——AI 员工给 CEO / 用户的状态与进展，也必须结论先行。

## 三、默认要求

- **语言**：默认使用中文白话，说人话。
- **顺序**：先说结论，再说原因，再说建议。
- **统一格式**（每条汇报都按这三段写）：

```
结论：
发生了什么。

原因：
为什么（只写关键原因，不展开技术细节）。

建议：
下一步怎么做（给可执行的 action，最好带选项）。
```

## 四、禁止项

- ❌ 长篇技术术语堆砌（不要把 endpoint / schema / contract 当汇报主体）。
- ❌ 大量 Contract（契约）描述（契约是给工程师看的，不是给 CEO 看的）。
- ❌ 冗长 Issue 复述（不要大段粘贴 issue / gate 文档原文）。
- ❌ 为了完整而完整（不要凑篇幅、不要面面俱到，抓重点）。

## 五、各角色执行要点（统一三段式）

- **产品经理**：结论=本次结论/缺口；原因=为什么重要或为什么缺；建议=下一步排期或待决项。
- **架构师**：结论=方案定了吗/卡在哪；原因=关键取舍；建议=下一步实现顺序。
- **工程师**：结论=做了什么/是否通过；原因=关键技术决策或风险；建议=下一步或需协调项。
- **QA**：结论=通过/未过；原因=失败根因（一句话）；建议=回归或阻断动作。
- **AI 员工（产品）**：对外汇报同样用 结论→原因→建议，让使用者一眼看懂状态。

## 六、主理人职责

主理人（齐活林）在派发任何任务时，必须在 brief 中带上本规范，并验收交付物是否符合三段式与禁止项。凡不符合格式的汇报，打回重述。
