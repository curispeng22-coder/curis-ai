# 新团队上下文规则

- 默认只读 4 类文件：全局规则、角色说明、当前 Issue、最近证据。
- 单次任务不读取历史会话、全仓文档或全部 Issue。
- 任务结束必须生成不超过 200 Token 的交接单。
- 需要更多历史时，只读取指定来源，不整批加载。
- 发现上下文过重时，先压缩事实和证据，再继续任务。
- 任何角色不得把自己的完整工作日志交给下一角色。

## 角色最小输入

| 角色 | 最小输入 |
|---|---|
| 研究席 | 研究问题、目标用户、指定来源 |
| 规划席 | 研究结论、产品方向、当前状态 |
| 调度席 | Issue、席位、状态、阻塞 |
| 架构席 | Issue、相关代码入口、架构约束 |
| 交付席 | Issue、允许文件、验收标准 |
| 质量席 | Issue、变更范围、验证命令 |
| 安全席 | 敏感边界、相关 Issue/Review |
| 文档席 | 目标文档、规则来源、变更记录 |
