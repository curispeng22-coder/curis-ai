01Product Vision

回答一个问题：Curis 到底是什么，为谁而做，凭什么存在。

1.1 Curis 是什么#

One-line Definition

Curis 是一个面向 CEO / Owner 的 AI Company Operating System：
把公司上下文、组织、能力与执行，收敛成一个可运行、可追溯、可复用的经营闭环。

它不是聊天机器人，不是任务管理器，不是 Agent 框架，也不是提示词工具箱。 Curis 的产品对象是一家公司，不是一次对话。

Curis 不是什么（同等重要）

不是为什么这条边界必须守住
不是 Task ManagerTask 是内部执行载体，不是产品的首要入口。用户的心智入口是 CEO、部门、项目和 Assistant，不是待办列表。
不是 Chat 产品对话产出的价值必须沉淀为 Artifact / Knowledge / Memory / Usage 记录，而不是滚动消失的聊天流。
不是 Agent 框架Curis 不向用户暴露 Agent 编排概念。Employee 是产品对象，Agent 只是 Capability 的一种类型。
不是模型套壳模型通过 Model Gateway 接入且可替换。任何单一模型或单一厂商都不构成 Curis 的架构。
不是 Demo 集合Mock、原型、截图与测试数量都不等于产品完成。未接线就必须显式标注为未接线。

当前交付形态

Local Desktop、单 Owner。架构层面保留 Tenant、Company、Identity 与数据隔离边界，为未来的商业化多租户留门， 但尚未交付的多租户 / Web / Mobile / Billing 能力不得被描述为已完成。

1.2 产品原则#

原则含义违反的典型形态
PR-1 事实优先界面只显示真实发生过的事实。没有事实就显示空态，绝不填充占位数字。用 0、-- 或编造数字冒充经营指标
PR-2 单一执行链所有 AI 执行必须经过 Task → Capability → Model Gateway → AI Usage → Artifact 这一条链。Assistant 绕过 Task 直接改业务对象
PR-3 产出必须沉淀执行结果必须落为 Artifact；有复用价值的经验必须由用户确认后进入 Memory。结果只出现在一次性对话里
PR-4 CEO 视角信息以经营视角组织：公司状态 → 部门 → 项目 → 人 → 执行，而不是以技术模块组织。首页塞满 Job / Queue / Runtime 术语
PR-5 可追溯每个结果都能回答：谁做的、用什么能力、花了多少 Token 与成本、依据哪些上下文。成果与执行记录断链
PR-6 人始终在环AI 可执行，但升级、接管、转派、取消、验收的最终权在 Owner 手里。不可中断、不可接管的黑盒执行
PR-7 收敛而非增生一个前端、一个 Shell、一个数据库、一套 Token、一份 Blueprint。并行的第二套 Workspace / Admin / 设计系统
PR-8 安全默认关闭凭证不进 Git、不进日志、不进 API 响应、不进 SQLite；缺配置时 fail-closed 而不是降级伪造。把 Key 存进业务表或打进日志

1.3 目标用户与角色#

角色在产品中的含义边界
Owner / CEO
主用户		 当前登录的经营者与最终决策人。使用全部页面，拥有全部写权限。 唯一的人类身份。所有关键决策、验收与升级由其完成。
AI Employee 受管理的执行主体：有岗位、职责、部门/项目归属与绑定能力。 不替代 Owner 决策，不能绕过 Task 执行，只能使用已绑定且已启用的能力。
Business Department 经营上下文单元，聚合项目、员工与成果。是 Local Desktop 的日常组织入口。 不是租户、不是登录身份、不是权限主体。
Global Assistant Owner 的常驻助理：读取真实状态、回答查询、下达指令并启动既有 Task。 不是第二套执行引擎；只能调用既有业务服务与既有 Task。
Platform Operator
未来		 未来平台治理角色（能力目录、跨公司策略、用量、审计）。 不是当前默认运行体系，不构成第二个当前产品。

1.4 核心价值#

V1 · 一个地方看懂公司
CEO Office 汇总公司状态、重点项目、风险与最近成果，替代在多个工具间拼凑信息。
V2 · 把 AI 变成可管理的组织
AI Employee 有岗位、有归属、有能力清单、有执行记录，像管理人一样管理 AI。
V3 · 每次执行都可追溯
Task 记录状态与事件，Artifact 记录成果，AI Usage 记录 Token 与成本，构成完整证据链。
V4 · 经验会累积
Knowledge 提供外部事实，Memory 沉淀已确认经验，Context Package 让下一个 Task 自动更聪明。
V5 · 一句话驱动公司
Global Assistant 读真实状态、下真实指令，指令落到既有 Task，而不是另起一套影子系统。
V6 · 本地优先、边界清晰
Desktop 单 Owner 交付，凭证与数据留在本地，同时保留未来商业化的租户与审计骨架。

1.5 产品边界#

IN SCOPE · 当前产品
  • 单一前端 frontend/、单一数据库 data/curis.sqlite
  • Local Desktop Owner 登录与首次 Onboarding
  • Company / Business Department / Project / Employee 闭环
  • Capability 注册、启停与员工绑定
  • Task 执行、控制、时间线、Artifact
  • Knowledge 导入检索、Memory 沉淀复用、Context Package
  • Model Gateway、单次回退、AI Usage 计量
  • Global Assistant Runtime（Identity / Snapshot / 通知 / 查询 / 指令）
OUT OF SCOPE · 当前不做
  • 第二套默认 Workspace / Admin 应用
  • 托管 Web 商业产品、独立 Mobile 产品
  • Billing、Marketplace、完整商业后台
  • Project 物理删除（BLOCKED_PENDING_CONTRACT）
  • Curis Asset Governance Runtime（Foundation 已定义，实现推迟）
  • 把 Mock / 原型 / 设计稿当作产品能力展示
  • CEO Office 固定秘书栏（已废弃方向）
  • Task-first 作为产品默认入口（已废弃方向）

Artifact → TaskArtifact 强制关联 Task，不存在无来源成果。
Knowledge vs MemoryKnowledge = 外部事实与参考资料；Memory = 经用户确认的可复用经验。两者不得互相冒充。

2.4 技术运行架构#

Next.js Frontend

127.0.0.1:8080→ FastAPI Workspace

启动契约唯一启动：CURIS_WORKSPACE_FRONTEND_PORT=3001 ./deploy/curis/start-local.sh；唯一停止：./deploy/curis/stop-local.sh。

6.1 交互链表达式#

每一条交互链用统一的六段式表达。缺任何一段都视为交互定义不完整，不得进入开发。

交互链六段式

  ① 触发        用户点了什么（按钮 / 卡片 / 行 / 键盘）
      ↓
  ② 前端行为    界面立刻做什么（打开抽屉 / 校验 / loading / 乐观更新）
      ↓
  ③ 后端触发    调用哪个域的写或读（不写具体接口路径，写语义动作）
      ↓
  ④ 数据变化    哪个实体的哪些字段变了 / 新增了什么记录
      ↓
  ⑤ 界面反馈    Toast / 状态变化 / 列表刷新 / 错误呈现
      ↓
  ⑥ 落点        停在原页 / 跳到哪个页面 / 打开哪个浮层
约定含义
停留不跳转，当前页内状态变化
跳转 P-xx主区域路由切换到该页面
浮层抽屉 / 弹窗 / 确认卡，主区域不变
乐观更新先改界面再等后端；失败必须回滚并提示
无乐观必须等后端成功才改界面（所有涉及执行与删除的操作）
PLANNED该交互链本 Blueprint 已定义，当前未实现
三条全局交互红线。 ① 不可逆操作（删除、取消执行、清空）一律无乐观更新，且必须二次确认并展示影响面； ② 任何写操作失败都必须把界面回滚到操作前状态，禁止停在"半成功"的中间态； ③ 禁止静默失败——后端报错必须有可见反馈，不允许只打控制台日志。

09Design Principles · 设计原则#

本节只讲视觉与观感，不讲页面结构（那是 Section 05）、不讲交互逻辑（那是 Section 06）。目的是让 Design 阶段有明确的审美坐标，而不是凭感觉发挥。

本节的边界。本节不是设计稿，不是组件库文档，不含具体像素规范。它定义"什么样算对、什么样算错"。高保真设计在 Blueprint 冻结后才开始，届时产出的设计规范是本节的下游，不得反过来修改本节而不改 Blueprint。

9.1 参照坐标

参照我们学什么我们不学什么
Apple克制的层级、充足的留白、内容优先、动效只服务于理解拟物化装饰、过度圆润、大面积毛玻璃
Linear信息密度与可读性的平衡、键盘友好、状态色的克制使用、干脆的过渡冷峻的纯黑科技感（Curis 是"公司"，不是"工具"）

Codex Desktop执行过程的可视化、日志的可读性、任务态的清晰传达面向工程师的术语暴露（Curis 面向 CEO，不面向开发者）

9.2 六条视觉原则

D-1 · 温暖而非冷峻

Curis 是"你的公司"，不是"运维控制台"。底色采用暖米（warm cream）而非纯白或纯灰，主色采用森林绿而非科技蓝。用户长时间停留不应有压迫感。

D-2 · 内容优先，容器隐身

边框、阴影、分隔线只做必要的结构提示。禁止卡片套卡片套卡片。任何装饰性元素都要能回答"去掉它读者会更难理解吗"，答不上来就删。

D-3 · 状态色是语言，不是装饰

绿=完成、蓝=进行、黄=需要你、红=失败、紫=人工、灰=未开始。这六个颜色在全产品含义唯一，不得为了好看在其他地方使用同色。

D-4 · 密度适中，偏向可读

桌面产品可以承载更高密度，但 CEO 是扫视型读者而非逐行阅读者。列表行高、卡片内边距宁可宽一点，让"一眼扫到异常"成为可能。

D-5 · 动效只用于解释因果

抽屉滑入（从哪来）、状态点脉冲（正在动）、数字平滑更新（值变了）。没有解释作用的动效一律不做。刷新时不得整页跳动。

D-6 · 空态是产品的一部分

每个空态都必须有：一句说明"这里将会有什么"、一个明确的下一步 CTA。禁止只放一句"暂无数据"。空态是新用户看到最多的界面。
