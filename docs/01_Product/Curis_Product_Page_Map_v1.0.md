# Curis Page Map v1.0

Status: REVIEW REQUIRED  
日期：2026-08-14  
文档性质：页面级产品地图  
实现边界：本轮只定义页面、状态、进入 / 返回关系和交互责任；不开发代码、不修改一级产品框架、不修改 `Curis_Product_Master_Map.md`、不修改 Runtime 或数据库。

## 0. 文档目的与使用方式

这份 Page Map 把六个一级工作区域继续下钻到“设计师可以画、开发可以拆、用户可以走”的页面级粒度。

它定义：

- 普通用户真正需要进入的页面和工作状态。
- 页面之间的进入、返回、恢复和检查器关系。
- 每个页面的主工作区、上下文侧栏、对话入口和用户介入点。
- 页面空态、首次使用、等待、异常和处理完成后的回收位置。
- 哪些成熟产品模式直接借鉴，哪些是 Curis 的差异层。

它不定义：

- 数据库表、API、内部 Runtime 状态机或实现组件。
- 最终像素尺寸、颜色、字体和视觉稿。
- 任何当前代码已经交付的事实。

## 1. 页面共同契约

### 1.1 固定 Desktop 壳层

```text
固定一级侧栏：我在哪里
  首页 / CEO 工作台
  业务空间
  组织中心
  人才市场
  资料库
  会议
  左下角头像：公司与个人设置

可折叠上下文侧栏：当前上下文是什么
  当前区域的列表、筛选、最近工作、业务或 Workspace 导航

自由主工作区：我正在做什么
  当前区域的入口页、独立 Workspace 或直接工作现场

按需右侧检查器：我正在看 / 修改什么
  当前对象的详情、设置、来源、关系、权限、结果和下一步
```

进入详情优先展开右侧检查器，保持中间工作不丢失。只有需要独立、连续、宽屏工作的内容才进入新的主工作区状态，例如研发代码、终端或会议工作面。

### 1.2 全局能力

所有页面共享以下能力，但它们不增加一级导航：

- CEO Assistant 对话：在当前上下文中处理意图、解释、委派、异常和返回。
- 全局搜索：搜索公司、业务、Workspace、员工、专家、Skill、Connector、资料、会议、结果和历史。
- 最近工作：恢复最近的业务、员工、资料、会议或工作对象。
- 通知 / 待处理：需要 CEO 决定、补充、批准、接管、恢复或查看的事项。
- 当前上下文面包屑：公司 → 业务 → Workspace / 员工 / 会议 / 资料。

默认对话入口是当前页面主工作区内的对话栏、Assistant 按钮或员工直接对话，不常驻成第三栏。对话产生对象或公司状态变化时，必须提供影响预览、确认边界和“进入工作 / 返回原处”。

### 1.3 通用状态处理

每个页面至少支持以下状态，不用把每个状态做成新的导航页：

| 状态 | 页面表现 | 用户可做什么 | 处理后回到哪里 |
| --- | --- | --- | --- |
| 空态 | 说明真实原因、下一步和预期结果 | 创建、导入、连接、招聘、邀请或开始 | 当前入口页或新工作面 |
| 首次使用 | 用一句话说明价值，给最少必要追问 | 由 Assistant 生成预览并确认 | 第一项可感知工作 |
| 等待用户 | 保留原上下文，显示等待原因和影响 | 补信息、批准、修改、接管、恢复、稍后处理 | 原工作对象或待处理队列 |
| 异常 | 显示事实、影响、责任人、回退和下一检查点 | 重试同一对象、修复能力、改用替代、人工回退、暂停 | 原工作，不创建假成功对象 |
| 详情 | 右侧优先展开，保留来源和关系 | 查看、编辑、对话、分配、引用、返回 | 原主工作区 |
| 完成 / 结果 | 显示结果、来源、版本、验收和下一步 | 接受、拒绝、继续、复盘、沉淀 | 来源 Workspace / CEO 工作台 |

### 1.4 Modal 使用边界

Modal 只用于删除、不可逆操作、高风险授权和高影响确认。普通详情、设置、招聘预览、Skill / Connector 说明、文件信息、员工设置和结果查看优先使用右侧检查器或当前工作面。

### 1.5 返回契约

从任何入口进入深层对象，都保留来源：

```text
公司 → 业务 → Workspace / 员工 / 资料 / 会议 → 当前对象
```

处理完成后优先提供“返回原工作”；如果用户从 CEO 工作台进入，则结果还要回收为 CEO 工作台的变化、问题、结果或待决定事项。关闭检查器只关闭对象，不关闭原工作。

## 3. 首页 / CEO 工作台

### 3.1 页面地图

```text
CEO 工作台
├── 公司简报 / 今日变化
├── 问题处理 / 待决定事项
├── 当前运行工作
├── 结果详情
├── 复盘与调整
└── CEO Assistant
```

四者是同一首页的工作状态，不是四套首页。用户从简报、问题、运行工作或 Assistant 进入详情，再返回 CEO 工作台。

### 3.2 页面：公司简报 / 今日变化

| 项目 | 定义 |
| --- | --- |
| 页面名称 | 首页 / CEO 工作台：公司简报与今日变化 |
| 用户为什么来到这里 | 了解公司最近发生了什么，并决定今天先关注什么 |
| 用户最想解决的问题 | 哪些变化重要，哪些需要我介入，哪项工作值得继续 |
| 页面主要对象 | 公司、业务、Workspace、员工、结果、问题、待决定事项 |
| 左侧上下文栏 | 最近工作；业务列表；当前运行；待处理筛选：需决定 / 等待我 / 仅知会 |
| 中间主工作区 | 公司简报、今日变化、重要结果、风险和下一检查点；按影响排序，不做数据大屏 |
| 右侧检查器 | 点击变化或结果时展开：发生时间、影响对象、负责人、来源、版本、新鲜度、下一步 |
| 对话入口 | 简报下方或右上 Assistant 入口；自动继承公司上下文 |
| 页面主操作 | 处理当前最高影响事项，或“继续今天最重要的事” |
| 次级操作 | 进入业务、员工、Workspace、会议、资料；查看全部待处理；搜索 |
| AI 自动做什么 | 汇总真实变化、去重低影响通知、解释重要性、准备建议和返回路径 |
| 用户什么时候介入 | 方向、成本、权限、外部副作用、结果验收、暂停 / 恢复或责任变化时 |
| 空态如何引导 | 尚无公司进入首次创建；公司已建但无业务进入第一项业务引导；不显示假指标 |
| 处理完成后回到哪里 | 回到 CEO 工作台，并更新变化、待处理和下一步 |
| 主要参考模式 | ChatGPT 对话入口 + ChatGPT Project 上下文 + Linear 信息层级 + 成熟 Dashboard 的重点摘要 |

### 3.3 页面：问题处理 / 待决定事项

| 项目 | 定义 |
| --- | --- |
| 页面名称 | 首页 / 问题处理与待决定事项 |
| 用户为什么来到这里 | 处理需要补充、批准、拒绝、接管、恢复或确认的事项 |
| 用户最想解决的问题 | 现在为什么卡住，做什么会解除，影响是什么 |
| 页面主要对象 | 问题、DecisionPacket、Handoff、能力缺口、结果验收、异常 |
| 左侧上下文栏 | 按来源筛选：公司 / 业务 / Workspace / 员工；按影响和等待时长排序 |
| 中间主工作区 | 待处理队列；每项显示事实、影响、负责人、用户动作和完成后去向 |
| 右侧检查器 | 原工作上下文、证据 / 来源、选项差异、成本 / 风险、人工回退和下一检查点 |
| 对话入口 | 当前问题卡内的 Assistant；可要求解释、补上下文或拟定回复 |
| 页面主操作 | 完成当前问题要求的真实动作：补充、批准、修改、接管、恢复或暂停 |
| 次级操作 | 稍后处理、转到负责人、打开来源 Workspace、查看历史 |
| AI 自动做什么 | 识别阻塞、准备最少必要信息、给出可比较选项、跟进处理结果 |
| 用户什么时候介入 | 高影响判断、缺失事实、授权、不可逆或外部承诺时 |
| 空态如何引导 | 明确“当前没有需要你处理的事项”，提供返回公司简报或继续工作 |
| 处理完成后回到哪里 | 返回原工作；已完成项离开待处理队列并进入简报 / 历史 |
| 主要参考模式 | ChatGPT 持续任务介入 + Codex / Claude Code 等待用户确认 + Linear Inbox |

### 3.4 页面：当前运行工作

| 项目 | 定义 |
| --- | --- |
| 页面名称 | 首页 / 当前运行工作 |
| 用户为什么来到这里 | 看哪些工作正在继续、等待谁、是否偏离预期 |
| 用户最想解决的问题 | 谁在做、做到哪一步、什么时候需要我 |
| 页面主要对象 | Workspace 工作、员工、交接、阶段结果、等待事项 |
| 左侧上下文栏 | 运行中 / 等待用户 / 失败 / 已完成；按业务和员工筛选 |
| 中间主工作区 | 工作卡片与简明进度；显示当前责任、下一步、预期结果，不展示内部状态机 |
| 右侧检查器 | 工作输入、阶段结果、交接、失败原因、重试范围和返回位置 |
| 对话入口 | 当前工作卡片中的 Assistant 或直接进入负责员工对话 |
| 页面主操作 | 进入正在等待或偏离的工作并处理 |
| 次级操作 | 暂停、查看结果、打开 Workspace、找负责人、返回简报 |
| AI 自动做什么 | 汇总进度、发现等待超时 / 责任未接住、低风险继续和升级 |
| 用户什么时候介入 | 工作边界、失败恢复、结果质量或高影响动作需要决定时 |
| 空态如何引导 | 没有运行工作时引导创建业务 / Workspace 或查看最近结果 |
| 处理完成后回到哪里 | 返回 CEO 工作台；工作继续则保留在当前运行列表 |
| 主要参考模式 | Codex / Claude Code 长任务状态 + ChatGPT 后台工作回收 |

### 3.5 页面：结果、验收与复盘详情

| 项目 | 定义 |
| --- | --- |
| 页面名称 | 结果详情 / 验收 / 复盘调整 |
| 用户为什么来到这里 | 查看一个真实结果是否算数，并决定下一轮怎么做 |
| 用户最想解决的问题 | 结果从哪里来、是否满足目标、下一步继续还是调整 |
| 页面主要对象 | Outcome、Evidence、工作版本、反馈、Acceptance、Decision |
| 左侧上下文栏 | 来源业务、Workspace、员工、关联会议和资料 |
| 中间主工作区 | 结果本体、版本对比、外部反馈 / 人工反馈、目标对照和结论 |
| 右侧检查器 | 来源链、引用、权限、新鲜度、责任、影响和建议改动 |
| 对话入口 | 结果下方 Assistant；可要求解释、改写、复盘或进入负责人对话 |
| 页面主操作 | 接受、拒绝并说明原因，或选择继续 / 调整 / 暂停 / 替换 |
| 次级操作 | 导出 / 沉淀到资料库、召开会议、打开 Workspace、查看旧版本 |
| AI 自动做什么 | 汇总证据、比较目标与结果、发现偏差、提出可验证的调整方案 |
| 用户什么时候介入 | 结果验收、公司方向、外部承诺、资源变化和复盘结论时 |
| 空态如何引导 | 无结果时回到来源工作；无证据时明确“尚不能判断”，不显示成功 |
| 处理完成后回到哪里 | 回到来源 Workspace；Decision 同步出现在 CEO 工作台 |
| 主要参考模式 | ChatGPT 可编辑成果 + Codex Review / Diff + Linear 项目结果视图 |

### 3.6 页面：首次创建公司状态

| 项目 | 定义 |
| --- | --- |
| 页面名称 | 首页 / 首次创建公司：CEO Assistant 创办引导 |
| 用户为什么来到这里 | 第一次打开 Curis，想从一句话开始，而不是先学习组织配置 |
| 用户最想解决的问题 | 我想做什么，Curis 能帮我先完成什么 |
| 页面主要对象 | 用户意图、Company 预览、第一项 Business、最小 Workspace、启动边界 |
| 左侧上下文栏 | 简化为步骤提示：想做什么 → 第一项业务 → 第一项工作；不显示空组织树 |
| 中间主工作区 | Assistant 对话、最少必要追问、业务 / Workspace 预览和首个可感知结果计划 |
| 右侧检查器 | 预览会形成什么、谁负责、需要什么能力、会问用户什么、缺口和人工回退 |
| 对话入口 | 中央主入口，直接聚焦输入目标；可用文字或自然语言继续 |
| 页面主操作 | 确认第一项工作边界并开始 |
| 次级操作 | 修改目标、暂不开始、查看能力缺口、使用人工回退 |
| AI 自动做什么 | 识别意图、生成最小业务方案、建议员工 / Workspace、说明事实与未知 |
| 用户什么时候介入 | 目标、范围、品牌 / 数据边界、外部副作用和是否开始时 |
| 空态如何引导 | “还没有公司”本身就是状态；解释下一步会产生什么，不创建空 Dashboard |
| 处理完成后回到哪里 | 进入第一项 Workspace 工作面；公司简报在完成后可回收结果 |
| 主要参考模式 | ChatGPT 对话首屏 + Relevance AI 自然语言创建 + Workbuddy 专家团预览 |

### 3.7 页面：已建立公司但尚无业务

| 项目 | 定义 |
| --- | --- |
| 页面名称 | 首页 / 第一项业务引导 |
| 用户为什么来到这里 | 公司已经存在，但还没有可产生结果的业务 |
| 用户最想解决的问题 | 下一项值得开始的业务是什么，怎样以最小成本开始 |
| 页面主要对象 | Company、业务建议、Workspace 起点、能力缺口、启动检查 |
| 左侧上下文栏 | 公司概览、业务为空态、人才市场 / 资料库快捷入口 |
| 中间主工作区 | Assistant 询问目标并生成第一业务与 Workspace 预览 |
| 右侧检查器 | 方案影响、需招聘 / 安装 / 导入的资源、人工回退和第一结果 |
| 对话入口 | 中央 Assistant |
| 页面主操作 | 确认第一项业务并开始搭建 |
| 次级操作 | 浏览专家、导入资料、先创建空业务草案、回到公司设置 |

| 处理完成后回到哪里 | 进入 Workspace 搭建预览或第一项 Workspace 工作 |

## 4. 业务空间

## 5. 研发 Workspace：完整 Page Map 示例

研发 Workspace 是页面地图的完整示例，不代表所有 Workspace 都采用这套布局。它参考 Codex、Claude Code、ChatGPT Project 和 Workbuddy，把对话、项目上下文、文件、Git、代码、终端、测试、Review 和多员工协作放进同一间可持续恢复的数字办公室。

### 5.1 研发页面关系

```text
业务空间 → 研发工作台
├── 研发办公室入口

├── 终端 / 运行
├── 测试 / 验证
├── Review / 交付

└── 等待、失败、恢复与返回
```

## 11. 页面进入与返回关系

### 11.1 主关系图

```text
第一次打开
  → CEO Assistant 创办引导
  → 第一项业务 / Workspace 预览
  → 启动检查
  → 第一项真实工作
  → 结果 / 验收
  → CEO 工作台

CEO 工作台
  → 业务空间总览 → 业务详情 → Workspace 独立工作面
  → 组织中心 → 员工工作面 → 回来源业务 / Workspace
  → 人才市场 → 招募 / 安装 → 组织中心 / 设置 → 回原工作
  → 资料库 → 资料详情 / 引用 → 回原工作
  → 会议 → Company / Workspace Meeting → 决定 / 责任 → 回来源工作
```

### 11.2 进入规则

- 一级侧栏点击只切换工作区域，不丢弃未完成的主工作；必要时保存工作上下文。
- 从业务进入 Workspace 后，第二侧栏切换为 Workspace 自有导航；可折叠并保留返回业务入口。
- 从任何卡片点击员工、专家、Skill、Connector、资料、结果或设置项，默认打开右侧检查器。
- 只有研发代码、终端、测试、Review、会议等需要连续宽屏操作的工作进入主工作区状态。
- 从人才市场进入招聘 / 安装时，来源工作保留在上下文中；完成后返回来源，不送到孤立的员工或设置页。
- 从 CEO 工作台进入问题 / 结果时，处理后必须有回 CEO 工作台的路径，并显示该事项已产生的变化。

### 11.3 关闭与返回规则

- 关闭检查器：回到当前主工作区，不改变对象状态。
- 取消新建 / 招聘 / 安装：回到来源页面，保留未提交输入为草案或明确丢弃确认。
- 完成高影响确认：回到原工作并显示影响、结果和下一步。
- 失败：回到同一对象的异常 / 等待状态，提供同对象重试、替代、人工回退或暂停；不新建成功副本。
- 会议结束：Company Meeting 回 CEO 工作台，Workspace Meeting 回 Workspace；决定和后续责任必须可追踪。
- 重启 / 恢复：优先恢复公司、业务、Workspace、员工和未完成工作上下文；状态以持久化事实为准。

```text
→ 专家详情
→ 招募预览
→ 确认公司身份、岗位、部门 / 业务、汇报关系、能力和权限
→ 招募完成
→ 组织中心员工详情
→ 组队进入一个 Workspace 或直接对话
```

如果只需要某个环节能力，则在招募预览中选择“仅作为当前环节能力”，不将其伪装成公司员工。

### 12.4 给员工增加 Skill

```text
组织中心员工详情
→ 右侧员工能力设置
→ 发现能力缺口
→ 人才市场 Skill 列表 / 详情
→ 安装 / 引入
→ 选择员工 / Workspace 使用范围
→ 权限 / 版本 / 影响检查
→ 返回员工详情或 Workspace 启动检查
→ 下一轮工作观察结果
```

### 12.5 创建 Workspace 并组队

```text
业务详情
→ 新建 Workspace
→ 描述工作目标或选择模板
→ Workspace 搭建预览
→ 从已有员工选择团队
→ 明确每人责任和交接
→ 启动检查
→ 进入 Workspace 独立工作面
```

组队不等于招聘，不复制员工身份，不抹掉员工历史。

### 12.6 进入研发 Workspace 工作

```text
业务空间
→ 研发 Workspace 入口
→ 选择 / 创建研发工作线程
→ 对话描述目标
→ @产品 / 开发 / 审查员工
→ 文件、代码、Git、终端、测试
→ Review
→ 用户接受、退回或提出局部修改
→ 结果 / 复盘
→ 回研发办公室和 CEO 工作台
```

研发 Workspace 允许用户在同一工作上下文内切换对话、文件、Diff、终端、测试和 Review；切换不是重新进入独立产品页面。

### 12.7 导入本地或外部资料

```text
当前 Workspace / 员工 / 会议
→ 打开资料库入口
→ 本地资料 / 本地文件夹，或外部资料库 / Connector
→ 查看来源、权限、范围和新鲜度
→ 导入 / 授权 / 索引
→ 资料详情
→ 引用回当前工作
→ 后续在资料库查看使用关系
```

连接或导入失败时回到原工作，提供修复、替代资料或人工继续；不显示已同步的假状态。

### 12.8 召开一次会议

```text
CEO 工作台问题 / 结果，或 Workspace 当前工作
→ 创建会议
→ Assistant 准备议题、参与者、资料和分歧
→ 选择 Company Meeting 或 Workspace Meeting
→ 多员工讨论和资料引用
→ 结论 / Decision
→ 后续责任与检查点
→ Company Meeting 回 CEO 工作台；Workspace Meeting 回 Workspace
```

### 12.9 从 CEO 工作台处理一个问题

```text
CEO 工作台问题处理
→ 查看事实、影响、负责人、来源和选项
→ 补充信息 / 批准 / 修改 / 接管 / 恢复 / 暂停
→ 原工作继续或进入复盘
→ 待处理事项关闭
→ 简报更新变化和下一步
```

“已读”不等于“已处理”；只有真实动作、责任转移或明确关闭才能离开待处理队列。

### 12.10 从结果进入复盘并调整下一轮

```text
Workspace 结果
→ 结果详情：来源、版本、反馈、新鲜度和目标对照
→ 用户验收 / 拒绝 / 标记未验证
→ Assistant 准备原因分析和调整方案
→ 复盘：技能 / 知识 / 工具 / 权限 / 上下文 / 工作方式 / 模型
→ 用户确认影响和版本变化
→ 下一轮 Workspace 工作
→ 结果比较与公司资料沉淀
→ CEO 工作台简报
```

## 13. 页面级设计与开发检查清单

设计师开始 UI Blueprint 前，每个页面必须能回答：

- 页面是否有唯一的用户问题和一个主操作？
- 左侧上下文栏是否只负责“我在哪里 / 当前上下文”？
- 中间是否保留真正的工作现场，而不是把检查项堆成后台面板？
- 右侧检查器是否按需出现，关闭后当前工作不丢失？
- 对话入口是否在当前上下文，而不是强迫用户切换到另一套聊天产品？
- 空态是否说明事实、原因、下一步和预期结果？
- 首次使用是否先给价值预览，而不是要求理解内部对象？
- 等待 / 异常是否保留同一对象、责任、原因、回退和返回路径？
- 结果是否有来源、版本、验收 / 未验证状态和下一步？
- 处理完成后是否回到原工作、业务或 CEO 工作台？
- 普通详情是否用检查器而不是新页面或 Modal？
- 该页面是否误把目录、Draft、连接或调用成功当成产品完成？

开发拆分时，每个页面至少要单独考虑：入口、正常工作、空态、首次使用、等待用户、异常恢复、详情检查器、返回原工作、重新打开恢复和必要的高影响确认。页面、按钮、API 或静态成功状态本身不构成产品完成。

本轮未发现必须修改一级产品框架的跨模块结构冲突。六个一级区域、左下角头像菜单、全局 Assistant / 搜索 / 通知和“固定一级侧栏 + 可折叠上下文侧栏 + 自由主工作区 + 按需右侧检查器”均可承载本页面地图。
