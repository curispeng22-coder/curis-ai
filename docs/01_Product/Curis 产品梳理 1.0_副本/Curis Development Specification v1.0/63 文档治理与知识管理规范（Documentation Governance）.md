# Curis Development Specification

# 63 文档治理与知识管理规范（Documentation Governance）

版本：v1.0-draft

---

# 1. 规范定位

本文档用于定义：

Curis开发过程中所有文档如何：

- 创建；
- 分类；
- 更新；
- 版本管理；
- 废弃；
- 被AI开发Agent使用。

目标：

保证：

```
产品方向一致

↓

技术决策一致

↓

开发上下文连续

↓

AI工具切换不中断
```

---

# 2. 核心理念

文档不是记录。

文档是：

Curis的长期组织记忆。

---

尤其在：

- 多AI开发；
- 多工具切换；
- 长周期研发；

环境下。

正式文档必须成为：

唯一可信来源。

---

# 3. 文档体系结构

Curis文档分层：

```
战略层

↓

产品层

↓

架构层

↓

开发层

↓

执行层

↓

历史层
```

---

# 4. 战略层文档

定位：

定义Curis方向。

---

核心：

```
Curis Product Bible
```

---

内容：

- 产品定位；
- 用户模型；
- AI公司模型；
- 商业方向。

---

修改权限：

高。

---

# 5. 产品层文档

定位：

定义具体产品能力。

---

包括：

- 页面规格；
- 用户流程；
- UI交互规范；
- 业务定义。

---

依据：

Product Bible。

---

# 6. 架构层文档

定位：

定义系统如何实现。

---

包括：

- Backend Architecture；
- AI系统架构；
- Memory；
- Context；
- Capability；
- Agent体系。

---

修改要求：

需要评估影响范围。

---

# 7. 开发层文档

定位：

指导代码实现。

---

包括：

- API规范；
- 数据库规范；
- 前端规范；
- 测试规范；
- 部署规范。

---

开发团队主要依据。

---

# 8. 执行层文档

定位：

指导当前工作。

---

包括：

- Sprint计划；
- Development Task；
- Handoff Report；
- Bug记录。

---

特点：

高频更新。

---

# 9. 历史层文档

定位：

保存历史。

---

包括：

- 废弃设计；
- 旧架构；
- 旧代码说明；
- 实验方案。

---

目录：

```
Archive
```

---

# 10. 文档优先级规则

当文档冲突：

按照：

```
Product Bible

↓

Development Specification

↓

Task Document

↓

聊天记录
```

---

优先级从上到下递减。

---

# 11. AI开发Agent读取规则

AI开发Agent不能读取所有文档。

---

根据任务加载：

```
产品上下文

+

模块规范

+

技术规范

+

当前任务
```

---

例如：

开发项目页面：

读取：

```
项目页面规范

+

前端组件规范

+

API规范
```

---

不读取：

无关商业文档。

---

# 12. 文档关联机制

每个开发任务必须关联：

```
Task

↓

Product Reference

↓

Technical Reference

↓

Code Change
```

---

例如：

任务：

开发能力切换器。

---

关联：

```
产品：

能力切换规范


技术：

Capability API


前端：

Capability Switcher组件
```

---

# 13. 文档版本管理

所有正式文档：

必须版本化。

---

格式：

```
Major.Minor
```

---

例如：

```
v1.0

正式版本


v1.1

新增内容


v2.0

重大调整
```

# 16. 文档废弃规范

废弃文档：

不能直接删除。

---

进入：

```
Archive
```

---

记录：

- 废弃原因；
- 替代文档；
- 时间。

---

# 17. AI生成文档规范

AI可以生成：

- 技术说明；
- API文档；
- 测试报告；
- 开发记录。

---

但必须：

经过确认。

---

AI生成内容：

默认状态：

Draft。

---

# 18. 文档与Memory关系

重要经验：

不直接保存聊天。

---

流程：

```
开发过程

↓

总结

↓

形成文档

↓

提取Memory
```

---

文档：

保存组织知识。

Memory：

保存AI执行经验。

# 22. 文档质量标准

优秀文档：

必须：

## 可理解

新人可以阅读。

---

## 可执行

开发可以依据。

---

## 可追踪

知道来源。

---

## 可维护

支持更新。

---

# 23. 验收标准

文档治理完成后：

必须达到：

---

## 单一事实来源

团队知道看哪里。

---

## AI上下文连续

工具切换不会丢失方向。

---

## 开发可追踪

知道为什么这么设计。

---

## 历史可回溯

知道过去发生什么。

---
