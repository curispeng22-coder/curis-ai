# Curis Development Specification

# 67 Curis MVP开发范围冻结清单（MVP Scope Freeze）

版本：v1.0-draft

---

# 1. 规范定位

本文档用于冻结 Curis MVP 第一阶段开发边界。

目标：

防止开发过程中：

- 无限扩展；
- 提前开发未来功能；
- 偏离核心产品；
- 将MVP做成简单工具或过度复杂平台。

---

# 2. MVP核心定义

Curis MVP：

不是：

- ChatGPT外壳；
- 任务管理工具；
- 模型管理工具。

---

Curis MVP是：

> 一个用户可以创建AI组织、配置AI员工、管理业务项目、调用AI能力并完成真实工作的AI Workspace。

---

# 3. MVP必须完成范围

## 3.1 AI组织体系

必须支持：

```
Company

↓

Department

↓

AI Employee
```

---

用户可以：

创建公司。

创建部门。

创建员工。

配置员工职责。

---

# 3.2 AI员工体系

必须支持：

员工：

包含：

```
Role

Responsibility

Capability Profile

Memory

Project Relation
```

---

示例：

```
内容负责人

职责：

管理内容增长项目


能力：

GPT

热点分析Skill

文案Skill
```

---

# 3.3 项目体系

必须支持：

项目作为业务执行容器。

---

项目包含：

```
目标

团队

任务

资料

成果

状态
```

---

项目类型不限。

支持：

- 软件研发；
- 内容运营；
- 知识管理；
- 研究分析。

---

# 3.4 任务体系

必须支持：

用户自定义任务。

---

任务来源：

## 用户创建

例如：

“分析10个竞品账号”。

---

## 项目拆解

例如：

“小红书增长项目”。

拆解：

- 热点分析；
- 选题生成；
- 内容制作。

---

## 员工执行

例如：

研发员工执行代码任务。

---

# 3.5 Capability体系

必须支持：

内部能力管理。

---

包括：

```
Model

Agent

Skill

Tool

Workflow

Connector
```

---

注意：

这是Capability Registry。

不是Marketplace。

---

# 3.6 已有Skill迁移

之前Admin团队创建的Skill：

保留。

---

处理：

```
Existing Skill

↓

Capability Registry

↓

Employee Capability
```

---

例如：

内容类：

```
热点分析Skill

文案Skill

SEO Skill

图片生成Skill
```

---

研发类：

```
代码分析Skill

测试Skill

Git Tool
```

---

# 3.7 Workflow体系

必须支持基础Workflow。

---

例如：

内容流程：

```
热点分析

↓

选题

↓

文案

↓

审核
```

---

研发流程：

```
需求

↓

开发

↓

测试
```

---

MVP：

支持配置和执行。

---

不要求：

自动生成Workflow。

---

# 3.8 Model体系

必须支持：

模型接入。

---

包括：

- Provider；
- Model；
- API配置。

---

例如：

```
OpenAI

Claude

Gemini

New API
```

---

MVP：

人工选择。

# 5. MVP不实现范围

以下功能明确延期。

---

# 5.1 智能调度中心

延期。

---

MVP：

人工配置：

```
员工

↓

能力
```

---

未来：

```
任务

↓

自动选择能力
```

---

# 5.2 多Agent自治协作

延期。

---

MVP：

支持：

员工调用Agent。

---

未来：

支持：

Agent团队自动协作。

---

# 5.3 自动Memory进化

延期。

---

MVP：

基础：

保存。

查询。

调用。

---

未来：

自动：

总结。

提炼。

优化。

---

# 5.4 Capability Marketplace

延期。

---

MVP：

内部Capability Registry。

---

未来：

第三方能力生态。

---

# 5.5 Enterprise Admin

延期。

---

MVP：

个人Workspace。

---

未来：

企业：

Admin。

权限。

治理。

---

# 6. MVP禁止事项

开发期间禁止：

---

## 禁止重新设计产品模型

例如：

将Curis改成聊天工具。

---

## 禁止拆成两个产品

例如：

独立Workspace产品。

独立Admin产品。

---

## 禁止绑定单一AI工具

例如：

只围绕Codex设计。

---

## 禁止提前开发生态

例如：

能力商城。

开发者平台。

---

# 7. MVP技术原则

必须：

---

## 模块化

支持未来扩展。

---

## 配置化

避免硬编码。

---

## 能力抽象

统一：

Capability。

---

## 数据可迁移

支持未来云端。

---

# 8. MVP完成判断

不是：

页面数量。

---

而是：

用户是否可以完成：

```
创建AI公司

↓

建立团队

↓

创建业务项目

↓

配置能力

↓

执行任务

↓

获得成果
```

---

# 9. MVP冻结规则

MVP期间新增需求：

必须回答：

## 是否影响核心闭环？

如果：

否。

延期。

---

## 是否未来版本能力？

进入Roadmap。

---

## 是否阻碍架构？

优先处理。
