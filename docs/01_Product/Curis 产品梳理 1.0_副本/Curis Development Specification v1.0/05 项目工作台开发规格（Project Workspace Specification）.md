# Curis Development Specification

# 05 项目工作台开发规格（Project Workspace Specification）

版本：v1.0-draft

---

# 1. 页面定位

项目工作台是项目执行核心页面。

项目中心负责：

管理项目。

项目工作台负责：

推动项目完成目标。

---

# 2. 页面目标

用户进入项目工作台后，可以：

- 查看项目状态；
- 与项目负责人沟通；
- 查看计划；
- 管理任务；
- 使用业务工作区；
- 查看资料；
- 查看成果；
- 查看经营数据。

---

# 3. 页面结构

项目工作台采用：

统一骨架

```
Project Workspace

```

# 22. API需求

## 获取项目工作区

```
GET /projects/{id}/workspace
```

---

## 获取任务

```
GET /projects/{id}/tasks
```

---

## 创建任务

```
POST /tasks
```

---

## 获取成果

```
GET /projects/{id}/artifacts
```

---

## 获取经营数据

```
GET /projects/{id}/metrics
```

# 23. 页面状态

支持：

## 初始化

项目创建完成。

---

## 工作区生成中

模板加载。

---

## 执行中

任务运行。

---

## 等待确认

需要用户决策。

---

## 阻塞

存在问题。

---

## 完成

产生成果。

---

# 24. 验收标准

项目工作台完成后：

用户可以：

打开项目。

理解项目状态。

创建任务。

执行任务。

查看成果。

查看数据。

与负责人沟通。

---

检查：

## 通用性

新增业务是否通过模板生成。

---

## 完整性

是否覆盖：

目标。

计划。

执行。

成果。

复盘。

核心：

项目工作台不是任务列表。
