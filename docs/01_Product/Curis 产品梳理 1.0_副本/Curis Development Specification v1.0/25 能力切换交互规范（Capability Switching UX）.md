# Curis Development Specification

# 25 能力切换交互规范（Capability Switcher UX）

版本：v1.0-draft

---

# 1. 设计定位

Capability Switcher 是 Curis 用户侧快速调整执行能力的入口。

目标：

让用户：

- 看见当前使用能力；
- 快速切换模型；
- 快速切换Agent；
- 调整执行策略。

---

# 2. 设计原则

默认：

AI自动调度。

---

用户：

不需要管理复杂能力。

---

但：

高级用户需要拥有即时控制权。

---

因此：

```
自动优先

↓

人工可干预

↓

高级配置隐藏
```

---

# 3. 入口位置

主要入口：

## AI秘书输入框附近

类似：

模型选择按钮。

---

展示：

当前执行能力。

例如：

```
Claude Code
⌄
```

---

点击展开：

Capability Switcher。

---

# 4. Capability Switcher结构

组件：

CapabilitySwitcher

---

展示：

## 当前能力

例如：

```
当前：

Claude Code
```

---

## 自动模式

默认：

```
Auto
```

---

说明：

由智能调度中心自动选择。

---

## 推荐能力

根据当前任务推荐：

例如：

```
推荐：

Codex

原因：

代码修改任务成功率最高
```

---

## 可用能力

展示：

```
GPT

Claude

Codex

Claude Code

Cursor

Trae

WorkBuddy

本地模型
```

---

# 5. 能力类型展示

不仅模型。

包括：

## Model

例如：

GPT。

Claude。

---

## Agent

例如：

Codex。

Claude Code。

---

## Skill

例如：

代码审查。

SEO分析。

---

## Tool

例如：

Git。

浏览器。

---

## Workflow

例如：

自动测试流程。

---

# 6. 当前任务绑定

切换能力时：

保持：

- 当前任务；
- 当前项目；
- 当前Context；
- 当前Memory。

---

例如：

正在：

开发首页。

当前：

Codex。

切换：

Claude Code。

---

结果：

继续首页开发。

---

# 7. 自动模式

默认：

Auto。

---

智能调度中心负责：

选择：

- 模型；
- Agent；
- Skill；
- Tool。

---

用户可以查看：

为什么选择。

---

例如：

```
Auto

当前选择：

Claude Code


原因：

复杂代码重构

历史成功率92%
```

---

# 8. 手动模式

用户选择：

指定能力。

---

例如：

```
固定使用：

Codex
```

---

适用于：

专业用户。

---

# 9. 临时切换

支持：

只影响当前任务。

---

例如：

测试：

使用GPT。

---

任务完成后：

恢复Auto。

---

# 10. 员工能力显示

员工页面：

展示：

员工装备。

---

例如：

研发负责人：

```
默认：

Codex


备用：

Claude Code


工具：

Git

测试Tool
```

---

但日常切换：

不进入员工页面。

---

# 11. 项目能力显示

项目页面展示：

当前项目可用能力。

---

例如：

研发项目：

```
开发：

Codex


测试：

Testing Agent


部署：

Deploy Tool
```

---

# 12. 调度透明度

系统自动选择时：

提供解释。

---

例如：

```
已自动切换：

Claude Code


原因：

Codex额度不足
```

---

# 13. UI要求

参考：

现代AI工作台。

---

要求：

- 小入口；
- 快速展开；
- 不打断工作；
- 当前状态明确。

---

避免：

进入后台页面。

---

# 14. 验收标准

用户可以：

在当前任务中。

3秒内：

查看。

切换。

确认。

---

同时：

普通用户无需理解技术。

高级用户拥有控制权。

---

# 本章冻结内容

Curis能力交互采用：

“自动调度 + 工作现场快速干预”。

能力中心负责管理。

调度中心负责选择。

Switcher负责快速控制。
