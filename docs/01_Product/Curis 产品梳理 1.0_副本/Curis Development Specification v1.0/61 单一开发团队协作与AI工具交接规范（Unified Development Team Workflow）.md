# Curis Development Specification

# 61 单一开发团队协作与AI工具交接规范（Unified Development Team Workflow）

版本：v1.0-draft

---

# 1. 规范定位

本规范用于解决：

Curis开发过程中多个AI开发工具切换导致的：

- 上下文丢失；
- 开发方向偏移；
- 重复实现；
- 架构不一致；
- 代码质量不稳定。

---

# 2. 核心原则

Curis采用：

```
一个产品目标

↓

一个技术架构

↓

一个开发主线

↓

多个AI开发工具协作
```

---

AI工具只是：

开发执行能力。

不是：

独立开发团队。

---

# 3. 开发团队模型

未来不再按照：

```
Codex团队

↓

Workspace


Workbuddy团队

↓

Admin
```

拆分。

---

统一：

```
Curis Development Team
```

---

团队可以使用：

- Codex；
- WorkBuddy；
- Claude Code；
- Trae；
- Cursor；
- 其他AI开发工具。

---

# 4. 开发主线原则

所有AI开发工具必须遵循：

唯一主线：

```
Product Bible

↓

Development Specification

↓

Git Repository

↓

Current Sprint Task
```

---

禁止：

任何AI工具根据自己的理解创建独立方向。

---

# 5. AI开发工具角色

不同工具：

属于不同执行能力。

---

例如：

## Codex

适合：

- 架构实现；
- 后端开发；
- 复杂代码修改。

---

## Claude Code

适合：

- 代码分析；
- 重构；
- 复杂调试。

---

## WorkBuddy

适合：

- 快速开发；
- UI实现；
- 本地任务执行。

---

## Trae/Cursor

适合：

- IDE辅助；
- 页面开发；
- 快速修改。

---

以上均属于：

Capability。

---

# 6. 任务分配原则

任务不是分配给：

某个AI工具。

---

而是：

分配给开发任务。

---

例如：

错误：

```
Codex负责Workspace
```

---

正确：

```
任务：

重构项目工作台


执行能力：

Codex
```

---

# 7. 开发交接机制

当一个AI工具额度结束：

不能直接切换继续聊天。

---

必须执行：

```
当前状态记录

↓

提交代码

↓

更新任务状态

↓

生成交接文档

↓

下一AI工具接管
```

---

# 8. AI交接文档规范

每次交接必须生成：

```
Development Handoff Report
```

---

内容：

## 当前任务

正在完成什么。

---

## 已完成

修改了什么。

---

## 未完成

剩余什么。

---

## 修改文件

哪些文件变化。

---

## 技术决策

为什么这样实现。

---

## 已知问题

当前风险。

---

## 下一步建议

下一工具继续做什么。

---

# 9. Git交接规范

AI工具切换前：

必须：

```
git status

↓

commit

↓

push

↓

记录commit id
```

---

交接后：

新的AI工具：

必须：

```
pull最新代码

↓

读取任务文档

↓

读取交接报告

↓

继续开发
```

---

# 10. 上下文交接规范

禁止依赖：

聊天历史。

---

必须依赖：

结构化上下文。

---

包括：

```
Project Context

+

Task Context

+

Development Handoff

+

Architecture Rules
```

---

# 11. 防止AI方向漂移

新AI接手任务前：

必须确认：

```
当前目标

↓

所属模块

↓

禁止修改范围

↓

验收标准
```

---

例如：

任务：

修改项目页面。

---

禁止：

顺便重构整个导航。

---

# 12. 多AI工具代码冲突处理

如果两个AI产生不同方案：

处理：

```
方案A

+

方案B

↓

技术评估

↓

选择方案

↓

统一实现
```

---

判断依据：

优先级：

```
产品架构

>

技术架构

>

代码便利性
```

---

# 13. 开发环境统一

所有AI工具：

使用：

同一个：

- Git仓库；
- 分支；
- 环境配置；
- 文档体系。

---

禁止：

各自维护独立版本。

---

# 14. 分支规范

统一：

```
main

正式版本


develop

开发主线


feature/*

功能开发


fix/*

问题修复
```

---

AI工具：

默认：

feature分支。

---

# 15. Code Review规范

AI生成代码：

必须经过：

Review。

---

检查：

## 架构

是否符合规范。

---

## 产品

是否符合需求。

---

## 质量

是否可维护。

---

# 16. AI开发日志

每个任务记录：

```
任务

↓

使用工具

↓

修改内容

↓

测试结果

↓

成本
```

---

用于：

未来AI研发效率分析。

---

# 17. AI额度管理

不同AI工具额度：

不影响产品连续性。

---

例如：

Codex额度耗尽。

流程：

```
任务状态保存

↓

WorkBuddy接管

↓

继续开发
```

---

产品目标不变化。

---

# 18. AI工具切换原则

切换原因：

可以是：

- 额度；
- 能力；
- 成本；
- 任务适配。

---

不是：

重新开始。

---

# 19. 开发资产唯一来源

最终有效资产：

只有：

```
Git代码

+

正式文档

+

任务记录

+
 
交接记录
```

---

聊天记录：

不作为正式依据。

---

# 20. 验收标准

单一开发团队模式完成后：

必须达到：

---

## 连续开发

AI工具切换不中断。

---

## 方向统一

不同AI不产生不同产品。

---

## 代码统一

不存在多个实现版本。

---

## 知识连续

开发经验持续沉淀。

---

# 本章冻结内容

本章定义Curis单一开发团队协作规范。

核心：

未来不再按照AI工具划分开发团队。

Codex、WorkBuddy、Claude Code等都是开发能力。

所有开发围绕同一个Curis目标、同一个代码主线、同一套架构规范持续推进。
