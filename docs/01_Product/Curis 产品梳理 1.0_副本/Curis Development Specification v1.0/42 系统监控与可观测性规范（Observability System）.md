# Curis Development Specification

# 42 系统监控与可观测性规范（Observability System）

版本：v1.0-draft（修正版）

---

# 1. 系统定位

系统监控与可观测性负责记录和分析 Curis 运行状态。

目标：

让系统具备：

- 可观察；
- 可追踪；
- 可分析；
- 可优化；
- 可恢复。

---

# 2. 核心理念

Curis不采用：

所有运行过程实时交给AI分析。

---

采用：

```
执行事件

↓

结构化记录

↓

指标统计

↓

规则检测

↓

必要时AI分析
```

---

# 3. 监控分层架构

```
第一层：

Execution Event

（事实记录）


↓

第二层：

Metrics System

（指标统计）


↓

第三层：

Rule Engine

（规则判断）


↓

第四层：

AI Analysis

（智能分析）
```

---

# 4. 第一层：执行事件系统（Execution Event）

定位：

记录发生了什么。

---

不调用AI。

---

记录：

```
Event

├── 时间

├── 用户

├── 项目

├── Task

├── Agent

├── Capability

├── 输入输出状态

├── Token

├── 成本

└── 结果
```

---

例如：

```
10:00

研发任务启动


Agent:

Codex


Token:

5000


结果:

完成
```

---

# 5. 第二层：指标系统（Metrics System）

定位：

统计运行情况。

---

不调用AI。

---

计算：

## 系统指标

- 请求数量；
- 成功率；
- 响应时间。

---

## AI指标

- Agent调用次数；
- Model使用情况；
- Token消耗。

---

## 业务指标

- 项目进度；
- 成果数量；
- 任务完成率。

---

# 6. 第三层：规则检测系统（Rule Engine）

定位：

自动发现异常。

---

不依赖AI。

---

规则示例：

## Token异常

```
当前任务Token

>

历史平均值 × 3
```

触发：

成本异常。

---

## 执行异常

```
连续失败3次
```

触发：

任务风险。

---

## 能力异常

```
模型失败率超过阈值
```

触发：

切换建议。

---

# 7. 第四层：AI分析系统（AI Analysis）

定位：

解决需要理解的问题。

---

触发方式：

## 用户主动请求

例如：

“为什么这个项目成本增加？”

---

## 异常触发

例如：

系统发现成本异常。

---

## 周期复盘

例如：

每周生成AI运营报告。

---

# 8. AI分析输入

AI不读取全部日志。

---

通过：

Context Engine。

生成：

分析Context。

---

包含：

- 异常指标；
- 相关任务；
- 相关Agent；
- 相关Workflow；
- 历史经验。

---

# 9. 成本控制原则

监控系统本身：

低Token运行。

---

默认：

日志：

0 Token。

---

统计：

0 Token。

---

规则：

0 Token。

---

AI分析：

按需消耗。

---

# 10. Agent监控

记录：

## 状态

- 空闲；
- 执行；
- 完成；
- 失败。

---

## 表现

- 成功率；
- 执行时间；
- 成本。

---

## 适用场景

例如：

某Agent适合：

代码重构。

---

# 11. Model监控

记录：

- 调用次数；
- Token；
- 成本；
- 响应速度；
- 错误率。

---

用于：

智能调度优化。

---

# 12. Workflow监控

记录：

流程执行状态。

---

例如：

```
Workflow:

代码开发流程


节点：

需求分析 √

代码修改 √

测试 ×
```

---

分析：

失败节点。

---

# 13. Memory沉淀规则

监控数据不会全部进入Memory。

---

流程：

```
运行记录

↓

分析

↓

判断长期价值

↓

生成Memory
```

---

保存：

经验。

规则。

最佳实践。

---

不保存：

普通运行日志。

---

# 14. AI诊断示例

系统发现：

```
研发项目成本上涨40%
```

---

规则系统：

发现异常。

---

AI分析：

读取：

- 成本变化；
- 模型调用；
- Workflow变化。

---

输出：

```
原因：

新增代码审查流程。


建议：

普通修改任务降低模型等级。
```

---

# 15. 与智能调度中心关系

监控数据反馈：

优化能力选择。

---

例如：

历史：

```
任务类型：

代码重构


Agent A:

成功率95%


Agent B:

成功率75%
```

---

调度中心：

调整优先级。

---

# 16. 与自进化系统关系

监控数据用于：

发现优化机会。

---

例如：

发现：

某Workflow长期失败。

---

生成：

优化建议。

---

# 17. UI设计要求

监控页面分层：

---

普通用户：

看到：

结果。

风险。

建议。

---

高级用户：

查看：

执行链。

日志。

成本。

---

避免：

展示大量技术日志。

---


---

```

```

---

## 获取异常

```

```

---

## 请求AI分析

```
POST /analysis
```

---

# 19. 验收标准

系统监控完成后：

用户可以：

知道发生什么。

知道消耗多少。

知道哪里异常。

知道如何优化。

---

同时：

监控系统自身不会造成大量Token消耗。

---

# 本章冻结内容

Curis采用：

事件驱动 + 指标统计 + 规则检测 + AI分析

的可观测体系。

核心：

AI负责理解和优化。

系统负责记录和计算。

避免使用AI处理所有运行数据，保证长期运行成本可控。
