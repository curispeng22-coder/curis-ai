# Curis Development Specification

# 70 Curis开发文档使用规范（Documentation Usage Guide）

版本：v1.0-draft

---

# 1. 规范定位

本文档用于定义：

Curis所有产品、架构、开发文档如何被不同角色使用。

目标：

避免：

- 文档数量过多导致无法执行；
- 开发团队阅读无关内容；
- 不同角色理解偏差；
- AI开发工具加载过多上下文。

---

# 2. 核心原则

Curis文档不是要求所有人全部阅读。

而是：

```
角色

↓

需要的文档

↓

完成对应工作
```

---

# 3. 文档分层体系

Curis文档分为：

```
产品战略层

↓

架构设计层

↓

开发执行层

↓

任务执行层

↓

历史归档层
```

# 9. AI开发Agent阅读规则

AI开发Agent不能默认加载全部文档。

---

根据任务加载：

```
基础上下文

+

模块规范

+

当前任务
```

---

例如：

开发员工页面：

读取：

```
AI Employee规范

+

前端组件规范

+

API规范
```

---

不读取：

无关商业规划。

# 14. 文档上下文控制

为了降低Token消耗：

禁止：

每次任务加载全部文档。

---

采用：

Context选择。

---

例如：

开发API：

加载：

API规范。

---

开发UI：

加载：

Design System。
