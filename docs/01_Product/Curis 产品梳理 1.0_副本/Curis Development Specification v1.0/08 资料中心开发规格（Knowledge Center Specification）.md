# Curis Development Specification

# 08 资料中心开发规格（Knowledge Center Specification）

版本：v1.0-draft

---

# 1. 页面定位

资料中心负责管理 Curis 的知识来源和知识资产。

它不是：

- 普通文件管理器；
- 网盘；
- 单纯上传中心。

它负责：

```
资料来源

↓

知识解析

↓

知识索引

↓

项目上下文

↓

AI员工使用

```

---

# 2. 核心目标

用户可以：

- 连接已有知识；
- 管理资料来源；
- 搜索知识；
- 将资料关联项目；
- 让AI员工使用知识。

---

# 3. 页面结构

```
Knowledge Center

├── 全部资料

├── 本地连接

├── 外部来源

├── 项目资料

├── 知识库

└── 同步状态
```

---

# 4. 全部资料

KnowledgeExplorer

---

## 4.1 页面目标

统一查看所有可使用资料。

---

## 4.2 展示字段

```

type

source

location

related_project

updated_at

status
```

---

来源。

所属项目。

状态。

---

# 5. 资料来源类型

支持：

## 本地文件

来源：

用户电脑文件夹。

---

例如：

```
/Documents/AI

/Projects/Curis
```

---

## Obsidian

来源：

用户 Vault。

---

支持：

- 选择Vault；
- 建立索引；
- 同步Markdown；
- 关联项目。

---

## Git

来源：

代码仓库。

---

支持：

- 仓库连接；
- 文件索引；
- 代码知识关联。

---

## 外部连接

包括：

- Notion；
- 网盘；
- 网页；
- 邮件；
- Connector。

---

## Curis内部资料

包括：

- AI对话；
- 会议记录；
- 项目成果；
- Workflow输出。

---

---

# 14. 知识引用

AI员工执行任务时：

可以引用：

相关知识。

---

例如：

研发员工：

执行开发任务。

自动读取：

- 技术方案；
- 架构文档；
- 历史问题。

---

内容员工：

读取：

- 用户画像；
- 历史内容；
- 数据分析。

# 18. API需求

## 获取资料列表

```
GET /knowledge
```

---

## 添加资料来源

```
POST /knowledge/sources
```

---

## 同步资料

```
POST /knowledge/sources/{id}/sync
```

---

## 搜索知识

```
GET /knowledge/search
```

---

## 获取项目资料

```
GET /projects/{id}/knowledge
```

# 20. 验收标准

资料中心完成后：

用户可以：

连接本地资料。

连接Obsidian。

搜索知识。

关联项目。

让AI员工使用资料。

---

检查：

## 产品

资料中心是否成为AI工作的知识基础。

---

## 数据

资料来源、知识、项目关系是否正确。

---

## 扩展

未来是否支持更多Connector。
