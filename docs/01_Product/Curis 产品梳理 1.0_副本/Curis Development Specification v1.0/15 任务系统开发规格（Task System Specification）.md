# Curis Development Specification

# 15 任务系统开发规格（Task System Specification）

版本：v1.0-draft

---

# 1. 页面定位

任务系统是 Curis 中连接：

目标

↓

执行

↓

成果

的核心执行单元。

---

任务属于项目。

关系：

```
Project

↓

Task

↓

Workflow

↓

Capability

↓

Artifact
```

---

# 2. 核心目标

任务系统负责：

- 创建工作任务；
- 分配执行主体；
- 调用AI能力；
- 跟踪执行过程；
- 管理结果；
- 支持自动化。

---

# 3. 任务来源

任务可以来自：

## 用户创建

用户直接提出。

例如：

“优化首页设计。”

---

## 项目负责人拆解

项目负责人根据目标拆分。

例如：

研发项目：

目标：

完成产品首页。

拆解：

- 页面设计；
- 前端开发；
- 测试。

---

## 会议生成

会议结论自动生成任务。

---

## 经营分析生成

例如：

分析发现：

内容效果下降。

生成：

内容优化任务。

---

## 自动化规则触发

例如：

每天10点自动执行。

---

# 6. 任务类型

支持：

---

## 6.1 普通任务

一次性执行。

例如：

生成产品方案。

---

## 6.2 定时任务

按照时间执行。

例如：

每天10点分析热点。

---

## 6.3 条件任务

满足条件触发。

例如：

Token超过限制。

自动暂停。

---

## 6.4 自适应任务

根据结果调整。

例如：

任务失败。

分析原因。

调整执行策略。

---

# 21. API需求

## 获取任务列表

```
GET /tasks
```

---

## 创建任务

```
POST /tasks
```

---

## 执行任务

```
POST /tasks/{id}/run
```

---

## 暂停任务

```
POST /tasks/{id}/pause
```

---

## 恢复任务

```
POST /tasks/{id}/resume
```

---

## 获取运行记录

```
GET /tasks/{id}/runs
```
