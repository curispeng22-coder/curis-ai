# Curis Development Specification

# 60 新版UI/UX重构规范（UI Redesign Specification）

版本：v1.0-draft

---

# 1. 规范定位

本规范用于指导 Curis 基于新版产品架构重新设计：

- Desktop UI；
- Workspace界面；
- AI员工交互；
- 能力切换体验；
- 项目工作流；
- AI协作场景。

---

# 2. 重构背景

当前历史情况：

```
Codex团队

↓

Workspace开发


Workbuddy团队

↓

Admin开发


部分阶段：

Workbuddy参与Workspace开发
```

---

导致：

- 多套设计方向；
- 多套页面结构；
- 多套交互逻辑；
- 原型与实现不统一。

---

因此：

新版UI必须重新建立。

---

# 3. 新版UI唯一依据

新版设计必须遵循：

```
Curis Product Bible v1.0

↓

Development Specification

↓

Frontend Design System

↓

新版UI设计
```

---

禁止：

直接继承旧UI。

---

# 4. 旧UI处理原则

所有旧UI：

统一归档。

---

包括：

- Figma文件；
- 原型图；
- 高保真设计；
- 页面截图；
- 交互流程。

---

状态：

```
Legacy Design

归档
```

---

用途：

仅用于：

- 历史记录；
- 对比产品演进；
- 避免重复错误。

---

禁止：

作为新版开发依据。

---

# 5. 新版UI核心目标

Curis不是：

AI聊天工具。

---

不是：

模型管理工具。

---

不是：

后台管理系统。

---

新版UI必须体现：

```
AI公司

↓

AI员工

↓

项目

↓

任务

↓

能力调度

↓

成果

↓

经验沉淀
```

---

# 6. 产品交互模型

用户主要操作对象：

不是模型。

---

不是Agent。

---

而是：

目标。

项目。

员工。

成果。

---

例如：

用户：

“开发一个网站。”

---

UI流程：

```
AI秘书理解目标

↓

创建项目

↓

配置AI员工

↓

执行任务

↓

查看成果
```

---

# 7. 全局UI架构

Curis Desktop：

```
Application Shell

├── AI秘书入口

├── Workspace导航

├── 当前工作区

├── 能力切换入口

└── 通知中心
```

---

# 8. AI秘书设计规范

AI秘书是全局入口。

---

支持：

- 悬浮；
- 展开；
- 收起；
- 主动提醒。

---

状态：

```
Idle

Thinking

Planning

Executing

Waiting

Completed
```

---

AI秘书负责：

理解用户目标。

---

不负责：

展示所有技术细节。

---

# 9. 首页重新设计

首页定位：

AI公司驾驶舱。

---

不是：

传统Dashboard。

---

展示：

```
今日状态

↓

重点项目

↓

待决策事项

↓

AI员工状态

↓

成果摘要
```

---

用户进入首页：

应该知道：

“我的AI团队现在在做什么。”

---

# 10. Workspace设计

Workspace是主要工作空间。

---

结构：

```
项目

↓

员工

↓

任务

↓

成果
```

---

不是：

页面集合。

---

# 11. 项目工作台设计

项目是核心执行入口。

---

页面结构：

```
项目目标

↓

团队

↓

任务

↓

资料

↓

成果

↓

数据
```

---

展示：

当前负责人。

执行状态。

风险。

下一步。

---

# 12. AI员工界面设计

员工不是：

聊天机器人列表。

---

员工页面展示：

```
员工身份

↓

职责

↓

当前任务

↓

能力配置

↓

Memory

↓

历史成果
```

---

例如：

研发负责人：

展示：

当前负责项目。

正在执行任务。

使用能力。

---

# 13. 能力切换设计

能力切换必须简单。

---

参考：

Codex模型切换交互。

---

但是Curis扩展为：

工作模式切换。

---

例如：

输入框附近：

```
研发模式 ▼
```

展开：

```
自动模式

软件开发模式

代码审查模式

研究模式
```

---

底层自动调整：

- Agent；
- Model；
- Skill；
- Tool；
- Workflow。

---

# 14. 能力中心设计

能力中心：

用于管理。

---

不是：

日常使用入口。

---

管理：

```
Model

Agent

Skill

Tool

Workflow

Connector
```

---

用户工作时：

使用：

Capability Switcher。

---

# 15. 任务执行界面设计

任务页面必须展示：

```
目标

↓

执行员工

↓

当前能力

↓

执行过程

↓

结果
```

---

不是简单聊天记录。

---

# 16. AI执行过程展示

展示：

结构化过程。

---

例如：

```
分析需求

↓

读取项目知识

↓

调用开发Agent

↓

执行修改

↓

测试

↓

生成成果
```

---

避免：

展示大量技术日志。

---

# 17. 成果中心设计

成果是价值输出。

---

展示：

```
成果

↓

来源任务

↓

执行员工

↓

版本

↓

验收状态
```

---

# 18. Knowledge交互设计

知识不是文件夹。

---

展示：

```
资料

↓

知识关系

↓

项目

↓

经验
```

---

支持：

AI理解和调用。

---

# 19. Admin界面原则

当前不与Workspace混合。

---

Admin负责：

```
能力

模板

权限

配置
```

---

Workspace负责：

```
业务执行
```

---

# 20. Design System执行要求

新版UI必须基于：

Frontend Design System。

---

禁止：

页面独立设计组件。

---

所有页面使用：

统一组件。

---

# 21. 新版UI设计流程

标准流程：

```
产品需求

↓

信息架构

↓

用户流程

↓

低保真原型

↓

高保真设计

↓

Design System映射

↓

前端实现
```

---

# 22. 设计验收标准

新版页面必须满足：

---

## 产品一致

符合AI公司模型。

---

## 交互一致

符合统一工作流。

---

## 技术一致

可通过组件实现。

---

## 扩展一致

支持未来Business Template。

---

# 23. 禁止事项

禁止：

- 复制旧UI；
- 根据旧页面继续开发；
- 为了复用代码保留错误交互；
- 将模型列表作为主要入口；
- 将聊天窗口作为核心产品。

---

# 24. 验收输出

新版UI设计完成后：

必须输出：

```
UI Design System

+

页面信息架构

+

交互流程

+

高保真原型

+

前端实现规范
```

# 本章冻结内容

本章定义Curis新版UI/UX重构规范。

核心：

旧UI全部归档。

新版UI从产品架构重新设计。

Curis的界面必须体现：

AI员工组织。

能力调度。

项目执行。

成果沉淀。

而不是传统AI聊天工具。
