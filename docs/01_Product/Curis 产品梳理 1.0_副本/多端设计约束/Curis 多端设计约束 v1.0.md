# Curis 多端设计约束 v1.0

## 1. 产品定位

Curis 是多端 AI Company OS。

不是单一 Web 应用，也不是单一桌面工具。

目标：

让用户通过不同设备管理自己的 AI 公司。

核心信息模型保持一致：

公司状态
业务
项目
任务
员工
能力
成果
知识
AI助理


---

# 2. 三端战略

## Desktop App（当前 MVP 主方向）

定位：

AI 公司 CEO 工作空间。

优先级最高。


使用场景：

- 长时间工作；
- 管理 AI 公司；
- 创建业务；
- 调度 AI员工；
- 查看执行过程；
- 使用 AI 助理。


设计特点：

- 大空间；
- 高信息密度；
- 多区域布局；
- 快捷操作；
- AI 助理常驻。


默认布局：

左侧：
系统导航

中间：
核心工作空间

右侧：
CEO 助理


目标体验：

像一个 AI 公司的私人办公室。


---

## Web App（未来商业化方向）

定位：

企业和团队访问入口。


支持：

- 多用户；
- Workspace；
- 权限管理；
- 团队协作；
- 企业部署。


Web 不是 Desktop 简单复制。

需要根据浏览器环境优化：

- 响应式布局；
- 多人协作；
- 权限体系。


保持：

相同业务模型。

不同交互表现。


---

## Mobile App（远程管理入口）

定位：

CEO 远程控制中心。


不是完整 Desktop 手机版。


重点展示：

- 公司状态；
- 今日简报；
- 待处理；
- 风险提示；
- AI通知。


支持：

远程确认：

- 审批；
- 决策；
- 发布；
- 任务确认。


例如：

“小红书业务已生成5篇文案，建议20:00发布。”

用户手机直接确认。


---

# 3. 信息架构约束

三端共享同一核心模型。


不要为不同端创建不同业务逻辑。


统一：

Business Layer

↓

Application Layer

↓

Presentation Layer


不同端只改变：

展示方式。

---

# 4. Desktop First 原则

当前 MVP：

优先完成 Desktop。


所有核心体验：

先在 Desktop 验证。


包括：

- CEO Office；
- CEO 助理；
- 业务管理；
- 项目执行；
- 数据洞察。


不要因为未来 Web/Mobile 需求降低 Desktop 体验。


---

# 5. 未来首页自定义能力

长期支持：

用户自定义 CEO Workspace。


不是简单换主题。

而是：

组件化工作空间。


未来 Widget：

- 公司健康度；
- Token成本；
- 业务状态；
- 项目进度；
- AI员工状态；
- 风险提示；
- Memory；
- 日历；
- 数据洞察。


用户可以根据角色组合首页。


例如：

## 创业者模式

关注：

收入
成本
业务
风险
成果


## 开发者模式

关注：

代码任务
GitHub
部署
Bug
Token成本


## 内容创作者模式

关注：

内容产出
发布计划
平台数据
收益


---

# 6. MVP限制

当前不实现：

- 首页拖拽编辑；
- Widget市场；
- 自定义布局保存；
- 多端同步配置。


但设计必须预留：

组件化结构。


---

# 7. 视觉约束

所有端保持：

Curis统一视觉语言。


方向：

Apple macOS

+

Linear

+

AI Company OS。


避免：

- 企业后台感；
- BI大屏感；
- 普通SaaS Dashboard。


Desktop：

强调空间感。


Web：

强调协作效率。


Mobile：

强调快速决策。


---

# 8. 最终目标

Curis 不是一个网站。

不是一个 App。

而是一套跨设备的 AI 公司操作系统。


当前：

Desktop 打磨核心体验。


未来：

Web 商业化。

Mobile 远程控制。

首页 Workspace 自定义。
