# Curis Product Bible

# 32 研发项目模板（R&D Project Template）

版本：v1.0-draft

---

# 1. 模板定位

研发项目模板用于定义软件研发类项目在 Curis 中的运行方式。

它不是一个固定研发页面。

而是一个：

Business Definition。

通过模板生成：

- 项目结构；
- 工作区；
- 角色；
- 任务流程；
- Workflow；
- 能力配置；
- 成果定义。

---

# 2. 适用场景

适用于：

- Web 应用开发；
- App 开发；
- 小程序开发；
- 内部工具开发；
- AI应用开发；
- 自动化系统开发。

---

# 3. 项目目标

研发项目目标：

将一个产品需求。

转化为：

```
需求

↓

方案

↓

开发

↓

测试

↓

发布

↓

成果
```

# 4. 默认项目结构

生成：

```
研发项目

├── 项目概览

├── 代码管理
```

# 5. 项目角色

默认角色：

职责：

- 理解用户目标；
- 制定计划；
- 分配任务；
- 跟踪进度；
- 汇报结果。

## 产品负责人

职责：

- 需求分析；
- 用户体验；
- 验收标准。

---

## 技术负责人

职责：

- 技术方案；
- 架构设计；
- 技术决策。

---

## 开发员工

职责：

- 编写代码；
- 修改功能；
- 处理问题。

---

## 测试员工

职责：

- 测试；
- 验证；
- 提交问题。

---

## 部署员工

职责：

- 构建；
- 发布；
- 环境管理。

# 12. 自动化任务示例

用户：

> 每天检查项目代码质量。

系统生成：

```
每天9点

↓

代码扫描

↓

问题分析

↓

生成报告

↓

通知负责人
```

---

用户：

> 开发任务Token超过预算自动停止。

配置：

```
Token达到阈值

↓

暂停任务

↓

通知负责人

↓

等待确认
```

---

# 13. 自进化方向

研发项目运行后：

系统分析：

- 哪些任务容易失败；
- 哪些Workflow效率低；
- 哪些能力效果好。

生成：

优化建议。

---

例如：

建议：

“代码测试阶段失败率较高，建议增加自动测试节点。”
