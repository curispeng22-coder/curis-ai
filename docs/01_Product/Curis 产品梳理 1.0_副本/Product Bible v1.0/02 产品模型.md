# Curis Product Bible

# 02 产品模型

版本：v1.0-draft

---

# 1. 产品模型

Curis 不围绕 AI 能力构建，而围绕业务对象构建。

产品对象如下：

公司
→ 部门
→ 员工
→ 项目
→ 任务
→ 成果

能力作为员工可调用资源存在。

---

# 2. 公司（Company）

定位：

用户创建的一个 AI 公司。

作用：

- 承载全部业务
- 管理组织
- 管理资源
- 管理经营

拥有：

- 部门
- 全局资料
- 全局能力
- 全局经营数据

---

# 3. 部门（Department）

定位：

承担某类业务职责。

示例：

- 研发部
- 内容增长部
- 行政部
- 产品部
- 市场部

拥有：

- 员工
- 项目
- 部门资料
- 部门经营数据

支持：

- 创建
- 编辑
- 暂停
- 解散
- 删除
- 恢复

---

# 4. 员工（Employee）

员工是 Curis 的责任主体。

员工包含：

- 岗位
- 人格
- Memory
- 能力
- 当前项目
- 历史成果

负责人只是员工承担的一种岗位。

例如：

研发负责人

内容负责人

行政负责人

项目负责人

员工可以参与多个项目。

员工调用能力完成工作。

---

# 5. 能力（Capability）

能力不是产品主对象。

能力属于员工装备。

能力类型：

- Model
- Agent
- Skill
- Tool
- Workflow
- MCP
- Connector
- Credential

员工可以：

- 首选能力
- 备用能力
- 自动切换能力

---

# 6. 项目（Project）

项目是业务执行中心。

所有业务：

必须归属于：

公司
→ 部门
→ 项目

项目拥有：

- 工作区
- 任务
- Workflow
- AI员工
- 资料
- 成果
- 会议
- 经营数据

---

# 7. 工作（Work）

工作是业务需求。

例如：

完成一个页面

写一篇文章

制作一个视频

分析热点

工作经过项目负责人拆解：

Work

↓

Task

↓

Workflow

↓

Result

---

# 8. 任务（Task）

任务属于项目。

支持：

- 普通任务
- 定时任务
- 条件任务
- 自进化任务

任务拥有：

- 输入
- 输出
- 执行员工
- Workflow
- Token
- 成本
- 风险
- 状态

支持：

- 暂停
- 重试
- 停止
- 恢复

---

# 9. 成果（Artifact）

成果来自：

任务执行。

成果类型：

- 网站
- APP
- 页面
- 图片
- 视频
- 文档
- 报告
- 数据
- 发布包

成果支持：

- 验收
- 评论
- 返工
- 发布
- 归档

---

# 10. 资料（Knowledge）

资料中心负责统一知识来源。

来源包括：

本地：

- 文件夹
- Obsidian
- Git

外部：

- 网页
- Notion
- GitHub
- Connector

内部：

- AI对话
- 项目成果
- 会议记录
- Workflow输出

资料经过索引后形成：

Knowledge

↓

Memory

↓

Context

供员工工作。

---

# 11. 会议（Meeting）

会议属于项目。

支持：

- 实时会议
- 后台研讨

会议结束：

生成：

- 决策
- 行动项
- 新任务

---

# 12. Business Definition

业务定义不是页面。

业务定义描述：

- 业务阶段
- 工作区模块
- 岗位
- Workflow
- Skill
- Tool
- MCP
- 成果
- 风险
- 审批

Curis 根据 Business Definition 渲染项目工作区。

---

# 本章冻结内容

本章定义 Curis 产品对象。

页面设计、业务模板、UI 设计均以本章对象模型为基础。
