# Curis Product Bible

# 22 Memory 系统（Memory System）

版本：v1.0-draft

---

# 1. 系统定位

Memory 系统负责让 Curis 中的 AI 员工具备持续工作的能力。

Memory 不是简单聊天记录保存。

它负责：

- 保存有效经验；
- 提供工作上下文；
- 帮助员工持续优化；
- 连接知识与执行。

---

# 2. 核心理念

AI员工不应该每次工作都从零开始。

完整关系：

```
资料中心

↓

知识

↓

Memory

↓

上下文

↓

任务执行

↓

经验沉淀
```

---

# 3. Memory 类型

Curis Memory 分为：

## 3.1 用户 Memory

记录：

用户偏好。

例如：

- 喜欢的输出格式；
- 工作习惯；
- 决策方式；
- 常用设置。

---

## 3.2 公司 Memory

记录：

公司层面的长期信息。

例如：

- 公司目标；
- 产品方向；
- 经营策略；
- 管理规则。

---

## 3.3 部门 Memory

记录：

部门业务经验。

例如：

研发部：

- 技术规范；
- 开发流程；
- 常见问题。

内容增长部：

- 内容方法；
- 爆款规律；
- 用户画像。

---

## 3.4 项目 Memory

记录：

项目专属经验。

例如：

- 项目背景；
- 历史决策；
- 当前目标；
- 已完成工作；
- 失败原因。

---

## 3.5 员工 Memory

记录：

AI员工长期经验。

例如：

研发负责人：

- 技术判断经验；
- 历史方案；
- 优化方式。

内容负责人：

- 内容策略；
- 用户反馈；
- 成功案例。

---

# 4. Memory 来源

Memory 可以来自：

## 项目执行

例如：

一次开发任务完成。

系统提炼：

- 有效方案；
- 问题；
- 解决方式。

---

## 会议

会议结束后：

提炼：

- 决策；
- 经验；
- 行动结果。

---

## 成果复盘

分析：

成果是否成功。

为什么成功。

为什么失败。

---

## 用户反馈

用户修改。

用户评价。

用户选择。

---

## 资料中心

读取：

- 文档；
- Obsidian；
- Git；
- 知识库。

---

# 5. Memory 生命周期

流程：

```
产生信息

↓

提取

↓

整理

↓

审核

↓

存储

↓

调用

↓

更新
```

---

# 6. Memory 提取

不是所有内容都进入 Memory。

系统需要判断：

是否长期有效。

---

适合保存：

- 方法；
- 规则；
- 偏好；
- 经验；
- 决策。

---

不适合保存：

- 临时聊天；
- 一次性任务细节；
- 无价值日志。

---

# 7. Memory 审核

Memory 写入支持：

## 自动写入

适合：

低风险经验。

例如：

格式偏好。

---

## 用户确认

适合：

重要经验。

例如：

产品方向。

经营策略。

---

## 项目负责人确认

适合：

项目经验。

---

# 8. Memory 调用

员工执行任务时：

根据：

当前项目。

当前任务。

当前角色。

自动加载相关 Memory。

---

例如：

研发员工：

执行开发任务。

调用：

- 技术规范；
- 历史Bug；
- 项目架构。

---

内容员工：

执行内容任务。

调用：

- 账号定位；
- 历史爆款；
- 用户反馈。

---

# 9. Memory 权限

Memory 根据归属控制访问。

---

公司 Memory：

公司成员可访问。

---

部门 Memory：

部门成员访问。

---

项目 Memory：

项目成员访问。

---

员工 Memory：

由员工自身使用。

---

# 10. Memory 与资料中心关系

资料中心：

保存原始知识。

Memory：

保存提炼经验。

---

例如：

Obsidian：

记录：

100篇产品思考。

---

Memory：

提炼：

用户偏好：

“产品设计需要先考虑用户体验。”

---

# 11. Memory 与项目关系

项目结束后：

项目 Memory 可以：

沉淀到：

部门 Memory。

---

例如：

研发项目完成。

总结：

- 技术方案；
- 开发经验；
- 常见问题。

进入：

研发部知识。

---

# 12. Memory 与自进化

Memory 是 AI 员工成长基础。

流程：

执行

↓

复盘

↓

提炼经验

↓

更新Memory

↓

下一次执行优化

---

# 13. Memory 管理

用户可以查看：

- 已保存 Memory；
- 来源；
- 创建时间；
- 使用次数。

---

支持：

编辑。

删除。

合并。

禁用。

---

# 14. 错误 Memory 修正

如果 Memory 错误：

支持：

用户修正。

删除。

覆盖。

---

避免：

错误经验持续影响执行。

---

# 15. AI秘书与 Memory

AI秘书可以：

管理 Memory。

例如：

用户：

> 删除关于旧产品方向的记忆。

AI秘书：

定位相关 Memory。

确认后删除。

---

用户：

> 记住以后产品文档都使用Markdown。

AI秘书：

生成用户 Memory。

# 18. 设计原则

Memory 的目标：

不是保存更多信息。

而是：

让 AI 员工越来越懂业务。
