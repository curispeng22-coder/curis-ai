# Curis Product Bible

# 20 能力系统（Capability System）

版本：v1.0-draft

---

# 1. 系统定位

能力系统负责管理 Curis 可以调用的外部和内部能力。

能力系统解决：

- 有哪些能力可用；
- 如何接入能力；
- 如何配置能力；
- 如何分配能力；
- 如何选择能力执行任务；
- 如何替换不可用能力。

---

# 2. 核心理念

能力不是业务。

能力服务业务。

关系：

```
业务目标

↓

项目

↓

任务

↓

员工

↓

能力

↓

执行结果
```

---

能力不直接承担业务责任。

例如：

Claude：

不是员工。

Codex：

不是项目负责人。

Workflow：

不是业务流程。

它们都是能力。

---

# 3. 能力模型

能力统一抽象为：

Capability。

包含：

- 基础信息；
- 类型；
- 来源；
- 配置；
- 权限；
- 状态；
- 成本；
- 健康状态。

---

# 4. 能力类型

## 4.1 Model

模型能力。

例如：

- GPT
- Claude
- Gemini
- DeepSeek
- 本地模型

用于：

推理。

生成。

分析。

---

## 4.2 Agent

智能执行主体。

例如：

- Codex
- Claude Code
- 专业业务 Agent

用于：

复杂任务执行。

---

## 4.3 Skill

专业能力。

例如：

- SEO分析；
- 文案优化；
- 数据分析；
- 代码审查。

---

## 4.4 Tool

工具能力。

例如：

- 浏览器；
- 文件操作；
- Git；
- 数据查询；
- API调用。

---

## 4.5 Workflow

自动执行流程。

例如：

- 自动测试；
- 每日热点分析；
- 数据报告生成。

---

## 4.6 MCP

外部能力连接方式。

用于：

发现和调用外部工具。

---

## 4.7 Connector

外部系统连接。

例如：

- GitHub；
- Notion；
- 邮件；
- 网盘；
- 第三方业务平台。

---

## 4.8 Credential

认证信息。

例如：

- API Key；
- OAuth；
- Token。

---

# 5. 能力来源

能力来源分为：

## 平台能力

由 Curis 提供。

未来由 Admin 管理。

例如：

- 官方 Agent；
- 官方 Skill；
- 官方 Workflow；
- 行业能力包。

---

## 用户能力

用户自己添加。

例如：

- 自己的模型 Key；
- 自己的 MCP；
- 自己的 Workflow；
- 自己开发的 Skill。

```
↓

```

# 18. 设计原则

能力系统负责：

管理“有什么可以用”。

业务系统负责：

决定“用来做什么”。

避免：

让用户直接管理复杂技术细节。
