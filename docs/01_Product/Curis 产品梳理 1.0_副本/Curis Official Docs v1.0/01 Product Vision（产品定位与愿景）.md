# Curis Official Docs v1.0

# 01 Product Vision（产品定位与愿景）

版本：v1.0

---

# 1. 产品名称

Curis

---

# 2. 产品定位

Curis 是一个：

> AI工作组织系统（AI Work Organization System）

它帮助用户创建、管理和使用自己的AI团队，将多个AI能力组织成可以持续工作的数字组织。

---

# 3. 核心理念

Curis不是：

- AI聊天工具；
- 模型聚合工具；
- 单一Agent平台；
- 自动化脚本工具。

---

Curis解决的问题：

当前用户拥有：

- ChatGPT；
- Codex；
- Claude Code；
- Gemini；
- 各类AI工具；
- 各类Skill和插件。

但是这些能力：

- 分散；
- 无组织；
- 无长期记忆；
- 无业务流程；
- 无持续成长。

---

Curis的目标：

将：

```
AI工具

↓

AI能力

↓

AI员工

↓

AI组织

↓

AI业务执行系统
```

统一管理。

---

# 4. 产品愿景

未来：

每个人拥有一家AI公司。

---

结构：

```
用户

↓

AI秘书

↓

AI管理层

↓

专业AI员工

↓

AI能力

↓

业务成果
```

---

# 5. 核心产品模型

Curis模拟真实组织。

---

## 公司（Company）

代表：

用户的AI组织。

---

例如：

```
Curis Studio
```

---

## 部门（Department）

代表：

业务领域。

---

例如：

```
研发部

内容部

研究部

运营部
```

---

## AI员工（AI Employee）

代表：

承担职责的AI角色。

---

例如：

```
研发负责人

内容负责人

数据分析员工
```

---

## 项目（Project）

代表：

具体业务目标。

---

例如：

```
AI工作台研发项目

小红书增长项目

知识库建设项目
```

---

## 任务（Task）

代表：

具体执行事项。

---

例如：

```
开发首页

生成30个选题

分析竞品
```

---

## 成果（Artifact）

代表：

最终输出。

---

例如：

- 代码；
- 文档；
- 图片；
- 视频；
- 分析报告。

---

# 7. AI员工理念

Curis中的AI员工：

不是聊天机器人。

---

AI员工拥有：

```
角色

+

职责

+

能力

+

Memory

+

项目关系

+
 
工作历史
```

---

例如：

研发负责人：

不是：

“调用Claude”。

---

而是：

```
研发负责人

负责：

软件开发项目


能力：

Codex

Git

测试Workflow


经验：

历史研发经验
```

---

# 8. Capability理念

Curis不绑定任何AI工具。

---

所有AI能力统一抽象：

```
Capability

├── Model

├── Agent

├── Skill

├── Tool

├── Workflow

└── Connector
```

---

例如：

研发能力：

```
软件开发模式

=

开发Agent

+

Codex

+

Git

+

测试流程
```

---

# 9. 长期记忆理念

Curis解决：

AI长期工作遗忘问题。

---

不是：

每次重新输入大量上下文。

---

而是：

```
项目Memory

+

员工Memory

+

知识库

+

上下文生成
```

---

目标：

用最少Token完成长期工作。

---

# 10. 产品核心竞争力

Curis核心不是模型。

---

模型会变化。

工具会变化。

---

长期价值来自：

## AI组织模型

让AI像团队一样工作。

---

## Capability体系

统一管理所有AI能力。

---

## Memory体系

让AI持续成长。

---

## Context体系

让AI高效工作。

---

## Knowledge体系

让AI理解组织资产。

---

```

↓

↓

企业AI操作系统

↓

AI生态平台
```

---

# 12. 产品原则

## 原则1

不绑定单一AI厂商。

---

## 原则2

不重复建设已有AI能力。

---

## 原则3

核心负责：

组织、管理、调度。

---

## 原则4

业务能力通过：

Capability和Template扩展。

---

## 原则5

AI负责执行。

人负责目标和决策。

---
