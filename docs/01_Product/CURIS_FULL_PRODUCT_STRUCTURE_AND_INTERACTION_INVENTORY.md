# PART 1 — Curis 到底是什么

**1.1 Curis 是什么？**
Curis 是一款让普通用户经营"一人 AI 公司"的桌面应用（macOS Local Desktop，单 CEO 使用）。一句话（Product Blueprint 原文）：Curis 让普通用户通过对话，把成熟的 AI 专家、技能、连接器和资料装配成一家可经营的公司，并在不同业务空间里获得真实结果。每个公司 = 一位真实 CEO + 多个有公司身份的 AI 员工。

**1.2 用户为什么需要它？**
服务对象是创作者、独立开发者、研究者、顾问、小商家、一人公司创业者。一个人经营业务需要研究、运营、内容、开发、分析等很多人手；Curis 让 CEO 通过一支 AI 员工团队获得这些能力，而且工作是"真"的：有岗位责任、有工作现场、有结果和证据、有需要 CEO 拍板的决策点——不是聊天玩票。

**1.3 用户打开 Curis 后，实际上是在干什么？**
日常循环：打开 App → 看 CEO 工作台的简报（今天发生了什么、哪些需要我）→ 与助理/员工对话推进工作 → 需要时进入业务的工作空间看现场、给指示 → 在关键节点做决定 → 结果回到工作台，进入下一轮经营。CEO 不逐个巡检每个工作空间，只在需要判断、授权或接管时被叫到。

**1.4 Curis 和普通 AI Chat 有什么区别？**
Chat 是一问一答，产出文本，没有身份、责任和结果追踪。Curis 里的 AI 是有公司身份的员工：有部门、岗位、责任、能力、工作空间；工作产生 Result（结果）和 Evidence（证明结果可信的记录）；重要节点必须 CEO Decision（决策）。产品硬规则：对话必须围绕真实职责、工作、经营方法和结果运转，"不形成独立聊天世界"。

**1.5 Curis 和 Agent Manager 有什么区别？**
Agent Manager（如 Coze 式货架）管理一堆平级 Agent 配置。Curis 里是公司组织：CEO → 部门 Leader → 员工，有 Company → Department → Business → Workspace 层级；外部专家要经"招募"才变成有公司身份的 Employee；责任通过 Assignment（责任分配：哪个员工 × 什么岗位 × 在哪个范围）落地。员工不是平级 Agent 列表。

**1.6 Curis 和 Workflow Builder 有什么区别？**
明确不做流程图画布、不做 Workflow 控制台。团队协作用"团队运转 / 默认流程"轻量表达（A→B 只表示"A 完成后 B 是默认下一棒"，不是强制流程图）。正常工作自动流转（员工完成自动交接），人只在 Decision Gate（决策关口）介入。用户看到的是"谁在做什么、为什么等待、下一步交给谁"，不是节点图。

**1.7 "AI 公司操作系统"具体是什么意思？**
Curis 固定一套公司运行语义（Company OS）：组织层级、员工/责任/分配、工作→结果→证据→决定、权限、失败恢复。这套语义对所有业务固定不变；每种业务在自己的 Workspace（工作空间）里长出专业工作方式。即：OS 提供公司骨架和规则，业务在工作空间里开放表达。

**1.8 CEO 在里面负责什么？**
CEO 是唯一真人、最终经营决策者：意图、业务方向、重大资源、权限、验收和 Decision Gate。明确不负责：流程图、任务路由、逐任务审批。日常默认通过各业务的 Leader（负责人，本身也是 AI 员工）经营，但可以随时直达任何员工的工作现场。

**1.9 AI Employee 在里面是什么？**
正式定义：员工 = 一个具有公司身份的专家/Agent。它的能力 = 身份/岗位/责任 + Agent/模型 + Skill（技能）组合 + 知识/文件 + 工具 + 连接器 + 权限 + 当前上下文。有真实身份（姓名/头像可编辑）、可被替换 Holder（责任当前持有人）而不改历史。员工状态只显示三种：空闲 / 工作中·简述 / 阻塞·原因；"已完成/等待"属于工作结果，不写成员工状态。

**1.10 Company 是什么？**
用户正在经营的整体。新公司不是空壳：创建时出厂即有 Company + CEO 身份 + 同一位 CEO 助理 + 空间工程部 + 数据分析部 + 真实原装 AI 员工（空间工程 6 人 + 数据分析师至少 1 人）。用户自己的业务（Business）可以为 0；没配模型密钥也照常建组织，只是如实显示"需配置/暂不可执行"。

**1.11 Department 是什么？**
稳定责任和共享能力的聚合。Curis 原装两个部门：①空间工程部——把经营目标变成可工作的业务空间（负责人 + 行业研究专家 + 经营方法专家 + 空间设计专家 + 搭建实施专家 + 质量验证专家）；②数据分析部——公司经营分析师（默认称呼"司衡"，可改名）负责公司/跨业务分析、报告与决策支持。用户部门随重复责任渐进形成，不是招人前置；长期 Business 必须归属一个 Department。

**1.12 Business 是什么？**
持续经营身份，同时是同类 Workspace 的分类/聚合层。必须归属 Department、至少拥有一个 Workspace（只有一个也正常）。持有 Business 级目标/策略。Business ≠ Project（旧项目对象，仅兼容），≠ 外部账号/频道。

**1.13 Workspace 是什么？**
独立经营单元 + 完整专业工作环境，是唯一 canonical（唯一正式）用户产品身份。不是一张页面。它有自己的目标/定位/策略、外部账号/经营对象、真实团队（Leader + 成员 + 明确职责）、员工工位（Employee Workstation）、专业工作面（Surface：业务内一种专业观察与工作面，如"经营概览""内容运营"）以及工作、结果、历史。两种形态：Generic（通用工作环境，合法可长期经营）和 Professional（专业环境，业务形成稳定专业方法后的目标形态）。"办公室/Office"只是历史隐喻，不再是产品身份。

**1.14 Work 是什么？**
一项真实工作。默认从目标、策略、经营计划、团队运转、结果、触发器、日程或员工判断等真实经营上下文产生，不是 CEO 手工逐项创建（CEO 可以主动提出、命名、调整、介入或接管）。固定连续链：Work → 执行 → Result/Evidence → Decision 或下一项 Work。

**1.15 Conversation 是什么？**
CEO 与 AI 员工/助理/会议的持续对话。四种：CEO 助理对话、员工工位对话（该员工的持续工作 Session）、会议对话、工作空间 Thread（围绕业务对象的讨论上下文）。同员工可有多个话题（topic）；对话可跨责任分配持续；侧栏"对话"是最近对话快捷入口（dismiss 只移出快捷区，不删记录）。

**1.16 Result / Evidence 是什么？**
Result = 工作产出（文档、代码、数据、发布、报告等）。Evidence = 证明结果真实与可信的记录（来源、执行详情、验证）。硬规则：内部完成 ≠ 外部结果；结果要回到 CEO/Leader 判断（查看 ≠ 验收）；外部平台没连接时如实显示"待连接 / 人工回填 / 未知"，绝不生成假数字。

**1.17 Decision 是什么？**
需要 CEO 拍板的决策点（P7 Decision Package）。固定 8 要素语义：发生了什么 / 为何 AI 不能自决 / 可选方案 / 每个方案的影响·风险·代价 / 员工推荐 / 推荐理由 / 你只需做的选择 / 选择后 AI 如何自动继续。高风险/不可逆事项不允许"一句话直接批"，必须先看完整方案。每个结论带来源标记（事实/规则/证据/员工估计/未知）。CEO 决定后 AI 自动继续——决定 ≠ 责任交接。

**1.18 用户如何通过 Curis 经营一个真实个人业务？**
链路：说出意图（一句话即可，允许模糊）→ Curis 理解情况、必要时研究 → 形成经营提案 → CEO 确认边界 → 创建 Business + 第一个 Workspace（原子创建）→ 团队承接 → 工作 → 真实结果/证据 → CEO 验收/复盘 → 下一轮。CEO 可以自己直接建，也可以委托空间工程团队建设。外部结果走 API 或 CEO 手动回填。

**1.19 Curis 最终希望给用户什么感觉？**
产品承诺（Blueprint 原文）："我说出想做的事，知道谁会负责，能在专业工作空间里看到工作与结果，并在关键节点做决定。" 设计原则是"低表面复杂度、高功能密度"——第一眼简单，开始工作后正确能力自然出现；一切状态真实，未知/缺口/未连接如实呈现。

# PART 2 — 现有产品结构是否真的支撑 Curis

## 2A. 逐对象判断（每条：为什么存在 → 何时用 → 与其他区域的关系 → 问题）

**2.1 七个一级区（CEO 工作台 / 业务空间 / 组织中心 / 人才与能力 / 经营洞察 / 资料库 / 会议）**
为什么：分别承载"经营注意力 / 实际经营 / 组织结构 / 外部能力 / 深度分析 / 资料引用 / 多人讨论"七类不可互相替代的工作。何时用：每天从工作台开始；经营进业务空间；查结构进组织中心；扩能力进人才；深看数据进洞察；找依据进资料库；讨论决策进会议。关系：共享同一 Company Truth，互相带范围跳转（如从业务卡进 scoped 洞察）并返回原处。问题：无重复；七区顺序固定、不增不减（Conversation/搜索/通知/助理/设置均明确不占第八区）。

**2.2 Company OS（公司运行语义层）**
为什么：固定"公司怎么运转"的共同规则（层级、员工、责任、证据、决定、权限、恢复），让不同业务可对比、可审计。何时用：无处不在（它是规则不是页面）。关系：所有一级区消费它。问题：无重复；四层执行范围（Company/Department/Business/Workspace）已统一贯通到对话、工作、结果、证据与用量记录（实现已验收 P0 合同）。

**2.3 Department**
为什么：聚合稳定责任与共享能力，承载两个原装支撑部门。何时用：看公司结构（组织中心）、跨业务协调（业务空间的部门工作面）。关系：Company→Department→Business→Workspace 的第二层。问题：见 2.8 分类——设计上"结构在组织中心、日常领导工作在业务空间的部门工作面"分工清晰，但当前实现的部门工作面是占位页（"部门办公室 · 规划中"），跨部门协调找不到自然入口。另外"Department 不是招人前置、长期 Business 必须归属 Department、Company 级员工可不属部门"三条组合规则对普通用户偏绕。

**2.4 Business**
为什么：持续经营身份与同类工作空间的聚合层。何时用：经营一项业务、看整体状态、进它的工作空间。关系：挂 Department、聚 Workspace；业务空间是它的经营入口。问题：设计的业务页面是四段连续结构（业务定义 → 经营状态 → 工作空间目录 → 业务团队），页面合同（Business Work Surface）仍是 Review 候选未由 CEO 最终接受；当前实现是另一套简化单页（定义卡+状态+空间目录+团队卡），与设计合同有偏差。

**2.5 Workspace**
为什么：真正干活的地方，唯一用户身份锚点。何时用：一切具体经营。关系：属于 Business；内部有团队、员工工位、专业工作面。问题：无结构性问题——这是全产品最扎实的部分（Frozen Shell 合同 + 通用工作空间/研发/小红书三种已实现实例）。

**2.6 Employee**
为什么：承担责任的主体。何时用：随时（工位、对话、组织中心、人才目录、会议、结果）。关系：员工 ∈ 组织轴，通过 Assignment 服务多个 Workspace。问题：无；交互规则全局统一（见 4A.10 的统一规则）。

**2.7 Team**
为什么：长期工作空间必须由真实团队承载（Leader+成员+明确职责），否则不算完整经营。何时用：组队、看"谁在这个空间工作"。关系：团队在组织轴；一个 Business 可聚合多个各有团队的工作空间。问题：无；"组队不复制身份"规则清晰。

**2.8 Conversation**
为什么：一切工作的对话载体（对话必须锚定真实工作）。何时用：随时。关系：四种对话各有归属（助理/员工工位/会议/空间 Thread）；侧栏快捷区是入口不是第二系统。问题：实现层快捷区信息密度低于设计意图（见 4A.3）。

**2.9 Work**
为什么：把"经营意图"变成"有结果的工作"。何时用：工作空间现场、CEO 工作台的"下一责任"。关系：Work→执行→Result/Evidence→决定/下一轮。问题：无。

**2.10 Result**
为什么：经营闭环的价值锚点（内部完成≠外部结果）。何时用：工位、工作空间、CEO 工作台、业务页、会议。关系：Result Reference（对话内轻量引用行）点击进 Utility 查看。问题：当前实现的 Result 详情以 JSON 折叠为主，类型化阅读（文档/代码/数据/报告分形态）还很粗糙——能力在、表达弱。

**2.11 Decision**
为什么：高影响/不可逆事项必须人来拍板。何时用：工作空间顶部决策横幅、会议决策面板、CEO 工作台待处理。关系：统一消费 P7 8 要素 + 三层信息层级（横幅 → 方案包 → 专业证据）。问题：无。

**2.12 Meeting**
为什么：重大分歧/高影响决定/跨员工协作需要共同讨论。何时用：会议一级区或从业务发起。关系：形成 Decision → 生成责任/工作 → 结果回到会议和业务。问题：无（实现核心完成；"多轮真实云端自主讨论"的最终验收仍在等真实使用证据，非代码阻塞）。

**2.13 Knowledge（资料库）**
为什么：公司的引用与沉淀空间（读、引用、来源追踪、Used By）。何时用：找依据、读资料、给工作挂参考资料。关系：范围=公司/业务/工作空间；工作引用资料、结果反向可查。问题：资料引用进/出工作的"返回现场"体验被登记为 P1 缺口。

**2.14 Talent（人才与能力）**
为什么：外部能力生态（发现→招募/安装/连接）。何时用：扩能力时。关系：专家招募后成为组织中心的员工；技能装给员工；连接器授权归设置。问题：无结构性问题；"能力项的用户语言表达"是 P1。

**2.15 Operating Intelligence（经营洞察）**
为什么：深度看趋势/比较/归因，与 CEO 工作台的"注意力"分工明确。何时用：想深看时，可从任何对象带范围进入。关系：数据分析部（司衡）的组织责任 → 分析 → 报告/证据 → 决策支持；只消费既有事实，不做第二套数据。问题：无。

**2.16 CEO Assistant**
为什么：跨七区的公司级协调员工（第一位 AI 员工/参谋长）。何时用：随时呼出；无大事时安静。关系：不占 Four-Pane、不等侧栏、不等于 CEO 工作台；可协调/跟进/升级，不替代专业部门。问题：无。

## 2B. 具体表达问题（产品模型对，但用户看到的不够好）

**2.17** 业务空间设计的"[部门]/[业务]/[工作空间]三直接入口"（Operating Work Directory）在当前实现中未做——实现是单页业务列表；对象层级≠导航层级这个设计亮点还没有落地到 UI。
**2.18** 通知/待处理：设计定位是全局能力，但从未有专门结构合同定义它的面板/入口；当前实现并入 Assistant 徽标 + "待处理"列表，且列表条目不可点击。完整通知结构当前未定义，需要 CEO 决定。
**2.19** 设置：设计有完整六组 IA（个人与外观/公司默认/模型与 AI/权限与安全/应用与数据/账户与帮助）+ 左下头像 → 账户 Popover 入口；当前实现只有"模型与设置"（模型连接）一页，另有一个无入口的"公司设置"草稿页。
**2.20** 全局搜索：实现里同时存在"顶部放大镜（打开弹层但检索未接入）"和"侧栏底部'搜索·暂未开放'（禁用按钮）"两个入口，状态互相矛盾。
**2.21** Result 详情、Composer 槽位、Quick Access 状态、账户菜单：能力合同都在，但当前实现的表达都低于设计（详见 PART 4/后续批次）。

## 2C. 结论分类

**完全支撑（结构完整 + 已有已验收实现）：**
2.22 七个一级区框架；2.23 Company OS 对象链与执行范围；2.24 Workspace（含 Shell/工位/Composer/状态投影）；2.25 Employee（统一交互规则）；2.26 Team；2.27 Conversation（结构）；2.28 Work；2.29 Result（结构）；2.30 Decision（P7）；2.31 Meeting；2.32 Knowledge；2.33 Talent；2.34 Operating Intelligence；2.35 CEO Assistant。

**基本支撑，但表达有问题：**

# PART 3 — Desktop App 空间与 Four-Pane

**3.1 总原则（先记住）**
Four-Pane（四区）是职责模型，不是永远显示四根栏。常驻的只有两样：Navigation（导航）+ Main（主区）。Context（上下文栏）和 Utility（工具栏）是"按需出现、用完可关"的自适应面板，默认收起。同一张壳承载三种工作职责：Reading（读资料/结果/证据）、Working（与员工/工作/会议持续工作）、Operating（看方向/责任/状态/做判断）——不是三套界面。

**3.2 Navigation 是什么？**
全局负责"我在哪里"。永远有：七个一级区（固定顺序）、对话快捷区（设计）、底部"模型与设置"入口与 CEO 账户。桌面原生窗口控制（红绿灯）在导航栏顶部（合同），另有全局搜索入口与导航收起开关。不能放：员工列表、业务流程图、某业务的专属菜单（业务专属导航属于 Context）、聊天首页。宽度 220px，可完全收起（收起后主区头部出现展开按钮）。

**3.3 Context 是什么？**
当前业务的"领域导航 + 工作上下文"栏。默认隐藏；由主区头部的 T2 开关或对话内上下文引用触发；窄窗口转抽屉。里面应该是：当前工作空间的 Domain Navigation（该业务自己的专业菜单）、当前对象/责任/相关文件目录、最近对象等"持续浏览型"信息。不该放：员工列表、员工对话、员工详情、完整业务真相。空态规则：没有上下文就不显示入口，不预留空面板。

**3.4 Main 是什么？**
"我正在做什么"的主工作区，必须自己成立（Main must stand on its own）：Context/Utility 全关时，CEO 仍能看懂业务整体状态并完成主要工作。默认承载：一级区的页面内容；在工作空间里 = 当前选中的专业工作面（业务展示区）+ 工作区（员工工位列表，每个员工一行，展开是对话工位）。什么时候换内容：点导航换区、换工作面、下钻对象时替换；面包屑显示层级，返回保留现场。

**3.5 Utility 是什么？**
"我正在看/修改什么"的右侧栏。默认关闭；由对话内结果引用（📄 … ▸）、点头像/姓名（员工详情）、对象动作触发；可拖宽、可"最大化"成全屏（Esc 退出）。适合放：Detail（详情）/ Editor（编辑器）/ Evidence（证据）/ Tool（专业工具）/ Result 阅读。不同对象打开后不一样：员工=六字段档案（永不含对话）；结果=预览+证据+执行详情；研发=代码差异/源码/预览三种模式；资料=来源/权限/引用/使用关系；小红书=图文预览/数据/审核。铁律：Utility 永远不承载对话——对话一旦出现必在 Main 的员工工位。

**3.6 完整 App 空间关系图（【设计】结构；【实现】已按此落地）**


## 5.1 CEO 工作台

**5.1.1 解决什么**：公司级注意力——今天需要知道、决定和推进的事。
**5.1.2 谁用**：CEO 一个人。
**5.1.3 何时进入**：App 启动默认落地页；随时从导航回。
**5.1.4 Navigation/Context/Main/Utility**：导航高亮"CEO 工作台"；本页不注册 Context/Utility 双栏（结果用页内浮层查看）。
**5.1.5 第一屏**【实现】：问候语 + 一句话定位（"只看今天需要知道、决定和推进的事情"）+ 公司事实条（公司名 · N 个工作空间 · "N 项需要关注"/"经营平稳" · 数据可用性说明）+「进入业务空间」按钮。
**5.1.6 两种首屏形态**：① 新公司 0 业务 = 左侧"创建业务"对话（助理提问 → 生成可编辑提案卡：业务名/目标/第一工作空间 → 确认并创建/返回修改）+ 右侧"公司已建立 · 开始第一项业务"卡；② 有业务 = 四块：今天最重要（主事项：摘要 + 来源责任 + 类型徽标 + RESULT 类带「查看结果 ▸」+「回到业务现场 →」）、持续关注（2–4 项）、重要结果、下一责任（含下次检查时间）；底部与助理的对话区。
**5.1.7 主要动作**：查看结果（原地打开结果视图，不跳页）、回到业务现场（→业务/工作空间）、进入业务空间、与助理对话。
**5.1.8 返回**：从任何下钻回来恢复本页状态；跨日连续性（昨日未决事项自然进入今天）为已接受产品合同。
**5.1.9 不退化为什么**：数据大屏、任务列表首页、固定秘书侧栏。

## 5.2 业务空间

**5.2.1 解决什么**：经营工作目录——从部门/业务/工作空间三个直接视角进入经营现场。
**5.2.2 谁用**：CEO（及查看经营的场景）。
**5.2.3 何时进入**：开始/查看经营；从工作台"进入业务空间"；从组织中心业务卡"进入业务详情"。
**5.2.4 设计结构 vs 实现**：【设计】Operating Work Directory：[部门]→部门工作面、[业务]→业务工作面、[工作空间]→专业工作空间三入口 + 业务组合 + 需关注。【实现】单页：多业务时顶部切换；业务页 = 业务定义卡（目标/定位 + 状态徽标：草拟中/经营中/已暂停/已归档）+ 经营状态三数字 + 工作空间目录（每行：空间名+状态·更新时间+「进入工作空间 →」；头部「新建工作空间」→ 搭建器）+ 业务团队卡（成员+责任）+「创建另一项业务」链接。【缺口】三入口未实现；部门办公室是占位页（"规划中"）。
**5.2.5 0 业务空态**【实现】："当前还没有经营业务" + 创建业务对话/表单 + 可折叠"委托空间工程团队"（输入目标 → 交给空间工程负责人 → 与负责人继续讨论 → 员工详情页）。
**5.2.6 工作空间门户**【实现】：另有独立"工作空间"页（卡网格：业务名+空间名+状态+部门+查看入口；「搭建工作空间」→ 搭建器：研发/小红书/抖音三模板 + 八阶段生命周期）。
**5.2.7 返回**：页间返回保留业务上下文；从工作空间返回所属业务。
**5.2.8 不退化为什么**：项目列表、无结果的业务卡片墙、统一看板。

## 5.3 组织中心

**5.3.1 解决什么**：公司的结构与行政真相——公司长成什么样、谁承担什么。
**5.3.2 谁用**：CEO；结构调整时。
**5.3.3 两个 Tab（固定）**：公司版图（默认）/ 员工目录。
**5.3.4 公司版图**【实现】：搜索框 + 空缺计数；按部门分区（部门头：名/职责/"N 个业务 · N 个空缺 · N 项需关注"）；业务卡（状态点+名+负责人+「查看业务 →」→ 聚焦视图：目标与经营方式/岗位结构/工作空间次级入口/右栏摘要 +「进入业务详情」→业务空间页）；未归属部门的业务有警示条。原装两部门（空间工程部/数据分析部）与新公司一起出厂显示。
**5.3.5 员工目录**【实现】：按部门分组员工卡（头像+名·岗位+部门+业务·岗位分配+状态点）+「查看 →」→ 员工详情页；底部"N 个岗位空缺 · 待招聘"→「去人才与能力 →」。
**5.3.6 边界**：组织中心只管结构与行政；Leader 的日常对话/交接/决定在业务空间的对应工作面承载（设计）。
**5.3.7 已验收**：组织中心 UI 与实现均已验收（canonical 组织投影）。

## 5.4 人才与能力

**5.4.1 解决什么**：外部能力生态——发现并引入专家/技能/连接器。
**5.4.2 三栏布局**【实现】：左栏 = 三个 Tab（专家/技能/连接器）+ 专业领域分类 + "公司已有"快捷（公司员工 N 名/已安装技能 N 项）；中列 = 列表（专家 Tab 内切换"可招聘与准备中/公司员工"；搜索+计数）；右栏 = 详情面板。
**5.4.3 点击卡片**【实现】：→ 右栏详情（"能为公司做什么" + 来源与使用条件折叠 + 动作）。
**5.4.4 专家**：→「招聘这位专家」→ 右侧滑出招聘面板（员工姓名/公司/部门可选/头像：8 款预置（鸢尾/青禾/珊瑚/琥珀/晴空/青梅/薄荷/岩蓝）或上传或暂不设置）→「确认加入公司」→ 成为公司员工（进组织中心）。已是公司员工 → 显示归属+已具备能力+「查看员工详情」。
**5.4.5 技能**：→「安装到公司」→ 安装后出现「分配给员工」下拉。
**5.4.6 连接器**：→ 连接状态说明（当前未提供安全授权入口，如实显示"未连接/需要授权"）。
**5.4.7 模型/提供方不在本页**：在「模型与设置」页（见 4.17）。
**5.4.8 边界**：专家 ≠ 员工（招募才转换）；原装员工不出现在待招聘列表。

## 5.5 经营洞察

**5.5.1 解决什么**：深度经营分析——趋势、比较、归因、报告与决策支持。
**5.5.2 与数据分析部的关系**：分析部（司衡）是组织责任主体；本区是产品工作面（分析师的工作位）。
**5.5.3 头部控件**【实现】：范围下拉（全公司 + 各业务）+ 7 天/30 天切换。
**5.5.4 三个 Tab**【实现】：① 概览 = 分析师头像卡 + 本期经营观察（结论→事实→分析→建议）+ 指标按钮排（点击跳"探索分析"）+ 右栏"事实可信度"（来源/人工记录/外部结果）与"继续分析"（探索业务/查看报告）；② 探索分析 = 同口径的当前/上一周期/样本对比 + 业务对比（不可比时说明原因）；③ 分析报告 = 左报告列表 + 正文（事实/分析/仍未知/建议）+「查看方案并交给 CEO 决定」→"已形成 CEO 决策事项" + 右栏证据与来源。
**5.5.5 数据诚实规则**：未知显示"—"不显示 0；无报告显示"还没有经营分析报告…不会自动生成示例报告"。
**5.5.6 返回**：从 CEO 工作台/业务/员工/版图带范围进入，完成后回原上下文。

## 5.6 资料库

**5.6.1 解决什么**：Company Reference Space——读取、引用、来源追踪与沉淀（不是文件管理器）。
**5.6.2 页头**【实现】：事实条（可浏览资料/明确归属/本地来源）+「导入文件」抽屉（资料根/路径/标题/使用范围/标签）+「新建资料」抽屉（标题/使用范围/标签/正文）。
**5.6.3 两个 Tab**【实现】：概览（最近使用与更新/常用资料/需要确认/来源覆盖说明）+ 浏览与搜索（关键词 + 筛选：使用范围（公司/业务·/工作空间·）、来源（手工内容/本地文件）、排序 + 条目列表（状态徽标：可引用/已归档/来源待恢复 + 范围 + 来源 + 标题 + 摘要 + "被 N 项工作引用"）+「加载更多」）。
**5.6.4 阅读详情**【实现】：独立页 = 正文卡（摘要+正文+标签）+ 右栏（来源与范围 / 被哪些工作使用→跳工作空间 / 相关结果与证据）+「归档资料」（确认后归档）+「查看技术详情」（哈希等）。
**5.6.5 选择器模式**【实现】：从工作项"添加参考资料"进入时，标题变为"为当前工作选择资料"，可多选后「添加 N 条并返回」回原工作。
**5.6.6 缺口**：引用后"返回现场"体验是 P1；外部格式（PDF/网页等）与连接器是后续边界。

## 5.7 会议

**5.7.1 解决什么**：持续的多人经营讨论——讨论、提案、决定、责任、结果续接。
**5.7.2 列表页**【实现】：头部（"会议" +「召开会议」）+ 当前会议列表（行 = 标题 + "背景 · N 位员工" + 状态徽标（讨论中/等待你决定/等待结果/已结束）+「进入会议 →」）+ 搜索 + 最近历史会议（标题 + 结果数 + 参与者 + 日期）。
**5.7.3 召开会议弹窗**【实现】：议题、背景、相关工作空间（联动业务）、推进负责人、参与员工多选、相关资料（知识条目）、你的参与方式三选（只在需要决定时参与/旁听并接收进展/参与完整讨论）→「开始会议」→ 进入会议详情。
**5.7.4 会议详情（房间）**【实现】两栏：主栏 = 参与者徽章（含"· 推进"标记）+ 决策面板（等待你的决定：「按建议处理」/「查看方案」/「暂缓」；展开后每方案显示 影响/风险/代价 + 来源标注[事实/规则/证据/员工估计/未知] +「选择这个方案」）+ 讨论时间线（系统事件居中、决策/结果/决定为事件卡、CEO 消息右对齐、员工消息带头像）+ 发言输入框 + "形成下一项决定"表单（发生了什么+方案一/二+提交 CEO 决定）；副栏 = 会议上下文（CEO 参与方式/查看相关工作空间/引用资料 N 项）+ 工作与结果（工作卡"已交给负责员工/已完成" + 结果卡 + 后台续跑状态）。顶部：「刷新进展」「结束会议」。
**5.7.5 持续性**：CEO 离开不结束会议（后台继续讨论/推进）；再次进入恢复完整时间线与状态；每 5 秒轮询刷新。
**5.7.6 闭环**：提案 → CEO 决定 → 生成责任/工作 → 结果/证据回到会议与业务。
