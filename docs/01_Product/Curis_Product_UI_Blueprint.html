02 · Curis UI 总原则

Curis 能力可以丰富，但默认视口只暴露当前任务立即需要的信息和动作。简洁不等于功能少。

Low Surface Complexity, High Functional Density

低表面复杂度，高功能密度。第一眼简单；开始工作后，正确能力在需要时自然出现。优先使用对象点击、+、···、Popover、Context Menu、Collapse / Expand、Hover Action、按需 Context Sidebar、按需 Utility Surface 与 Focus View。

反模式

不以传统企业工作台方式同时堆叠大量 Button、Card、永久 Tab、固定工具栏和全部能力。每个 Button、Tab、Menu、Pane 必须回答“用户为什么现在需要看到它？”；回答不了就降低层级或删除。

层级何时可见示例
L1 · ALWAYS VISIBLE当前工作的核心。Workspace 身份、当前责任、Workstation 状态、正在展开的 Conversation、一个 Composer。
L2 · CONTEXTUAL当前对象或当前责任真正需要时。Handoff、Needs CEO、轻量 Result 引用、Code / Diff / Preview、错误和恢复说明。
L3 · ON DEMAND用户主动调用。+、···、Popover、Context Menu、Focus View、Context Sidebar、Utility Surface。
L4 · ADVANCED / INTERNAL普通用户默认不出现。完整 Permission、协议、Session History、Git / Worktree、Trace、Runtime 状态机与高级诊断。
CEO Review Delta 已应用：当前 UI 只消费公司版图 / 员工目录、人才与能力 Market / Discover 和 Employee 三态状态语义；不新增导航、不把历史组织模型或旧员工状态带回当前界面。
真实状态，不伪装接通：完整产品可以先定义正确位置，真实能力再接通。Provider / Agent / Connector / 权限必须如实表达：已可用、未连接、未安装、需要授权、需要配置、健康未知、不可用、未来接入、阻塞或未知；不能用示例数据声称已连接、已授权、已完成。

一级导航 · 长期存在

只负责“我在哪里”。顺序固定：CEO 工作台、业务空间、组织中心、人才与能力、经营洞察、资料库、会议。最近工作可放下方；头像 / 设置在左下。搜索、通知 / 待处理、CEO Assistant 是全局能力，不占一级导航。

04 · 按任务调用的空间原语

不要先选组件再塞内容。先看任务关系，再选择空间。

空间原语何时使用正确示例不应使用
Context Sidebar当前工作天然需要持续浏览目录、层级、集合、Thread、文件或历史。资料库的来源 / 文件夹 / 外部库；研发首版的当前 Project / Workspace、Responsibility、相关文件 / 目录、Recent Work / Recent Object。员工列表，以及 CEO 工作台、业务空间总览、组织中心、人才与能力、会议首页为了填栏而出现的二级导航。
Flexible Utility Pane用户必须保持当前主要工作，同时查看或微调当前选中的辅助对象。研发首版：Code / Source、Diff / Changes、Preview / Result；小红书：图文 / 发布预览 / 数据 / 任务；抖音：视频 / 脚本 / 素材 / 字幕 / 封面 / 数据；资料阅读时的来源、权限、引用。固定 Inspector、固定成果栏、完整专家介绍、完整员工工作、资料深度阅读、完整会议讨论。
Dialog / Focus View用户暂时离开浏览状态，集中查看、比较或判断一个对象，关闭后回到原列表。人才与能力的 Expert、Skill、Connector；业务与结果的完整介绍。两三行状态、快捷筛选或需要持续进行的实际工作。
Popover轻量状态、快捷操作、简短说明、通知、筛选或上下文菜单。待处理提示、通知、筛选、更多操作。专家档案、结果来源链、招聘装配、员工对话。
Full Workspace对象本身已经成为用户当前主要工作。员工直接对话、研发项目、会议工作面、内容工作室、资料深度阅读。只需快速瞥一眼属性或执行轻量操作的对象。
可折叠的正确定义：需要时出现，不需要时不存在；出现以后允许用户折叠。Context Sidebar 和 Flexible Utility Pane 都不是“默认存在，再让用户收起”的固定布局部分。

05 · 空间选择顺序

任何点击和新页面先经过这个判断，不允许“一律右栏”。

01这是当前主要工作吗？
是 → Main Workspace / Full Workspace；多个 Employee Workstation 在 Main Workspace 同时存在。
02只是临时聚焦查看一个对象吗？
是 → Dialog / Focus View。
03必须保持当前工作，同时查看或编辑辅助对象吗？
是 → Flexible Utility Pane。
04需要持续浏览目录、层级或集合吗？
是 → Context Sidebar（项目、Thread、资料目录、文件、业务对象、历史；不是员工）。
05只是非常轻的信息或操作吗？
是 → Popover。
06没有命中以上条件吗？
保持一级导航 + 主工作区，不人为加辅助空间。

06 · 七个一级区域的空间组合

它们共享视觉系统、一级导航、交互语言、返回逻辑和状态表达，但不共享固定的四栏模板。

一级区域默认空间按需空间与点击规则
CEO 工作台一级导航 + 宽主工作区。公司简报、今日变化、当前运行、重要结果、待处理直接在主区；轻量提示用 Popover；完整结果或判断用 Focus View；只有需要保持当前现场时才用 Flexible Utility Pane。
业务空间一级导航 + Operating Work Directory 宽主工作区。同一 Company Truth 提供[部门]→Department Work Surface、[业务]→Business Work Surface、[工作空间]→Professional Workspace三个直接入口；不强制按对象层级逐层进入，进入 Workspace 后由专业工作面决定 Context Sidebar 或 Pane。
组织中心一级导航 + 公司版图 / 员工目录。公司版图回答“公司长成什么样、业务扩张到哪里”；默认展示 Department、Business、经营状态、Role / Staffing、风险和重要结果。Organization Center 只负责结构与行政；Leader Workstation / Conversation 属于业务空间的对应 Work Surface。员工目录反查 Role / Business / Department。
人才与能力一级导航 + Market / Discover 主区。专家 / Skill / Connector、搜索、分类、推荐和卡片直接在主区。点专家优先打开大 Focus View，完整展示身份、擅长、能力、案例、来源和招募；点击“招募”后才进入合适的装配空间。
经营洞察一级导航 + Operating Intelligence 主区。公司经营、业务分析、组织与员工、模型与能力、分析报告、专项研究；按当前范围显示趋势、比较、归因、来源 / 新鲜度 / 未知 / 手动回填。分析报告可追问并回到原 Business / Workspace / Employee。
资料库一级导航 + 资料 Context Sidebar + 主工作区。最近、本地、文件夹、外部资料库、公司产生需要持续浏览，故侧栏成立。点资料阅读时进入主区；只看来源 / 权限 / 引用 / 使用关系时才开 Flexible Utility Pane；轻量操作用 Popover。
会议一级导航 + 宽主工作区。即将开始、需要准备、历史会议直接在主区；进入具体会议后成为 Full Workspace。Conversation 拥有完整主区；成员、资料、Proposal 只按需以 Pane / Focus / Popover 出现。

07 · 对象点击与返回契约

空间选择服务于当前任务；关闭或返回必须保留来源和未完成输入。

对象默认打开方式为何不是统一 Utility Pane
专家Focus View；招募时进入装配空间。身份、介绍、擅长、能力、案例、来源与招募需要完整阅读和判断。
Skill / ConnectorFocus View；安装 / 授权进入专注步骤或设置返回路径。用户需要理解能力范围、依赖、来源、授权与可用性，而非只扫属性。
员工快速查看：Focus View；实际协作：所在 Workspace 的 Employee Workstation / Full Workspace。员工自己的持续 Session 位于 Main Workspace，不能退化为组织列表旁的聊天或 Context Sidebar 条目。
资料阅读：主工作区；属性：Flexible Utility Pane；轻量操作：Popover。资料正文与来源属性是两种不同任务。
业务 / 结果完整理解和判断：Focus View；继续经营：进入业务或 Workspace。避免挤压业务空间，也避免把结果当成仅供查看的右栏字段。
会议会议首页是主区；实际会议进入 Full Workspace；Decision 回到来源 Workspace 与 Employee Workstation。讨论、资料和决定是连续工作，不是侧栏详情或中央团队群聊。

用户在当前访问期间手动收起后，系统尊重其布局。Conversation可跨Assignment持续；责任变化更新真实Scope/消息引用与权限，不强制新Conversation。执行Session按真实Provider能力处理；人工接续和恢复回同Work。

13 · 自动化、结果与学习的渐进式表达

Organization / Role / Responsibility / Business / Workspace 自动产生协作语义。用户看谁在做什么、为何等待、下一步，不看 Workflow DAG。

自动工作现场

产品经理 · 空闲 架构师 · 空闲 开发工程师 · 工作中 · Shell 适配 QA · 阻塞 · 缺少输入

员工只显示空闲 / 工作中·<desc> / 阻塞·<cause>。刚完成什么、等待什么和是否达成，属于 Goal / Task / Result 的内容，不写入 Employee 状态。支持串行、并行、回退、重新分配、请求帮助和 CEO 介入；自动与人工继续同一 Employee Session。

不增加独立 Console

所有 Workspace 只自然表现：下一次运行、当前运行、负责员工、当前阶段、下一步、等待原因、需要我、失败、恢复。配置从 Studio 或对象 Pane 进入；允许 Workspace 内嵌的轻量 Workflow Editor（Add Role、Delete Role、Reorder、Responsibility、Employee Binding、Input、Output、Next、Return），不创建独立 Workflow / Automation / Scheduler / Runtime Console、自由 DAG 或无限画布。

15 · Workspace Studio：持续演进的专业工作空间

Studio 是 Workspace 的配置与演进空间，不是一级导航、不是一次性创建向导、不是普通用户从零画流程。

用户看到的工作空间

  • 工作空间：做什么、属于哪个 Business、主要 Goal。
  • 专业界面：研发的项目 / 文件 / 测试 / Review；内容运营的日历 / 内容 / 数据 / 自动化。
  • 团队：有哪些 Workstation，谁负责什么。
  • 能力：Skill / Agent / Tool / Connector / Knowledge。
  • 自动工作：何时开始、何时交接、何时等 CEO、失败如何继续。
  • 结果：Result、数据回收、Review 与反馈。

“参考竞品”不能只记录功能名。每个重要参考必须说明其对象、空间、交互、功能布局与视觉语言，再转译为 Curis 规则。

减少视觉噪音的正式规则

对象、行、面包屑、Hover Action、Popover、Composer Action 与命令优先成为入口。一个视口通常只保留 0–1 个强主按钮；完整信息进入 Focus View，轻量状态进入 Popover，持续工作进入主区。Tab 仅在同一对象下确有稳定、同级的工作视图时出现，不以永久 Tab 代替渐进披露。

17 · Workspace 内部结构权威指针（消费 Frozen Shell Contract）

本 UI Blueprint 只定义空间原语、七区导航与通用交互基调。任何 Workspace 内部结构（四栏 Pane、Adaptive Surface 默认收起、Main 自成立、Main = Domain Business Surface + 工作区、Employee List/Row/Status、Conversation、Composer、Model/Agent-backed、Employee Detail/Result → Utility、Context Isolation、Runtime ≠ UI 展开、长内容块规则）一律以 Frozen Curis_Workspace_Shell_Contract_And_Shared_Patterns.md 为准，本文件不重复定义、不新增规则。下列为本文件直接消费的 Shared 规则索引（真值与细节以该 Frozen 文件为准）：

Professional Workspace / Multi-Surface 接受边界：Four-Pane 是职责模型，不是固定四根物理栏。Navigation 负责公司级导航；Context 负责当前业务的 Domain Navigation 与当前上下文；Main 显示当前选中的 Professional Surface 及相关工作；Utility 承载当前对象的 Detail / Editor / Evidence / Tool；CEO Assistant 是 Global Company Employee，不是第五个 Pane。切换 Surface 只改变 Truth 的观察与工作入口，不新建 Runtime、Team、Employee、Cycle、Result 或 Session。

壳层与导航（消费 Frozen §0–§2）

  • Navigation / Main 为默认基础桌面；Context / Utility 为 Adaptive Surface，默认收起（Frozen §0.1 Main must stand on its own）。
  • 四独立 Pane 顶部齐平、各自 Pane-local Header，无全局 Topbar（Frozen §1.2 / §1.5）。
  • Main = Domain Business Surface（业务展示区，内部架构名非强制 UI 标题）+ Shared Work Area（工作区）；Employee Workstation ∈ 工作区 ≠ 整个 Main（Frozen §0.1 / §3.1）。

工作区与员工（消费 Frozen §3.1 / §3.8 / §3.14）

  • 工作区 = Employee Workstation List，普通列表行（不做 Card）；Employee Row 两行结构（头像跨两行 + 姓名岗位 + 当前职责 + UI Status 投影 + 展开箭头）。
  • Shared Employee UI Status = Runtime Truth 的用户侧投影（空闲 / 工作中·<desc> / 阻塞·<cause>），不改动 Runtime State Schema（Frozen §3.1）。
  • 点头像/姓名 → Utility Employee Detail（六字段，无 Conversation）；Conversation 只在 Main Workstation（Frozen §3.12 / §3.14）。
  • Runtime State ≠ UI 展开状态；收起不暂停、不改变真实工作状态（Frozen §3.1）。

Conversation 与 Composer（消费 Frozen §3.1 / §3.4 / §3.5）

  • Conversation 不 Card 化、普通短消息自然流；长内容（长文本/Tool/Terminal/Code/Diff/Structured Result）用 bounded embedded content block，块内滚动、可进 Utility 完整查看；不 Frozen px/字数/样式（Frozen §3.1 Delta-X12）。
  • Shared Composer Shell 固定语义槽位（Input / + Add / 访问权限 / 工作模式 / 已选资源 / 执行选择 Model·Agent / Voice / Send），布局仅 Desktop 推荐、响应式可重排（Frozen §3.5）。
  • Provider Adaptation：Shared 固定槽位 + 显性区分 Model-backed / Agent-backed；Provider 决定权限/模式/能否切模型/Agent 原生设置，不写死具体 Provider（Frozen §3.5）。

引用与隔离（消费 Frozen §3.4 / §3.12）

  • Result / Artifact 在 Conversation 内用轻量引用（📄 标题 ↗），点击 → Utility 专业预览；Utility 内可完整展示（Frozen §3.4）。
  • Context Isolation：History/Knowledge 不自动注入进行中 Workstation Context；Context 只答本次工作上下文，不含完整员工详情 / 不含 Conversation（Frozen §3.12）。
