# B1. 判断方法（六类执行方式 + 五层职责分离 + 三条判定纪律）

## 六类执行方式
| 类别 | 定义 |
|---|---|
| AI DIRECT | AI 本身可完成（研究/分析/写作/脚本/计算——经 Curis 云模型执行） |
| API / CONNECTOR | 需平台正式 API/OAuth/Connector 授权（企业资质应用+权限申请+用户授权） |
| COMPUTER USE | 无 API，但可通过操作真实网页完成——必须逐项验证：网页有无该能力/是否登录/会话能否持续/验证码/高风险确认/稳定性/回执可靠性 |
| AI ASSISTED | AI 准备材料/分析/建议，最终动作用户完成 |
| USER REQUIRED | 只能用户完成（手机 App 独占、真人、支付、实名、扫码） |
| CURRENTLY UNAVAILABLE / FUTURE | 今天无法接入闭环只记录结果 / 能力变化后可升级 |

## 五层职责分离（不混判）
`INFORMATION（能不能看到）→ ANALYSIS（能不能分析）→ RECOMMENDATION（能不能建议）→ DECISION（该不该自主决定）→ EXECUTION（能不能执行）`。
看到≠该决定：星图/百应 AI 可读可析，**是否接单永远是 CEO 决定**（商业承诺+信用分风险）。

## 三条判定纪律
1. **网页存在 ≠ AI 能稳定执行**：按钮存在只是必要条件。
2. **回执必须有可靠来源**：无回执的自动化不可进闭环。
3. **平台风险不对称**：账号是被经营资产，任何可能触发风控的路径默认降级，除非收益显著且经 CEO 授权。

# B4. 普通发布真实自动化边界（重点重研）

**Path A — Official API（官方存在，L3 证实）**
- 接口：上传视频（获 video_id）→ 创建视频（发布）；scope=`video.create`；需**权限申请+用户 OAuth 授权**；mp4/webm ≤128MB；支持话题/挂小程序；**发布后有审核期，期间仅自己可见**；部分旧发布能力已下线（能力状态需实测确认）。
- 资质链：Curis 运营方需**企业资质开发者应用+该权限过审**；用户（CEO 的抖音号）OAuth 授权即可，个人账号可授权。
- 能力边界：标题/话题 ✓；封面（API 证据不足，UNKNOWN）；定时（无证据）；**挂商品/团购（无 API，✗）**；回执=item_id ✓ 可靠。
- 结论：**普通视频发布存在真实自动化通道**——当前未落地的原因是 Curis Connector 体系未实现+权限未申请，不是平台不存在。

**Path B — Computer Use（Web 创作者中心）**
- L1 证实：Web 发布页真实存在（四体裁、拖拽上传、表单）；登录后可操作。
- 三个未验证的硬问题：①登录会话如何持续（每次扫码 vs 浏览器 profile 保持——后者有风控与账号共享风险）；②文件上传自动化稳定性；③抖音风控对自动化操作的态度（无官方容忍声明，风险不对称）。
- 结论：**TECHNICALLY POSSIBLE BUT UNVERIFIED**；只适合"CEO 在场"的单次辅助（AI 打开页面+备好字段），不适合无人值守。

**Path C — User Manual（当前主路径）**
- 交接卡：AI 备齐标题/话题/封面建议/文案→CEO App/Web 发布→贴链接回执。ASSISTED 成熟度。

**成熟度结论**：普通发布当前真实成熟度 = **ASSISTED（AI 备齐 + 人执行）**；升级路径明确且不依赖黑科技：**API 落地 → AUTOMATED（普通视频）**；Computer Use 作为补充而非主路径。

# B8. Qualification：Curis 到底需要知道多少

四种方式分析：
- A（AI 读取数据+规则自动判定）：可做**hint**，不可做最终态——规则会变（有效粉丝新规先例）、平台可能有隐藏条件（违规/信用分）。
- B（告诉用户"可能已满足"，用户去平台确认）：**正确的最终确认步**——一次 App 内点击，成本低。
- C（用户看到后告诉 Curis）：作为兜底合法，但丢策略时机。
- D（API 直读资格状态）：部分存在（数据接口可得粉丝/有效粉丝），完整资格状态 API UNKNOWN。

**结论：Curis 需要"知道结果"，不需要"复制平台的资格规则引擎"。** 资格系统价值不在复述门槛（抖音 App 自己会提示），而在：①资格状态**直接改变 AI 团队下一步经营**（解锁直播→筹备开播包；解锁挂车→启动选品）；②跨多账号的资格对比与达成预测；③把"达标"转化为自动经营动作。实现形态：**AI 算 Gap→提示确认→记录状态→触发经营动作**（AOB：AI 算、人确认、记录为准）。九字段资质档案 SIMPLIFY 为：状态/差距/下一步+确认来源。

# B10. 数据自动获取边界

**先问 AI 经营需要什么，再决定保存什么。真正改变下一轮 Strategy 的字段只有**：完播率（+5s 完播/2s 跳出）、播放量、互动率、粉丝净增、有效粉丝、划走率、粉丝画像分布、吸粉/脱粉。数据中心 20 个指标不等于 Curis 保存 20 个——**经营需要 ~9 个核心字段**，其余按需。

获取三档：①**导出文件**（L1 证实导出按钮存在于作品/粉丝数据）——当前主档，AI DIRECT 处理；②API（企业资质，T+1）——Connector 后升级；③Computer Use 读屏——不优先（不稳定+成本高+有导出在）。

Mobile-only 数据（任务收益明细/钱包/直播数据）→ 用户低频回填，只收经营所需（金额/状态/来源）。

# B11. Revenue 需要反馈到什么程度

Curis 不做完整钱包对账（那是抖音钱包的事）。经营复盘需要：**按结算状态（应计/待结算/可提现/已到账/扣减）+ 按机会/内容归因的金额结果 + 成本项**。回填频率天然低频（T+15/月结）。字段收缩为：来源/金额/状态/日期/归因（机会 ID）。

价值结论：Computer Use 的真实价值排序 = **读（数据/机会/规则）> 导出触发 > 表单填写辅助 > 无人值守执行（不做）**。它的正确产品化不是"自动发布"，而是**"登录会话内的 AI 浏览助手"**：CEO 打开并登录一次，AI 在会话内完成读/筛/整理，高风险动作仍交接。

# B13. 按 Account 阶段的 AI / USER 分工

| 阶段 | AI 能做到哪 | CEO 做什么 |
|---|---|---|
| 1 接管 | 引导/档案/资格初算 | 扫码 |
| 2 起号 | 全部生产+规划+任务机会判断 | App 报名+投稿（交接卡）；提供导出 |
| 3 增长 | 生产/分析/实验设计/复盘 | 发布执行；每周数据文件拖入 |
| 4 资格开放 | Gap 计算+达成提醒+开通包 | App 内确认资格/实名/缴费/学习任务 |
| 5 发现机会 | Web 侧候选读取（星图/变现广场）+带回机会的 Fit 分析 | App 任务/团购带回；星图可让 AI 会话内读 |
| 6 围绕机会生产 | ~100%（命题解析→生产→审核就绪） | 素材实拍类（探店/出镜） |
| 7 发布/执行 | 普通内容=备齐（未来 API 自动）；变现内容=绑定前全备 | 挂车/绑任务/绑 POI/送审确认 |
| 8 数据/收益 | 导出处理/归因/状态机 | 低频回填钱包/任务收益 |
| 9 Learning/下周期 | 自主完成分析+提案；CEO Gate 后自动排下一周期 | 确认策略调整 |

**总答案：AI 自主经营到"经营决策与内容生产全链自主 + 平台动作人工 + 数据半自动"；即 AI 负责"经营大脑与工厂"，CEO 负责"平台上的手"。**

# B14. 经营闭环成熟度（重新定义）

- **L1 AI Production**：AI 只生产内容，人经营。 
- **L2 AI Production + Analysis**：+数据回流分析（人工供数）。
- **L3 AI Operating with Human Platform Actions**：AI 经营决策/生产/复盘自主，平台动作由人执行（交接卡闭环）。**← 抖音在 Curis 的当前位置**（数据靠导出回填属 L2.5，发布 ASSISTED；综合定级 **L3（低配）**）。
- **L4 AI Operating with Computer/API Execution**：发布/数据/读单经 API 或稳定 Computer Use 真执行（普通发布自动化、数据自动化、星图/百应读单自动化）。**升级条件（全部明确可达）**：①Curis Connector 体系实现+video.create 权限申请落地；②数据接口权限或导出自动化；③登录会话内 Computer Use 稳定化（会话保持方案+风控边界）；④变现发布的绑定类动作**不会**因 L4 消失（平台无 API）。
- **L5 Autonomous Operating**：含机会获取与变现执行全自动——**抖音模型下不可全达**（App 绑定/支付/实名/真人环节是平台设计使然）；L5 只在"平台开放完整 API"的世界线成立。

升级顺序建议：数据自动化（价值最高/风险最低）→ 普通发布 API → 会话内 Computer Use 读取 → 变现辅助深化。
