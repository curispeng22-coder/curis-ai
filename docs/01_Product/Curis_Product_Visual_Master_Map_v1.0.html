视角一 · Company View

Curis 这家公司由什么组成

Curis 不是任务流，而是一家 AI 公司操作系统：CEO 通过 CEO 助理建立并经营一家公司，AI 员工在业务办公室中承担责任、交付可被验收的真实成果。下面的对象、不变量与模块共同定义了这家公司的世界。

产品不变量（12 条）
  1. 没有结果目标，不能建立正式业务。
  2. 没有明确责任，不能启动工作。
  3. 有 Capability 不代表有可用 Capacity。
  4. 内部完成不等于外部结果。
  5. 没有来源和证据，不能标记 Verified。
  6. Unknown / Stale / Conflict / Waiting / Blocked 都是真实状态。
  7. 高影响变化必须有影响预览、模拟、CEO 决定和可逆路径。
  8. AI 只能在授权范围内自动执行，不能静默改变高影响公司状态。
  9. 岗位和员工是产品身份；Model/Agent 可替换，不改变岗位责任。
  10. 业务退出要保护承诺、完成交接、释放资源并保留学习。
  11. 外部平台未连接时，必须提供 CEO 手动反馈路径，不得填充演示数字。
  12. 一个页面只有一个主行动；配置动作与经营动作分开。

Curis 当前实现

半完成 当前 FoundingRun 已有 INTENT→CLARIFY→PROPOSED→CEO_CONFIRMED→Company 状态链，但只建立“公司壳 + CEO 助理”，缺少 Company Thesis、首个业务、最小团队、启动检查；且前序仍以表单式向导为主，非对话式。CEO Desk 建立后 Assistant 仍“未命名/未设角色”。

OpenOPC 参考

OpenOPC 的 Org → New organization 同样先建组织再加成员；但它默认值多、内部状态隐藏，用户前台名词少。Curis 不必复制其 CLI/YAML 架构，但应借鉴：把组织/角色/员工的内部状态下沉，前台只呈现“公司在筹建什么”；以及其“自组建（Self-Built）”理念——给定目标即自动起草架构、招人。

最终方案

待讨论 采用用户 §6 重定向：CEO 助理先于一切出现；模型连接是启动依赖、非产品主角；创办以对话为主，助理主动帮 CEO 思考；不一次规划全部公司，先建立可开始经营的最小公司。需 CEO 裁决：是否允许“先浏览后连接”、Thesis 草案的落库时机。

OpenOPC 参考

Curis 当前实现

半完成 新 Runtime 角色槽位与旧 Department/Employee CRUD 并存；专业员工仍以候选/提议状态出现，前台“岗位→员工→能力”未成清晰主线；入口读取偶发不稳定。CEO Assistant 已创建但未命名/未设角色。

OpenOPC 参考

OpenOPC 在 Org → Team 直接呈现角色图、名册（Roster）、角色检视器；Employees + 人才市场支持“招募至空缺角色”“重用已有员工（带历史经验）vs 新人”；Team Roster → Deploy 把雇佣员工变成可见办公室 Agent。Curis 应借鉴：岗位/员工/模型三层稳定分离、空缺角色直接招募、经验员工可复用；以及其阻塞升级（blocking message 暂停发送者、激活最适合角色、超权限升级人类所有者）。不复制：不把 Agent 当员工身份、不回到 Task-first。

最终方案

已确认 新建 Role→Employee→Capability 前台体验，旧 CRUD 下沉；首屏表达“岗位→员工→能力→当前承担 Agent/Model”，明确模型可替换；部门成立由业务工程部按重复责任自动建议，不预设空部门。

Normal结果摘要/来源/恢复动作可读

ConflictEvidence 冲突→进入审查
Success可追溯事实，非成功徽章
Curis 当前实现

已有底层 FoundingRun/组织版本/RoleSlot/CapBinding/Simulation/ResourceCheck/OperatingVersion/Evidence/Acceptance/DecisionPacket/Trace 底层机制已存在，方向正确。

OpenOPC 参考

OpenOPC 同样把执行细节（agent config、transition、runtime team）放在配置文件与运行详情，不在主创建流暴露。Curis 应保持一致：保留机制、降层呈现。

最终方案

已确认 保留最近 Runtime 的真实可靠性机制（隔离、幂等、候选/供给分离、Sim/Operating 分离、CEO 审批、原子激活、回滚、Evidence、Acceptance、失败暂停、显式执行引用）；纠偏方向＝降层 + 翻译 + 串回经营，不删除这些机制，也不在其上增加更多门禁页面。

底层 Runtime 与可见性规则

Runtime 负责保证公司工作真实、可恢复、可验收；不成为 CEO 产品中心。以下为必须“翻译成人话”的对照（Master Map §11.2）。

底层事实CEO 前台语言
Simulation 未通过“这间办公室还不能开始工作，因为平台授权未完成；可去授权，或先使用手动回传。”
CAPABILITY_BINDING=PROPOSED_NOT_AUTHORIZED“员工方案已准备好，但公司还没有授权它使用这项能力。”
UNVERIFIED“这条结果已记录，但还没有可信来源或 CEO 验收。”
Handoff WAITING“上一位员工已交付，下一位员工还没接收；责任在 X，预计 Y。”
Rollback“已暂停这次组织变更，员工权限已撤回；原方案仍可恢复。”
Provider/Quota error“模型额度已用完；已暂停新的外部动作，可切换备用模型或稍后重试。”
四层分工：产品语义层 → 业务运行层 → 可信执行层 → 基础设施层。CEO 默认只见前两层的人话；高级详情可展开技术证据。
