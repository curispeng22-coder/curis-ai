## §1 抖音真实产品结构（真实平台是什么）

结论：抖音不是一个"内容发布站"，而是一个**资格分层的内容经营系统**——内容层（视频/图文/直播）之下压着四套平行的经营体系：创作者体系（创作者中心）、电商体系（商品橱窗/精选联盟/电商学习中心）、商单体系（巨量星图，独立站点）、激励体系（全民任务/官方活动），外加一个开放平台（developer.open-douyin.com）对外提供受资质约束的数据与操作 API。

各体系真实入口（L2）：
- 创作者中心（网页）：creator.douyin.com —— 官方自述：授权管理、内容管理、互动管理、数据管理；登录身份两种：**创作者 / MCN 机构**（L1 实证）
- 数据中心直达：creator.douyin.com/creator-micro/data-center/operation（L2 URL 存在；内部字段见 §4–6）
- 电商体系：创作者中心内"电商带货 → 立即加入抖音电商"（L3 电商学习中心 101721）；规则与学习在 school.jinritemai.com
- 商单体系：xingtu.cn（独立站点、独立达人入驻、独立信用分体系，L2/L3 星图官方手册）
- 激励体系：抖音 APP → 我 → 创作者服务中心 → 全民任务/任务中心（L3 官方规范）
- 开放平台：developer.open-douyin.com（能力中心列出"视频数据""用户互动数据"等数据开放能力，L2/L3）

创作者中心登录页官方宣传的四组能力（L1 抄录）：作品发布及管理（视频、图文、全景视频等体裁）／作品数据分析（数据多维度与深度分析）／商单任务变现（全渠道变现）／创作灵感洞察。

对 Curis 的含义（L5 推断，但基于上述事实）：Curis 的 Platform Definition 至少要表达：多体系并存（内容/电商/商单/激励）、每个体系有自己的资格门槛与规则源、账号资格是"分体系"的而不是账号级单一布尔值。

## §2 账号经营目标（真实抖音语境下账号为什么存在）

真实抖音账号的存在理由只有三种（L3 证据可归因）：
1. **流量→卖东西**：带货（商品橱窗/短视频挂车/直播挂车）、团购（本地生活）——资格由电商体系定义。
2. **流量→卖流量**：商单（星图接广告）、全民任务/官方激励（平台直接付钱买内容与播放）。
3. **流量→卖人/私域**：直播（打赏/带货）、账号本身增值（可交易资产，L5）、导私域变现（平台限流风险区，L4）。

关键：三种理由的**资格门槛、结算周期、违规风险完全不同**（§10–§16）。因此 Account Goal（PC-096）在抖音上不是标签，而是**决定账号适用哪套资格体系与结算规则的选择**。L5：一个账号可叠加多个 Goal（如带货+商单），但每个 Goal 独立跟踪资格与收益。

## §3 接管（CEO 把抖音账号交给 Curis 的真实含义）

L1 实证（本会话实际操作 creator.douyin.com）：
- 未登录状态 = **登录墙**，无任何后台可见。三种登录：抖音 APP 扫码（官方推荐）、手机验证码、密码。
- 两个身份入口：**"我是创作者" / "我是MCN机构"**（机构登录另有权益页）。
- 登录页存在《账号授权协议》链接（第三方应用授权协议文本独立存在）与《抖音社区自律公约》。

由此确立的接管事实（对 Curis 直接可用）：
1. 接管第一步永远是 **CEO 本人扫码/验证**——任何第三方（包括 Curis）无法代登录。这与 Curis"Identity/Connection/Execution 三分离"一致：账号身份归 CEO，连接由 CEO 亲自建立。
2. 网页端登录墙意味着：Browser 通道（PC-059）理论可行但每个会话仍需 CEO 扫码一次；长期自动化不能依赖浏览器会话。
3. 程序化接管必须走开放平台 OAuth：需要**企业资质 + 应用审核 + 单项权限申请**（L3，§19）。个人 CEO 用户以"创作者"身份授权给一个已过审应用即可使用数据接口——但**该应用本身必须由有企业资质的主体运营**（L3：企业资质认证→应用审核→接口权限申请）。
4. UNKNOWN：开放平台对"个人开发者/个人应用"是否有低资质数据通道（未查证到明确条款，见 §25）。

接管动作清单（Curis 侧真实步骤，L1/L3 综合）：CEO 扫码登录创作者中心（网页或 APP）→（若走 API）在开放平台完成应用授权 OAuth → Curis 拉取账号基本数据确认身份 → 记录初始 Snapshot（粉丝数/作品数/资格状态）→ 建立 Account 档案（Goal/定位/责任归属）。

## §7 起号（0 粉新号的真实路径）

按资格门槛串联的真实阶段（全部 L3，门槛数字见 §18 表）：
1. **第 0 天**：0 粉可做的事：实名认证（免费）、发布内容、参加**全民任务**（官方明确 0 粉丝 0 作品可参与）、开通团购达人（<1000 粉可开通，L4）、开 DOU+ 付费投放（付费无粉丝门槛，L4）。
2. **1000 粉前**：只能橱窗带货权限（粉丝不足 1000 时仅获得橱窗权限，L3 官方原话）；直播带货 2025 新规后有效粉丝 200 即可——**新号最快变现路径是全民任务+团购+直播**（L5 综合）。
3. **1000 粉**：视频/图文挂车开通（粉丝达 1000 的次日开通，L3）。
4. **1 万粉**：内容标签可修改（<1 万不可改，L3）；星图部分任务类型开放。
5. **10 万粉**：主页出现"找我合作上星图"按钮（可开启服务管理，L3 星图官方手册）。

起号期真实经营问题（L5 综合，但每条挂在上述 L3 事实上）：前 1000 粉是资格驱动期——选题应优先选"能过审、能涨粉"而不是"能变现"；保证金 500 元是该不该早交的真实决策（早交=早开橱窗拿新手流量扶持 vs 白交占用现金，L5）。

## §8 增长（真实增长机制）

- 推荐反馈指标序（L4，官方创作者教育口径）：**完播率 > 点赞 > 评论 > 转发**；完播率=完播次数/播放次数。
- 付费放大：DOU+/千川为官方付费流量（L2 官方产品存在；**价格与投放参数 UNKNOWN**，见 §25）。实验记录必须区分自然流量与付费流量（PC-079 直接验证）。
- 发布节奏：数据中心日更看板支持"周对比"，但抖音官方未承诺任何"最佳发布时间"公式（L4 教育内容多、官方规则无）——Curis 的实验记录（PC-078）比"最佳时间模板"更诚实。
- 合集/置顶/话题是官方内容组织工具（L2/L3 字段见 §5）。
- 增长的资格联动是抖音特色：涨粉本身会**解锁机会**（§7 阶段表），所以"增长"在抖音上同时是"资格积累"——PC-098（阶段×机会联动）被抖音强验证。

## §9 变现方式全景（真实变现结构）

抖音对创作者的变现通道（每条都有独立资格+独立结算，证据见 §10–§14）：

| 通道 | 资格核心门槛 | 结算节奏 | 钱在哪看 |
|---|---|---|---|
| 商品带货（橱窗/短视频/直播挂车） | 实名+有效粉丝（200/500）或粉丝 1000+保证金 500 | 确认收货+15 天 | 电商带货/精选联盟钱包 |
| 团购带货（本地生活） | <1000 粉可开通（L4） | 按订单核销/结算（L4，规则中心为准） | 团购结算钱包 |
| 商单（星图） | 星图入驻条件+开通任务要求；信用分体系 | 任务验收后（个体提现/企业对公/MCN） | 星图结算 |
| 任务激励（全民任务） | 0 粉可参与 | 任务结束次日，最迟下月 15 日 | 钱包 |
| 直播（打赏/带货） | 直播带货有效粉丝 200（2025-02-17 起） | 打赏月结（L4）/带货按联盟 | 直播中心 |
| DOU+ 反向 | 不是变现，是投入——进预算侧 | 即时扣费 | DOU+ 订单 |

结论（L5）：抖音收益不是一条流水，是**多条异质结算流**——周期从"次日"到"确认收货+15 天"到"下月 15 日"不等。PC-103 的"低频回填合法"被强验证，且必须按"应计 vs 已到账"建模（§16）。

## §10 商品带货深拆（橱窗/精选联盟）

资格与开通（L3 电商学习中心 101721）：
- 带货权限 = 直播间添加商品 + 经营达人商品橱窗 + 短视频添加商品 + 图文添加商品（四件套一体授权）。
- 流程：实名认证 → 申请入口（创作者中心→电商带货→立即加入抖音电商）→ 粉丝不足 1000 仅得橱窗权限；达 1000 的次日开通视频/图文挂车。
- **保证金：500 元商品分享保证金**；可申请退还，退款后电商带货权限随之关闭。
- 新作者须先完成"经营护航"必修学习任务才能分享商品（学习任务=官方开课闸门，L3 星图手册转述+电商学习中心）。
- 连续 180 天无成交 → 平台收回带货权限，符合条件可重新申请（L3/L4）。

结算（L3 电商学习中心 102025/112620）：
- 佣金=付款金额×佣金率；**确认收货+15 天**无售后无纠纷才结算；扣除技术服务费后进可提现余额；**余额≥100 元**可提现；售后退货→佣金退回扣减。
- 官方规则原文注明"精选联盟平台不负责达人佣金结算"（结算链路由商家侧完成）——Curis 不应把结算延迟归因于平台故障。

真实经营含义：带货账号的"收益"永远滞后成交 15–45 天（确认收货+售后期+结算）；**退货率直接吃佣金**。Curis 收益追踪必须记录：订单额、佣金率、预期结算日、售后扣减、实际到账（PC-103 MODIFY 依据）。

## §11 团购带货（本地生活）

- 团购达人权限：粉丝不满 1000 也可开通（L4，官方门槛以 APP 内实时提示为准）；挂载本地生活团购链接（套餐优惠）。

## §19 无 API 经营路径（Fallback 完整走通）

事实基础：抖音**没有面向个人的内容发布开放 API**（内容发布仅 APP/创作者中心网页，L1/L2）；数据 API 存在但需企业资质应用（L3）。因此"CEO 只有一个抖音号+一部手机"时 Curis 的完整经营路径：

1. **接管**：CEO 扫码登录创作者中心一次（L1 已证必须本人操作）→ Curis 记录账号档案。
2. **起号/生产**：Curis 全链（选题→Brief→生产→Variant）无平台依赖，100% 可用。
3. **发布**：ASSISTED 模式——Curis 备好 Variant（含标题/话题/封面建议）→ CEO 在 APP/创作者中心粘贴发布 → 回填链接作为回执（PC-054 原样成立）。PC 端创作者中心网页可发布（视频/图文体裁，L1 登录页自述），比纯 APP 略降摩擦。
4. **数据**：三档可选——手工周期录入（数据中心看板字段，§4–6）/ Browser 采集（CEO 登录会话内）/ API（若走企业资质应用）。首月手工完全够用（字段只有十来个）。
5. **互动**：创作者中心"互动管理"（评论/私信）人工或 Browser 查看；Curis 拟回复+CEO 发送。
6. **变现**：资格申请（实名/保证金/任务报名）全部人工；Curis 负责跟踪资格状态（PC-097）与提醒门槛达成。
7. **收益**：钱包明细人工查看，低频回填（T+15 结算节奏天然低频，§16）。

结论：无 API 时**唯一断点只有"发布执行"与"资格操作"两处人工动作**，其余全链 Curis 可覆盖（L5 综合，基于上述逐项事实）。

## M12. Account Stage × Monetization（从真实门槛反推）

不采用抽象阶段，以真实资格节点定义阶段（L3 门槛体系）：
- **Stage 0（0–200 有效粉）**：目标=第一笔钱+资格积累。可用：变现任务（0 门槛类）/全民任务/（<1000 粉团购）。数据重点：有效播放、涨粉效率。变现优先级：任务>团购>打赏。
- **Stage 1（200–500 有效粉）**：解锁直播带货（L3）。目标=首场低成本的直播验证或继续任务。
- **Stage 2（500–1000）**：解锁视频挂车（有效粉丝 500）。目标=首单佣金；选品学习。
- **Stage 3（1000–1万）**：解锁完整橱窗+挂车稳定期+内容标签（1 万前锁定，L3）。目标=收益结构从"任务"转向"佣金/团购"；筛选高适配商品。
- **Stage 4（1万–10万）**：星图部分任务开放；目标=商单化（报价体系）+组合收益。
- **Stage 5（10万+）**："找我合作上星图"开启（L3）；目标=收益结构优化（商单为主），**不再只追涨粉**。
- 结论：**Account Stage 有真实产品价值**——它决定可用机会集/数据重点/下一步动作（验证 PC-018/PC-098），且阶段锚点=平台资格节点而非抽象成长曲线；平台自身也在 App 用"创作阶段·开启创作之旅"任务模型表达阶段（L1 截图，PC-018 官方实证）。

## M18. Revenue / Settlement Model（收益语义模型）

平台真实支持的语义（全部有证据，不自创）：

- **验收关键**：PendingSettlement 的"天数"按变现方式异质（带货约 15–45 天；任务最迟下月 15；团购看核销；商单看验收）——收益预测必须按类型分别建模（L5）。
- **Special 语义**：有效播放（结算计量单位，L1；官方定义细节 UNKNOWN）；瓜分制（奖池占比，L1）；核销（团购，L4）；阶梯佣金（佣金率随销量变化，L3）。

## M19. Cost / Revenue / Profit

真实成本项（全部有证据）：保证金 500（可退，L3）；DOU+/上热门（L1 入口）；制作成本（探店需到店，L4）；工具/模型成本（Curis 侧，L5）；退货扣回（L3）。

## M20. 三层 Performance（严格区分）

- CONTENT PERFORMANCE（L1 字段）：播放/完播/互动/划走率——"这条内容怎么样"。
- ACCOUNT PERFORMANCE：粉丝净增/有效粉丝/资格进度/违规状态——"账号经营得怎么样"。
- BUSINESS RESULT（收益状态机，M18）："这项业务真赚了多少"。
- 官方自身即三层数据分离（数据中心 vs 收入页 vs 电商后台），Curis 不得混合呈现（验证 PC-112）。示例：视频 A 100 万播放 0 收入 vs 视频 B 2 万播放佣金 3000——Account Goal 决定哪个是"成功"（L5，机制由 L1/L3 支撑）。

## M31. 第二轮反证：为什么不是 ChatGPT/Codex？

若方案只是"研究→写文案→做视频→发布"，则失败。Curis 的增量必须且能够证明为：
1. **资格地图**：ChatGPT 不知道这个账号差 196 个有效粉丝；Curis 有 M11 持续状态。
2. **结算状态机**：T+15/核销/验收/瓜分多流水的钱，对话工具不会记账；Curis 有 M18。
3. **机会库+Fit 对照**：机会是跨时间积累并按账号对照筛选的资产，不是一次性问答。
4. **多 Agent 组织**：生产/审核/数据/收益是不同 Work 流，有回执与状态，不是聊天。
5. **市场反馈→Learning→下一周期**：M27 循环需要持久化数据（画像/实验/收益），对话工具无记忆载体。
6. **多账号聚合**：10 个号的资格/收益/风险一眼视图，对话工具无结构。
结论（L5）：Curis 把"AI 完成任务"升级为"AI 持续经营账号赚钱"的证明=**状态（资格/结算/机会）+循环（M27）+组织（Coverage Matrix）**三者在对话工具中不存在。成立。

## M32. CEO 没提出但研究主动发现的问题

1. **游戏出品人**任务体系（L1 筛选器）——CEO 未提，已入 Map。
2. **瓜分制结算**语义（L1"奖励已瓜分0%"）——收益不确定性与时机策略。
3. **阶梯佣金**（L3）——佣金率随销量动态变化，静态记录会算错收益。
4. **有效粉丝 vs 粉丝数**双轨门槛（L3）——1000 粉老号可能仍无挂车资格（M25）。

## PART III 结论：十五问白话回答

1. **普通人通过抖音赚钱的真实方式**：变现任务（含全民任务/星图任务/游戏出品人）、商品带货（CPS 佣金）、团购分佣、星图商单、创作激励（创作基金）、内容付费、直播（打赏+带货）、平台活动奖励、自己开店。每一种都有独立资格、独立结算规则（M2 表）。
2. **0 粉第一笔钱**：App 创作变现→变现任务里 0 门槛的命题任务（截图实证"最高收益¥200/¥250、按有效播放结算"），任务结束次日~下月 15 日到账；现实预期几十到两百多元，不是稳定收入。
3. **1000 粉最现实路径**：先查**有效粉丝**——≥200 可直播带货、≥500 可挂车、1000 粉可开橱窗（交 500 保证金）；不够就继续任务+团购，同时做互动唤醒。1000 粉≠自动能带货（最大反直觉发现）。
4. **成熟账号流量变收入**：诊断顺序=资格面（开什么了吗）→转化面（挂车了吗）→机会面（商单/任务参加了吗）→定位面（画像匹配吗）→结构面（只有播放型收益吗）；转换器=资格开通×机会匹配×内容商业化。
5. **最困难的 5–10 件事**：①机会只在手机 App 里；②没有任何个人可用 API；③收益晚到 15–45 天且会被售后扣回；④资格门槛多层且规则会变（有效粉丝新规先例）；⑤商单双审核+信用分惩罚；⑥探店/直播必须真人；⑦佣金动态（阶梯）难追踪；⑧核销率吃掉团购收入；⑨定位与赚钱机会冲突；⑩多账号管理。
6. **Curis 真正能解决多少**：资格地图、结算状态机、机会库与 Fit 对照、生产全链、数据回收、复盘 Learning、多账号聚合——困难 3/4/7/8/9/10 的"认知与管理层"全部可解决；困难 1/2 的"执行层"不可解决但可辅助到只剩 App 上的三步操作。
7. **必须 CEO 亲自做的**：扫码登录/实名/缴费/学习任务、App 报名与投稿、挂车挂链、开播出镜、探店到场、提现、接单与发布的最终确认。
8. **Mobile-only 只能辅助的**：变现任务全流程、选品页、团购、直播——Curis 做决策支持+步骤清单+截图识别+回执回填（M16 方案候选，未定稿）。
9. **没有 API 怎么闭环**：数据走 Web 数据中心+官方导出+低频手工回填（结算天然低频）；机会走 Intake 多通道；决策与状态全部在 Curis——闭环断点只有"手指操作"本身。
10. **Curis 怎么知道今天有什么机会**：不假设持续扫描（成本/风控不划算）；=CEO 低频带回（截图/分享/快填）+Web 可覆盖源（星图/活动/数据导出）的定期获取+资格解锁事件的自动推导（自己产生的机会）。
11. **怎么知道机会适不适合**：Fit 对照卡（M17）——定位/受众/资格/经济性（佣金与结算方式）/内容可行性/风险六维结构化对照，不给假精确评分，最终 CEO 决定。
12. **怎么知道真赚到钱**：结算状态机区分 播放量/应计/可提现/已提现/已到账/扣减；只有 CashReceived 且扣除成本后的数字才叫赚钱（M18/M19/M20 三层绩效）。
13. **第一笔钱后怎么放大**：M27 Learning Loop——归因到 机会×内容×受众×策略×成本，判断偶然性，决定加码/复制/换向，更新资格地图与机会监视条件，进入下一周期。
14. **修正了哪些想当然**：①资格从"开关"改为多层动态地图；②收益从"数字"改为异质结算状态机；③机会发现从"自动扫描"改为"低频带回+事件推导"；④成长阶段从抽象曲线改为平台资格节点；⑤_browser 能力预期下调（核心变现页 App-only）；⑥平台官方 AI 工具存在→Curis 差异化必须压在经营层。
15. **最终判定**：经营链 Account→State→Growth→Qualification→Opportunity→Selection→Content→Publication→Result→Revenue→Settlement→Learning→Next Cycle 的每一环都有真实平台机制与证据支撑，且 0 粉/1000 粉/10 万粉三个模拟全程无"以后需要某功能"的空洞。
