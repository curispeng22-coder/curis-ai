# Curis 产品主线版

状态：产品架构返工交付稿  
日期：2026-08-13  
读者：CEO、产品、设计、开发、质量

这份文件只讲 CEO 怎么使用 Curis。开发先照主线实现，再看文末技术附录。它不授权业务代码，也不把当前页面或测试写成已完成产品。

## 1. Curis 是什么

Curis 是一位 CEO 经营一家 AI 公司的工作空间。

CEO 先告诉 Curis 自己是谁、想经营什么；Curis 帮 CEO 建立公司、安排一位 AI 助理、搭建一间业务办公室。办公室可以是研发、内容运营或 CEO 以后定义的其他业务。AI 员工在办公室里承担明确工作，CEO 能看到进展、等待、失败、结果，并决定下一步。

Curis 不是任务清单，也不是一堆 Agent 卡片。任务只是办公室里的一种工作记录。

## 2. 唯一用户主线

```text
打开 App
→ 认识 CEO
→ 连接一个最小可用模型
→ 认识 Assistant
→ 建立 Company
→ 进入 CEO Desk
→ 查看业务版图 / Workspace Portal
→ 选择一个业务模板
→ 写下这个业务的目标
→ 创建 Workspace，看到真正的办公室首页
→ 配置 AI 员工和所需能力（缺口可以先留着）
→ 开始一次工作
→ 成功、等待输入或失败恢复
→ 收到外部结果，或由 CEO 手动补充结果
→ CEO 查看并确认结果
→ 反馈、调整、开始下一周期
```

### 2.1 打开 App：先看到“我是谁”，不是后台

首屏只做两件事：确认本机 CEO 身份，告诉 CEO 下一步。

- 必填：姓名。
- 可选：称呼、时区、语言、头像。
- 身份固定显示“CEO”，不显示虚构的 Admin、默认公司或示例业务。
- 已有未完成设置时，继续上次位置；没有时，从身份开始。

首屏文案：

> 欢迎来到 Curis。先告诉我怎么称呼你，我会陪你把第一间业务办公室搭起来。

主操作：`继续`  
次操作：`稍后设置头像`  
空态：没有公司时显示“你还没有建立公司，下一步我们会一起开始。”  
失败态：显示“本机工作空间暂时无法打开，请重试”，不显示技术堆栈。  
返回：退出回到身份页。  
下一页：最小模型向导。

### 2.2 最小模型：只准备一个能工作的助手

模型设置是准备工作，不是 Curis 的首页。

页面只要求 CEO 选择一个服务、选择一个模型、完成一次连接测试。目录里可以看到其他服务，但没有必要一次配置全部服务。未配置时仍可浏览公司和办公室；没有可用模型时不能让 AI 真正执行。

主操作：`连接并继续`  
次操作：`先看看 Curis`、`更换模型服务`、`查看连接详情`  
空态：`还没有连接模型。连接一个模型后，Assistant 才能替你准备和执行工作。`  
失败态：`这次没有连接成功。检查服务或凭证后重试，也可以先进入 Curis 浏览。`  
返回：回到身份页；返回不会丢失 CEO 身份。  
下一页：Company Welcome。

### 2.3 Assistant：先认识自己的第一位 AI 员工

Company 建立后，Assistant 不再是一个孤立聊天框，而是 CEO 的第一位 AI 员工。

它负责整理今天要看的信息、准备工作、提醒等待、召集专业 AI 员工、把结果带回 CEO。它不会替 CEO 默默发布、承诺、花钱或改变公司结构。

欢迎文案：

> 我是你的 AI 助理。我会帮你整理公司正在发生的事，把工作交给合适的人，并在需要你决定时把问题带回来。

主操作：`进入我的 CEO Desk`  
次操作：`先看看我能帮什么`  
空态：`公司还没有业务，我会陪你搭建第一间办公室。`  
失败态：`Assistant 还没有准备好，但你的公司草案已保存。`  
返回：回到 Company Welcome。  
下一页：CEO Desk。

### 2.4 Company Welcome：公司刚刚建立

Welcome 只回答三件事：公司已经建立了什么、Assistant 是谁、下一步去哪里。

页面显示：公司名称、CEO 身份、Assistant 名称 / 责任、`去 CEO Desk`、`开始搭建第一间办公室`。

主操作：`去 CEO Desk`  
次操作：`直接搭建业务办公室`、`以后再说`  
空态：`公司已建立，还没有业务办公室。`  
失败态：`公司信息暂时无法读取，重试后仍可回到上次位置。`  
返回：身份菜单或重新查看 Assistant。  
下一页：CEO Desk。

### 2.5 CEO Desk：每天从这里开始

CEO Desk 不是数据看板，而是 CEO 今天的工作台。

首屏顺序固定：

1. 一句话公司状态。
2. 今天最重要的一件事。
3. 等 CEO 处理的事项。
4. 各业务办公室的状态。
5. Assistant 的提醒与下一检查点。

主操作：`进入今天的主事项`  
次操作：`查看业务版图`、`问 Assistant`、`查看最近结果`  
空态：`公司还没有业务。先选择一间办公室，Curis 才能开始替你经营具体事情。`  
失败态：某一块信息读取失败时只在该块显示`暂时读不到，重试`，不把整页变成错误页。  
返回：返回 Welcome 或当前办公室；保留原来的业务位置。  
下一页：业务版图 / Workspace Portal。

### 2.6 业务版图：看公司正在经营什么

业务版图展示 CEO 已经建立的业务办公室和可搭建的模板。

- 已建立的办公室显示：名称、目标、当前阶段、负责人、最近状态、下一步。
- 未建立的模板显示：适合解决什么问题、会有哪些主要工作、需要 CEO 提供什么。
- 没有示例业务；没有选择就没有业务实例。

主操作：`搭建一间办公室`  
次操作：`打开已有办公室`、`查看模板介绍`  
空态：`你的公司还没有业务办公室。选择一个方向开始，之后也可以继续增加。`  
失败态：`暂时无法读取业务版图，请重试；已有办公室不会被删除。`  
返回：CEO Desk。  
下一页：Workspace Portal。

### 2.7 Workspace Portal：选择业务起点

Portal 是模板选择和已建办公室的入口，不是任务中心。

首批模板：

- 研发工作台：把一个研发目标变成研究、设计、构建、验证和回顾。
- 小红书运营工作台：把受众和内容目标变成选题、图文、发布、互动和线索回流。
- 抖音 / TikTok 运营工作台：把趋势和内容目标变成脚本、视频、发布、互动和成交信号回流。

默认方案：三张模板卡等量展示；不替 CEO 预选业务，不把任何模板写成默认任务。

主操作：`选择这个模板`  
次操作：`查看已建办公室`、`比较模板`  
空态：`还没有已建办公室，下面是可以开始搭建的业务方向。`  
失败态：`模板暂时无法加载，请重试；不会因此创建空业务。`  
返回：业务版图 / CEO Desk。  
下一页：Workspace Studio。

### 2.8 Workspace Studio：把模板变成自己的办公室

Studio 只让 CEO 做业务决定，不要求 CEO 先理解技术名词。

四个区域：

1. `这间办公室要达成什么`：目标、对象、周期、成功样子。
2. `谁负责什么`：岗位、负责人、需要 CEO 介入的地方。
3. `还缺什么`：模型、工具、资料、平台连接、人工输入；缺口是责任卡，不是搭建大门。
4. `先预览一次`：用已有能力模拟路径，确认页面和步骤是否合理。

主操作：`创建办公室`  
次操作：`保存草案`、`添加岗位`、`去补能力`、`预览一次`  
空态：`先写下这间办公室要得到的结果。`  
失败态：`办公室草案没有保存成功，请重试；已填写内容保留在当前页面。`  
返回：Workspace Portal，回去时保留模板和草案。  
下一页：对应业务办公室首页。

### 2.9 业务办公室：先看到业务，再看到任务

所有办公室共享一个外壳：

- 左上：办公室名称、目标、当前周期。
- 中央：本周期主要业务对象和阶段。
- 右侧：AI 员工、能力缺口、等待 CEO、最近结果。
- 底部：运行记录、资料、下一步。

缺能力时的统一文案：

> 这项工作还缺少“图片素材”能力。你可以继续整理目标和岗位，也可以现在去补齐。缺口负责人：CEO。

主操作：`开始本周期` 或 `继续搭建`  
次操作：`查看 AI 员工`、`补齐能力`、`打开资料`、`返回 Portal`  
空态：显示该业务自己的第一步，不显示通用“新建任务”。  
失败态：显示“这次工作没有完成”、原因、负责人、`重试`、`改用人工输入`、`回到原步骤`。  
返回：Workspace Portal / CEO Desk，回到原阶段。  
下一页：AI 员工工作区或结果页。

研发办公室的首页重点是：研发目标、研究问题、变更、验证状态、代码 / 测试结果。  
小红书办公室的首页重点是：受众、选题、图文草稿、发布状态、评论 / 私信、线索。  
抖音办公室的首页重点是：趋势窗口、脚本、素材、成片、发布回执、观看 / 互动 / 成交信号。

### 2.10 AI 员工与能力：可以边搭边补

AI Team 页面让 CEO 看懂谁在负责什么；能力中心让 CEO 看懂公司拥有什么。

搭建阶段允许：

- 先创建岗位，再找人。
- 先写业务目标，再补工具或资料。
- 先保存办公室，再连接外部平台。
- 先看人工处理方式，再决定是否自动化。

只有当 CEO 点击`开始真实工作`或`发布到外部平台`时，系统才集中告诉 CEO 当前还缺什么，并给出一次清晰的处理页。普通搭建不被层层拦住。

### 2.11 运行：成功、等待、失败都说人话

开始工作后，办公室必须明确显示：现在做到哪一步、谁负责、下一步是什么。

- 成功：显示完成了什么，以及结果在哪里。
- 等待 CEO：显示需要 CEO 回答的问题和截止时间。
- 等待外部：显示等哪个平台或哪个人工输入。
- 失败：显示发生了什么、是否已经产生外部影响、如何重试或改走人工。
- 不确定：显示“还不知道”，不显示绿色完成。

真实运行 / 发布前只出现一次`开始前检查`：它把模型、员工、资料、权限和输出方式汇总在同一页。检查不是五个连续页面，也不是让 CEO 先完成全部能力建设。

### 2.12 结果、CEO 确认、反馈

结果页回答：做了什么、依据是什么、外部发生了什么、还不知道什么。

结果来源可以是：

- 外部平台真实回执。
- CEO 手动填写的结果。
- AI 员工提交的工作产物，等待 CEO 判断。

主操作：`确认这个结果`  
次操作：`要求修改`、`继续下一周期`、`暂停这项工作`、`补充人工结果`  
空态：`还没有结果，完成一次工作后会出现在这里。`  
失败态：`结果不完整或已过期，请补充、重试或退回原办公室。`  
返回：原办公室的原阶段。  
下一页：CEO Desk 的下一事项 / 下一周期。

## 3. 默认产品取舍（不作为 CEO 前置决策）

以下方案由产品架构师直接给开发，CEO 不需要在开发开始前逐项确认：

| 问题 | 默认方案 |
|---|---|
| 首个模板 | 三个模板同时可见，不自动创建；深度闭环先做研发工作台，但目标由 CEO 自己填写 |
| 模型 | 只要求一个可用模型；目录可浏览，其他模型以后再加 |
| 缺能力 | 责任卡 + 可继续搭建；不阻断草案、目标、岗位和办公室首页 |
| AI 员工 | 先用岗位和责任表达；能力未齐时显示“还不能执行”，不隐藏岗位 |
| 外部平台 | 没连接就提供人工输入窗口；不造发布回执或指标 |
| 开始前检查 | 真实运行 / 发布前一次性出现；搭建过程不反复弹门禁 |
| Assistant | 一个共享入口，落到 CEO Desk / 办公室上下文；不做第二套聊天产品 |
| 研发任务 | CEO 进入研发办公室后自行创建；不预置、不命名、不填入固定示例 |
| 一级入口 | CEO Desk、经营、业务版图、AI Team、能力中心、知识、工作流、日历 / 定时、成果 / 健康 / 设置 |
| 禁止入口 | Agent Center、Task Center、Workforce Center 不做一级导航 |

## 4. 技术附录：给实现和验收

用户主线里的“公司、办公室、员工、能力、运行、结果”必须有真实可回访的对象。内部实现可沿用现有对象，但页面不得把内部对象名直接当 CEO 文案。

| 用户看到 | 实现至少要能回访的对象 |
|---|---|
| CEO 身份 | `CEOProfile` |
| 公司 | `Company`、`CompanyProposal`、`FoundingRun` |
| Assistant | `CEOAssistant`、`Brief`、`Handoff` |
| 业务办公室 | `Workspace`、`WorkspaceDraft`、`BlueprintVersion` |
| 岗位 / AI 员工 | `RoleSlot`、`AIEmployee`、`StaffingProposal` |
| 能力 | `Capability`、`Connection`、`Health`、`Binding` |
| 工作一次 | `Run`、`Workflow`、`Schedule` |
| 结果 | `Outcome`、`ExternalReceipt`、`ManualEvidence`、`Evidence` |
| CEO 处理 | `Acceptance`、`Decision`、`Feedback` |

完成证明不是页面截图。每个开发队列项必须同时验证：真实对象、保存后刷新、整包重启、正常路径、等待、失败、恢复、1440 / 1024、三主题与 Packaged Desktop；未连接平台必须明确人工回填。
