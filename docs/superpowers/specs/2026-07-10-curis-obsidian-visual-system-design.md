# Curis Workspace Obsidian 视觉系统设计

日期：2026-07-10

## 目标

将现有 60 篇中文知识文档从“纯文字资料库”升级为可快速理解、可在 Obsidian 原生渲染的双层视觉知识库。

## 选择

采用用户确认的 C 方案：双层视觉系统。

1. 每篇关键文档先给一张“一眼看懂”的高层图。
2. 架构、运行和开发文档按需要增加详细关系图、流程图、时序图、状态图或实体关系图。
3. 正文继续解释边界、状态与事实依据，图表不替代正式契约。

## 技术形式

- 使用 Obsidian 原生支持的 Mermaid fenced block。
- 优先使用兼容性稳定的 `flowchart`、`sequenceDiagram`、`stateDiagram-v2` 和 `erDiagram`。
- 不依赖外部 CDN、图片服务器、插件或本地绝对路径。
- 图中尽量使用中文，仅保留必要的产品和技术名称。

## 视觉规则

- 一张图只表达一个中心结论。
- 节点文字保持短句，详细说明留在正文。
- 当前能力使用实线；未来或受 gate 约束的关系使用虚线或明确标注。
- Admin Platform、Workspace、shared、租户私有能力和未来市场能力保持边界清晰。
- 高风险流程必须显示人工确认、安全边界或 fail closed。
- 不使用依赖固定颜色才能理解的语义。
- 单图节点原则上不超过 15 个；超出则拆分。

## 覆盖范围

计划向八个知识域加入约 50 张 Mermaid 图：

- 产品愿景：产品进化、AI 公司操作系统、用户层次、产品哲学、战略飞轮、十年路线。
- 商业模式：Hybrid 收入结构、定价公式、护城河、Capability 飞轮、AI 员工价值、竞争定位、商业化 gate。
- 技术架构：L0-L6、双产品边界、员工/模板/部门/工作流、Skill/Tool/Capability、模型路由、凭证、三类事件与 Billing。
- 开发规划：版本、Phase、Sprint、五席协作、Research 到 Development、Issue 生命周期。
- 创业历程：项目历程、架构演进、商业模式演进。
- 产品设计：信息架构、Admin、Workspace、员工旅程、工作流体验、商业配置中心、UI 骨架、CEO 用户流程。
- 融资材料：BP 叙事、市场进入漏斗、未来估值阶梯。
- 开发文档：API 边界、数据库域、Contract 层、系统状态、测试金字塔和部署拓扑。

## 放置方式

- 高层图放在核心结论或定义之后，正文之前。
- 详细流程图放在对应流程、运行路径或状态章节附近。
- 每张图前使用中文二级标题说明阅读目的。
- 不重复已有纯文本代码块；若 Mermaid 完整表达同一内容，则删除重复的 ASCII 流程块。

## 验收标准

- 八个知识域均获得视觉覆盖。
- 至少 45 张 Mermaid 图，且关键产品、商业、架构和运行文档全部有图。
- Mermaid fenced block 成对闭合，无空图、无超长节点和明显语法错误。
- Wiki Link、Frontmatter、状态标记和原有事实边界保持不变。
- 不引入外部资源、运行时代码、凭证或新的产品承诺。
- 通过文档数量、链接、敏感信息、占位符和全仓回归验证。

## 非目标

- 不制作依赖特定 Obsidian 主题的装饰性图稿。
- 不增加需要手工同步的 PNG/SVG 副本。
- 不把战略推演画成已经实现的系统。
- 不重写现有产品范围、商业 gate 或开发事实源。
