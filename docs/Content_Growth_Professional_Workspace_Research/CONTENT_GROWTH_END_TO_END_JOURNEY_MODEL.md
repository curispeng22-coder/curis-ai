## 0. 红线与本轮纪律

- 本轮**只研究产品怎么被真实操作**，不画 IA / Wireframe / Figma / 视觉 / 前端 / Runtime / Schema / DB / Authority 修改。
- 所有行为挂在已有 Curis 对象：Signal/Opportunity/Topic = **Artifact + Surface 投影**；Research/Brief/Evaluation/Publication = **Work/Result**；Channel = **Channel 对象 + Module + Connector**；Variant/Publication 消费 Frozen 内容域契约（per-Account 真相、Target≠Eligibility、OAUTH_FAILURE_KEEPS_ACCOUNT 等不变量）。
- **想不清→说不清→不做 UI**：本模型用文字即可完整模拟每个动作。
- 证据标记：`[CURIS-AUTH]`=消费 Frozen 语义；`[REUSE]`=复用已有对象/行为。

## 1. 固定步骤格式（每条 Journey 的每一步必须遵守）

```
STEP XX
【用户当前看到】  当前页面 / 对象 / 状态 / 重要信息。
【用户动作】      点击「按钮名」/ 输入什么 / 选择什么 / 对谁说什么。
【立即反馈】      0–2 秒内看到什么。
【系统后台】      创建/更新：Work / Result / Artifact / Handoff / Decision / Channel/Account 状态。
【Employee 行为】 谁接手 / 做什么 / 是否需沟通。
【页面/状态变化】 按钮变成什么 / 对象状态变什么 / 出现什么新信息 / 用户仍停留哪。
【可返回/可撤销】 怎么返回 / 能否撤销 / 撤销影响。
【异常】          本步失败时具体发生什么 / 用户下一步能点什么。
【下一步】        正常情况下自然进入哪里。
```
禁止写「进入下一阶段」「系统处理」「员工继续工作」这类空话；必须说清**具体**发生什么。

## 2. 稳定动作词汇表（候选 · 语义锁定 · 不冻结文案）

本轮统一以下中文动作词，保证跨 Journey 语义稳定（UI 文案可微调，但动作指向不变）：

| 动作词 | 语义 |
|---|---|
| 继续经营 | 从驾驶舱默认进入，什么都不配就起步 |
| 就做这个 | Topic→创建 Content Intent + Brief，进入内容 |
| 先调研 | Topic/机会→建 Research Work（带上下文） |
| 直接生成 | 跳过深度 Research，Quick/Structured 出 Draft |
| 问员工 | 三入口之一·直接对话，自动携带当前对象上下文 |
| 调整方向 | 改 Topic 价值判断/定位/跨渠道，回评分 |
| 暂缓 | 标暂缓移出推荐，入收藏 |
| 放弃 | 软删（可恢复） |
| 添加来源 | 粘 URL/账号/关键词，加入监控或本次 Scope |
| 仅本次使用 | 该来源只用于当前 Work，不入长期监控 |
| 加入长期监控 | 该来源成为常驻 Source |
| 查看依据 | 展开 Evidence/Source/Strength 链（Utility） |
| 接受结论 | Research Result 直接采纳，不续查 |
| 继续研究 | 让 Employee 续接同一 Research Work 补查 |
| 再来一版 | 基于当前 Intent/Brief 再生成一版 Draft（计数+1） |
| 恢复上一版 | 把 Draft 回滚到上一保留版本 |
| 选为推荐版 | 在多版中指定对外推荐版 |
| 选择素材 | 从素材库选图/视频/封面 |
| 让TA生成 | 让 Employee 生成封面/配图/视频（几版） |
| 准备发布 | 内容标「可发布」，进入发布目标选择 |
| 发布 | 提交 per-Account 发布（Human-in-the-loop 确认） |
| 重试 | Failed/Rejected 后按原因重提 |
| 重新授权 | 账号 OAuth 失效后走平台重授权 |
| 查看回执 | 打开 Connector 回填的 per-Account 发布记录 + 真实 URL |

## 4. JOURNEY A — FIRST-TIME SETUP（首次建立业务）

模拟：用户第一次进入 Curis，说「我想开始做 AI 科技内容。」一直走到「第一次收到可执行的选题推荐」。

### STEP A01
【用户当前看到】首次进入 Workspace，经营驾驶舱显示空态引导：「你还没有开始任何经营。想从哪开始？」下方一个输入框 + 三个轻建议卡片（「做内容增长」「做产品研发」「其他」）。
【用户动作】在输入框输入：「我想开始做 AI 科技内容。」
【立即反馈】输入框下方出现「理解中…」气泡，0.5 秒后显示一句话回执：「好的，我帮你建立『AI 科技内容』经营空间。我会问你几个必要问题，其余我来推断。」
【系统后台】创建 Office（Domain identity 直挂 Company，产品归属 Business `[CURIS-AUTH]`）+ 初始 Content Intent 草稿（topic=AI 科技内容，core_message/goal 暂空）+ 一个 `setup` 类型 Work。
【Employee 行为】王颖接手 `setup` Work，准备追问；不立即广播团队。
【页面/状态变化】输入框上方出现进度条「经营建立 1/4」，当前停在「目标」。
【可返回/可撤销】可清空重说；未落库实质配置，撤销=放弃本次输入。
【异常】若输入为空或无法识别意图 → 提示「说一句你想经营什么，比如『做 AI 科技内容』」；不报错崩。
【下一步】系统进入必要追问（A02），但仅问**必须**项。

### STEP A02
【用户当前看到】对话流中王颖发来一条带选项的消息：「为了给你更好的建议，先确认 3 件事（其余我推断）：①主要面向谁？②主要在哪发？③已有账号吗？」每项给推荐选项 + 「跳过，你帮我定」。
【用户动作】点击「跳过，你帮我定」三次（或逐项选：①科技爱好者/从业者 ②小红书+抖音 ③暂无账号）。
【立即反馈】每点一次，该项显示「✓ 已确认/由我推断」；第三条若选「暂无账号」显示「可以先不连，之后随时加」。
【系统后台】更新 Content Intent（audience / channel_hint / has_accounts），写入 Office 的 business_goals 草稿。
【Employee 行为】王颖根据选择或推断，填充 audience/tone/positioning 初稿，存入 Office 的 growth_context。
【页面/状态变化】进度条「2/4」，进入「来源与定位」。
【可返回/可撤销】可回上一步改选；已填项保留。
【异常】用户中途离开 → 见 Doc 5 状态连续性；回来从断点续。
【下一步】A03（来源/对标/历史）。

### STEP A03
【用户当前看到】王颖：「我需要一些『米』才能研究。请补充（可全跳过）：①要重点看的网站/账号 ②对标账号 ③历史内容（用于分析定位）。」
【用户动作】用户说：「以后重点看 OpenAI、Anthropic 官网，再加这 3 个网站（粘 3 个 URL）。对标先不填。历史内容没有。」
【立即反馈】每条 URL 被即时识别类型（Website/RSS/Specific URL），列表预览：「OpenAI 官网—Website ✓」「Anthropic 官网—Website ✓」「3 个网站—Website×3 ✓」；下方按钮「加入长期监控 / 仅本次使用」。
【系统后台】创建 5 个 Source（type=Website，monitoring=长期），挂到 Office 的 Source 集合；无对标、无历史则留空，不阻断。
【Employee 行为】王颖把 5 个 Source 标记为「高优先级情报源」；无对标时，她后续自动从公开搜索发现候选对标（标记「扩展发现」）。
【页面/状态变化】进度条「3/4」，进入「团队与起步」。
【可返回/可撤销】可删某个 URL（点列表项→删除）；可改「长期监控/仅本次」。
【异常】某 URL 无法识别 → 标「未能识别，请手动选类型」并给下拉；不整步失败。
【下一步】A04（最小团队 + 首次采集）。

### STEP A04
【用户当前看到】王颖：「我已经为你组建内容团队（研究/创作/渠道/增长各 1 人），他们会在后台工作。你现在只需要看结果。要不要看团队成员？」按钮：「看看团队 / 不用，开始吧」。
【用户动作】点击「不用，开始吧」。
【立即反馈】进度条「4/4」完成；驾驶舱顶部出现一条结果卡：「AI 科技内容经营空间已建立 ✅ 团队就位，正在监控 5 个来源、分析定位中…」
【系统后台】`setup` Work 闭合为 Result；创建 4 个 Employee Service 关系（[REUSE] Organization Routing）；启动后台 `intel-scan` Work（监控 Source）+ `positioning-analysis` Work（无历史则用对标推断）。
【Employee 行为】王颖开始周期性采集 5 个 Source；无历史/对标时，她用公开搜索生成「建议账号定位」草稿，等用户采用/修改/跳过。
【页面/状态变化】空态引导消失；驾驶舱出现①员工最新结果（「团队已就位」）、⑤在途（「分析定位中」「监控 5 来源」）、⑧下一步推荐（「等首次机会出现」）。
【可返回/可撤销】随时点「看看团队」可补看；建立动作不可单步撤销，但 Office/Source 可后续编辑。
【异常】团队组建失败（极少）→ 提示「团队未能全部就位，可重试」并提供「重试」；业务空间已建，不丢。
【下一步】A05（用户离开，系统继续）或 A06（首次机会出现）。

### STEP A05（状态连续性：用户离开）
【用户当前看到】用户在 A04 后关闭或去别处。
【系统后台】`intel-scan` 与 `positioning-analysis` 继续在 Runtime 跑（不依赖用户在线）。
【Employee 行为】王颖按监控频率采 Source、聚类 Signal、发现 Opportunity、生成「建议账号定位」；结果以 Result/Artifact 落库。
【页面/状态变化】无（用户离线）。当用户回来时见 A06。
【可返回/可撤销】不适用。
【异常】某 Source 失效 → 标「失效」并暂停该源采集，其余继续；用户回来见提示（见 Journey I）。
【下一步】A06（用户回来，首次机会/定位建议到达）。

### STEP A06（首次发现 Opportunity → 通知）
【用户当前看到】用户第二天打开 Workspace，驾驶舱③「需关注的变化」出现 1 张卡：「OpenAI 发布新模型传闻，3 个来源同时提及（强度高）」；⑧下一步：「王颖建议先调研或进选题」。②经营重点显示「AI 科技内容 · 定位分析中」。
【用户动作】点该卡 → 展开看详情（来源+摘要+王颖判断）。
【立即反馈】右栏 Utility 打开：Signal 原文 + 来源链接 + 「转选题 / 问王颖 / 忽略」。
【系统后台】Signal(Artifact) 已落库并由王颖聚类；Opportunity 草稿已生成（status=观察中）。
【Employee 行为】王颖在「信息与机会」Surface 维护全量池；CEO 只看压缩投影。
【页面/状态变化】驾驶舱③卡展开为详情；其余卡不动。
【可返回/可撤销】关闭 Utility 回驾驶舱；卡不消失（未处理）。
【异常】通知重复？→ 同一 Opportunity 只投影一次，已读后降权，不重复弹（见 Doc 5 状态）。
【下一步】A07（王颖给出初始定位/关键词/对标建议）。

### STEP A07（Audience/Tone/Brand + 关键词/对标/来源建议）
【用户当前看到】驾驶舱①出现王颖结果卡：「账号定位建议已生成（AI 科技主号：面向从业者，专业但易懂；调性=可信+前瞻）」+「建议初始关键词 8 个」「建议对标账号 5 个（公开发现）」+ 按钮「查看 / 采用 / 修改 / 跳过」。
【用户动作】点「查看」→ 右栏展示定位三段（Audience/Tone/Brand Context）、关键词列表、对标账号（带平台+理由）；再点「采用」。
【立即反馈】「已采用定位与关键词 ✅ 对标账号已加入监控源（你可删减）」。
【系统后台】写入 Office growth_context（positioning/audience/tone/brand_context）+ 8 个 keyword Source + 5 个对标账号 Source（monitoring=长期）；定位建议 Result 标记 adopted。
【Employee 行为】王颖把对标账号纳入 `intel-scan` Scope；后续 Signal 质量提升。
【页面/状态变化】驾驶舱①卡变为「定位已采用 ✅」；②经营重点显示定位。
【可返回/可撤销】「修改」可改任一段；「跳过」则不写定位（仍可由后续 Research 推断）。
【异常】用户改了定位后觉得不对 → 可再次「修改」覆盖；历史版本留痕（Doc 5）。
【下一步】A08（进入选题推荐）。

### STEP A08（最终出现「推荐 3 个选题」）
【用户当前看到】约数十分钟后（或用户主动点「信息与机会→选题」），驾驶舱出现王颖结果卡：「基于近期信号，推荐 3 个选题 👇」+ 3 张 Topic 卡（标题+一句价值判断+预计价值+研究建议），每张有「就做这个 / 先调研 / 直接生成 / 问员工」。
【用户动作】用户读 3 张卡（本 Journey 到此完成目标）。
【立即反馈】每张卡可点开看「为什么值得做」（推荐理由+支撑 Evidence 入口）。
【系统后台】3 个 Topic(Artifact) 已生成（status=推荐，score 驱动排序），各带来源 Opportunity + 初步价值评估。
【Employee 行为】王颖完成「信号→机会→选题」闭环，等待用户裁决。
【页面/状态变化】驾驶舱②经营重点 + ⑧下一步推荐（「选一个开始做」）。
【可返回/可撤销】用户可点任一张卡深入；不强制选。
【异常】迟迟无选题 → 驾驶舱提示「今天信号不足，建议等监控积累或手动加来源」；不伪造选题。
【下一步】自然进入 Journey C（选一个→调研/就做）。

> **Journey A 验收点**：1 次表达意图 + 3 个必要确认 + 少量「采用/跳过」→ 走到「推荐 3 个选题」。不是 12 步向导。✅

## 5. JOURNEY B — SOURCE MANAGEMENT IN REAL USE

### B 路线一：对话中即时管理

### STEP B01
【用户当前看到】在任意对话（Conversation）里，用户想让研究重点看某些源。
【用户动作】输入：「以后研究 AI 模型时重点看 OpenAI、Anthropic 和这 3 个网站（粘 3 个 URL）。」
【立即反馈】系统自动识别 2 个品牌词（匹配已有 Website Source→标记「优先」）+ 3 个新 URL（识别为 Website），弹出识别预览：「匹配：OpenAI 官网、Anthropic 官网（已监控，设为优先）／新增：3 个网站（Website）」。
【系统后台】把 2 个已有 Source 的 priority 升为「高」；新建 3 个 Website Source（monitoring=长期，priority=高）；写入 Office Source 集合。
【Employee 行为】王颖在下次 Research 时优先用这 5 个源，并在 Scope 标注「用户指定优先」。
【页面/状态变化】对话流出现「已加入长期监控并设为优先 ✅ 6 个来源」确认卡。
【可返回/可撤销】点确认卡「撤销」→ 5 个 Source 优先级/新增回退。
【异常】URL 识别失败 → 单条标「未识别，请选类型」并给下拉；其余照常。
【下一步】B02（作用范围选择）。

### STEP B02
【用户当前看到】确认卡下出现作用范围选择：「这些来源——①仅本次使用 ②加入长期监控（优先，可扩展）③仅限这些来源（不扩展）」。
【用户动作】选「②加入长期监控（优先，可扩展）」。
【立即反馈】卡更新：「已设为长期优先；遇到空白时王颖可自动扩展公开搜索（会标记『扩展』）。」
【系统后台】Source.monitoring=长期；Scope 策略=优先+允许扩展（扩展来源在 Evidence 中标「扩展」）。
【Employee 行为】王颖后续 Research 以这 6 源为主，空白时扩展并标注。
【页面/状态变化】无新页面；对话卡定稿。
【可返回/可撤销】可改选 ①③（改策略）。
【异常】无。
【下一步】B03（批量/删除/暂停 — 在对话或专业区）。

### STEP B03（批量 URL / 删除 / 暂停）
【用户当前看到】用户在对话里说：「再加这 10 个网址（粘多行）」「把第 3 个网站删了」「OpenAI 先暂停监控」。
【用户动作】分三条消息或一次带指令：「批量加 10 个；删第 3 个；暂停 OpenAI。」
【立即反馈】逐条回执：「+10 个 Website 已识别」「第 3 个网站已删除」「OpenAI 官网已暂停（配置保留，停止采集）」。
【系统后台】批量建 10 个 Source；删 1 个（彻底）；OpenAI Source.status=暂停（保留配置）。
【Employee 行为】王颖 Scope 去掉 OpenAI 直至恢复；其余继续。

## 9. JOURNEY F — PUBLISHING REALITY（概述；深见 Doc 4）

### STEP F01
【用户当前看到】Draft 标「可发布」，点「发布」→ 发布目标选择：Channel→Account→Variant 树，默认勾选推荐账号（XHS·AI科技主号 等）。

【页面/状态变化】发布面板显示每账号 Variant 预览 + 风险检查（合规/频率/定位）。

【异常】某账号未授权 → 标「需授权」阻断该账号；其余可继续。
【下一步】F02（确认发布 → per-account 状态）。

### STEP F02（逐账号发布 + 9 态真相）
【用户当前看到】预览无误，点「发布」。面板列出每账号状态流：Ready→Publishing→（Published / Platform Reviewing / Failed / Rejected）。
【用户动作】点「发布」后等待；可看实时状态。
【立即反馈】各账号独立回执：XHS 主号「已发布 ✅（URL）」；抖音主号「平台审核中 ⏳」；某账号「失败：授权过期」。

【页面/状态变化】发布 Result 显示「部分完成」：成功 N / 审核中 M / 失败 1；每账号独立状态卡。

【异常】失败 → 见 Journey I / Doc 5；成功账号不受影响（FACT_NOT_ROLLED_BACK）。
【下一步】F03（查看记录 / 打开平台）。

### STEP F03（回执 / 真实 URL / 记录）

## 12. JOURNEY I — ERROR RECOVERY（概述；深见 Doc 5）

14 类异常逐条见 Doc 5。本处给主线锚点：
- Source 失效 → B04（标红、暂停、重授权/替换）。
- Research 无结论/冲突 → C06 续查；冲突证据并排标 Unknown。
- Topic 重复 → 去重合并（Doc 5）。
- Draft 质量差 → D02 改/重生成；达标前不进发布。
- 图片生成失败 → D04 上传/重试/复用历史。
- 账号授权过期 → E02 标红+自动暂停+重授权（F02 失败即此）。
- 某 Channel 不可连接 → E01 标 Unavailable+替代。
- 账号定位不匹配 → F01 灰显+确认覆盖。
- 发布部分成功 → F02「部分完成」独立状态，成功账号不受影响。
- 平台驳回 → F02 Rejected→改后重提。
- Analytics 拉取失败 → G01 诚实标「数据暂不可用」。
- Employee 执行失败 → 重试/转交（Doc 5）。
- 用户中途改方向 → 随时「调整方向/暂缓/放弃」，原 Work 软终止。
