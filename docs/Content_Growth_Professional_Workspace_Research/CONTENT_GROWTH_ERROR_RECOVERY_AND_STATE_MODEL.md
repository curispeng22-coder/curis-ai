## 0. 红线与纪律

- **RESEARCH 状态**：本文只研究「错误/中断/历史」在产品中如何被诚实表达与可操作恢复，不画 UI / IA / Wireframe / Figma / 视觉 / 前端 / Runtime / Schema / DB，不修改 Doc 4 Frozen Authority。
- **复用已有对象**：Signal/Opportunity/Topic = Artifact + Surface 投影；Research/Brief/Evaluation/Publication = Work/Result；Channel = Channel 对象 + Module + Connector；Variant/Publication 消费 Frozen 契约（per-Account 真相、Target≠Eligibility、OAUTH_FAILURE_KEEPS_ACCOUNT 等）。
- **错误不能伪造成功，状态必须诚实**（`FACT_NOT_ROLLED_BACK` / `RECEIPT_FROM_CONNECTOR` / `PUBLICATION_PER_ACCOUNT_TRUTH` 延伸）：
  - 任一账号失败 ≠「整体失败」也 ≠「整体成功」；每账号独立真相。
  - 数据拉不到 → 诚实标「暂不可用」，**绝不**用旧数据冒充「最新」。
  - 未收到 Connector 回执 → 标「回执待回」，**不**假成功。
  - 账号失效 → 保留账号与历史，仅降级当前执行（`OAUTH_FAILURE_KEEPS_ACCOUNT`）。
- **想不清→说不清→不做 UI**：每类异常在本文用文字即可完整模拟「用户看到什么 / 能点什么 / 系统保留什么 / 谁修 / 是否需 CEO / 从哪继续」，禁止「UI 阶段再决定」缺口。
- **不污染旧对象**：用户改方向、放弃、异常中止 → 原 Work/对象软终止或保留，新动作新建对象，互不串。
- 证据标记：`[CURIS-AUTH]`=消费 Frozen 语义；`[REUSE]`=复用 Doc 1/2/3 已有行为。

## 1. 空状态（Empty States）清单

> 原则：**不伪造、不阻塞、可先起步**。空态只告诉用户「现在没有 X，你可以先 Y 或等系统」，绝不编造内容填充。引导文案一律指向一个具体动作（加来源 / 等监控 / 去别处），不出现「暂无数据」死墙。

| # | 空态 | 用户看到什么引导 | 能不能先开始 | 提示文案原则 |
|---|---|---|---|---|
| 1 | **首次无业务**（无 Office） | Doc 1 A01 空态引导：「你还没有开始任何经营。想从哪开始？」+ 输入框 + 3 轻建议卡 | ✅ 输入一句话即起步 | 不假设领域；说「说一句你想经营什么」而非报错 |
| 2 | **无 Source** | 设置区/对话提示：「还没有监控任何来源。粘 URL 或说『看某官网』即可加」 | ✅ 边做边加；无源时 Research 标 Unknown | 不伪造情报；提示「无源则结论不可靠」 |
| 3 | **无 Signal** | 驾驶舱③「需关注变化」显示：「监控中，暂未出现值得注意的信号」 | ✅ 业务照常；等采集积累 | 诚实「暂无」，不生成假信号；给「加来源可加速」 |
| 4 | **无选题**（无 Topic） | 驾驶舱⑧「下一步推荐」：「等首次机会出现」或「今天信号不足，建议等监控积累」 | ✅ 可手动开新选题 | 不伪造选题；给明确等待原因与可操作加速项 |
| 5 | **无 Research** | 选题卡动作区正常存在（就做这个/先调研/直接生成）；无 Research 指「尚未调研」 | ✅ 可「直接生成」跳过 | 区分「未调研」与「调研无结论」，两者文案不同 |
| 6 | **无 Draft** | 内容 Surface 空：「还没有草稿。点生成或说话让 TA 写」 | ✅ 一句话即出（Quick 路径） | 不预填占位文；直接给生成入口 |
| 7 | **无 Channel** | 渠道空态：「还没有连接任何渠道。要发到哪？」+ 平台列表 | ✅ 先创作，发布时再连 | 创作不依赖渠道；连渠道不强制一次性全连 |
| 8 | **无账号**（有 Channel 无 Account） | Channel 详情：「已连接 · 0 账号 · 加账号」 | ✅ 先不发布；内容可存草稿 | 有 Channel 无账号不报错，发布时标「需加账号」 |
| 9 | **无发布记录** | 驾驶舱⑥「发布结果」：「还没有发布过」+ 历史为空提示 | ✅ 首次发布后自然填充 | 不显示占位统计；明确「首次发布后出现」 |
| 10 | **无反馈** | 反馈 Surface：「发布后这里会出现评论/私信/数据」 | ✅ 等发布回流 | 不编造互动；提示触发条件（需先发布） |
| 11 | **无数据（Analytics）** | 增长 Surface：「还没有可用数据」或（拉取失败时）「数据暂不可用」 | ✅ 业务照常 | **不**用旧数据冒充；见 E12 |

> 空态与异常的区别：空态是「本来就没有」（合法初始态），异常是「本来有、后来坏了」（见 §2）。两者都不得阻塞、不得伪造。

## 2. 14 类异常逐条（STEP E01–E14）

> 每条严格 9 小节。动词锁定 Doc 1 §2：重试 / 重新授权 / 改后重提 / 查看依据 / 继续研究 / 接受结论 / 恢复上一版 / 调整方向 / 暂缓 / 放弃 / 问员工 / 替换 / 重新生成 / 查看回执 / 返回经营。人物：王颖（Research&Intel）、李想（Producer）、陈帆（Channel Operator）、周明（Strategist）。

### STEP E01 — Source 失效（404 / 授权过期 / 反爬）
【用户当前看到】驾驶舱③或 Source 列表出现：「⚠️ [Source 名] 采集失败（原因：404 / 授权过期 / 403 反爬）」，该项标红「失效」。
【用户动作】点提示 → 右栏 Source 详情（最近采集时间 + 失效原因 + 按钮「重新授权 / 替换 / 暂停」）。可点其一。
【立即反馈】详情展开；若选「暂停」立即显示「已暂停（配置保留，停止采集）」。
【系统后台】该 Source.health=失效，采集任务自动暂停（**不删**）；Office Source 集合保留该对象与历史采集。`[REUSE]` Doc 3 §1.3 / Doc 1 B04。
【Employee 行为】王颖在后续 Research 中若该源必需，Evidence 标「缺失源」并显式标 Unknown；**不自动修复**（属外部授权/可达性问题，非员工能力范围）；**无需 CEO**。
【页面/状态变化】Source 列表该项持续标红「失效」直到恢复；不影响其他 Source 采集与既有 Signal。
【可返回/可撤销】「重新授权」→ 走平台/抓取策略重授权，成功后 health 回正常；「替换」→ 换 URL 新建等价源；「暂停」→ 停采保留；均可逆。
【异常】重授权仍失败 → 提示「仍失败，建议替换或暂停」，不静默丢弃；用户可「放弃重授权」留失效态。
【下一步】恢复后王颖自动补采；若长期失效，Research 结论以现有源 + Unknown 呈现（见 E02）。

### STEP E02 — Research 没有结论（Unknown 扩大）
【用户当前看到】王颖结果卡：「《X》调研完成，但证据不足以给出确定结论」；右栏结论区标「结论：Unknown（扩大）」+ 缺口说明（如「办公场景真实数据不足」）。
【用户动作】可选：「继续研究」（补查指定缺口）/「接受结论」（按 Unknown 决策，如暂不做或缩小范围）/「问员工」/「调整方向」/「放弃」。
【立即反馈】选「继续研究」→ Research 状态条恢复「进行中（续查）」，原 Conclusion 保留为「上一版结论」；选「接受结论」→ Topic 标对应状态。
【系统后台】Research Result 的 Conclusion=Unknown（合法事实态，`[CURIS-AUTH]` §5.3 UNKNOWN 合法），Unknown 项显式列出缺口；不写伪确定结论。`[REUSE]` Doc 1 C06。
【Employee 行为】王颖**不会**强行给结论；续查时只补缺口、不重复已有部分；**不自动把 Unknown 变确定**；**无需 CEO**（纯研究判断，用户裁决）。
【页面/状态变化】结论区始终显示 Unknown + 缺口，而非「无法研究」报错；Topic 状态随用户选择变「调研完成-待决」等。
【可返回/可撤销】可回「上一版结论」（若续查过）；可改选其他动作；Unknown 结论不进「可发布」内容（无依据不创作，见 E05）。
【异常】续查仍无数据 → Unknown 扩大而非缩小，系统建议「暂不做或缩小范围」，不伪造成功调研。
【下一步】用户「接受结论」后决定就做/暂缓/放弃，或「继续研究」补查（回 C06 流）。

### STEP E03 — Research 找到相互冲突证据（并排标 Unknown，不强行二选一）
【用户当前看到】结论区出现两处并排 Evidence：「证据 A（来源 X：有效）⚔ 证据 B（来源 Y：无效）」，中间标「⚠️ 冲突·均待证实」，而非「择一采纳」。
【用户动作】可选：「继续研究」（让王颖补第三方核验）/「接受结论」（按「冲突未决」记录，决策时知会风险）/「问员工」。
【立即反馈】冲突项在 Evidence 列表以「并排 + 待证实」样式呈现；「查看依据」可展开双方原文。
【系统后台】Evidence 集合对冲突项各记 source_ref + 各自强度，Conclusion 标「冲突·Unknown（二选一证据不足）」；**不**生成「一方胜出」的伪结论。`[CURIS-AUTH]` UNKNOWN 合法。
【Employee 行为】王颖并列呈现、标注强度差与可信度差，**不替用户二选一**；续查优先补权威源；**不自动修复冲突**；**无需 CEO**。
【页面/状态变化】结论区「风险」段新增「存在冲突证据，建议谨慎」；Topic 价值判断附注冲突。
【可返回/可撤销】续查后可刷新冲突标记；用户可「接受结论」保留冲突记录进入内容决策。
【异常】补查后一方被更强证据推翻 → 冲突标记解除，结论更新；仍平手则维持 Unknown。
【下一步】按 E02/E03 用户裁决后，进「就做这个」（附冲突风险提示）或暂缓。

### STEP E04 — Topic 重复（去重合并，保留多来源）
【用户当前看到】新建/系统推荐选题时，提示：「发现相似选题《GPT-5.6 办公》与《AI 办公实测》疑似重复，已合并为 1 个候选」；或驾驶舱出现「2 个选题已合并」通知。
【用户动作】点合并卡 → 看合并详情（保留的多来源列表 + 各自价值）；可选「确认合并」/「拆开」（确非同一）/「忽略」。
【立即反馈】合并后 Topic 卡显示「来源：Opportunity×2 + Signal×3」，单一候选入池；「拆开」则还原两个独立 Topic。
【系统后台】相似 Topic 归并为同一 Artifact（status=推荐），source_refs 保留多来源（不丢任一）；评分取并集加权。`[REUSE]` Doc 3 §4.2 去重/合并。
【Employee 行为】王颖在「信息与机会」Surface 维护去重候选队列，自动聚类并标记「建议合并」；**可自动合并（软建议）**，但用户可一键拆开；**无需 CEO**。
【页面/状态变化】选题池去重后计数减少，不重复占推荐位；历史重复标「历史重复」可查。
【可返回/可撤销】「拆开」恢复独立；合并为软操作，可回退。
【异常】误合并（用户认为不同）→ 「拆开」即还原，无数据损失。
【下一步】合并后 Topic 正常走「就做这个 / 先调研 / 直接生成」。

### STEP E05 — Draft 生成质量差（改 / 重生成，达标前不进发布）
【用户当前看到】生成 v1 后用户判「质量差」：内容 Surface 显示 v1 正文 + 版本列表；用户点「再来一版」「直接在正文改」或说「这段重写」。
【用户动作】「重新生成」（换角度出 v2）/「说话改」（局部改写）/「编辑 Brief」后重生成 /「问员工」给方向。
【立即反馈】每次生成/改写出新版（v1.1 / v2…），版本列表累计；「恢复上一版」在 ≥2 版后可用。
【系统后台】李想基于 Brief/Intent 重产出 Draft 版本（计数+1），保留各版 Artifact；**未过审核前 Draft.status≠READY**。`[REUSE]` Doc 1 D01–D03。
【Employee 行为】李想按反馈改；**不自动标「可发布」**——必须过 D05 审核（品牌/事实/合规/AI 标识/渠道规则）才 READY；**无需 CEO**（创作质量由用户+审核把关）。
【页面/状态变化】质量未达标时「准备发布」按钮禁用（灰显+理由「尚未通过审核」），阻断进发布。
【可返回/可撤销】「恢复上一版」回滚到任一保留版；编辑可覆盖；版本历史留痕（见 §5）。
【异常】连续 N 版仍差 → 提示「已生成 N 版，请选定或调整 Brief/方向」，禁止无限生成；可「调整方向」或「放弃」。
【下一步】达标（过审）后「准备发布」启用，进 F01 选账号。

### STEP E06 — 图片 / 视频生成失败（上传 / 重试 / 复用历史）
【用户当前看到】Draft 点「添加素材」→「让TA生成」后，素材区显示：「⚠️ 封面未生成（原因：生成服务超时 / 内容被拒）」，候选位空。
【用户动作】可选：「重试」（重生成）/「上传」（本地图）/「复用历史」（从素材库引旧 Asset）/「问员工」。
【立即反馈】选「重试」→「生成中…」再出候选；选「复用历史」→ 素材库列表展开，点选即引用。
【系统后台】Asset(Artifact) 生成失败时**不写入**破损资产；「复用历史」引用已有 Asset（不重生成）；用户上传则新建 Asset 入素材库。`[REUSE]` Doc 1 D04。
【Employee 行为】李想（或视觉子能力）重试生成；失败不静默留空，**提示明确**；**无需 CEO**。
【页面/状态变化】Draft 在无封面时仍可标「可发布」（封面非硬阻塞，依平台），但素材区标「无封面/待补」；用户决定补或发纯文。
【可返回/可撤销】「替换」换图；「复用历史」可改选其他旧 Asset；上传可删重传。
【异常】多次重试均失败 → 建议「上传或复用历史」，不卡死生成流程。
【下一步】有可用素材（生成/上传/复用任一）后，继续 D05 审核 → 发布。

### STEP E07 — 账号授权过期（标红 + 自动暂停该账号发布，不动其他；重授权恢复）
【用户当前看到】渠道/发布时，某账号（如抖音主号）标红「需重新授权」；发布面板该账号行标「需授权 · 已自动暂停发布」；其余账号正常。
【用户动作】点该账号「重新授权」→ 跳平台 OAuth 页 → 授权回 Curis；或「暂停」（维持失效）/「断开」。
【立即反馈】重授权成功后该账号变「已连接 ✅」，红标消失，暂停自动解除；发布面板该行恢复可勾选。
【系统后台】Channel Account.authorization_state 降级（Expired），**账号与历史 Publication 保留**，当前执行降级、停发该账号（`OAUTH_FAILURE_KEEPS_ACCOUNT` `[CURIS-AUTH]` §3）；其余账号状态不变。`[REUSE]` Doc 2 §2.2 / Doc 1 E02、F02。
【Employee 行为】陈帆**不删除账号**、不静默绕过；仅标记并暂停该账号发布，转其他可用账号（若策略允许）；**不自动修复授权**（需用户平台授权）；**无需 CEO**。
【页面/状态变化】仅该账号标红/暂停，其他账号 Context 不受影响；驾驶舱⑥该账号历史发布记录仍在。
【可返回/可撤销】「重新授权」恢复；「断开」保留历史但移除连接；失效期间不丢数据。
【异常】重授权中途取消/失败 → 维持 Expired，提示「仍失效，发布将跳过该账号」；不伪造连接。
【下一步】恢复后该账号重新进入 Target 候选（见 E09/E10）；未恢复则发布时按策略处理（BEST_EFFORT 跳过 / ALL_REQUIRED 阻断，见 E10）。

### STEP E08 — 某 Channel 不可连接（标 Unavailable + 替代 RPA / 手动）
【用户当前看到】连某平台（如某平台无官方 Connector）时，渠道列表该平台标「Unavailable · 非官方支持」，并附「替代：RPA / 手动（合规风险自担）」。
【用户动作】可选：「标记为 Unavailable」（接受不可用）/「用 RPA/手动替代」（知情后开启）/「跳过该平台」。
【立即反馈】选替代 → 提示「已启用 RPA/手动模式，发布需手动确认，非官方、风险自担」；选跳过 → 该平台不出现在发布树。
【系统后台】Channel 对象 status=Unavailable（能力态 `UNAVAILABLE` `[CURIS-AUTH]` §5.1）；Connector 不承发布，替代路径仅作手动记录，不伪造回执。`[REUSE]` Doc 2 §1.2。
【Employee 行为】陈帆**不伪造**该 Channel 的自动发布能力；仅按用户选择提供手动流程骨架；**无需 CEO**（平台能力事实）。
【页面/状态变化】发布选目标时该 Channel 灰显/不在树（除非用户开替代）；明确标注「手动」。
【可返回/可撤销】可随时切回 Unavailable 或关替代；历史手动发布记录如实留存（标「手动」）。
【异常】替代 RPA 执行失败 → 同 E13 处理（不静默）；回执标「手动提交，待你确认平台结果」。
【下一步】该 Channel 内容走手动/替代；或用户换可用 Channel 发布。

### STEP E09 — 某账号定位不匹配（灰显 + 确认覆盖 或 阻断）
【用户当前看到】发布选目标时，某账号（如个人 IP 号）灰显 + 理由：「该内容与账号定位『个人 IP』偏差大（内容偏专业测评）」，按钮「确认覆盖发布 / 不发布此账号」。
【用户动作】「确认覆盖发布」（知情覆盖）/「不发布此账号」（取消勾选）/「问员工」/「调整方向」（改内容以匹配）。
【立即反馈】选覆盖 → 灰显变可勾，附「已确认覆盖」标记；选不发布 → 该行取消，不影响其他账号。
【系统后台】Target（想发）与 Eligibility（能发）分离（`TARGET_NE_ELIGIBILITY` `[CURIS-AUTH]` §3）：账号仍是 Target 仅 BLOCKED/需确认，**禁静默删除**；覆盖发布记录覆盖标记，Variant 仅用目标账号 Context（`NO_CROSS_ACCOUNT_CONTEXT_LEAK`）。`[REUSE]` Doc 2 §3.2。
【Employee 行为】陈帆在发布时提示不匹配，**不自动强行发也不静默剔除**；由用户确认；**无需 CEO**（定位匹配是用户业务判断）。
【页面/状态变化】覆盖后该账号 Variant 生成并标「覆盖发布」；不匹配未确认则保持灰显不可发。
【可返回/可撤销】取消覆盖即回灰显；已发布覆盖版不可撤销事实（见 §4），但可后续调整定位。
【异常】用户误覆盖后觉得不对 → 下次发布可改选；已发布事实保留（不回滚）。
【下一步】确认后随其他账号一起进 F02 逐账号发布。

### STEP E10 — 发布部分成功（成功账号不受影响，失败账号独立状态）
【用户当前看到】点「发布」后面板逐账号流：XHS 主号「已发布 ✅（URL）」；抖音主号「失败：授权过期」；另一账号「平台审核中 ⏳」。顶部总结：「部分完成：成功 1 / 审核中 1 / 失败 1」。
【用户动作】对失败账号：「重试」（看原因）/「重新授权」（若为授权）/「改后重提」/「放弃该账号」；对审核中账号：等待或「查看回执」。
【立即反馈】每账号独立状态卡实时更新；成功账号显示真实 URL（可点回平台）；失败账号附原因。
【系统后台】每个 Variant 创建 Publication（**per-Account 唯一真相源**，`PUBLICATION_PER_ACCOUNT_TRUTH` `[CURIS-AUTH]` §3）；Connector 回填各自状态/回执/URL；**不伪造整体成功**；已发生事实**不回滚其他账号**（`FACT_NOT_ROLLED_BACK`）；未执行部分是否继续读 `distribution_execution_policy`（`FUTURE_EXECUTION_GOVERNED_BY_POLICY`：BEST_EFFORT 跳过失败继续其余 / ALL_REQUIRED 整体中止待修）。`[REUSE]` Doc 1 F02。
【Employee 行为】陈帆监控各回执，对失败账号触发重试/重授权，**不动成功账号**；**不自动把部分成功说成全成功**；**无需 CEO**（执行层按策略）。
【页面/状态变化】驾驶舱⑥「发布结果」显示每账号独立状态（如「XHS 已发布 / 抖音失败」），无聚合「成功」假象；失败账号保留可操作按钮。
【可返回/可撤销】Scheduled 可改/撤；Failed 可「重试」；Rejected 需「改后重提」（见 E11）；已 Published 事实不可撤销（见 §4）。
【异常】Connector 回执迟到 → 标「回执待回」，不假成功；超时未回按 Failed 诚实呈现。
【下一步】失败账号修复后单独重试；成功账号正常进入数据回流（G01）。

### STEP E11 — 平台审核驳回（Rejected → 改后重提，附原因）
【用户当前看到】某账号 Publication 状态变「Rejected · 平台驳回」，附原因（如「含外链违规」「疑似硬广」）；行内按钮「改后重提 / 查看回执 / 问员工」。[REUSE] Doc 1 F02 / Doc 2 §5.2。
【用户动作】点「改后重提」→ 回 Draft/素材改（李想按原因修，如去外链、加 AI 标识）→ 重新提交该账号；或「放弃该账号」。
【立即反馈】修改后该账号 Publication 状态回 Ready→Publishing→（Published / 再 Reviewing）；原因记录在回执。
【系统后台】回执来自 Connector（`RECEIPT_FROM_CONNECTOR` `[CURIS-AUTH]` §3），原因原样存 Publication Result；重提创建新 Publication 实例（旧 Rejected 事实保留，不覆盖）。`[REUSE]` Doc 2 §5.1（Rejected 态）。
【Employee 行为】李想按驳回原因局部修（不重生成整篇），陈帆重提；**不自动无视驳回强行发**；**无需 CEO**（合规修正是标准执行）。
【页面/状态变化】该账号行状态 Rejected→修正中→重新流转；其余账号不受影响（per-Account 真相）。
【可返回/可撤销】「放弃该账号」软终止该 Publication；已 Rejected 事实留痕不可抹。
【异常】重提再被驳 → 再给原因，循环改；多次驳回建议「问员工/调整方向」或换账号。
【下一步】通过后该账号转 Published，进数据回流（G01/E12）。

### STEP E12 — Analytics 拉取失败（诚实标「数据暂不可用」，不显示旧数据冒充）
【用户当前看到】增长 Surface / 驾驶舱⑦显示：「⚠️ 数据暂不可用（原因：平台接口超时 / 账号失效 / 配额耗尽）」，**不**显示任何数字。
【用户动作】可选：「重试」/「查看回执」（看哪个账号数据缺）/「问员工」/「返回经营」先去做别的。
【立即反馈】重试中显示「拉取中…」；失败维持「暂不可用」；成功则数字出现并标「更新于 [时间]」。
【系统后台】Analytics 拉取失败时**不回退显示上一周期旧数**，Evaluation Result 标「数据缺失·未评估」；缺数账号单独标（如抖音失效则仅抖音缺，XHS 正常仍显）。`[CURIS-AUTH]` UNKNOWN 合法 / `RECEIPT_FROM_CONNECTOR`。`[REUSE]` Doc 1 G01。
【Employee 行为】周明在数据源缺失时**不编造**增长结论，标「数据暂不可用，无法评估」；成功账号数据照常评估；**不自动伪造**；**无需 CEO**。
【页面/状态变化】增长 Surface 明确分区：有数据账号显数字，缺数据账号显「暂不可用」；不混用。
【可返回/可撤销】数据回来后自动刷新；历史「暂不可用」时段留痕（不补假数）。
【异常】长期拉不到（如账号失效）→ 提示「该账号数据持续不可用，建议重授权（见 E07）」，仍不冒充。
【下一步】数据恢复后周明出 Evaluation（什么有效+为什么+建议），进 G02 下一周期。

### STEP E13 — Employee 执行失败（重试 / 转交其他员工；不静默失败）
【用户当前看到】某 Work 状态卡显示：「⚠️ [员工名] 执行失败（原因：工具超时 / 权限不足 / 上下文丢失）」，附「重试 / 转交 / 问员工」。
【用户动作】点「重试」（同一员工重跑）/「转交」（换同责员工，如王颖→其他 Research 员工）/「放弃该 Work」/「问员工」。
【立即反馈】重试 → 状态回「进行中」；转交 → 提示「已转交 [员工名]，继续处理」；均不静默消失。
【系统后台】Work 标 failed + reason；重试重建执行上下文；转交更新 Responsibility（经 ⑦ Organization Routing `[REUSE]`），原执行记录留痕；**不删除 Work、不假装完成**。`[REUSE]` Doc 1 §3 最小团队。
【Employee 行为】失败员工不自认成功；系统按路由重试或转交同责员工（王颖/李想/陈帆/周明内部互换）；**不静默失败**；**无需 CEO**（执行层容错）。
【页面/状态变化】驾驶舱⑤「在途」该 Work 保持可见（标失败），不凭空消失；修复后回正常流。
【可返回/可撤销】可「放弃该 Work」（软终止，可恢复）；转交/重试可逆（新失败再处理）。
【异常】多次重试/转交均失败 → 提示「持续失败，建议问员工或调整任务」，不卡死用户。
【下一步】修复后 Work 闭合为 Result，回到原业务流（Research→Topic / Draft→发布 等）。

### STEP E14 — 用户中途改变方向（随时「调整方向 / 暂缓 / 放弃」，原 Work 软终止，新方向新建）
【用户当前看到】任意 Work/Surface 动作区常驻：「调整方向 / 暂缓 / 放弃 / 问员工」。用户点任一对当前对象生效。
【用户动作】
- 「调整方向」：改 Topic 价值判断/定位/跨渠道 → 回评分（Doc 3 §4.5），原 Research/Brief 保留可溯。
- 「暂缓」：标暂缓移出推荐，入收藏（Doc 1 §2），不占推荐位。
- 「放弃」：软删当前对象（可恢复），不进后续。
- 开新方向：用户说「换个方向做 Y」→ 系统新建 Topic/Intent（**不**在旧对象上硬改语义）。
【立即反馈】原对象标「已暂缓/已放弃/方向已调整」；新对象出现在选题池/内容 Surface；旧对象数据不丢。
【系统后台】原 Work 软终止（status=abandoned/paused，保留 Artifact + 历史），**不删**；新方向建独立 Topic/Intent/Work（`[REUSE]` Doc 1 C07 / Doc 3 §4.5）；**不污染旧对象**上下文。`[CURIS-AUTH]` INTENT_EXCLUDES_INFERENCE（旧 Intent 结论性语义不动）。
【Employee 行为】负责员工（如王颖/李想）收到新方向，原方向 Work 停手；**不把旧结论塞进新对象**；**无需 CEO**（方向是用户业务决策）。
【页面/状态变化】驾驶舱⑧「下一步推荐」切到新方向；原对象在回收区/收藏可见；两对象独立 Context。
【可返回/可撤销】「放弃」可从回收区恢复；「暂缓」可重启；新/旧对象互不串（见 §5 历史隔离）。
【异常】误放弃 → 回收区恢复，无数据损失；误开新方向 → 新对象可单独放弃。
【下一步】新方向正常走调研/内容/发布；旧对象静置待恢复或彻底删。

## 3. 状态连续性（State Continuity）

> 核心不变量：对象在 Runtime 持续存在，不依赖用户在线；用户离开期间 Work 继续，回来时在同对象上「续」，不新建、不丢进度。投影去重：同一对象只投影一次，已读降权，不重复弹（`[REUSE]` Doc 1 A06 异常段）。引用 Frozen `PUBLICATION_PER_ACCOUNT_TRUTH`：发布真相逐账号独立，连续性也逐账号。

### SC1 — Research 进行中 → 用户去别处 → 30 分钟后回来
- **在哪里看到仍在进行**：用户离开期间无界面；回来时驾驶舱⑤「在途」显示「《X》调研中 · 王颖」+ 进度（已采 N 源）；若已闭合则见①结果卡。
- **完成以后在哪里出现**：Research 闭合为 Result → 驾驶舱①王颖结果卡「调研完成 ✅」+ 按钮「查看结论 / 继续研究 / 问员工」；原 Topic.status=调研完成。
- **通知是否重复**：同一 Research 只投影一次；若离开前已读部分，回来只升「新完成」提示，已读降权，不重复弹。
- **Result 与原 Topic 关联**：Research Result 经 Scope 反向链回原 Topic（Artifact 引用），点结论「查看依据」可溯到 Topic/Opportunity；Topic 卡显示「关联 Research ✅」。`[REUSE]` Doc 1 C04–C05。

### SC2 — Draft 未完成
- **在哪里看到仍在进行**：内容 Surface 该 Draft 标「草稿·vN·未过审」，版本列表保存中间版；驾驶舱⑤「在途」显「内容准备中」。
- **完成以后在哪里出现**：过 D05 审核 → Draft.status=READY，内容 Surface 标「✅ 可发布」，驾驶舱⑧「下一步」显「选账号发布」。
- **通知是否重复**：Draft 状态变化只投影一次（「可发布」提示出现后不重复）；多次局部改不刷通知。
- **Result 与原 Topic 关联**：Draft 经 Content Intent 链回 Topic（Intent 弱服务 Topic/Office `[CURIS-AUTH]`）；版本历史见 §5。

### SC3 — Scheduled Publication（定时发布）
- **在哪里看到仍在进行**：Calendar / 驾驶舱⑥显「已定时 · [时间] · 待发」；发布面板该账号 Publication=Scheduled。
- **完成以后在哪里出现**：到时由 Connector 执行 → Publication=Publishing→Published（回执+URL 回填）；⑥变「已发布 ✅」。
- **通知是否重复**：定时态只投影一次；发布完成才出「已发布」通知，不重复。
- **Result 与原 Topic 关联**：Publication 经 Variant→Intent→Topic 链回（`[CURIS-AUTH]` 关系树）；回执可溯到原选题。
- **Frozen 引用**：`SCHEDULING_IS_CONDITIONAL`——不支持定时的平台置空/标不支持，不写死强规则；连续性依平台能力诚实表达。

### SC4 — Failed Account（账号失效中）
- **在哪里看到仍在进行**：渠道/发布面板该账号持续标红「需重新授权 · 已暂停」；驾驶舱⑥其历史 Publication 仍在，新发布被阻断。
- **完成以后在哪里出现**：重授权（E07）后该账号回 Connected，自动解除暂停，重新出现在 Target 候选；其**历史发布记录不变**（per-Account 真相保留）。
- **通知是否重复**：失效只投影一次（红标持续，不每日重弹）；恢复后出「已恢复」一次性提示。
- **Result 与原 Topic 关联**：该账号 Publication 历史经 Account→Binding→Office 链回，重授权不丢旧回执（`OAUTH_FAILURE_KEEPS_ACCOUNT`）。

### SC5 — Pending Decision（待用户裁决）
- **在哪里看到仍在进行**：驾驶舱⑧「下一步推荐」显「待你决定：就做这个 / 先调研 / 调整方向」；对象标「待决」（如 Research Unknown、Topic 推荐）。
- **完成以后在哪里出现**：用户裁决后对象流转（就做→内容 Surface；调研→Research；放弃→回收区）；⑧切下一推荐。
- **通知是否重复**：同一待决对象只投影一次；已读降权，新待决才升提示。
- **Result 与原 Topic 关联**：决策写入对象状态并链回 Topic；历史决策留痕（§5 Strategy adjustments）。

> 连续性总规则：**同一对象单投影 + 已读降权 + 进度可续 + 历史可溯**，全部基于已有 Artifact/Work/Result，不新造状态机。

## 4. 返回与撤销（Undo）

> 严格区分 **「页面返回」（导航，无数据变更）** 与 **「数据撤销」（修改对象状态/版本，有副作用）**。

### 4.1 页面返回（导航层 · 无数据副作用）
| 动作 | 行为 | 影响 |
|---|---|---|
| 关 Utility | 关闭右栏下钻（查看依据/回执/详情），回驾驶舱/原 Surface | 无写；对象状态不变 |
| 返回经营 | 从专业区（渠道/Source/反馈）回驾驶舱，Context 保留 | 无写；不丢当前 Work |
| 回上一步 | 在 Journey 流中回退（如 C02 回选题、F01 回内容 Surface） | 对象状态回退到上节点，但已落库部分保留（如 Research 已建则标「研究中」可续） |

### 4.2 数据撤销（对象层 · 有副作用，受不变量约束）
| 可撤销 | 机制 | 影响范围 | 约束 |
|---|---|---|---|
| **Draft 恢复上一版** | 「恢复上一版」→ 回滚到上一保留 Version（v1.1→v1） | 仅当前 Draft 版本指针；其他版留痕 | 仅 ≥2 版后可用；`[REUSE]` Doc 1 D02/D03 |
| **Source 删除可恢复** | 删→进回收区；「恢复」取回 | 单 Source 配置 + 历史采集 | 彻底删需二次确认；失效态也可恢复后重授权 |
| **Topic/Work 放弃可恢复** | 软删→回收区；恢复取回 | 单对象 + 关联子对象引用 | 不丢历史 Publication/Research（`[CURIS-AUTH]` 不回滚） |
| **Scheduled 改/撤** | 定时发布前可改时间/撤 | 仅该账号 Publication（Scheduled 态） | 一旦 Published 不可撤（见下） |
| **Employee 转交/重试** | 换执行者或重跑 | Work 执行上下文；原失败记录留痕 | 不伪装已完成 |

### 4.3 不可撤销（事实层 · 硬约束）
- **发布后事实不可撤销**：Publication=Published 即平台事实，`FACT_NOT_ROLLED_BACK`——Curis 内**不能**「撤销发布」；要撤只能去平台删内容（用户手动），且 Curis 回执仍标「已发布」（不篡改）。`[CURIS-AUTH]` FACT_NOT_ROLLED_BACK / RECEIPT_FROM_CONNECTOR。
- **已发生账号状态不回滚其他账号**：XHS 已发、抖音失败 → 不能因抖音失败把 XHS 标未发。
- **历史结论/数据不可伪造覆盖**：Unknown/暂不可用/Rejected 等事实态留痕，新结论另存版本，不抹旧（`INTENT_EXCLUDES_INFERENCE` / UNKNOWN 合法）。

### 4.4 撤销影响总结
- 撤销**只**动目标对象当前态/版本指针，**不**波及其他账号、其他版本、已发布事实、历史回执。
- 任何撤销均留痕（谁、何时、从何版到何版），供 §5 历史追溯；软删 ≠ 硬删，回收区兜底。

## 5. 对象历史（Object History）

> 原则：**不做 Activity Log 墙**（不堆全量时间线刷屏）。只在「用户需要解释现在为什么这样 / 想恢复 / 想追溯」时，经 Utility 下钻按需查看。历史是**对象自带的版本与决策链**，不是独立日志系统。

### 5.1 六类历史与查看时机
| 历史类型 | 用户何时需要 | 怎么按需查看（Utility 下钻） | 恢复/追溯 |
|---|---|---|---|
| **Topic history** | 忘了这选题怎么来的、被合并/调整过 | Topic 详情「历史」→ 来源 Opportunity + 合并记录 + 方向调整 | 拆合/恢复暂缓（E04/E14） |
| **Research history** | 结论变过几次、续查补了什么 | Research 详情「版本/续查」→ 各版 Conclusion + 新增 Evidence 标记 | 「接受结论」回上一版（C06/E02） |
| **Draft versions** | 想回到某版、比对差异 | 内容 Surface 版本列表 + Comparison Utility 并排高亮 | 「恢复上一版」（D02/D03，§4.2） |
| **Employee actions** | 谁做了什么、转交过没 | Work 详情「执行记录」→ 员工 + 动作 + 时间 + 失败原因 | 转交/重试（E13） |
| **Publication receipts** | 发了没、平台啥说、真实 URL | 驾驶舱⑥「查看回执」→ Connector 回填状态/URL/时间/消息 | 重提/重试（E10/E11） |
| **Strategy adjustments** | 定位/方向/策略改过几次 | Office growth_context「调整记录」或周明建议卡「历史建议」 | 覆盖/回退定位（A07 异常段） |

### 5.2 历史不堆墙的三条规则
1. **默认不显示**：驾驶舱/列表只显当前态；历史入口是对象内的「历史/版本」下钻，不主动铺开。
2. **按需展开**：用户点「查看依据 / 版本 / 回执 / 历史」才拉详情（Utility 右栏），关即收。
3. **关联不复制**：历史是同一 Artifact/Work/Result 的版本链与决策链（`[CURIS-AUTH]` 关系树），不另建副本数据；恢复=指针回退，非新建。

### 5.3 与 Doc 1 Journey D 版本策略呼应
- D01 出 v1 记版本号；D02 Patch 出 v1.1 子版本（保留 v1 可回滚）；D03 比稿并排 + 「选为推荐版」；版本达上限（如 5）提示选定/合并，禁无限生成。
- 本文 §4.2 / §5.1 的「恢复上一版」「版本列表」「Comparison Utility」即消费该策略，不重定义。
- 历史追溯边界：`INTENT_EXCLUDES_INFERENCE`——Intent 不存推理过程，故「历史」记录的是**结论性决策**（采纳/放弃/覆盖/版本指针），不是 Prompt/CoT。
