# CONTENT GROWTH — CONTENT CREATION MECHANICS
### 内容创作机制：从 Content Intent/Brief → Draft → 编辑 → 版本 → 比稿 → 素材 → 审核 → 标记「可发布」的按钮级操作剧本

Status: **RESEARCH / EXPERT RECOMMENDATION**（非 Frozen，非 Authority 修改）

Companion 文件：
- `CONTENT_GROWTH_END_TO_END_JOURNEY_MODEL.md`（主文件，固定步骤格式 §1、稳定动作词汇表 §2、Journey D 概述 D01–D05、FINAL ACCEPTANCE TEST §13）
- `CONTENT_GROWTH_CONTENT_EMPLOYEE_INTERACTION_MODEL.md`（§2 内容生产、§3 内容/素材库）
- `Curis_Content_Growth_Domain_Authority.md`（Frozen，只消费不修改；Intent/Brief/Variant/Publication 契约与不变量）

本文件范围：仅研究**内容创作机制**这一子域的产品操作行为——Brief 的产生与编辑、Draft 默认生成与版本策略、直接改/说话改的 Patch 语义、比稿 Comparison、素材 Asset 发起与复用、审核五项的通过与失败、内容库 vs 素材库的区分与复用。复用主文件 §2 稳定动作词汇与主文件 §13 的 STEP 编号风格。**不重复发布细节**（见主文件 F01）。不画 UI/IA/Figma/前端/Runtime/Schema/DB，不修改 Domain Authority。

## 0. 红线与纪律

- 本轮**只研究产品怎么被真实操作**，不画 IA / Wireframe / Figma / 视觉 / 前端 / Runtime / Schema / DB / Authority 修改。
- 全部行为挂在已有 Curis 对象 `[REUSE]`：
  - **Content Intent** = Frozen 契约（`topic` / `core_message` / `business_goal`，只承载 WHY/WHAT/GOAL，**禁存**推理/CoT/中间草稿 `[CURIS-AUTH]` `INTENT_EXCLUDES_INFERENCE`）。
  - **Brief** = Work（结构/要点/调性/渠道初步）；**Draft / Asset** = Artifact（挂在 Brief Work 下，版本可追溯）。
  - **Variant / Publication** = Frozen 契约（发布阶段消费，本文件仅指到主文件 F01）。
- **版本有节制**：默认生成 **1–3 版** Draft，不做无限版本生成器；版本上限由 Unit-Economics Auto-Selector 约束 `[REUSE]` 主文件 §2 / Doc 2 §2.3。
- **审核五项**固定 = 品牌 / 事实 / 合规 / AI 标识 / 渠道规则；**通过才标「可发布」**，不通过不阻塞编辑。
- **CEO 默认只见推荐成品 + 必要备选**，不强制看全部版本（Doc 2 §2.2）。
- **内容库 vs 素材库**：逻辑分开，但同「资产与知识」Surface 下两个视图——内容库管「做了什么」，素材库管「用什么做的」（Doc 2 §3.1）。
- 证据标记：`[CURIS-AUTH]`=消费 Frozen 语义；`[REUSE]`=复用已有对象/行为。

## 1. Brief 的产生与编辑

### STEP B01
【用户当前看到】驾驶舱③「需关注的变化」里一张 Topic 卡「GPT-5.6 办公实测」；用户已点开该卡，动作区显示「就做这个 / 先调研 / 直接生成 / 调整方向 / 问员工 / 暂缓 / 放弃」（[REUSE] 主文件 C02 动作词）。
【用户动作】点「就做这个」。
【立即反馈】按钮变「准备内容中…」约 1 秒；跳转「内容」Surface，主区出现一张 **Brief 卡片（草稿态）** + 下方按钮「生成草稿 / 编辑 Brief / 问员工」。
【系统后台】创建 **Content Intent**（仅写 `topic`=`GPT-5.6 办公实测`、`core_message`（暂用 Research 结论摘要）、`business_goal`（来自 Office growth_context）；**不写**任何推理/CoT/中间草稿 `[CURIS-AUTH]` `INTENT_EXCLUDES_INFERENCE`）+ 创建 **Brief Work**（status=起草中）；原 Research Result 链接回该 Intent（[REUSE] 主文件 C07）；Topic.status=已采用。
【Employee 行为】李想（Producer）接手 Brief Work，基于 Intent + 已链接的 Research Evidence 起草 Brief 字段（目标/受众/核心信息/结构要点/调性/渠道初步）；起草在后台进行，用户不强制等待。
【页面/状态变化】用户停在「内容」Surface，Brief 卡显示「李想起草中」状态条；驾驶舱①出现「内容准备中」结果卡。
【可返回/可撤销】可点「调整方向」回 Topic 改定位（Topic 回推荐态）；可点「放弃」软删 Intent+Brief（可恢复，[REUSE] 主文件 §2「放弃」）。
【异常】Brief 起草失败（如 Evidence 不足）→ 提示「内容准备失败，可重试／先调研」；Intent 已建，可重生成 Brief 或退回调研。
【下一步】Brief 卡片落定后进入 STEP B02（查看）或 STEP B03（编辑）；完成点「生成草稿」进入 §2 D01。

### STEP B02
【用户当前看到】「内容」Surface，Brief 卡片已完成起草（李想填好）。卡片分区显示：
- 顶部：Intent 三行（`topic` / `core_message` / `business_goal`）。
- 主体：Brief 六字段——①目标受众 ②核心信息 ③结构要点（分点大纲）④调性（如「可信+前瞻、专业但易懂」）⑤建议篇幅/格式 ⑥渠道初步（如「小红书主号优先，抖音次发」）。
- 右下角小字：「推荐成品视图已就位（CEO 默认只看此处）」。
【用户动作】用户读卡片；可点任一字段旁的「查看依据」，或点「生成草稿」直接往下走；也可点「问员工」对李想说「结构再聚焦一点」。
【立即反馈】点「查看依据」→ 右栏 Utility 展开该 Brief 字段的来源链（来自哪个 Research Evidence / 哪条 Signal 强度）；点「问员工」→ 直接进入对话，自动携带当前 Intent+Brief 上下文（[REUSE] Doc 2 §1.2）。
【系统后台】无新写（仅 viewed 标记）；「查看依据」读取已链接 Result 的 Evidence 引用 `[CURIS-AUTH]`。
【Employee 行为】若用户「问员工」，李想在原 Brief Work 内局部调整，不重建 Intent。
【页面/状态变化】Brief 卡不变（仍是草稿态，未锁）；Utility 可开可关。
【可返回/可撤销】关 Utility 回卡片；Brief 仍可改（见 B03）。
【异常】Evidence 链接缺失某字段 → 该字段标「依据待补」，不阻断生成。
【下一步】用户满意则点「生成草稿」（§2 D01）；要改则 STEP B03。

### STEP B03
【用户当前看到】Brief 卡片处于草稿态，每字段右侧有「编辑」入口（铅笔图标）；顶部有「编辑 Brief」按钮（整体模式）。
【用户动作】点「编辑 Brief」进入编辑模式；改「核心信息」文本框（如删一句、改目标受众为「科技从业者+管理者」）；或单点某字段旁的「编辑」只改那一项；改完点「保存」。
【立即反馈】每次保存后卡片对应字段即时刷新；若改动了 Intent 级字段（topic/core_message/business_goal），提示「将更新 Intent」。
【系统后台】更新 Brief Work 的对应字段；若涉及 Intent 三字段，则更新 Content Intent（仍只写 WHY/WHAT/GOAL，不改禁存项 `[CURIS-AUTH]`）；记录一次 Brief Edit 历史（挂在 Work 下）。
【Employee 行为】李想收到 Brief 变更通知，后续 Draft 基于新 Brief；若变更大，李想可主动建议「重新生成草稿」。
【页面/状态变化】卡片退出编辑态显示新值；若已生成过 Draft，提示「Brief 已改，已有草稿是否基于新 Brief 重生成？」给「重生成 / 保留原稿」。
【可返回/可撤销】编辑模式内「撤销」回上一次保存；保存后可用 Brief Edit 历史回滚某一版 Brief（[REUSE] 主文件 Doc 5 历史版本）。
【异常】保存冲突（Employee 同时改）→ 提示「李想刚改了结构要点，以谁为准？」给「用我的 / 用李想的 / 合并」。
【下一步】点「生成草稿」进入 §2 D01（若尚未生成）或回到 §3 重生成。

## 2. Draft 生成

### STEP D01
【用户当前看到】「内容」Surface，Brief 卡片完成。按钮区：「生成草稿 / 编辑 Brief / 问员工」。
【用户动作】点「生成草稿」。
【立即反馈】按钮变「生成中…」；约 2 秒后主区出现**第 1 版 Draft**（标题 + 正文 + 建议标签 + 建议封面占位「待添加」），同时按钮区变为：「再来一版 / 直接在正文改 / 说话改 / 比稿 / 添加素材 / 准备发布 / 历史版本」。
【系统后台】Brief Work 产出 **Draft(Artifact) v1**（version=1，status=当前）；记录版本号与时间戳；李想标记 v1 为「当前版」；**默认行为**：李想判断是否需要多版——若 Brief 指向多渠道/多风格，自动补 **v2、v3**（默认共 1–3 版，`[REUSE]` Doc 2 §2.2「默认 1–3 版」），均已落库可追溯 `[CURIS-AUTH]` 版本挂在 Work 下。
【Employee 行为】李想基于 Brief 生成 v1；如判断需多版，自动补 v2/v3，并各自标注风格差异（如 v2=更口语、v3=更专业）。
【页面/状态变化】主区显示当前版（默认 v1 或李想选的基准版）正文；右侧出现**版本列表**（v1 当前；若自动出 v2/v3 也并列，各带一句风格标签）；「准备发布」在选推荐版前灰显。
【可返回/可撤销】「恢复上一版」仅在已有 ≥2 版后可用；当前可「编辑 Brief」重生成（见 B03）。
【异常】生成失败 → 提示「草稿未生成，重试」；Brief 保留不丢。
【下一步】用户可改（§3）、加素材（§5）、或「再来一版」（D02）。

### STEP D02
【用户当前看到】已有 v1（可能已有 v2/v3）。按钮区有「再来一版」。
【用户动作】点「再来一版」。
【立即反馈】按钮变「生成中…第 N+1 版」；约 2 秒后版本列表新增 **v(N+1)**，主区切到该新版并显示「这是基于当前 Intent/Brief 的新一版」。
【系统后台】在 Brief Work 下新增 Draft 子版本（version 计数 +1，如 v4）；不覆盖旧版；所有版本挂在 Work 下可追溯 `[CURIS-AUTH]`。
【Employee 行为】李想产出新版，标注与上一版差异点（如「这次开头更直接」）。
【页面/状态变化】版本列表计数 +1；当前版指向新版；若计数达上限（默认 5，见 `[REUSE]` Doc 2 §2.3 成本上限）则「再来一版」按钮旁出现提示。
【可返回/可撤销】可「恢复上一版」回滚（见 §3 E03 / §4 C02）；已生成版不丢。
【异常】达版本上限 → 提示「已生成 5 版，请选定或合并，建议进入比稿」（[REUSE] 主文件 D03 异常）；按钮变「版本已满，先选推荐版」。
【下一步】继续改（§3）或「比稿」并排比较（§4 C01）。

## 3. 编辑机制

### STEP E01
【用户当前看到】主区显示某版 Draft 正文（如 v1），正文为可编辑富文本；段落/标题/标签均可点选。
【用户动作】直接点正文第二段，删一句、改一个词，或在标题处改字；点空白处或「保存」。
【立即反馈】就地高亮刚改处（淡色标记「已编辑」），1 秒内保存成功提示「已保存」。
【系统后台】**更新当前版 Draft 内容**（不新建版本）；记录一次 Edit 操作（作者=用户、diff 片段）挂在 Work 下，供撤销与历史查看。
【Employee 行为】无（纯用户就地编辑）；李想后续若重生成会参考最新正文。
【页面/状态变化】正文显示新内容；版本列表该版标「已手动编辑」小标；出现「撤销刚才修改」按钮。
【可返回/可撤销】点「撤销刚才修改」→ 回退本次保存前的正文（仅撤最后一次手动编辑，不跨版本）。
【异常】编辑丢失（断网）→ 提示「未保存，是否重试」；原文不动。
【下一步】可继续改、说话改（E02）、或去比稿（§4）。

### STEP E02
【用户当前看到】正文下方有输入框「对内容说什么，或直接点正文编辑」；用户想表达意图而非逐字改。
【用户动作】选中第二段，输入：「这段更口语一点」；或输入：「标题换 3 个备选」「缩短一半」「保留上一版」。
【立即反馈】若说话改：对应段/标题实时变为新版本，版本列表出现 **v1.1（口语化·局部）** 或 **v1.2（缩短）** 子版本标签；若说「标题换 3 个」则标题区出现 3 个候选可点选其一。
【系统后台】说话改 = **Patch 当前 Version**：生成子版本（如 v1.1），**保留父版 v1 可回滚**；不覆盖原版（[REUSE] 主文件 D02）；「保留上一版」则显式快照当前为独立版本再改。
【Employee 行为】李想执行局部改写（语义级），记 Edit 记录；多候选（如 3 个标题）由李想一次产出。
【页面/状态变化】版本列表多出子版本；「撤销刚才修改」出现（撤本次 Patch 回父版）；「恢复上一版」仍可用（回更早保留版）。
【可返回/可撤销】「撤销刚才修改」→ v1.1 回退到 v1（仅撤本次 Patch）；「恢复上一版」→ 回更早的保留版本（语义不同，见 E03）。
【异常】改写失败（指令不清）→ 提示「未能修改，换个说法或点正文直接改」；原文不动。
【下一步】多次说话改积累 v1.1/v1.2…；或「恢复上一版」清掉局部改（E03）。

### STEP E03
【用户当前看到】经 E01/E02 后，版本列表有 v1、v1.1、v1.2 等；按钮区有「撤销刚才修改」与「恢复上一版」。
【用户动作】情况 A：刚做完一次说话改（v1.2），点「撤销刚才修改」。情况 B：想回到更早的干净版，点「恢复上一版」。
【立即反馈】A：v1.2 的本次 Patch 撤销，正文回到 v1.1（父版），版本列表 v1.2 标记「已撤销（可恢复）」。B：当前版回滚到上一**保留版本**（如从 v1.2 回到 v1），主区显示 v1 正文，版本列表高亮 v1 为当前。
【系统后台】A = 仅撤最后一次 Edit/Patch 记录，父版内容不变；B = 将 Draft.current_version 指针指向目标保留版本，旧「当前版」保留为历史（不删，可追溯 `[CURIS-AUTH]`）。
【Employee 行为】无（用户自助版本控制）；李想不介入。
【页面/状态变化】主区正文随选择变化；版本列表「当前」标记移动；「撤销刚才修改」在无可撤时灰显，「恢复上一版」在仅 1 版时灰显。
【可返回/可撤销】两者均可再次操作；「恢复上一版」后可再「撤销」回到被回滚的版（因历史都保留）。
【异常】无版本可撤/可恢复 → 按钮灰显并提示「已是首版」。
【下一步】满意后去比稿选推荐版（§4）或加素材（§5）。

> **E01/E02/E03 关键区别**：「撤销刚才修改」= 撤**最后一次**编辑/Patch（回到父版，轻量）；「恢复上一版」= 把**当前指针**移到**上一个保留版本**（跨子版本回滚，历史全留）。前者针对「刚改错」，后者针对「想回到某个干净节点」。

## 4. 比稿 / Comparison

### STEP C01
【用户当前看到】已有 ≥2 版（如 v1、v1.1、v2，或 v1/v2/v3）。按钮区「比稿」。
【用户动作】点「比稿」。
【立即反馈】主区切为 **Comparison Utility**：多版**并排**（左 v1 / 中 v1.1 / 右 v2），每版标题+正文同屏；顶部显示「差异高亮：开」。
【系统后台】读取 Brief Work 下所有 Draft 版本 Artifact；启动差异计算（段落级 diff），不新建对象。
【Employee 行为】李想不参与（比稿为系统展示）；若用户问，李想可补充每版适用场景说明。
【页面/状态变化】并排视图出现；相同段正常显示，**差异段高亮**（增=绿底，删=红删线，改=黄底）；每版下方有「选为推荐版 / 预览 / 关闭比稿」。
【可返回/可撤销】点「关闭比稿」回单版主区；不丢任何版本。
【异常】版本过多（>5）→ 比稿默认显示最近 3 版 + 下拉切其他，避免拥挤。
【下一步】用户高亮阅读后点某版「选为推荐版」→ C02。

### STEP C02
【用户当前看到】Comparison 并排视图中，v2 下方有「选为推荐版」按钮；其余版标「备选」。
【用户动作】点 v2 的「选为推荐版」。
【立即反馈】v2 标「★推荐」，其余标「备选」；主区退出比稿、单版显示 v2；按钮区「准备发布」由灰显变可用（基于推荐版）。
【系统后台】Draft.recommended_version = v2（[REUSE] 主文件 D03）；其余版本保留为备选（Artifact 历史，可追溯）；CEO 默认视图此后只显推荐版 + 备选摘要（[REUSE] Doc 2 §2.2「CEO 默认看到推荐成品+必要备选」）。
【Employee 行为】李想据用户选择聚焦 v2，后续素材/审核围绕推荐版。
【页面/状态变化】版本列表 v2 带星；「准备发布」启用；比稿视图关闭。
【可返回/可撤销】可改选其他版为推荐（再点别的版的「选为推荐版」即可，无次数限制）。
【异常】未选推荐版就点「准备发布」→ 提示「请先选推荐版」（或默认用当前版，给确认）。
【下一步】加素材（§5）或直接「准备发布」进入审核（§6 R01）。

## 5. 素材 Asset

### STEP A01
【用户当前看到】推荐版 Draft 正文需要封面/配图/视频；正文区「封面」占位显示「待添加」，按钮区有「添加素材」。
【用户动作】点「添加素材」→ 弹出三选项：「上传 / 从素材库选 / 让TA生成」；用户选「让TA生成」（或选其他）。
【立即反馈】选「让TA生成」后追问「生成几版？」给「1 / 2 / 3」；选「从素材库选」则打开素材库视图（见 §7）；选「上传」则出文件选择。
【系统后台】记录素材请求挂到当前 Draft（Asset 将关联该 Draft Artifact）；若「从素材库选」则进入素材库查询（不新建，[REUSE] §7）。
【Employee 行为】选「让TA生成」→ 李想（或视觉子能力）接手生成；选「从素材库选」→ 无 Employee 介入，用户自助。
【页面/状态变化】弹出选项层；选择后进入对应流程（生成中 / 库视图 / 上传框）。
【可返回/可撤销】可关弹层取消；已挂请求未生成前可撤销。
【异常】无素材库可选项（空库）→ 「从素材库选」仍可用但提示「库为空，建议让TA生成或上传」。
【下一步】生成流程 → A02；库选流程 → A03（复用历史）。

### STEP A02
【用户当前看到】用户选「让TA生成 2 版」；按钮变「生成中…封面 2 版」。
【用户动作】等待约 3 秒；出现 2 张封面候选（缩略图 + 风格标签，如「科技蓝 / 极简白」）。
【立即反馈】候选下方各有「选这张 / 局部重做 / 替换 / 复用历史」；点「选这张」则该图成为 Draft 封面。
【系统后台】生成 **Asset(Artifact) 2 张**，关联当前 Draft；历史素材库追加（若为新生成，[REUSE] Doc 2 §3.1 素材库）；记录 Asset 来源=AI生成。
【Employee 行为】李想产出 2 版封面；如用户「局部重做」（如「左上角加 logo」），李想在该 Asset 上 Patch 出新子版本（同 Draft 的 Patch 语义）。
【页面/状态变化】Draft 封面占位显示所选图；素材区列出 2 候选（已选的标「使用中」）；「局部重做」在原 Asset 上出 v1.1；「替换」换另一张或重新生成。
【可返回/可撤销】「替换」换图（旧 Asset 仍留库）；「局部重做」可撤销回该 Asset 上一版；未选前可换生成版数重来。
【异常】生成失败 → 提示「封面未生成，可上传或重试」；Draft 不阻塞，可先发布无封面或后补。
【下一步】审核（§6）或继续其他素材（视频同理）。

### STEP A03
【用户当前看到】用户在「添加素材」选「从素材库选」或 Draft 素材区点「复用历史」；系统打开**素材库视图**（「资产与知识」Surface 下的「素材库」子视图，与「内容库」并列但逻辑分开，[REUSE] Doc 2 §3.1）。
【用户动作】在素材库搜索「GPT 封面」→ 过滤出历史封面；点一张旧封面「引用到当前 Draft」。
【立即反馈】该 Asset 被引用为当前 Draft 封面，提示「已复用历史素材（不重生成）✅」；素材库视图可关。
【系统后台】当前 Draft 的 Asset 关联指向**已有 Asset Artifact**（引用，不新建、不重生成）；素材库与内容库保持分离视图但共享 Asset 对象（[REUSE] Doc 2 §3.1「共享 Image/Video/Brand Asset」）。
【Employee 行为】无（用户自助复用）；李想不介入。
【页面/状态变化】Draft 封面显示复用图；素材区标「复用·历史」来源；内容库与素材库视图边界清晰（用户在素材库挑「用什么做的」，不在内容库挑「做了什么」）。
【可返回/可撤销】可「取消引用」换别的；复用不破坏原 Asset。
【异常】历史素材失效/删除 → 提示「该素材已不可用，建议让TA生成或上传」。
【下一步】完成素材后去审核（§6 R01）。

> **内容库 vs 素材库（本步锚定）**：内容库管理 Topic/Research/Brief/Draft/Published（「做了什么」）；素材库管理 Image/Video/Brand/Reusable Asset（「用什么做的」）。同一 Draft 可引用素材库中的 Asset，但两库视图分离、检索维度不同，详见 §7。

## 6. 审核 / Review

### STEP R01
【用户当前看到】推荐版 Draft 完成（含封面），按钮区「准备发布」已可用。
【用户动作】点「准备发布」。
【立即反馈】系统触发**审核检查条**，逐项跑：品牌 / 事实 / 合规 / AI 标识 / 渠道规则；约 1–2 秒后显示五项各自状态（绿勾/黄警/红叉）。
【系统后台】创建**审核 Result**，记录每项（品牌/事实/合规/AI标识/渠道规则）的通过/失败与证据引用；该 Result 挂在 Brief Work 下（[REUSE] Doc 2 §2.2 审核项；Frozen 审核五项固定）。
【Employee 行为】李想（Producer）配合审核——如系统检出「缺 AI 标识」，李想补标识后复审；渠道规则项由陈帆（Channel Operator）提供该账号规则（如小红书禁词）。
【页面/状态变化】审核面板列出五项；全绿则 Draft 标「✅ 可发布」、按钮变「发布」；有失败项则列具体问题。
【可返回/可撤销】审核中不阻塞编辑；可关面板回Draft继续改（见 §3）。
【异常】审核服务超时 → 提示「审核未完成，可重试」；Draft 保持原态。
【下一步】全绿 → 去发布（§8 P01，指主文件 F01）；有失败 → R02。

### STEP R02
【用户当前看到】审核面板显示失败项，例如：「⚠️ 缺 AI 标识（合规项）」「⚠️ 第 3 段事实待核实（事实项）」「⚠️ 含平台敏感词『最』（渠道规则项）」。每项下方有「一键让员工修改」。
【用户动作】读具体问题；可逐一点「一键让员工修改」，或先自己改（回 §3）。
【立即反馈】点「一键让员工修改」→ 该项显示「李想处理中…」；数秒后该项变绿勾并附改后说明（如「已加『本文由 AI 辅助生成』标识」「第 3 段已附来源链接」「已替换敏感词」）。
【系统后台】审核 Result 对应项状态由 fail→pass，附修改记录（Employee=李想）；全部转绿后 Draft.status 自动置 **READY（可发布）**。
【Employee 行为】李想按失败项逐一修：补 AI 标识、核实事实加来源、按渠道规则改词；改完提交复审（系统自动复检该项）。
【页面/状态变化】失败项逐条变绿；全部通过后 Draft 标「✅ 可发布」，主区顶部状态条变绿，按钮区「发布」启用。
【可返回/可撤销】用户可中途停止「让员工修改」改自己手动改；修改均可经版本历史回滚。
【异常】某项员工也修不了（如事实无可靠来源）→ 该项仍红，提示「事实无法核实，建议删除该表述或补充来源」；不强制通过。
【下一步】全部通过 → §8 P01（发布，主文件 F01）；仍有红项不进发布。

### STEP R03
【用户当前看到】首轮审核有失败项，员工修改后进入**复审**；或用户手动改完点「重新审核」。
【用户动作】点「重新审核」（或员工改完系统自动复检）。
【立即反馈】审核条重跑五项；原失败项显示最新状态；若全绿 → 「✅ 可发布」；若仍红 → 继续列具体问题（不假装通过）。
【系统后台】复审覆盖原审核 Result（或追加一轮 Result 版本，挂在 Work 下可追溯）；通过则锁定 Draft.status=READY。
【Employee 行为】李想对未过项继续修，直至全绿或用户裁定放弃该项。
【页面/状态变化】状态条在「审核中→可发布/仍有问题」间切换；通过后才出现「发布」入口。
【可返回/可撤销】复审不过可再改再审；全程编辑不锁。
【异常】反复不过 → 提示「该内容多处不达标，建议重生成草稿或调整 Brief」（回 §1/§2）。
【下一步】通过 → §8 P01。

## 7. 内容库 vs 素材库

### STEP L01
【用户当前看到】用户在「资产与知识」Surface 看到两个并列视图标签：「内容库」与「素材库」（逻辑分开同 Surface，[REUSE] Doc 2 §3.1）。内容库默认显示该 Office 的 Topic/Research/Brief/Draft/Published 列表；素材库显示 Image/Video/Brand/Reusable Asset。

【系统后台】两库读同一组 Artifact（Draft/Asset 等），按类型投影到不同视图；不复制对象（[REUSE] Doc 2 §3.1「共享」）。
【Employee 行为】无（用户自助检索）。
【页面/状态变化】视图切换；列表按筛选刷新。
【可返回/可撤销】切回另一库；筛选可清除。
【异常】无。
【下一步】检索复用 → L02。

### STEP L02
【用户当前看到】用户在内容库搜索「GPT-5 实测」→ 出现 3 篇历史同主题内容；点其中一篇 → 见其 Brief 结构、用的素材、发布账号、表现摘要。
【用户动作】点「复用历史」→ 选「复用此 Brief 结构」或「复用此封面素材」；系统提示「将基于复用创建新 Intent/Brief 引用，不重做 Research/重生成」。
【立即反馈】提示「已引用历史 Brief 结构 ✅ 新内容将继承其骨架，你可微调」；或在素材库点旧封面「引用到当前 Draft」（同 §5 A03）。
【系统后台】新 Intent/Brief Work 通过**引用**关联历史对象（不复制、不重 Research）；素材引用指向已有 Asset Artifact（[REUSE] Doc 2 §3.2「复用历史避免重 Research/重生成」）；记录 reuse_ref。
【Employee 行为】李想基于复用骨架起新 Draft，省去从零；不重新调研（除非用户要求）。
【页面/状态变化】新 Brief 卡预填历史结构；用户可改；进入生成时更快出稿。
【可返回/可撤销】可取消复用引用，回到空白 Brief；引用不破坏原历史对象。
【异常】历史对象已软删 → 提示「该历史已归档，是否恢复」；恢复后可复用。
【下一步】复用后走 §1–§6 正常流程（更快），最终进 §8 发布。
