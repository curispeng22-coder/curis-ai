## 1. 核心论点：为什么需要「专业经营环境」，而非「又一个对话生成器」

**价值高地不在生成，在闭环。** `[INF][COMP]`

专业内容团队愿意付费的，从来不是「AI 帮我写一篇」——而是：
> 信息 → 信号 → 选题池 → 分平台生产 → 发布 → 数据回流 → 学习 → 下一轮

这条链路上，直接对话生成只是其中**最易被商品化、最不稀缺**的一环 `[COMP]`。无管理的直接生成会累积「隐性成本」：声调漂移、平台违规限流、无法归因、资产不可复用 `[COMP]`。

**Curis 的差异化**：把 16 阶段闭环 + 跨中西方平台适配 + 数据回流成「共享增长真相」做成单一操作系统，而非又一个聊天生成器。`[CAND]`

> **原则（贯穿全文）**：`CAN DO ≠ SHOULD DO ≠ WORTH DOING`。

## 2. 完整经营闭环（16+ 阶段）

下图是 Content Growth 的主价值链。每个阶段的详细「输入/员工/方法/Tool/结果/证据/交接/成本/复用/CEO投影/UI需求」见 `CONTENT_GROWTH_OPERATING_MATRIX.md`。

```
经营目标 (Business Goal)
  → ① 信息搜集 Information Gathering        [SHARED]
  → ② 信息池 / Signal Pool                  [SHARED]
  → ③ 机会发现 Opportunity Discovery        [SHARED]
  → ④ 选题池 Topic Pool                     [SHARED]
  → ⑤ 选题判断 Topic Judgment               [SHARED + CEO Gate(高价值)]
  → ⑥ 调研 Research / Deep Research         [SHARED；按保质期决定深度]
  → ⑦ 内容策略 / Brief                      [SHARED]
  → ⑧ 内容创作 Content Creation             [SHARED 核心观点 → 分叉点]
  → ⑨ 素材生产 Asset Production             [SHARED 资产 + CHANNEL 格式]
  → ⑩ 审核 Review / Approval                [SHARED 合规闸 + CHANNEL 平台规则]
  → ⑪ 渠道适配 Channel Adaptation           [分叉：SHARED 观点 → CHANNEL 形态]
  → ⑫ 发布 Publishing                       [CHANNEL；Human-in-the-loop 默认]
  → ⑬ 数据回收 Data Recovery                [CHANNEL 原始 → SHARED 真相]
  → ⑭ 用户反馈 User Feedback                [CHANNEL 收件箱 → SHARED 信号]
  → ⑮ 效果评估 Evaluation                    [SHARED 归因 + 判断]
  → ⑯ Learning / Strategy Adjustment        [SHARED 学习方法]
  → 下一周期 (Next Cycle)                    [回到 ①/④/⑤]
```

**关键纪律**：
- **发布不是终点** `[CURIS-AUTH]`：Publication（per-Account 真相）是事实记录，但其后必须有 ⑬–⑯ 回流，否则闭环断裂。
- **⑪ 是分叉点**：一条 `Content Intent`（WHY/WHAT/GOAL，共享上游 `[CURIS-AUTH]`）在 ⑪ 才开始按账号分叉为 `Content Variant`（per-Account）`[CURIS-AUTH]`。
- **SHARED 与 CHANNEL 的边界**见 OUTPUT 3；哪些阶段属哪层见 §3。

## 3. 工作面分层（SHARED vs CHANNEL 一览，详情见 OUTPUT 3）

| 层 | 包含阶段 | 建几次 |
|---|---|---|
| **SHARED（Content Growth 层，建一次）** | ①②③④⑤⑥⑦⑧⑨(核心观点/资产) ⑩(合规闸) ⑬(→真相) ⑭(→信号) ⑮⑯ | 1 次，跨渠道复用 |
| **CHANNEL（XHS / Douyin / …）** | ⑪ 格式适配 · ⑫ 发布 · ⑬ 渠道原始数据 · ⑭ 渠道反馈 · ⑩ 平台规则 | 每渠道封装在 Module + Connector |

**结论（压力测试 XHS & Douyin 后）**：约 **60–70%** 的内容增长实质价值（研究/策略/资产/评估/学习）是 **SHARED**；仅 **30–40%** 为 **CHANNEL-SPECIFIC**（规则/格式/发布/渠道分析/渠道反馈）`[COMP][INF]`。

## 4. CEO 体验原则（详情见 OUTPUT 4）

- **默认 Main 不呈现**：信息池、选题池、Research 数据库、内容库、Analytics Dashboard。
- **默认 Main 应呈现**：员工结果、当前经营重点、需要关注的变化、需要决定的事情、重要在途工作。
- **每个阶段投影规则**：`Internal Complexity → Employee Result → CEO Projection`（如：内部 300 条 Signal → CEO「今天有 3 个变化值得关注」）。
- **CEO 不是每步审批人**：仅 Relevant Gate（方向变化/重大投入/明显风险/重要外部动作/超策略边界/高价值机会/重大取舍）才找 CEO。CEO 默认操作：批准 / 调整 / 讨论 / 暂停。

---

## 5. 单位经济与深度模型（详情见 OUTPUT 5）

- **三条路径**：Quick（对话直接生成）/ Structured（结构化工作）/ Deep（持续监控→研究→内容→多渠道→数据→下一周期）。
- **渐进投资**：系统按价值与复杂度自动选 Quick / Structured / Deep，而非要求用户学 Workflow。
- **Worth-Doing 拐点**：当 `预期业务价值 × 跨渠道复用次数 × 迭代学习收益 > 结构化运营搭建成本` 时，专业闭环才 WORTH DOING；否则直接生成更划算。

## 6. 最小可行 AI 团队（员工按责任组织，不按步骤拆人）

**禁止**：信息搜集 1 人、选题 1 人、调研 1 人、文案 1 人、审核 1 人……（按步骤机械拆 = Token 黑洞 + 协调成本爆炸）`[CAND]`

**最小可行编制（按长期 Responsibility 组织）** `[CAND][INF]`：
1. **Growth Strategist / Operating Owner** — 经营目标、策略、Brief 终审、CEO 接口、Gate 裁决。可兼。
2. **Research & Intelligence** — 信息搜集、Signal、Opportunity、调研（Deep Research）。
3. **Content Producer** — Brief→草稿→素材→渠道适配（共享核心观点生产）。
4. **Channel Operator**（每渠道或共享）— 发布、渠道数据回收、渠道反馈/私信合规。

- **一个员工可承担多环节**：低音量时 Producer 兼 Research；高音量时再拆岗 `[CAND]`。
- **路由规则**：`Responsibility Requirement`（WHAT）→ Organization Routing（WHO）→ Employee（HOW）`[CURIS-AUTH]`；不为每步起一个员工。
- **防 Token 烧穿**：Intent 一次生成、N 账号复用（`HIGH_REUSE`/`FULL_DIVERGENCE`）`[CURIS-AUTH]`；研究深度绑定内容「保质期」；上下文隔离（不预载全量 Workspace/账号资料）`[CURIS-AUTH]`；批量与复用优先。

## 7. FINAL 16 QUESTIONS — 逐条回答

> 以下为研究结论的硬回答；每条标注结论与依据标记。

**Q1. 为什么这套系统比直接对话生成更值得用？**
→ 价值在闭环与复利：信号→选题→研究→生产→多渠道→数据→学习，每篇内容沉淀为可复用资产、品牌一致、合规可控、可测量归因。直接生成是其中最商品化的一环，不积累资产/品牌/合规/学习 `[COMP][INF]`。

**Q2. 什么情况下反而应该直接生成？**
→ 单条、低 stakes、一次性、单平台、低合规风险内容（临时促销、灵感头脑风暴、A/B 变体量产）。Quick Path 必须保留（§11 / OUTPUT 5）`[COMP][INF]`。

**Q3. Content Growth 是否应该是 Professional Workspace 边界？**
→ **是**，作为「专业经营环境 / 嵌入式领域应用」，但**边界是 Content Growth 域，不是「小红书」**。渠道（XHS/Douyin）是其内部节点 `[CAND][INF]`。

**Q4. 小红书 / 抖音应该处于什么层？**
→ 两者均为 **Channel**（可拆为 Module：格式/发布/分析/反馈 + Connector）。属于 Content Growth Workspace 之下，自身**不是** Workspace `[COMP][INF]`。（详见 OUTPUT 3）

**Q5. 完整经营闭环是什么？**
→ §2 的 16 阶段主价值链；发布不是终点，必须回流至 ⑬–⑯ `[CURIS-AUTH]`。

**Q6. 哪些研究 / 资产可以跨渠道复用？**
→ SHARED：信息、Signal、Opportunity、Topic、Research、Strategy、Brief、Knowledge、核心资产观点、Evaluation 方法、Learning。仅格式/发布/渠道分析/渠道反馈为 CHANNEL `[COMP][INF]`（OUTPUT 3）。

**Q7. 选题池到底如何工作？**
→ Signal(②③) → Opportunity(③，按 趋势/受众/定位/竞争/历史/缺口/时效/成本/跨渠道 评分) → Topic Pool(④，curated + 优先级)。CEO 默认看：推荐什么 / 为什么 / 价值 / 建议怎么办 `[COMP][INF]`。

**Q8. 信息搜集到底如何工作？**
→ 指定来源（平台搜索/对标账号/关键词/热点/评论/指定 URL/官方/行业媒体/用户文件/历史内容/历史数据）→ 持续监控 → 去重 → 过滤 → 形成 Signal。判定「是否值得做」仍 100% 人工/员工决策 `[COMP][INF]`。

**Q9. 每一步员工实际怎么干活？**
→ 见 `CONTENT_GROWTH_OPERATING_MATRIX.md`（每阶段 16 项：输入/员工/方法/Tool/结果/证据/交接/成本/复用/CEO投影/UI需求）。

**Q10. 每一步需要什么 Tool / Capability？**
→ SHARED 能力（研究/信号/选题/策略/Brief/资产/评估）由 Employee Operating Layer 组合；CHANNEL 能力（格式适配/发布/渠道分析/渠道反馈）由 **Connector + Module** 承担 `[CURIS-AUTH]`（OUTPUT 3 详列）。

**Q11. 最小 AI 团队应该是什么规模？**
→ 4 类 Responsibility（§6）：Strategist / Research&Intel / Producer / Channel Operator；低音量可合并至 2–3 人，高音量再拆 `[CAND][INF]`。

**Q12. 如何避免为了一个内容启动十几员工、烧大量 Token？**
→ 按 Responsibility（WHAT）路由而非按步骤起人；Intent 一次生成 N 账号复用；研究深度绑定保质期；上下文隔离不预载；批量复用；渐进投资自动选深度（OUTPUT 5）`[CURIS-AUTH][CAND]`。

**Q13. 用户默认每天应该看到什么？**
→ 员工结果 + 当前经营重点 + 需关注变化 + 需决定事项 + 重要在途工作；而非信息池/选题池/Dashboard（OUTPUT 4）`[CAND]`。

**Q14. 哪些专业复杂度应该隐藏在员工后面？**
→ 全部阶段内部复杂度：300 Signal→3 变化；20 选题→3 推荐；大量 Research→结论；多 Draft→推荐成品+备选；大量 Analytics→什么有效+下一步（OUTPUT 4）`[CAND]`。

**Q15. 现有 XHS 六大 Surface 哪些仍成立、哪些需要重组？**
→ **重组建议（待 CEO 裁决）** `[CAND]`：
  - 上升为 **Workspace 共享 Surface**（不再属 XHS）：Topic Pool、Research、Assets/Knowledge、CEO Overview、Evaluation/Learning。
  - 降为 **XHS Channel Module**（4 子模块）：Format Adaptation、Publishing、Channel Analytics、Channel Feedback（私信通/蒲公英）。
  - Calendar：维持「Content Operating 内部主视图、非默认入口」裁定（承前序 XHS 研究，OPEN QUESTION Z1/Z7 仍待 CEO）。
  - 即：XHS 不应是 6 个 Surface 的独立 Workspace，而是 Content Growth Workspace 下的一个 Channel。

**Q16. 下一步产品应该研究 / 实现什么，而不是先画什么页面？**
→ 优先级（研究/实现，非 UI）`[CAND]`：
  1. Operating Loop Runtime + Responsibility Routing（WHAT→WHO→HOW 落地）
  2. Signal Schema + Opportunity 评分模型
  3. Intent→Variant 复用引擎（`HIGH_REUSE`/`FULL_DIVERGENCE`）
  4. Channel Connector Framework（XHS / Douyin：格式/发布/分析/反馈 Module）
  5. CEO Projection / Value Layer（内部复杂度→CEO 投影）
  6. Unit-Economics Auto-Selector（Quick/Structured/Deep 自动选）
  - **不先画页面**：UI 必须最后衍生（OUTPUT 4 已定义 CEO 体验与 Surface 语义，可供后续 UI 研究消费）。
