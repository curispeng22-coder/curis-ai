# CONTENT GROWTH IA ROUND 1 — RED-TEAM TAKEOVER REVIEW

> Status: Review  
> Authority Class: REVIEW  
> Scope: IA Round 1 structural alignment only  
> Decision: **IA ROUND 1 READY FOR CEO ACCEPTANCE**

## Review basis

本轮只复核最终 Pre-IA Gate、Product / Company OS Shared Authority、Content Growth Domain Authority、Channel Capability Evidence Audit、Autonomy Guardrail Calibration Audit，以及 IA Model 与 Low-Fidelity Structural Proof 的一致性。

本轮不把 Research Candidate、Runtime Calibration 或演示 Mock 升格为 Product Truth；也不做视觉验收、功能扩展或实现验收。

## 1. 原 IA 结论：保留

以下结论与 Current Product Truth 一致，可被 IA 消费：

- `Workspace` 是唯一 canonical identity；Content Growth 是 Professional Workspace Candidate，不是 Verified Professional Workspace。
- Content Growth 的默认入口语义是 Domain-scoped CEO Operating Result / selected Surface candidate，不是新全局 Main、Dashboard Runtime 或第二套 Truth。
- Main 继续遵守 Shared Shell 合同：`selected Professional Surface + Shared Work Area`；Main 不变成固定 Dashboard。
- XHS、Douyin、TikTok、YouTube、Bilibili 是 Channel；账号是 Channel Account 对象，不是 Workspace。
- 默认经营结果面只压缩呈现当前最值得 CEO 关注的 0–3 个事项；0 项进入 Quiet experience；进行中状态只轻量呈现。
- Result → Evidence、Result → 问员工并携带 Context、Result → 按建议继续、Quick Path、专业能力按需下钻均保留。
- Responsibility 不等于 Employee；示例员工不冻结 Headcount、组织结构或员工数量。
- CEO 不被要求配置 Workflow、Agent 或专业参数。
- 能力状态必须诚实表达；不得把目标能力、Mock、通用 Bridge 或单个 API / 测试结果当作完整产品能力。

## 2. 因最终 Gate 修正的结论

### 2.1 Operating State 不再是 IA 或 Runtime 合同

8 Operating States 与 4 Cognitive Buckets 现在明确为 Research / Accepted Candidate。它们不定义固定 UI 栏目、后台分流、Runtime State Schema、排序算法或固定卡片数量。

IA 只消费“默认经营结果面优先呈现当前最值得 CEO 关注的事情”这一结果面语义。`需我点 / 需我决定 / 值得看 / 就绪` 仅是 Low-Fidelity Design Fixture，不是分类系统。

### 2.2 Capability Truth 改为直接消费 Audit

五个平台没有任何 audited `VERIFIED` capability，但不能被压扁为“全部 UNKNOWN”。IA Model 与 HTML 已按 Audit 原样保留 `PARTIAL / CONDITIONAL / UNKNOWN / UNAVAILABLE`。

因此 IA 不得暗示：已连接账号、真实 Publish、真实 Published URL、实时 Analytics、实时 Comments 或真实 Multi-account。发布演示明确标记为 `TARGET SCENARIO / NOT CURRENT CAPABILITY`；XHS 的内部/人工未验证状态也不被表述为真实平台发布。

### 2.3 Shared Shell 与 Content Growth Domain 的边界

Universal Conversation 的最终归属是 **B：Shared Workspace Work Area / Shared Workspace Shell capability**，不是 Content Growth 独立一级入口。其入口位置与数量由 Shared Shell 决定，本 Domain IA 不冻结。

Shared Shell 负责 Main 框架、Shared Work Area、通用对话、Employee / Team shared pattern 及其按需可达方式。Content Growth 只负责领域默认 Surface、专业对象视图和领域 Result 行为。HTML 中的“Shell · 经营结果 / Shell · 对话”只是结构 fixture，不代表 Content Growth 拥有两个一级 Tab。

## 3. Current Capability Truth

当前可被 IA 消费的最小真相如下：

| 能力 | 当前表达 |
|---|---|
| 五平台 audited VERIFIED | 无 |
| Auth | 五平台均 `PARTIAL`；不等于 OAuth / 账号归属已验证 |
| Publish | XHS 及其他平台均不得当作默认可用；Audit 状态为 `CONDITIONAL`，没有 live publication evidence |
| XHS Schedule / Publication Status / Receipt / Comments | `PARTIAL`，属于内部或人工未验证状态 |
| XHS Analytics | `UNAVAILABLE` |
| 其他平台 Schedule / Publication Status / Analytics / Comments | 主要为 `UNKNOWN`；不得补写为实时能力 |
| Multi-account | `UNAVAILABLE`；不得暗示已存在 Channel Account resolver |

Capability Truth 由 Capability Registry / Current Implementation Evidence 决定。IA 只能展示状态与等待、未连接、未知、人工未验证或需要证据等诚实结果。

## 4. Candidate → IA Truth 越级检查

未发现新的 Candidate 升格为 Current Product Truth 的阻塞问题。

仍属于 Candidate / Fixture / Calibration 的内容已被边界化：

- 8/4 状态与桶：Candidate，不得作为固定 IA 分类。
- 0–3、排序、重要度、运行轻量行：结果面候选表达；不得被解释为已证明的 Runtime 数值策略。
- 目标发布流、推荐账号、真实外部平台闭环：`TARGET SCENARIO / NOT CURRENT CAPABILITY`。
- Retry、Timeout、Observation、Cost、Cycle / Chain 限额及 Confidence 规则：继续留给 Runtime Calibration / Implementation；IA 不制造数字合同。
- Shared Shell 的持久入口具体位置：Shell 级候选，不由 Content Growth IA 冻结。

## 5. Domain 是否重复发明 Shared Shell

修正后没有发现 Content Growth 再造一套 Workspace Shell 的结构性问题：

- 没有冻结 Content Growth 自有一级导航数量。
- 没有把 Universal Conversation、Team 或 Employee 变成 Content Growth 私有导航体系。
- 没有新增 Domain-owned Main、Work、Result、Team 或 Employee Truth。
- 专业对象只通过 Result、Context、当前 Work 或 Shared Shell 下钻按需出现。

Shell 入口的最终位置仍需在 Shared Shell 级别继续细化，但这不要求 Content Growth IA 猜测一个新的 Domain 结构，因此不构成 IA Blocker。

## 6. Final decision

# IA ROUND 1 READY FOR CEO ACCEPTANCE

IA 可以进入 CEO Acceptance，前提是消费范围保持如下：

1. 消费 Current Product / Shared Shell / Domain Truth：Workspace identity、Main 合同、Domain-scoped default Surface、Shared Work Area 与上述 Result / Context 行为。
2. 消费但标为 Candidate：0–3 注意力项、Quiet 表达、8/4 研究语言、Shell 入口的具体位置、示例员工与示例流程。
3. 不得假设 Current Capability：五平台 VERIFIED、连接账号、真实发布、Published URL、实时 Analytics / Comments、Multi-account、自动策略学习或已校准的通用成本/重试/超时阈值。
4. 留给 Runtime Calibration / Implementation：Capability Registry 的真实证据闭环、外部平台授权与连接、发布及回执、数据读取、成本与周期预算、重试/超时/链深限制、观察数量与学习阈值、运行恢复与实际通知策略。

继续保持 Low-Fidelity Structural Proof；本裁决不等同于视觉验收、Runtime 完成或 Capability Acceptance。

**STOP FOR CEO REVIEW.**
