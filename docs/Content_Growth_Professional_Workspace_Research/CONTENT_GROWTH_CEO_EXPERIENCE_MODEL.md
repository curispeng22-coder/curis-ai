## 0. 设计宪法（两个最高要求之一：用户是小白 CEO）

> AI 员工处理复杂过程；CEO 主要看 **结果 / 价值 / 建议 / 风险 / 需要决定的事**。
> 后台可以复杂，前台必须简单。`[CAND]`

本研究的所有 Surface / 投影规则均服从此宪法。UI 必须**最后**衍生（不在本研究范围）。

## 1. 投影规则：Internal Complexity → Employee Result → CEO Projection

每个 Stage 必须定义三级投影。CEO **永不**看到原始复杂度，只看第三级。

| Stage | Internal Complexity（员工内部） | Employee Result（员工产出） | CEO Projection（CEO 看到） |
|---|---|---|---|
| ① 信息搜集 | 监控 N 个来源、去重过滤 M 条原始 | 结构化 Signal 候选 | 「已监控 N 来源，本周新增 M 条相关信号」 |
| ② Signal Pool | 300+ 条 Signal | 聚类+打标 Signal 对象 | 「今天有 3 个变化值得关注：…」 |
| ③ Opportunity | 多 Signal 聚合模式 | Opportunity 候选 | 「发现 2 个高潜机会：A 趋势上升 / B 竞争空白」 |
| ④ Topic Pool | 20 个候选选题 | 评分+优先级池 | 「推荐 3 个：①价值…②…③…；建议先做①」 |
| ⑤ 选题判断 | 战略对齐+资源+风险 | 入选/WAIT/SKIP/STOP | 「3选1已定，符合本季重点；1 高价值机会需您确认预算」 |
| ⑥ Research | 大量 Research/Evidence/Unknowns | 研究结论+证据包 | 「结论：X 成立，意味着…；建议…；3 处未知待证实」 |
| ⑦ Brief | 受众/目标/调性/CTA/合规 | Content Intent | 「已定方向：讲 X，目标 Y，调性 Z；将分 N 渠道」 |
| ⑧ 创作 | 多版本草稿 | 推荐成品+备选 | 「推荐成品 + 1 备选；已对齐 Brief」 |
| ⑨ 素材 | 图文/视频/封面多格式 | 主视觉+渠道格式包 | 「素材就绪：主视觉 + 3 渠道格式包」 |
| ⑩ 审核 | 禁词/AI标识/平台规则校验 | 通过/驳回(原因) | 「N 条待发已过合规；1 条 AI 标识需补」 |
| ⑪ 适配 | 分叉为 N 账号 Variant | 每账号变体 | 「将发 XHS+抖音，已按各平台格式适配」 |
| ⑫ 发布 | per-Account 发布执行 | Publication 真相 | 「已发布 XHS(阅读中)/抖音(审核中)；异常将提示」 |
| ⑬ 数据 | 多平台原始指标 | 共享增长真相 | 「本周 XHS 收藏率↑12%，抖音完播↓5%」 |
| ⑭ 反馈 | 评论/私信/@提及分类 | 线索+新 Signal | 「2 条高意向评论转线索；1 起投诉已处理」 |
| ⑮ 评估 | 归因+决策树 | 评估结论+假设 | 「什么有效、为什么、下一步建议」 |
| ⑯ Learning | 策略更新 | 下一 Cycle 假设 | 「策略微调：增加 X 类选题；已记录」 |

> 核心：**内部 300 条 → CEO 3 条；内部 20 选题 → CEO 3 推荐；内部大量 Research → CEO 结论；内部多 Draft → CEO 推荐成品+备选；内部大量 Analytics → CEO 什么有效+下一步。** `[CAND]`

## 2. Relevant Gates（CEO 不是每步审批人）

仅 **真正 Relevant Gate** 才找 CEO。依据 Company OS Shared Authority §0.2（Goal/Positioning/Audience/Monetization/material Budget/不可逆外部承诺 → CEO Gate）：

| Gate 类型 | 触发场景 | CEO 动作 |
|---|---|---|
| 方向变化 | 选题偏离本季重点/策略信封 | 批准/调整 |
| 重大投入 | Deep Research 高成本 / 多平台大投放 | 确认预算 |
| 明显风险 | 合规红线临近 / 平台限流预警 | 讨论/暂停 |
| 重要外部动作 | 首次对外发布/商单/投放 | 批准 |
| 超策略边界 | 选题超出 Approved Strategy Envelope | Gate |
| 高价值机会 | 竞争空白/趋势红利 | 确认抓取的取舍 |
| 重大取舍 | 渠道优先级/资源分配 | 决策 |

**日常由 Team 自主推进**（CONTINUE/ADJUST），不逐级上报。`[CURIS-AUTH]`

**CEO 默认操作应简单**：`批准 / 调整 / 讨论 / 暂停` 四选一。`[CAND]`

## 3. Default Workspace Experience（用户每天打开看到什么）

### 3.1 不应默认呈现（反模式）
- ❌ 信息池全量
- ❌ 选题池全量
- ❌ Research 数据库
- ❌ 内容库
- ❌ Analytics Dashboard（裸仪表盘）

### 3.2 应默认呈现（正面模式）`[CAND]`
1. **员工结果**（各 Responsible Employee 最新交付摘要）
2. **当前经营重点**（本季方向 + 在途关键选题）
3. **需要关注的变化**（信号/数据异常 → 3 条级投影）
4. **需要决定的事情**（待 CEO Gate 卡，附建议）
5. **重要在途工作**（发布中/审核中/研究中状态）

> 即：默认 Main = **「经营驾驶舱」**，不是「工具台」。专业 Surface（选题池/Research/资产/分析/反馈）继续存在，用于**深入工作与追溯**，但默认不占 Main。`[CAND]`

### 3.3 与现有权威的对齐
- 承 `Curis_Company_OS_Shared_Authority` 三层模型：User Surface（驾驶舱投影）← Employee Operating Layer（复杂过程）← System Runtime（确定性）。
- 承 Content Growth Domain Authority：Office=经营单元、Publication per-Account 真相；CEO 看的是「员工结果投影」，不是 per-Account 原始状态。`[CURIS-AUTH]`

## 4. Quick Path 必须保留（不消灭简单用法）`[CAND]`

Professional Workspace 不能要求用户学 Workflow。

- 用户仍可说：「帮我写一篇关于 GPT-5.6 的小红书笔记。」
- 系统按 **价值与复杂度自动选** `Quick / Structured / Deep`（见 OUTPUT 5），而非要求用户手动选模式。
- Quick Path 走：对话 → 直接生成（SHARED 生成 + 单 Channel 适配 + Human-in-the-loop 发布）。
- 仅当检测到「多平台/品牌一致性/合规敏感/需测量迭代」时才升 Structured/Deep。

## 5. 隐藏在员工后的专业复杂度清单（回答 CEO Q14）

以下复杂度**默认不暴露**给 CEO，由员工/系统吸收：
- 信号去重/聚类算法、选题评分维度、研究证据链、多版本草稿、渠道格式规范（XHS 3:4 vs 抖音 9:16）、平台合规禁词表、私信防封节奏、per-Account 发布状态、归因决策树、策略信封比对。
- CEO 仅在 **Gate** 或 **异常** 时，看到被翻译成「价值/风险/建议」的上述复杂度。
