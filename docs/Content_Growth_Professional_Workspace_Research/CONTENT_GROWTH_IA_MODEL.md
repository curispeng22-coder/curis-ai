### 2.1 Workspace 身份（来自 CEO Authority Reconciliation，已同步）
- `Workspace` 是唯一 canonical user/product identity；`Office` 仅历史/实现/migration provenance。
- Content Growth = **Professional Workspace Candidate**，不是 Verified Professional Workspace。
- XHS / Douyin / TikTok / YouTube / Bilibili = **Channel**（非 Workspace）；具体账号 = **Channel Account**。
- 共享契约：`Main = selected Professional Surface + Shared Work Area`；Content Growth 的 CEO Operating Result 仅是 **Domain-scoped default selected Surface / projection**，不是新全局 Main、不是 Dashboard Runtime、不是第二套 Truth。
- Surface **不拥有独立 Runtime / Work / Result / Team Truth**（消费 Frozen `NO_SURFACE_RUNTIME`）。

### 2.2 经营结果面（Content Growth 提供的 Domain 投影）
经营结果面回答一个问题：

> **「现在最值得 CEO 关注的事情是什么？」**

它不是按 8 态 / 4 桶切成固定栏目，而是按「当前最值得关注」排序的注意力项（详见 §4）。

### 2.3 与 Shared Workspace Shell 的责任切分（Final Alignment #3 核心）

| 能力 | 归属 | 说明 |
|---|---|---|
| 通用对话 / Universal Conversation | **Shared Shell 提供** | 跨 Workspace 复用的输入与沟通能力；Quick Path 即此能力的自然延伸 |
| Main 框架（selected Surface + Shared Work Area） | **Shared Shell 提供** | 不因 Content Growth 而改变；各 WS 只贡献自己的默认 Surface |
| 入口位置 / Persistent entry | **Shared Shell 决定（候选）** | 本 IA 不把入口位置或数量冻结为 Content Growth 规则 |
| 团队 / AI 员工入口 | **Shell 提供（按需可达）** | 员工是 Workspace/Company 级资源，非 Content Growth 私有 |
| 经营结果（CEO Operating Result） | **Content Growth 提供（Domain-scoped default Surface）** | 内容领域的「最值得关注」投影逻辑、注意力项、Result 行为 |
| 专业 Surface 对象视图（Source/Topic/Research/Content/Channel/Feedback…） | **Content Growth 提供（按需下钻）** | 声明专业 Responsibility；由 Shell 的导航/下钻机制承载 |
| Result → Evidence / 问员工带 Context / 按建议继续 | **Content Growth 提供（领域行为）** | 建立在 Shell 的对话与 Work Area 之上 |

**目标**：未来任一 Professional Workspace 只需贡献「自己的默认 Surface + 领域对象视图」，不重复造「经营结果 / 对话 / 团队」三件套。

## 4. Main = 经营结果面（默认落地）—「最值得关注」单列表

Main **不**按 8 态 / 4 桶分固定栏目。它只回答：

> **「现在最值得 CEO 关注的事情是什么？」**

（8 态 / 4 桶在此仅作 Research / Accepted Candidate 投影语言；**具体 Runtime 状态机、排序算法、bucket 数量本轮不定义**，留给 Runtime Calibration。）

呈现规则：

- 头条：一行「最近值得你关注的 **N** 件事」（N 允许 **0 / 1 / 2 / 3**）。
- **0 件** → Quiet 健康态：「团队正在正常运行，没有需要你处理的事情。」——不造 KPI 墙 / 假推荐 / 重复状态。
- **1–3 件** → 按重要度排序的注意力卡（最多 3，超过折叠「更多」）：
  每卡字段：谁完成 → 结论 → 价值（Business Meaning，锚定 Goal）→ 风险/Unknown（仅必要时）→ 建议 → 动作（查看依据 / 问员工 / 按建议继续 / 重新授权 / 确认方向）。
- **进行中状态仅轻量存在**：页面底部一行「团队正在进行 3 项工作（调研 / 发布准备 / 数据检查），完成后会在这里出现结果。」——不单列栏目、不刷屏；不表示平台已真实发布或已获得实时数据。
- HTML 中用于区分卡片的「需我点 / 需我决定 / 值得看 / 就绪」角标仅为 **DESIGN FIXTURE（设计示意）**，不得成为 IA Contract；真实分桶/排序由 Runtime 决定。

## 5. Context 模型（三入口 + 下钻携带）

- 点「**查看依据**」→ 打开对象视图，带面包屑「← 经营结果」，Context 不丢。

## 11. Capability Truth 表达（直接消费真实 Audit）

**真实结论（Channel Capability Evidence Audit 已执行）**：截至当前，五个平台（XHS / Douyin / TikTok / YouTube / Bilibili）**均无任何 audited VERIFIED capability**。但各能力按 Audit 原样消费，不得一概写「全部 UNKNOWN」。

### 11.1 Channel × Capability 真实矩阵（来自 Audit §2，原样消费）

**身份与获取**

|---|---|---|---|---|

| Douyin | `PARTIAL` | `UNKNOWN` | `UNKNOWN` | `UNAVAILABLE` |
| TikTok | `PARTIAL` | `UNKNOWN` | `UNKNOWN` | `UNAVAILABLE` |
| YouTube | `PARTIAL` | `UNKNOWN` | `UNKNOWN` | `UNAVAILABLE` |
| Bilibili | `PARTIAL` | `UNKNOWN` | `UNKNOWN` | `UNAVAILABLE` |

**分发与反馈**

| Channel | Publish | Schedule | Publication Status | Receipt/URL | Analytics | Comments/Feedback |
|---|---|---|---|---|---|---|
| XHS | `CONDITIONAL` | `PARTIAL` | `PARTIAL` | `PARTIAL` | `UNAVAILABLE` | `PARTIAL` |
| Douyin | `CONDITIONAL` | `UNKNOWN` | `UNKNOWN` | `CONDITIONAL` | `UNKNOWN` | `UNKNOWN` |
| TikTok | `CONDITIONAL` | `UNKNOWN` | `UNKNOWN` | `CONDITIONAL` | `UNKNOWN` | `UNKNOWN` |
| YouTube | `CONDITIONAL` | `UNKNOWN` | `UNKNOWN` | `CONDITIONAL` | `UNKNOWN` | `UNKNOWN` |
| Bilibili | `CONDITIONAL` | `UNKNOWN` | `UNKNOWN` | `CONDITIONAL` | `UNKNOWN` | `UNKNOWN` |

**读法（来自 Audit §1 / §2 原文）**：
- `Auth=PARTIAL` 仅指 Curis 侧凭据管线（provider 名、本地 secret 存取、已测 Douyin-cookie 元数据路径），**不等于平台 OAuth / 账号归属已验证**。
- `Publish=CONDITIONAL` 五平台均是把平台名传给同一通用 bridge，依赖外部自托管服务 + cookie + 已批准外部动作；**无 live publication 证据**，不得显示为默认可用 / 已验证。
- `XHS Schedule=PARTIAL`：Curis 持久化 `scheduledFor` 并到达内部 `SCHEDULED`，**不等于平台侧定时**。
- `XHS Publication Status=PARTIAL`：诚实区分等待能力 / 人工未验证回执；不轮询平台状态。
- `XHS Receipt/URL=PARTIAL`：CEO 可记录显式 `UNVERIFIED` 人工回执；无真实 Published URL 证据。
- `Analytics`：XHS `UNAVAILABLE`（明确无指标）；其余 `UNKNOWN`（实现缺失，非平台不能）。
- `Multi-account=UNAVAILABLE`：无 Channel Account 对象 / 按账号 resolver，旧 resolver 只取首个匹配凭据。

### 11.2 IA-safe 表达边界（来自 Audit §5，原样消费）

| IA 问题 | 安全假设 | 允许表达 |
|---|---|---|
| 显示已连接账号？ | **否** | 显示「未连接 / 未验证 / 未知」；不编造账号身份 |
| 显示渠道目录条目？ | **是，仅作可发现元数据** | 明确区分 catalog 可见性 vs 安装/授权/健康 |
| 把 Publish 显示为可用？ | **否 / CONDITIONAL** | 禁用或责任态：「发布能力未连接」；可设计配置/恢复入口 |
| 显示 Curis 侧排期？ | **仅 XHS** | 「已排期」= 内部计划，非平台定时；其余未知 |
| 显示平台发布状态？ | **否** | XHS 可显示「等待发布能力」或「人工回执未验证」；不声称轮询 |
| 显示真实 Published URL？ | **否** | 无审计证据支持 |
| 接受人工回执？ | **仅 XHS，显式未验证** | 标 `CEO_MANUAL` / `UNVERIFIED`；绝不转为已验证平台真相 |
| 显示 Analytics？ | **否** | XHS：「暂无数据 / 数据能力未连接」；其余仅 unknown/unavailable |
| 显示实时平台 Comments？ | **否** | XHS 可给 CEO 人工录入，标 manual/unverified provenance |
| 把渠道 Search/Research 当渠道能力？ | **否** | 人工/受控研究仅带自身 provenance，绝不写「已读取平台」 |
| 支持多账号？ | **否** | 不提供账号切换 / 按账号 eligibility / 按账号发布声明 |

→ IA 可建模 `Unavailable / Not connected / Unknown / Needs authorization / Waiting for capability / Manual-Unverified / Real-world evidence required`，**不得**把 `Connected / Publish / Published URL / Analytics / Comments / Multi-account` 当默认可用能力。

### 11.3 状态值语义（诚实使用）

| 值 | 含义 | IA 当前可用 |
|---|---|---|
| `VERIFIED` | 实现 + 可定位证据证明确实具备 | **当前无**（五平台均否） |
| `PARTIAL` | 实现/证据仅证明确认链的有界部分 | 按 Audit 矩阵原样使用（如 XHS Schedule/Status/Receipt/Comments、五平台 Auth） |
| `CONDITIONAL` | 存在实现路径，但缺外部服务/账号/授权或真实证据 | 按 Audit 矩阵原样使用（如五平台 Publish/Receipt），须附条件说明 |
