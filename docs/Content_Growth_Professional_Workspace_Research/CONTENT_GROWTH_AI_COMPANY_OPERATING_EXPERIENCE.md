## 1. 责任分配的最高原则（三句话）

```
USER PROVIDES      →  意图(Intent) + 参考(Reference) + 约束(Constraint)
AI TEAM PRODUCES   →  研究(Research) + 策略(Strategy) + 配置(Configuration) + 执行(Operation)
CEO CONSUMES       →  结果(Result) + 价值(Value) + 建议(Recommendation) + 相关决策(Decision)
```

对边三个判断门槛（每次想让 CEO 配置/选择前必须先过这三关）：

1. **这件事真的只有 CEO 能决定吗？** 若 AI 员工根据 Goal / Reference / Existing Assets / Evidence / Strategy Envelope 可合理判断 → 不麻烦 CEO。
2. **这是用户独有事实吗？** 只有用户自己知道（如「是否愿露脸」「是否已有产品」「预算/时间限制」「个人偏好」）才问。
3. **这是不可逆外部动作吗？** 仅发布到外部平台、 OAuth 授权、重大预算/方向/风险 → 才需 CEO 确认或外部授权。

## 2. 四类动作归属速查（与审计文件 §1 一致）

| 标记 | 含义 | CEO 行为 |
|---|---|---|
| **A · AI AUTO** | AI 员工自己决定并执行，不惊动 CEO | 不出现、不配置 |
| **B · AI RECOMMEND → USER CONFIRM** | AI 给专业答案，CEO 只确认重大方向 | 看「建议这样做」+ 采用/调整/讨论 |
| **C · USER FACT REQUIRED** | 只有用户知道的事实 | 提供事实（一句话） |
| **D · EXTERNAL AUTHORIZATION** | OAuth / 平台授权 | 点一次授权 |
| **E · EXPERT OVERRIDE** | 默认隐藏，高级用户主动深入才手工配置 | 主动进专业区 |

详见 `CONTENT_GROWTH_CONFIGURATION_OWNERSHIP_AUDIT.md`。

## 3. CEO 做什么 / AI 做什么 / CEO 何时确认 / Expert 藏哪

### 3.1 CEO 做什么（常态）
- **说**：表达目标（「我想做 AI 科技内容，先涨粉，以后接广告」）。
- **提供参考**：贴一个喜欢的账号/视频/帖子/网站链接，或说「重点看这个」。
- **看**：结果卡（发生了什么 / 员工做了什么 / 什么值得关注 / 为什么 / 建议怎么办）。
- **确认**：对 AI 的建议点「采用 / 确认发布 / 按建议继续」。
- **调整**：说一句修改意见（「第二段更口语」），或点「调整 / 讨论」。
- **讨论**：不懂就「问员工」，携带当前对象上下文。

### 3.2 AI 做什么（常态，后台）
- 市场/赛道/对标研究、Audience/Tone/定位推断、关键词派生、Source 发现与维护。
- 账号历史分析、用途/角色/默认推荐。
- 选题发现与评分、Research 多源比对、内容生成与版本、素材生成、审核五项自检与修复。
- 发布适配（Variant）、目标账号推荐、回执归集、反馈归一化、Evaluation 与下一轮建议。

### 3.3 CEO 何时确认（仅这四类）
- **重大方向**：经营定位/对标结论/选题大方向（B 类，一眼确认或调整）。
- **不可逆外部动作**：发布到外部平台（Human-in-the-loop 一次确认）。
- **外部授权**：OAuth 连账号（D 类，点一次）。
- **Strategy Envelope 越界**：要变现/换赛道/超预算 → CEO Gate（批准/调整/讨论/暂停）。

### 3.4 Expert 能力藏哪（默认折叠）
- 全量 Signal 池、选题评分明细、Research Scope/置信度、版本比稿、素材库管理、Connector 健康、平台规则、授权令牌、发布逐账号精调时间 → **均默认隐藏**。
- 仅当用户主动点 7 个 Professional Surface 之一（信息与机会 / 选题 / 研究与洞察 / 内容 / 增长与评估 / 反馈 / 渠道）才展开，**且可随时退回投影层**。
- 日常 CEO 不进这些区；AI 员工在主用。

## 4. FIRST-TIME EXPERIENCE（重新设计）

### 4.1 有对标链接（Reference-driven）
模拟：「我想做成这个账号这样。」+ 贴一个账号链接。

- **链接识别**（A）：系统识别是 XHS/Douyin/YouTube 账号或单条帖子/视频，建档为 Reference。
- **账号/内容分析**（A）：王颖读取该账号历史内容、类型、受众互动、表达方式、更新规律、增长特点、商业化方式。
- **受众推断**（A）：从互动画像 + 内容主题推断其 Audience，不要求用户填。
- **选题/表达/更新/增长/商业化模式**（A）：拆成可学习的模式与「不适合照搬」的部分。
- **结合用户目标形成方案**（A→B）：王颖把分析结论 + 用户目标（涨粉/接广告）合成「自己的经营方案」。
- **CEO 看到的不是分析报告，而是建议**（B）：
  > 「我们建议你这样做：① 定位=AI 科技从业者视角的实用测评；② 主要发小红书+抖音；③ 调性=可信+前瞻；④ 前 3 周重点做『新模型实测』系列。预计价值：6–8 周起量，接广告路径清晰。主要风险：同质化，需用第一手实测拉开。下一步：我可以先帮你盯 OpenAI/Anthropic 动态并推荐选题。」
  - 按钮：**「按建议开始」/「调整」/「讨论」**。不是「填写定位表」。
- **用户点「按建议开始」** → 后台自动落 Office growth_context（positioning/audience/tone/keyword/source/competitor 全由 AI 填好），启动监控与研究。CEO 不需碰任何字段。

### 4.2 无对标链接（No-reference path）
模拟：「我想做 AI 科技内容，先涨粉，以后接广告。」

- **AI 自完成**（A）：市场研究 → 赛道研究 → 寻找对标（公开搜索发现候选）→ Audience 判断 → Channel 判断 → 定位 → 关键词 → Source 发现 → 内容策略 → 初始选题。
- **向 CEO 汇报建议**（B）：同样以「我们建议你这样做 + 为什么 + 预计价值 + 主要风险 + 下一步」呈现。
- **不能反过来要求用户先提供这些答案**。若用户零输入，AI 用行业常识起最小可行方案，随信号积累自修正。

### 4.3 只问 USER FACT（C 类，且尽量少）
系统最多优先确认 3 类**只有用户知道**的事实：
1. **目的**：涨粉 / 带货 / 接广告 / 卖自己的产品 / 做个人 IP / 其他自然语言。（B 中可选项，但目的影响方案，值得先问一句；给推荐+「其他」）
2. **有没有想参考的内容**：账号/视频/帖子/网站/文件链接，或「没有也可以」。（Reference，C/D 边界）
3. **是否影响方案的独有事实**（仅当真影响才问）：是否愿露脸 / 是否已有产品 / 是否已有账号 / 预算或时间等真实限制。
- **禁止一开始要求用户配置**：Audience / Tone / Brand Context / 关键词 / Source / 对标账号 / 渠道组合 / 发布频率 / Research Scope / Employee / Workflow。这些全部 A 或 B，由 AI 完成。

## 5. 重跑主要 JOURNEY（标注责任归属）

> 每个 Journey 在 Round 2 步骤号后标注本轮归属：**[CEO DOES]** 表示 Round 2 让 CEO 做、本轮应反转；**[AI DOES]** 表示 AI 负责；**[CEO CONFIRMS]** 表示 CEO 仅确认；**[EXPERT ONLY]** 表示降级隐藏。

### 5.1 First-time（Round 2 Journey A）
- A01 说意图 → **[CEO DOES]** 说；**AI** 建 Office+Intent。
- A02 三问（受众/渠道/账号）→ **本轮反转**：三问全部 **[AI DOES]** 推断，仅「目的」与「是否已有账号/产品/愿露脸」等 USER FACT 才 **[CEO CONFIRMS]**（且可全跳过）。原 A02 的「主要面向谁/主要在哪发」改为 AI 直接给建议，不提问。
- A03 补 Source（原让用户粘 5 URL）→ **[CEO DOES]→反转 [AI DOES]**：AI 自动发现初始 Source 池（主题+对标+公开搜索），用户零输入即可起步；仅「重点看这个/别看那个」属自然语言快捷（B01），非必经。
- A04 团队就位 → **[AI DOES]**，CEO 只见「团队已就位」结果卡，不展示「建立了 4 个员工」。
- A05 离开系统继续 → **[AI DOES]**（Runtime 后台）。
- A06 首次 Opportunity 通知 → **[AI DOES]** 聚类+通知，CEO 看压缩投影。
- A07 定位/关键词/对标建议 → **本轮反转 [AI DOES]+[CEO CONFIRMS]**：AI 已填好 growth_context；CEO 只见「我们建议这样定位」结果卡，点「采用/调整/讨论」，不出现空白字段待填。
- A08 推荐 3 选题 → **[AI DOES]**，CEO 看 3 张卡。

### 5.2 Source（Round 2 Journey B / Doc 5）
- B01–B05 对话中粘 URL/批量/失效/重授权 → **保留为自然语言快捷 [CEO DOES 轻量说]**（「重点看这个」「别看这个」「以后关注这个网站」），AI 完成识别/分类/优先级/监控策略/失效处理。
- B06–B07 专业 Source 管理区 → **[EXPERT ONLY]**：降级为 Employee Working Area，CEO 默认不可见；高级用户主动进才显示底层字段。

### 5.3 Topic（Round 2 Journey C）
- C01 点 Topic 看详情 → **[CEO CONFIRMS]** 看推荐理由+价值。
- C02 先调研 → **[CEO CONFIRMS]** 点一下；Research 全 **[AI DOES]**。
- C03 补 Source → 自然语言 **[CEO DOES 轻量说]**，AI 入 Scope。
- C04 进行中离开 → **[AI DOES]**。
- C05 完成通知 → **[AI DOES]** 通知，CEO 看结论。
- C06 不同意补查 → **[CEO DOES 说一句]**「这个结论我不同意」→ AI 续接同一 Work。
- C07 就做这个 → **[CEO CONFIRMS]** 点一下；Brief 全 **[AI DOES]**。

### 5.4 Research（Round 2 §5）
- Scope/来源/多源比对/置信度/Unknown → **[AI DOES]**（专业 Working View）。
- CEO 默认只看 结论/业务意义/价值/风险/未知/推荐/依据入口 → **[CEO CONFIRMS]** 接受或说一句补查。

### 5.5 Content（Round 2 Doc 3）
- B01 就做这个 → **[CEO CONFIRMS]**；Brief **[AI DOES]** 生成。
- B03 编辑 Brief（原让用户填字段）→ **本轮反转 [AI DOES]**：默认 AI 产 Brief，CEO 看成品；深度改 Brief 降 **[EXPERT ONLY]**。
- D01 生成草稿 → **[AI DOES]** 出 1–3 版，默认推荐版；CEO 见推荐成品。
- E01/E02 直接改/说话改 → **保留为可选 [CEO DOES 轻量说]**（「第二段更口语」），但**非默认路径**；默认 CEO 直接看推荐版。
- D03/E03 比稿/选版本（原让用户并排比稿选）→ **本轮反转 [AI DOES]**：AI 推荐推荐版并标「备选」；CEO 看推荐版+备选摘要，深度比稿降 **[EXPERT ONLY]**。
- A01/A02/A03 素材（原让用户选生成几版/上传/库选）→ **本轮反转 [AI DOES]**：AI 生成并选封面/配图，CEO 看结果；深度素材库管理降 **[EXPERT ONLY]**。
- R01/R02 审核（原让用户看五项/点一键修改）→ **[AI DOES]**：AI 自检五项并自动修复，仅把「已通过/需你知情的风险」告诉 CEO；CEO 不逐条处理。

### 5.6 Channel（Round 2 Journey E / Doc 4）
- E01 连 Channel → **[D EXTERNAL AUTHORIZATION]** 点一次 OAuth；AI 建 Channel 对象。
- E02 加账号+命名+定位（原让用户命名/配 Audience/Tone）→ **本轮反转 [AI DOES]+[CEO CONFIRMS]**：AI 读账号历史→分析→建议命名→建议定位→建议角色→建议默认；CEO 只见「我们分析了这个账号，建议这样用」+[采用/调整/讨论]，不出现空白命名框与定位下拉。
- STEP 07 设默认账号 → **[AI DOES]** 推荐默认并随表现自调；CEO 不手动设。

### 5.7 Account（同上，矩阵）
- 8 账号矩阵（XHS 3 / Douyin 2 / TikTok 2 / YouTube 1 / Bilibili 1）→ **[AI DOES]** 逐个分析+建议命名/定位/角色/默认；CEO 全程只见每账号「建议这样用」卡，可逐张 采用/调整/讨论。
- 日常切账号 → **[AI DOES]** 按内容定位 Context filter 推荐，CEO 不记忆账号。

### 5.8 Publishing（Round 2 Journey F / Doc 4）
- F01 发布目标树（原让用户勾 Channel→Account）→ **本轮反转 [AI DOES]+[CEO CONFIRMS]**：AI 根据 内容+Channel Strategy+Account Positioning+历史表现+Eligibility+Distribution Policy 推荐「发哪些平台/哪些账号/何时/如何适配」；CEO 见建议卡：
  > 「建议发布到：小红书主号 + 抖音主号，预计今天 20:00 / 21:00」
  > **[确认发布] / [调整] / [讨论]**
  不先甩完整 Channel→Account 树给小白。
- 逐账号 Variant / 9 态 → **[AI DOES]**；Human-in-the-loop 确认 **[CEO CONFIRMS]**（不可逆外部动作）。
- 时间精调/覆盖发布/不匹配放行 → **[EXPERT ONLY]**。
- 失败/驳回/重授权 → **[AI DOES]** 自动修复或提示；CEO 看 per-Account 独立真相（不伪造整体成功）。

### 5.9 Evaluation / Next Cycle（Round 2 Journey G）
- G01 数据/反馈回来 → **[AI DOES]** 归集归一化、Evaluation（什么有效+为什么+建议）。
- G02 第二天 → CEO 看「上周评估：收藏率↑12%，建议继续并扩抖音」+[按建议继续/讨论/暂缓] → **[CEO CONFIRMS]** 点一下，AI 自动起下一轮。

## 6. DAILY CEO（极简，重新模拟）

用户第二天打开 Content Growth：

- 进入即**经营驾驶舱**（默认 Main），无 Signal 池 / 无选题库 / 无 Analytics 仪表盘。
- 典型日只看到：
  - **③需关注变化**：「OpenAI 新动态，3 源提及」（点开看依据）
  - **①结果**：「上周内容评估：收藏率↑12%，建议扩抖音」
  - **⑤在途**：「GPT-5.6 选题研究中 / 抖音主号平台审核中」
  - **⑧推荐**：「下一周期已启动：3 个新选题 👇」
- **用户不需要知道**：Signal / Opportunity / Research Scope / Variant / Publication 状态机 / Channel Account Binding。
- **用户只需知道**：今天发生了什么？员工做出了什么结果？什么值得关注？为什么？建议怎么办？有没有需要我决定的事？
- **无重要事项时**：页面非常安静（仅一句「一切正常，监控中」），不制造噪音。
- 每日决策 < 3 次；无 Gate 时「按建议继续」即可。

## 7. QUICK PATH（仍最简单）

「帮我写一篇 GPT-5.6 小红书笔记。」

- 一句话 → AI 直接出成稿（**AUTO**，不进选题池/不建 Research/不弹设置）。
- 必要时一句修改（「标题换个更抓的」→ AI 改）。
- AI 给**发布建议**（不是账号树）：「建议发到小红书主号，预计现在发」→ 一次确认。
- 专业系统不污染 Quick Path：不要求选题/Research/选员工/配流程/选账号矩阵。
- 若 AI 判断「值得先调研」→ 仅轻提示「这个主题值得先查一下，预计能提升准确性」，给「继续调研/直接生成/讨论」三选一，不强制。

## 8. FINAL REAL USER TEST（仅靠文字完整模拟 · 贴链接叙事）

> 逐段标 CEO 行为 = 说 / 看 / 确认 / 调整 / 讨论。验证全程无「配置/填表/选专业参数/管后台/维护池/设规则」。

**「我想做 AI 科技内容，主要想涨粉，以后接广告。我很喜欢这个账号（贴链接），想做这种感觉。」**
→ **[说]** 表达意图+目的+贴 Reference。AI 识别链接（A），读该账号历史：内容类型=新模型实测、受众=科技从业者、表达=第一手口语、更新=周更、增长=靠搜索红利、商业化=接广告。（A）结合用户目标合成方案。（B）CEO 看到：
> 「我们建议你这样做：定位=AI 科技从业者视角的实用测评；主发小红书+抖音；调性=可信+前瞻；前 3 周做『新模型实测』系列。预计 6–8 周起量，接广告路径清晰。风险：同质化，用第一手实测拉开。下一步：我先帮你盯 OpenAI/Anthropic 并推荐选题。」
按钮：**按建议开始 / 调整 / 讨论**。

**→ 用户点「按建议开始」[确认]**
→ AI 后台自动落 Office growth_context（定位/受众/调性/关键词/Source/对标全由 AI 填），启动 `intel-scan` + `positioning-analysis`（A）。CEO 只见「团队已就位，正在分析这个参考账号并监控相关动态 ✅」。

**信息搜集（后台，CEO 不看）**
→ 王颖分析参考账号 + 公开搜索发现对标 + 派生关键词 + 建初始 Source 池（A）。无用户填表。

**推荐选题**
→ 数小时后/次日，驾驶舱③出现 Signal「OpenAI 新模型传闻，3 源提及」；①出现「推荐 3 个选题 👇」（A）。CEO **[看]** 3 张卡。

**调研**
→ CEO 点一张「先调研」**[确认]**；王颖建 Research Work 多源比对（A）。进行中 CEO 可离开；回来见「调研完成 ✅ 值得做」结果卡（A 通知）。CEO **[看]** 结论（价值/风险/未知/建议）。

**内容**
→ CEO 点「就做这个」**[确认]**；李想建 Intent+Brief+生成 1–3 版 Draft，默认推荐版（A）。CEO **[看]** 推荐成品。

**修改两次 + 恢复一次旧版本**
→ CEO 对内容说「第二段更口语」「标题换 3 个」**[说]**；李想 Patch 出 v1.1/v1.2（A，保留 v1 可回滚）。CEO 说「还是用早一点的」→ 李想恢复上一保留版（A）。**全程 CEO 只说话，不进版本管理器。**

**又生成封面**
→ 李想判断需封面，自动生成 2 版并选 1（A）。CEO **[看]** 结果；如需换可说一句（**[说]**）。

**选择 XHS 主号和抖音主号发布（CEO 视角反转）**
→ 内容标可发布，CEO 点「发布」**[确认]**；**不出现账号树**。陈帆按内容+策略+历史+Eligibility 推荐：「建议发布到：小红书主号 + 抖音主号，预计今天 20:00 / 21:00」**[看]**。CEO 点「确认发布」**[确认]**（Human-in-the-loop）。

**抖音账号授权过期**
→ 抖音主号 `authorization_state=Expired`，标红（A，Frozen `OAUTH_FAILURE_KEEPS_ACCOUNT`）。陈帆提示「抖音主号待授权，其余可先发」；XHS 主号正常发。

**重新授权**
→ 建议卡给「重新授权」入口，CEO 点一次 OAuth **[D EXTERNAL AUTHORIZATION]**；账号恢复 Connected，自动解除暂停（A）。

**小红书发布成功，抖音进入平台审核**
→ XHS 主号 Publication=Published（真实 URL 回填，A）；抖音主号=Platform Reviewing（A）。CEO 看 per-Account 独立状态：「部分完成——成功 1 / 审核中 1」（不伪造整体成功，Frozen `PUBLICATION_PER_ACCOUNT_TRUTH`）。

**第二天数据回来**
→ 周明做 Evaluation（A）：「收藏率↑12%，因 GPT-5.6 切中搜索红利；建议继续并扩抖音」。CEO **[看]** 结果卡「上周评估：收藏率↑12%，建议继续并扩抖音」+[按建议继续/讨论/暂缓]。

**点击继续，下一周期开始**
→ CEO 点「按建议继续」**[确认]**；AI 自动起下一轮（新 Topic/Research，A），驾驶舱⑧出现新选题。
