# CONTENT GROWTH — CEO DAILY SIMULATION

Status: **RESEARCH / EXPERT RECOMMENDATION**（非 Frozen，非 Authority 修改）

Companion: `CONTENT_GROWTH_CEO_OPERATING_STATE_MODEL.md`（8 态 S1–S8 / 信息合同 / 优先级 / 生命周期 / 注意力）

## 0. 纪律与口径

- 本文件是 Doc 1 的**实证**：用同一位「小白 CEO」（做 AI 科技内容 / 涨粉后接广告 / 喜欢某账号）连续 5 天，验证 8 态模型在真实经营流中如何表现。
- 全部对象 / 团队 / Frozen 不变量沿用 Doc 1 §0。状态标记严格用 **S1 QUIET / S2 RESULT / S3 WATCH / S4 DECISION / S5 IN_PROGRESS / S6 READY / S7 ACTION_REQUIRED / S8 ALERT**。
- 每条日模拟回答：第一眼看到什么 / 第二个看到什么 / 哪些完全不显示 / 用户做几个动作 / 处理后页面如何安静。
- 目标：每天 CEO 操作 ≤ 3 次；无重要事项时页面安静（S1）。

## 1. DAY 1 — 刚建立 Content Growth

> 语境：CEO 上午说「我想做 AI 科技内容，主要涨粉，以后接广告。我喜欢这个账号（贴链接）。」点「按建议开始」。下午/晚上第一次回来。

### 1.1 建立时（上午，已发生在前置 Round 3 §8，此处只接状态）

- 王颖识别链接 → 读历史 → 合成方案（B 建议卡）→ CEO 点「按建议开始」→ 后台落 Office growth_context（全 AI 填）。**此处不展开**（前置已证）。
- 团队组建（王颖/李想/陈帆/周明）后台完成，CEO **不**见「建立了 4 个员工」。

### 1.2 第一眼看到（下午打开）

| 项 | 状态 | 内容 |
|---|---|---|
| 顶部 | **S2 RESULT** | 「团队已就位，正在分析你喜欢的账号并监控相关动态 ✅」 |
| 底部 | **S1 QUIET** | 「目前没有需要你处理的事情。监控中：参考账号 1 · 自动发现源 8 · 对标 5」 |

- **第二个看到**：无第二项（S1 独占，页面安静）。
- **完全不显示**：Signal 池、选题库、Research Scope、账号矩阵、团队明细、阈值——全部 HIDE（Doc 1 §5）。
- **用户动作数**：0（看一眼即可，系统自己在跑）。
- **处理后如何安静**：本来就是 S1，无动作也不脏。

### 1.3 当天傍晚（员工后台推进）

- 王颖完成对标分析 + 初始 Source 池 + 关键词派生（AUTO，Round 3 §4.1）。这些**不投影**（HIDE，纯内部进度）。
- 若分析产出一条「值得关注」的初步信号（如该对标换了内容方向），可能升 **S3 WATCH**：「你喜欢的账号最近开始做视频实测，值得留意。」——仅一条低调条目，**不**弹通知（Doc 1 §3.3）。

> **DAY 1 小结**：CEO 动作 0–1 次；页面始终安静；AI 真实在经营（分析/监控），但只在越过阈值时给一条 S2/S3。

## 2. DAY 2 — 机会出现 + 研究进行中

> 语境：次日。王颖监测到 OpenAI 新动态，聚类出 Opportunity，并已对 CEO 昨天点过「先调研」的选题启动 Research。

### 2.1 第一眼看到（按 §6 优先级）

| 顺序 | 状态 | 内容 |
|---|---|---|
| 1（顶） | **S3 WATCH** | 「OpenAI 发布新动态，3 源提及，可能影响你的选题方向。」[查看依据] |
| 2 | **S5 IN_PROGRESS** | 「GPT-5.6 选题研究中…（王颖，多源比对中）」 |
| 3 | **S2 RESULT** | 「推荐 3 个选题 👇：① GPT-5.6 办公实测 ② 模型横评 ③ 科普长文」[就做这个/先调研] |

- **第二个看到**：S5 进行中（低优先级状态条）。
- **完全不显示**：8 个 Source 的逐条采集记录、Signal 聚类队列、Research 内部步骤、账号矩阵——HIDE。
- **用户动作**：点「推荐 3 选题」展开看理由（1 次查看，非决策）；可选点某选题「先调研」（若昨天未点）。**动作 ≤ 2 次**。
- **想知道「为什么值得」**：点 S3/S2 的「查看依据」→ 下钻研究与洞察 / 信息与机会 Surface（Doc 1 §10），看完「返回经营」Context 不丢。

### 2.2 研究中离开再回（状态连续）

- CEO 点开 S5 后又去别处，30 分钟后回：S5 仍在（或已转 S2 若研究完成）；**不重复通知**，已 SEEN 的 S2/S3 降权保留（Doc 1 §7）。
- 若研究完成：S5 → **S2 RESULT**「调研完成 ✅ GPT-5.6 值得做（切搜索红利，争议已比对）」+ 一次轻 NOTIFY（仅此一次）。

> **DAY 2 小结**：CEO 动作 ≤ 2 次；看到了「机会+进行中+结果」三类，但页面不堆砌；AI 持续经营真实存在且可见其产出。

## 3. DAY 3 — 研究完成 + 内容就绪

> 语境：第三天。昨天点「就做这个」的选题，李想已生成内容并通过审核五项。

### 3.1 第一眼看到

| 顺序 | 状态 | 内容 |
|---|---|---|
| 1 | **S6 READY** | 「内容已准备好：GPT-5.6 小红书笔记（已过品牌/事实/合规/AI标识/渠道规则）。」[查看/发布] |
| 2 | **S2 RESULT** | 「昨日研究结论：GPT-5.6 切中搜索红利，建议做。」（已读降权） |
| 3 | **S5 IN_PROGRESS** | 「抖音主号平台审核中…（昨天发的另一篇）」 |

- **第二个看到**：S2 已读降权项。
- **完全不显示**：3 版 Draft 对比、版本号、素材库、比稿过程、审核五项明细——EXPERT ONLY（Round 3 §5.5），CEO 只看「已通过」。
- **用户动作**：
  1. 点 S6「查看」看成品（1 次）。
  2. 点「发布」→ 转 **S7 ACTION_REQUIRED**（一次确认，见 DAY 4）→ 计 1 次确认。
  - 若对内容说一句「标题换更抓的」→ 李想改（AUTO，非必经），算 1 次轻说。
- **处理后如何安静**：发布确认后 S6→S7→(确认后)S5 发布中；驾驶舱回落到 S5(低优先)+S1。

### 3.2 内容生产的「AI 承担」实证

- CEO **全程未编辑 Brief、未管版本、未选素材、未逐条过审核**（Round 3 §5.5 反转）。李想产成品并自检自修，CEO 只看推荐成品 + 一句可选修改。
- 证明 Doc 1 §3.6：S6 只投影「做好了，满意就发」，复杂度 HIDE。

> **DAY 3 小结**：CEO 动作 ≤ 3 次（查看+发布确认，或 +1 句修改）；内容生产完整但默认不要求 CEO 管理版本/比稿。

## 4. DAY 4 — 发布确认 + 某账号授权失效

> 语境：第四天。CEO 触发发布，抖音主号授权恰在此时过期。

### 4.1 发布会话（点「发布」后）

- CEO 点 S6「发布」→ 陈帆按 内容+策略+历史+Eligibility 推荐（Round 3 §5.8）：**S7 ACTION_REQUIRED** 卡：
  > 「建议发布到：小红书主号 + 抖音主号，预计今天 20:00 / 21:00。确认发布？」
  > **[确认发布] / [调整] / [讨论]**
- CEO 点「确认发布」（**1 次 Human-in-the-loop**，Frozen 红线 D 类）。

### 4.2 授权失效并发（真实连续）

- 系统执行时，抖音主号 `authorization_state=Expired`（Frozen `OAUTH_FAILURE_KEEPS_ACCOUNT`）。
- 陈帆处理：小红书主号正常发 → **S2 RESULT**「小红书主号已发布 ✅（真实 URL 已回填）」；
- 抖音主号 → **S7 ACTION_REQUIRED**「抖音主号授权已过期，点此重新授权（约 10 秒）。其余可先发。」+ 同时该发布标记 **S8 ALERT** 部分失败真相（Frozen `PUBLICATION_PER_ACCOUNT_TRUTH`，不伪造整体成功）。

### 4.3 第一眼看到（DAY 4 打开时）

| 顺序 | 状态 | 内容 |
|---|---|---|
| 1（顶） | **S7 ACTION_REQUIRED** | 「抖音主号授权已过期，点此重新授权。」[重新授权] |
| 2 | **S8 ALERT** | 「部分完成：小红书已发布 ✅，抖音发布失败（待授权）。」 |
| 3 | **S2 RESULT** | 「小红书主号已发布 ✅（URL）」 |

- **第二个看到**：S8 部分完成真相（诚实，不掩盖抖音失败）。
- **完全不显示**：授权令牌、Connector 日志、逐账号精调时间——EXPERT / HIDE。
- **用户动作**：
  1. 点「重新授权」→ OAuth 一次（D 类外部授权，**1 次点击**）→ 账号恢复 Connected，自动解除暂停，抖音重发 → 转 S5。
  2. （可选）点 S2 的 URL 去平台看一眼。
  - **动作 ≤ 2 次**。

### 4.4 处理后如何安静

- 授权完成 + 抖音重发成功后：S7/S8 闭合 → RESOLVED→HISTORY；驾驶舱回落 S5(抖音发布中，低优先) → 不久 S2(发布成功) → 最终 S1。
- 不残留红色、不重复弹窗。

> **DAY 4 小结**：CEO 动作 ≤ 2 次（重授权 + 可选看 URL）；异常(Doc 1 §3.8)诚实呈现 per-account 真相；AI 自动修复可自愈部分，仅阻断性动作交 CEO 一次点击。

## 5. DAY 5 — 数据回来 + 下一周期建议

> 语境：第五天。发布内容数据回流，周明做 Evaluation，并基于结论建议下一周期。

### 5.1 第一眼看到

| 顺序 | 状态 | 内容 |
|---|---|---|
| 1 | **S2 RESULT** | 「上周评估：收藏率↑12%、涨粉 +340。原因：GPT-5.6 切中搜索红利 + 第一手实测调性。建议：继续并扩抖音。」[按建议继续/讨论/暂缓] |
| 2 | **S3 WATCH** | 「抖音主号昨发内容起量，可考虑提频。」（可选） |
| 3 | **S5 IN_PROGRESS** | 「下一周期已启动：3 个新选题研究中…」 |

- **第二个看到**：S3 值得关注（低优先）。
- **完全不显示**：原始指标表、归因模型、跨账号对比、基准线——增长与评估 Surface（EXPERT 才深潜，Doc 1 §10）。
- **用户动作**：
  1. 点 S2「按建议继续」→ 周明自动起下一轮（新 Topic/Research，AUTO）→ 驾驶舱出现新 S5/S2。
  - **动作 1 次**（或点「讨论」了解细节，算 ≤2）。

### 5.2 下一周期自然涌现

- 「按建议继续」后：王颖基于 Accepted Learning（Round 4 §6，≥3 次证据才固化）启动新选题监测 → 数小时后新的 S3/S2 出现（如 DAY 2 循环）。
- 证明：AI 团队**持续经营**是真实闭环，不是一次性；CEO 只在「结果/价值/建议」层消费。

> **DAY 5 小结**：CEO 动作 ≤ 1–2 次；看到了「评估结果+建议+下一周期在途」；一句话即让公司继续转。

## 6. 五天总览（CEO 视角）

| Day | 第一眼顶态 | 用户动作数 | 页面最终 | AI 真实在经营 |
|---|---|---|---|---|
| 1 | S2 团队就位 / S1 安静 | 0–1 | S1 安静 | 分析参考账号+建源+监控 |
| 2 | S3 机会 / S5 研究 / S2 选题 | ≤2 | S1+少量S2/S3 | 监测+聚类+Research |
| 3 | S6 内容就绪 / S2 结论 | ≤3 | S5+S1 | 生成+审核+发布 |
| 4 | S7 重授权 / S8 部分失败 | ≤2 | S5→S1 | 发布+自愈+重发 |
| 5 | S2 评估建议 / S5 下一周期 | ≤2 | S5→循环 | Evaluation+起新轮 |

**结论**：五天 CEO 日均动作 < 3 次；无重要事项日（DAY 1 傍晚后）页面安静（S1）；AI 员工持续经营真实存在且可见其产出；需判断时（DAY 4 重授权、DAY 5 按建议继续）能判断；不需时页面安静；专业复杂度（Signal/Research Scope/版本/素材/指标原始值）全程按需下钻，不默认暴露。

## 7. QUICK PATH 交叉校验（DAY 3 中途插入）

DAY 3 上午，CEO 突然说：「帮我写篇 GPT-5.6 小红书。」

- **不进 Operating State 流程**：不走 S2/S3/S6 选题池（Doc 1 §12）。
- 走 `Conversation → 成稿(李想 AUTO) → 一句修改(可选) → 发布建议(S7 一次确认)`。
- 成稿完成后**自然进经营历史(HISTORY)**，但**不弹** S2/S3 卡、不要求进驾驶舱——Quick Path 与 8 态模型正交，互不污染。
- 证明：即便系统已有完整 Source/Topic/Research/Account/Publishing 能力，一句话仍最简（Round 3 §7 / Round 2 Journey H）。
