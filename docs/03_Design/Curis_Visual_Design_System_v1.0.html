Curis Visual Design System

CEO 工作空间
的视觉语法

为 Curis 一人 AI 公司系统制定的可执行视觉系统。以 Codex 式深灰和主题相关的 CEO 主动作为基底， 适配 CEO 专属办公室与 AI 员工协作空间。安静、有主序、证据优先。

01

设计原则

Curis 不是 Dashboard，也不是聊天应用。它是 CEO 与 AI 团队共同经营一家公司的空间。

CEO 优先

每个屏幕先回答“CEO 现在该知道什么、该做什么”，再呈现细节。避免把系统内部状态直接铺成面板。

状态先于动作

先让 CEO 看清当前经营状态、证据与风险，再给出动作。没有状态的动作是噪音。

证据驱动

所有判断必须能追溯到外部结果、AI 产出或 CEO 决策。 decorative 图表和空指标不被接受。

AI 即员工

AI 以岗位、责任、容量和交接出现，不是消息气泡列表。每条 AI 输出都绑定 Owner 与下一步。

Workspace 即房间

Workspace 是具体业务的真实办公空间，不是通用任务列表。不同业务可以拥有不同布局与工具。

安静但警觉

界面保持低对比、单色表面，只在需要 CEO 注意的地方使用强调色与语义色。

视觉禁用项

正确做法

使用中性表面、单一绿色强调、低对比边界、留白分隔区域；状态用小型标签或边线表达。

禁止做法

紫色渐变、白色背景上的多彩卡片、霓虹背景、纯黑画布、夸张仪表盘、游戏化积分。

02

设计令牌

所有视觉决策收敛为可复用令牌。组件、页面和 Workspace 都必须引用这些变量，禁止页面私有色板。

颜色：语义映射到 Curis 概念

深色主题以深灰表面和品牌绿为主动作；浅色主题以白色表面和深色主按钮为主动作。绿色仍可作为 AI 就绪与正向信号，蓝色只代表决策与信息；语义色只用于需要警觉的状态。

主题动作映射：深色主题主按钮使用 #32f08c，hover 使用 #0fdc78，文字使用 #0c0c0d；浅色主题主按钮沿用深色 #30333a，hover 使用 #17181a，文字使用 #ffffff。不要把成功色或状态色替代主按钮。

间距、圆角、阴影与层级

间距

4 · 6 · 8 · 12 · 16 · 24 · 32 · 40

组件内部用 8/12，卡片之间用 16，页面区块之间用 32/40。

圆角

2 · 4 · 6 · 8 · 10 · 9999px

按钮/输入框 6px，卡片 8px，弹窗/抽屉 10px，头像/标签 9999px。

阴影

避免大面积投影。抽屉/弹窗使用 shadow-lg/xl；hover 使用细微 overlay 变化。

层级

使用 overlay-l1 ~ l4 表达悬停、选中、激活状态，不额外加深背景色。

04

组件

组件是经营语义的可复用载体。每个组件必须同时携带默认、hover、focus、禁用、加载和错误状态。

05

页面级 UI 语法

每个页面都是 CEO 经营路径上的一个阶段，不是独立 Dashboard。

CEO Desk / 每日入口

上半屏 · Assistant Brief

“早上好，昨天有 3 个变化”。按必须决定 / 建议关注 / 已由团队处理分组。每项可展开来源、置信度、影响和推荐动作。

上半屏 · Company Pulse

六个状态点：价值、执行、供给、风险、方向、连续性。状态为 On Track / Attention / At Risk / Blocked / Unknown / Stale / Conflict，没有虚假总分。

下半屏 · Matters

三类事项卡：Decision（蓝色边线）、Exception（琥珀边线）、Opportunity（绿色边线）。底部只有 CEO 动作：决定、调查、委派、召集、等待、静默。

下半屏 · Timeline / Handoffs

今日会议、AI 交接、Workspace 检查点和结果回报。每条交接显示承担者、当前阶段、预计回报时间和查看证据。

AI Organization Control Panel

组织地图

CEO → Assistant → 专业 AI / 部门。每个节点显示负责结果、当前承诺数、容量、质量、成本和最近证据。

责任矩阵

Outcome × AI 员工的二维视图。明确谁对什么结果负责，谁提供输入，谁验收输出。

升级队列

越权、失败、阻塞和待 CEO 确认的 AI 请求。每条记录显示原因、建议解法和回滚路径。

Workspace Studio

三栏布局

左侧业务结构（Outcome、Stages、Roles、Agents、Tools、Knowledge）；中央 Blueprint Canvas；右侧配置检查与模拟。

Blueprint Canvas

节点表示业务阶段，连线表示输入输出关系。每个节点显示 Owner / Input / Output / 成功与失败出口。

运行模拟台

运行正常、Agent 缺席、工具失败、外部延迟、证据冲突、CEO 拒绝六类场景。未通过检查不能提交 CEO 审批。

06

图标与图像

图标是语义的速记，不是装饰。图像必须服务于 CEO 理解公司经营状态。

图标风格

使用 1.5px 线框图标，圆角端点，16px / 20px / 24px 三档。默认颜色 icon-secondary，hover / active 升至 icon-default，品牌动作使用 icon-brand。

图像使用

避免 stock photo 和 generic 3D 插图。必要时使用：办公室空间示意图、AI 员工头像、业务证据截图、外部数据图表。

AI 员工头像

使用单色几何形状 + 首字母，不采用拟人化照片。CEO 头像可上传照片，AI 员工保持抽象身份标识。

数据可视化

只允许在 Workspace 运行台使用趋势图，且必须关联真实外部结果。禁止装饰性仪表盘和无来源的数字墙。

07

动态与微交互

动画必须有意义：引导注意力、确认状态变化、减少认知负荷。禁止为了“科技感”而炫动。

场景时长缓动目的
按钮 hover150msease确认可点击，反馈响应
抽屉滑入250mscubic-bezier(0.16, 1, 0.3, 1)自然出现，不抢夺焦点
弹窗打开200mscubic-bezier(0.16, 1, 0.3, 1)强调决策上下文
状态变化200msease-out让 CEO 注意到状态迁移
骨架屏循环 1.2sease-in-out等待真实数据，不用假内容
滚动揭示300msease-out长列表分段进入，但不过度
正确做法

使用 subtle 的位移、透明度和缩放变化；状态变化伴随颜色迁移；减少跳动和闪烁。

禁止做法

霓虹脉冲、无限循环的 decorative 动画、页面整体视差、AI 打字机效果的过度使用。

08

无障碍要求

CEO 可能在任何时间、任何状态下使用 Curis。界面必须可感知、可操作、可理解、可兼容。

色彩

状态不能仅依赖颜色，必须同时提供文字标签或图标。关键信息对比度不低于 4.5:1，大号文字和 UI 组件不低于 3:1。

键盘

所有交互元素可通过 Tab 到达，焦点顺序符合视觉顺序。Modal 和 Drawer 打开时焦点陷阱，关闭后回到触发点。

屏幕阅读器

按钮和链接有明确标签，图标按钮提供 aria-label，动态更新使用 aria-live 区域，表格使用正确的 th/scope。

动画

尊重 prefers-reduced-motion。在 CEO 设置中提供减少动画选项。

09

设计验收标准

视觉系统只有在产品流程中走通才算完成。漂亮页面不能替代经营闭环。

设计师验收

检查项标准
令牌一致性所有屏幕只使用本系统定义的 color / type / space / radius / shadow 令牌，无页面私有色板。
CEO 路径能从 Welcome → Founding Brief → Company Design → First Business → AI Team → Launch Check → CEO Desk 走通，不依赖口头解释。
状态完整性每个关键组件都设计了 Empty / Loading / Error / Disabled / Focus / Hover 状态。
视觉禁用项无紫色渐变、白色背景多彩卡片、纯黑背景、装饰性仪表盘、游戏化元素。

开发者验收

检查项标准
CSS 变量使用本文件定义的 CSS 自定义属性，禁止硬编码十六进制色值。
组件复用优先使用已有 Button / Card / Table / Drawer / Modal / Input 原语，不创建页面私有组件。
响应式1280px 以上完整桌面，1024px~1279px 紧凑，1024px 以下抽屉导航。
无障碍通过键盘 Tab 走通主要流程，焦点可见，状态标签不依赖颜色。

产品团队验收

检查项标准
经营语义每个按钮、标签、状态都对应真实经营动作或状态，不是系统内部字段。
证据链CEO 能从任何状态追溯到证据、Owner 和下一步。
AI 员工存在感AI 以员工身份出现，有岗位、容量、责任和交接，不只是聊天记录。
Workspace 差异化不同业务 Workspace 在保留统一身份与导航的前提下，允许不同布局和组件。

最终验收路径

END-TO-END CHECK

表达意图 → 创建公司 → 配置第一条业务 → 批准 AI 团队 → 启动 Workspace → 查看外部结果 → 做出决策 → 回到下一天

如果新 CEO 能在无产品经理解释的情况下走完这条路径，视觉系统才算通过。
