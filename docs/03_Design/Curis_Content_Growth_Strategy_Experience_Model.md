# 1. 总览：用户如何理解「这块业务现在的经营方法」

策略体验分三层，用户**自上而下自然下钻**，不是被迫读配置：

```
Business Home（全局：公司今天怎么经营）
   └─ 当前经营节奏（轻量入口：今天怎么运行）
   └─ 经营方向 Strategy Experience（这块业务：为什么存在 / 重点 / Mix / 平台 / 节奏 / 最近学）
        └─ 账号 Strategy Experience（这个账号：目标 / 定位 / 阶段 / 偏好 / 时间 / 表现 / 学到的）
```

三层都用**自然语言 + 渐进披露**，绝不做成「经营方向配置 / 账号配置 / 平台配置」三棵设置树。

# 2. 重新审视 Business Home（Brief §2）

## 2.1 当前 Home 已有模块（保留）

Needs CEO · 当前经营节奏 · 今天值得做 · 正在生产 · 自动发布 · 账号动态 · AI 在做什么 · 增长反馈。

## 2.2 结合运营 Handoff 重新判断信息架构

Handoff §4 要求 Home 看见 9 项经营层信息。但**不再简单堆 5 个新模块**——重新设计为 CEO 每天早上打开后 **5–10 秒读懂**的 8 个问题优先级：

| 优先级 | 用户 5–10 秒要知道 | 对应模块（自然命名） | 来源（Handoff） |
|---|---|---|---|
| 1 | 有没有真正需要我决定的事 | **需要我决定**（仅重大事项 P7） | Needs CEO |
| 2 | 公司今天按什么策略运行 | **当前经营节奏**（轻量入口） | Operating Rules |
| 3 | 有什么重要机会 | **今天值得做**（机会面，非审批队列） | Intelligence / Topic |
| 4 | AI 已经自动做了什么 | **正在生产 / 即将自动发布** | Execution |
| 5 | 有什么异常 | **账号动态**（OAuth/限流/平台变动高亮） | Feedback / 异常 |
| 6 | 最近用户在反馈什么 | **大家最近在问什么**（社区信号轻量） | Audience |
| 7 | AI 最近学到了什么 | **最近学到了什么**（轻量增量） | Learning |
| 8 | 有没有值得改变经营策略的建议 | **策略建议 / 观察中**（区分于 Needs CEO） | Strategy Evolution |

> **重心变化**：在原有 Home 基础上，把 Handoff 的「当前经营目标 / 重要平台机会 / 重要用户信号 / 当前策略提案 / 最近学到了什么」**吸收进既有模块**，而非新增 5 个等大卡片：
> - 「当前经营目标」→ 并入「当前经营节奏」入口的常驻一行（见 §3）。
> - 「重要平台机会 / 用户信号」→ 并入「今天值得做」「大家最近在问什么」。
> - 「当前策略提案 / 最近学到了什么」→ 见 Doc 4（Strategy Evolution），在 Home 以低存在感条目出现，不抢 Decision/Attention。

## 2.3 视觉优先级纪律（沿用 Spec §3.1）

Decision Banner（最突出）> Attention 高亮卡 > 普通活动行。**不要**把 8 项机械做成 8 个等大 Dashboard 模块。

# 3. 「当前经营节奏」升级为真正经营入口（Brief §3）

## 3.1 命名与定位

当前 Wireframe 只显示「每天收集几次 / 准备几条 / 几点自动发布」。运营 Handoff §2(E) 明确 **Operating Rules 只是 Strategy 的执行层**。

重新定位这个入口——它是用户理解「我们为什么这样经营」的**渐进披露主入口**，不只是节奏表：

- 候选用户语言：`经营策略` / `经营方式` / `当前策略` / `运营计划`。
- **推荐默认命名：`经营方式`**（最口语、最不「设置感」；承载「为什么这样经营 + 今天怎么运行」）。

## 3.2 渐进披露（不一次展示所有内容）

```
[ 经营方式 ]（Home 顶部轻量入口，常驻一行）
   今天怎么运行：收集 3 轮 · 计划 2 条 · 抖音 20:30 / 小红书 20:00 自动发布
   [ 查看经营方式 → ]

点开 → 经营方式面板（第一层，摘要）
   · 为什么这样经营（一句话：目标驱动 + 当前重点）
   · 当前重点（最近重点做什么）
   · 今天怎么运行（扫描 / 生产 / 发布）
   · 哪些账号有自己的特殊规则（列表，可各点开）
   · 最近 AI 调整过什么（留痕，可查看）
   · 策略建议（轻量，见 Doc 4）
   [ 调整经营方式 ]（进入对话或直接编辑）

再下钻 → 单账号特殊规则 / 某次 AI 调整的依据 Evidence
```

> 每一层都**只露摘要 + 下钻入口**，避免一次性信息洪流。这与 Handoff §5「用户能查看某员工现在怎么工作」的渐进披露一致。

## 3.3 经营方式 = 聚合入口，不是万能策略中心（DELTA T1）

「经营方式」只是**当前这块业务如何经营的 SUMMARY / ENTRY SURFACE**，**它不拥有全部策略**。

真实策略继续分别归属各自的归属主体：

| 变化发生在哪 | 真实归属主体 | 例子 |
|---|---|---|
| 「以后每天也看看这个网站」 | 信息收集 **Employee Method** | 改的是信息收集员工的来源组合 |
| 「以后小红书晚上 9 点发」 | 该 **Account / 平台运营**对应的发布规则 | 改的是账号级 Operating Rule |
| 「这个月教程多一点」 | **经营方向 / 账号**的临时内容策略 | 改的是内容策略（临时 Operating Rule） |
| 平台能力 / 限制 | **Platform Facts** | 四态消费，不写死数字 |

因此「经营方式」页面**只聚合展示**上述各主体的当前状态与最近变化，并提供**下钻入口**到对应主体（方向 / 账号 / 员工方式 / 规则）；**不演化成巨大的 Strategy Settings Center**。

> 一句话：**经营方式负责「让人一眼看懂现在怎么经营 + 顺手能改」；真正的策略数据始终住在它们本来该在的地方。**

# 4. 经营方向 Strategy Experience（Brief §4）

用户进入一个经营方向后，看到的是「这块业务现在的经营方法」，**不展示内部 Policy 对象**。

| 区块 | 用户语言 | 内容 |
|---|---|---|
| 目标 | 这个方向为什么存在 | 主/次目标（首启问的 Goal 落点）；一句话定位 |
| 当前重点 | 最近重点做什么 | 近期主题 / 系列栏目 |
| 内容策略 | 大致内容构成 | Content Mix 方向（如「教程类偏多」），**比例可视化不写死数字**，随数据演化 |
| 平台组合 | 哪些平台/账号参与 | 参与账号列表（用户面「账号」，非 Target Account Set） |
| 经营节奏 | 信息收集 / 内容生产 / 发布 | 引用「经营方式」入口的同源数据 |
| 最近学习 | AI 最近发现了什么规律 | 轻量「最近学到了什么」条目（见 Doc 4 §12） |

> 目标感：CEO 看完应觉得「这是这块业务现在的经营方法」，而不是「我在填一个策略配置表单」。

# 5. 账号 Strategy Experience（Brief §5）

同一经营方向下不同账号可以不同。点某个账号后，用户自然理解：

| 维度 | 用户语言 | 注意 |
|---|---|---|
| 主要目标 | 这个账号主要想做到什么 | 可继承方向，也可单独 |
| 定位 | 它在这平台上是什么角色 | 口语定位，非内部策略对象 |
| 当前阶段 | 现在处在哪个阶段 | 冷启动 / 增长 / 稳定 / 转化（用户语言阶段标签） |
| 内容偏好 | 它喜欢什么形式 | 形式偏好，非加权公式 |
| 发布时间/频率 | 一般什么时候发 | **区分两种建议来源**（见下） |
| 平台特殊要求 | 这个平台有什么特别 | 引用 Platform Facts 四态，不写死数字 |
| 最近表现 | 最近怎么样 | 轻量指标，跟目标挂钩，不默认播放量=成功 |
| AI 学到的账号规律 | 这个账号自己的规律 | **必须区分**（见下） |

## 5.1 平台通用建议 vs 本账号学到的建议（关键区分）

用户必须能分清两类建议的来源：

- **平台通用建议**：行业经验初版（如「这类内容通常晚上发效果更好」），标注「行业经验」。
- **本账号学到的建议**：根据**这个账号自己的历史数据**学出的（如「你这个号周二晚收藏率更高」），标注「你的账号数据 · 证据强度」。

> 绝不要把研究的固定时间（晚 8 点 / 日更 3 条）写成默认真理；默认呈现标注置信来源，随本账号数据演化（Handoff §10）。

# 6. Topic / Opportunity Experience（Brief §9）

「今天值得做」继续保留（已 APPROVED CANDIDATE），但运营研究加入了更多来源（平台活动 / 政策变化 / 热点 / 搜索趋势 / 用户评论 / 对标账号 / 产品更新 / 内部资料）。

机会卡需能解释（**不展示内部 w1–w8 评分公式**）：

- **为什么值得做**：自然语言 + 信号，非评分
- **来自哪里**：哪个来源 / 哪个用户问题（溯源）
- **服务哪个经营目标**：对齐 Goal
- **适合哪些账号**：自然语言推荐，非机械勾选
- **时效性如何**：如「平台活动本周末结束」轻量标注

> 机会面 = Opportunity Surface，**不是 CEO 审批队列**（对齐 I1-B）。

# 7. Audience / Community Experience（Brief §10）

闭环必须可见：`评论 → User Signal → 用户洞察 → Content Opportunity`。评论区**不只是自动回复工具**。

在不同界面出现到**不同深度**：

| 界面 | 社区出现程度 | 示例 |
|---|---|---|
| Business Home | 极轻量 | 「大家最近最常问什么」Top 1–2 问题条 |
| Employee Method（社区员工） | 中 | 「最近高频问题 / 正在增长的需求 / 已变成下一条内容的问题」 |
| Content Journey | 轻量 | 某条内容下方「这个选题来自用户评论中的高频问题」溯源 |
| Utility（数据看板） | 深 | 需求趋势图、问题→内容闭环列表 |

用户至少能看到：**大家最近最常问什么 / 哪些需求正在增长 / 哪些问题已经变成下一条内容**。

# 8. First-Run 重新检查（Brief §15）

方向 KEEP：连接账号 → AI 建议分组 → 推荐默认经营节奏 → 就这样开始。

运营 Handoff 加入 Goal，重新判断首启是否增加**一个非常轻量**的问题：

> **「你最希望这个账号帮你做到什么？」**
> 候选（自然语言，单选 + 其他）：`涨粉` / `获得客户` / `推广产品` / `建立个人影响力` / `做品牌` / `其他`

**比较三方案（给推荐）**：

| 方案 | 评价 | 推荐度 |
|---|---|---|
| 完全不问 Goal | 最快，但 Curis 只能从账号历史猜目标，初期策略漂移 | 不推荐 |
| **只问一个 Goal** | 最小摩擦，目标驱动所有下游（Handoff §1：目标驱动而非播放量）；其余 Content Mix/Source/时间/指标由 Curis 给初始建议后逐渐学习 | **推荐** |
| AI 根据账号历史推荐 Goal | 体验更顺，但首启需账号已有数据；新账号无历史时退化成「只问一个 Goal」 | 可选增强 |

> 首启**不一次问** Content Mix / Source Portfolio / 发布时间 / 指标 / 员工方法——这些由 Curis 给初始建议，之后逐渐学习（I4.8 不复杂化）。
