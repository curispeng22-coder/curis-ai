# 1. 为什么 INFORMATION RADAR 是经营的第一性能力

一个专业内容团队不是「想到什么发什么」，而是**持续比对手更早、更准地发现机会**。但情报系统有两个失败极端：

- **全网无限搜索**：噪声大、Token 消耗高、准确率下降、无业务边界。
- **只看某平台热榜**：来源过窄、形成信息茧房、错过政策/竞品/用户侧信号。

正确做法是建设一个**有边界、有结构、会自我优化的 Source Portfolio（信息源组合）**。

# 2. 候选信息源分类（每类为什么值得看）

| 私信 | 自己账号私信 | 高意图用户需求、潜在客户 | 每日 | 意图分类、转化信号 |

# 3. Source Portfolio 的长期结构

一个「信息收集员工」应维护的不是一个扁平列表，而是**分层组合**：

- **官方源（权威层）**：平台官方、公司博客——低噪声、高置信，必须常驻。
- **行业媒体层**：广覆盖、中等噪声，每日轻量。
- **垂直网站层**：深度、早期，按主题低频。
- **平台热点层**：高频、强时效，但需「上升期 vs 爆发期」判别。
- **对标/竞品层**：借鉴与差异化。
- **用户信号层**：评论/私信/社群——最高业务价值，直接进选题与洞察。
- **内部资料层**：素材复用。
- **临时观察源**：活动期/项目期短期加入，结束后评估去留。

每类源应有独立扫描节奏，避免「一刀切天天全扫」。

# 4. 每个 Source 应维护的治理属性（运营方法，非字段）

研究层面，每个来源应被长期跟踪这些维度（产品再决定如何存储/展示）：

- **来源类别**（官方/媒体/垂直/热点/对标/用户/内部/临时）
- **关注主题**（关联经营方向/账号）
- **扫描频率**（高频/每日/隔日/每周/活动期）
- **优先级**（高/中/低，影响 Token 预算分配）
- **历史有效性**（曾产生多少有效信号）
- **最近质量**（近 N 次扫描的信号密度）
- **产生过多少有效选题**（转化为内容的计数）
- **是否暂停**（临时停用而不删除）

# 5. 信息源必须自动优化（核心机制）

来源不是「加进来就永远扫」。AI 应基于**贡献度**提出优化建议：

**示例 A（降频）：**
> Source A 扫描 90 次，产生 2 个选题，表现一般。AI 建议：「该网站近期有效选题贡献低，建议从每日改为每周扫描。」

**示例 B（建议加入）：**
> 多次搜索都引用某新网站，且它常比其他媒体更早出现 AI 产品信息。AI 建议：「建议加入固定来源，类别=垂直网站，频率=每日。」

**示例 C（建议删除）：**
> Source C 连续 60 天零有效信号且多次产生低质/误报。AI 建议：「建议移除或暂停。」

**示例 D（建议升优先级）：**
> Source D 在 3 次活动中均较早提供关键信息。AI 建议：「提升为高优先级常驻源。」

**贡献度评分草图（研究示意，非产品规格）：** 为让「自动优化」可落地，建议用可解释的分值驱动建议，AI 据此提出「继续重点 / 降频 / 暂时观察 / 建议删除 / 建议加入」：
```
来源贡献分 = 0.4·有效信号率        （近 N 次扫描中进入机会池的比例）
           + 0.3·有效选题转化数    （实际产出内容的计数，按时间衰减）
           + 0.2·表现加成          （该源选题的历史表现是否高于均值）
           + 0.1·时效早性          （是否常比其他源更早出现关键信息）
           − 0.2·误报/低质率       （产生噪声或被驳回的建议比例）
```
- 分层阈值（示例）：≥0.7 持续重点；0.4–0.7 维持；0.2–0.4 降频观察；<0.2 且持续窗口（如 60 天）建议暂停/删除。
- 新源默认「观察期」不计入删除建议；活动期临时源单独计时。
- 此公式仅作**研究示意**，权重与阈值须在产品设计阶段结合实测校准，且任何删除/长期降权核心源仍走 CEO 确认（见 Doc7 边界）。

**重要原则——不默认静默永久修改：**
- 高频小幅调整（临时降频观察、活动期临时加源）可由 AI 在规则内执行并留痕。
- **结构性变化（删除源、长期降权核心源、改变扫描预算分配）必须让 CEO 知晓**，由其确认。这与 Doc7 的「AI 自主 vs CEO 决策」边界一致。

# 6. Token / 成本效率（专门研究）

社媒运营不能成为无限 Token 黑洞。具体手段：

1. **Source Registry 边界**：只扫登记过的源，不临时全网信马由缰。
2. **分级扫描频率**：官方/用户信号高频，垂直/媒体中频，临时源低频。
3. **结构化数据优先**：RSS、平台 API、官方 JSON、趋势接口优先于全文抓取。
4. **先轻量筛选，再深度阅读**：标题/摘要/热度先过筛，仅高潜信号拉全文。
5. **去重与合并**：同类来源（多个 AI 媒体）合并比对，避免重复消耗。
6. **历史缓存**：已读且未变的内容不重复拉取；热点只看增量。
7. **低价值源降频/暂停**：用第 5 节的贡献度机制自动执行。
8. **Task-scoped Context**：每次选题/复盘只注入相关源的最近信号，不全量上下文。
9. **知识按需读取**：通用方法论常驻，平台特定事实按需查官方源。
10. **信号质量门禁**：设定最小相关度阈值，低于则丢弃，不进入选题池。

> 目标三角：**信息覆盖足够广 + 成本可控 + 信号质量高**。三者靠「有结构的源组合 + 自动优化 + 分级深度」同时达成，而非靠堆算力。

# 7. 情报如何转化为机会（衔接 Doc3）

雷达扫描产出的不是「新闻」，而是分类信号：
- **Growth Opportunity**（平台活动/新功能/流量倾斜）→ 评估适配度 → 进选题候选。
- **Topic Signal**（热点/搜索上升/用户高频问题）→ 进选题池。
- **Risk Signal**（合规变化/负面舆情）→ 升级 CEO / 合规核查。
- **Competitor Signal**（对手动作）→ 差异化选题。
- **User Signal**（评论/私信问题）→ 用户洞察与内容机会（见 Doc4）。

信号进入统一「机会池」，由选题策略（Doc3）消费。

# 8. 给产品设计的输入（非本文件实现）

- 用户需能「对话式增删源」与「列表式管理源」。
- 每个员工（信息收集/选题/平台运营/社区/数据分析）各有其关注的源子集。
- 来源优化建议需有「建议→CEO 确认/驳回」的轻量流程。
- 扫描应有可视化预算与频率，避免无声失控。

## 来源与置信度
- 平台官方：各 Creator Center / 官方博客 / 安全与信任中心（最高置信，须实时验证）。
- 社媒倾听与情报：Sprinklr、Pluggo、Brandwatch、Highperformr 等 2025 最佳实践（通用方法，置信高）。
- 具体平台热点/权重数值：见 Doc1 来源注释，标 NEEDS VERIFICATION。

**元警示（来源质量，复查补充）**：本轮检索到部分中文「平台算法解析」疑似 SEO/营销号或 AI 生成内容（布马、部分搜狐/青瓜传媒转载）。这些**仅作方向性假设**，不得直接编码为产品规则；任何用于产品判定的平台事实必须以**官方来源实时验证**为准，第三方数字一律 NEEDS VERIFICATION。高置信事实（抖音 2025 创作者大会四大计划、小红书社区公约 2.0、YouTube「发布频率/订阅数非排名信号」）应优先采用。
