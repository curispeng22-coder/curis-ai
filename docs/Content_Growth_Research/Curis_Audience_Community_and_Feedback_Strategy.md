# 1. 粉丝画像不应止步于人口统计

多数团队停留在「年龄/性别/地区」，但**经营价值在更深的层**：

- 他们为什么关注（价值动机）
- 最关心什么问题（需求）
- 哪些内容互动最多 / 收藏最多 / 带来关注最多
- 哪些问题经常出现（可被内容覆盖）
- 什么表达方式更容易被接受（语气/形式）
- 什么内容会流失用户（负信号）

画像应是**动态演化**的：随内容、平台、阶段变化，由数据持续修正，而非一次性设定。

---

# 2. 评论是金矿，不只是回复对象

评论若只用于「自动回复」是巨大浪费。正确闭环：

```
评论 / 私信 / 社群发言
   ↓ 进入 User Signal 池
分析：高频问题 / 情绪 / 需求 / 可被内容回答的
   ↓
提炼为 Content Opportunity
   ↓
进入下一轮选题（见 Doc3）
```

**真实示例（业务化）**：大量用户都问「Curis 能不能接 Codex？」——这本身应成为下一条产品介绍/答疑内容。评论不进选题池，就是机会流失。

评论分析的维度：
- **高频问题**：重复出现 → 必做内容。
- **情绪极性**：正向（强化）、负向（风险/澄清）、困惑（教育机会）。
- **可被内容回答**：直接转化为选题。
- **对产品的诉求**：私信/评论中暴露的需求 → 反馈产品/业务。
- **负反馈信号**：「不感兴趣」类表达、争议、违规风险 → 升级。

---

# 3. 互动的分级处理（发布不是终点）

内容发出后的评论/私信/收藏/分享/关注/用户问题应分流：

| 类型 | 处理方式 | 理由 |
|---|---|---|
| 常规评论 | 自动回复 / 轻量互动 | 维持活跃、信号正向 |
| 高价值问题 | AI 员工认真回复（拟人、有信息量） | 建立信任、转化为内容 |
| 内容机会 | 提炼进选题池 | 闭环增长 |
| 品牌/风险相关 | 升级 CEO 判断 | 避免擅自处置引发危机 |
| 负向/争议 | 标记、谨慎回应或升级 | 平台反对制造对立（小红书公约 2.0），需合规 |
| 私信高意图 | 分类为潜在客户，进获客流程 | 服务获客目标 |

> 原则：不是所有评论都回，也不是都不回。**分级**决定资源投入与风险边界。

# 4. 社区经营（长期资产）

- 铁粉/社群是抗流量波动的压舱石（抖音铁粉机制、B站粉丝私域、小红书粉丝群）。
- 社区反馈应反向塑造内容与产品（见第二节闭环）。
- 互动质量重于数量：B站强调正向互动与社区信用分；小红书重信任指标（转发>评论>赞）；TikTok 重评论深度>数量。

---

# 5. 用户洞察如何进入策略

洞察不是报告，而是**策略输入**：
- 高频问题 → 选题（Doc3）。
- 流失内容特征 → 调整 Content Mix / 停止低质类型。
- 接受度高的表达 → 沉淀为品牌语言/语气指导。
- 私信意图 → 获客与转化优化。
- 竞品评论中的痛点 → 差异化内容。

洞察应写入「这个账号自己的方法」，随轮次积累。

---

# 6. 私信与社群的信令价值

- 私信常含最高意图用户：应分类（咨询/投诉/合作/潜在客户），高意图进获客/转化流程，合作类升级。
- 社群/粉丝群：最忠实用户的真实困惑，周聚合即选题源。
- 半公开社区（Reddit/Discord/论坛）：B2B 尤甚，早期兴趣在正式询单前已显现。

---

# 7. 给产品设计的输入

- 「社区员工」需持有：评论关注范围、回复策略（分级）、用户问题提炼规则、升级阈值。
- 用户应能查看「用户洞察」面板：高频问题、情绪、需求、内容机会。
- 反馈闭环需可见：评论→洞察→下一条内容 的链路应可追踪。
- 风险/品牌类互动须有「升级 CEO」的明确路径与留痕。
