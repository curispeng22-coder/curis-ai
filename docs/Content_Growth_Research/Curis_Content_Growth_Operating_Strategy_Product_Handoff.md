# 1. 核心经营模型

八步飞轮；每一步标注「用户感知 / 员工执行 / 仅内部逻辑」。

| 步骤 | 用户需要感知什么 | 员工需要执行什么 | 仅内部经营逻辑 |
|---|---|---|---|
| **Goal 目标** | 经营目标声明（主/次目标） | 无（由用户/CEO 定） | 目标驱动所有下游策略派生，不靠播放量 |
| **Intelligence 情报** | 重要机会 / 风险 / 异常提示 | 信息收集员工维护 Source Portfolio、扫描、筛选、贡献度评估 | 扫描频率、Token 预算、去重、分级深度 |
| **Strategy 策略** | 当前策略摘要、策略提案 | 选题员工定选题标准/Mix/优先级；平台运营员工定发布策略；社区员工定互动策略；数据员工定指标/实验 | 选题业务适配分等加权（**不暴露公式**） |
| **Operating Rules 规则** | 当前经营节奏（扫描/生产/发布时间频率/自动边界） | 规则编译与执行 | 策略→规则的编译机制 |
| **Execution 执行** | 自动进行中的工作、发布状态 | 制作 / 发布 / 互动 | 制作流程、平台 API 调用 |
| **Feedback 反馈** | 重要用户信号、平台/账号异常 | 数据员工拉指标；社区员工提炼用户问题 | 信号归一化 |
| **Learning 学习** | 最近学到了什么 | 数据员工判断有效/无效 | 观察窗口、相关≠因果、防过拟合 |
| **Strategy Evolution 进化** | 当前策略提案、Needs CEO | AI 自主微调（规则内）、提长期调整建议 | 进化判定、决策边界 |

> 设计要点：飞轮要「可见可干预」，不是黑箱。用户在 Business Home 看到的是每步的「用户感知」列；「仅内部逻辑」列不应直接暴露给用户，但必须可被 AI 员工执行。

# 2. 五层策略归属（产品设计矩阵）

## A. 经营方向 (Business Direction)
归属：CEO / 主理人；结构性，改动须 CEO。
- 业务目标（主/次）
- 总体定位
- Content Mix 方向
- 平台组合
- 品牌语言

## B. Account（单账号）
归属：账号策略 + CEO 确认。
- 单账号目标 / 定位
- 当前成长阶段（冷启动/增长/稳定/转化）
- 发布节奏
- 平台个性策略

## C. Employee Method（职责归属，≠ 固定创建 5 个 Employee，≠ 复杂员工设置后台）
归属：对应员工（AI 可自优化，结构性改须 CEO）。同一职责可由同一虚拟员工/能力承担。

> **Employee Method ≠ 复杂员工设置后台。** 产品应优先支持 **Conversation-driven modification + Inspectable / Direct Edit**——两者操作**同一份长期工作方法**，允许用户以对话或直接编辑任一员工的工作方式，且两处改动互相可见、一致。不要把员工工作方式呈现为需要逐项配置的复杂后台面板。

- **信息收集员工**：信息来源、扫描频率、关注主题、来源质量
- **选题员工**：选题标准、Content Mix、优先级
- **平台运营员工**：发布时间、发布频率、平台活动
- **社区员工**：评论监控、回复策略、用户问题提炼
- **数据员工**：指标、观察窗口、实验、策略提案

## D. Platform Facts
只包含：平台**当前真实**规则 / 活动 / 能力。
- 产品必须支持四态（与 Frozen Authority 对齐）：
  - **VERIFIED（官方已验证）**：来自官方来源、可确认当前真实生效。
  - **CONDITIONAL（条件性/待核）**：部分确认或存在前提条件，需持续核证。
  - **UNKNOWN（当前无法确认）**：尚未取得可确认依据，状态待查。
  - **UNAVAILABLE（已确认当前不存在/不支持）**：已确认平台当前不提供该规则 / 能力 / 活动。
- **禁止**把研究中的第三方数字（如「收藏权重 96」「CES 1/1/4/4」「前 5 作品保护期」）变成产品规则。见 §13。

## E. Operating Rules（编译后的执行规则）
- 扫描计划、生产节奏、发布时间、发布频率、自动执行边界。
- 由策略编译，AI 在边界内微调；结构性变化须 CEO（见 §6）。

# 3. 用户交互方式要求

两类交互必须**修改同一套长期经营方法**，不得形成「聊天一套 / GUI 一套」。

**CONVERSATION-DRIVEN（对话驱动）示例：**
- 「这个网站不错，以后每天也看看。」→ 加入固定来源。
- 「这个来源最近没价值，以后少看。」→ 降频/暂停。
- 「这个月小红书多做一点教程。」→ 调整该账号 Content Mix / 发布节奏。

**INSPECTABLE / DIRECT EDIT（可查看 / 直接编辑）示例：**
- 打开信息收集员工 → 当前信息来源 → 添加 / 删除 / 暂停 / 改频率。

> 设计硬约束：对话与列表编辑操作**同一份底层经营方法**；任一处修改，另一处可见且一致。不允许两套独立存储。

# 4. Business Home 必须看见什么

只提炼经营层必需信息，**不要**把所有指标堆成 Dashboard：

- 当前经营目标（主/次）
- 当前经营节奏（扫描/生产/发布）
- 重要 Opportunity（平台活动 / 流量倾斜 / 新功能）
- 自动进行中的工作（制作中 / 待发布 / 扫描中）
- 平台 / 账号异常（限流预警 / 合规触线 / 数据异动）
- 重要用户信号（高频问题 / 增长需求）
- 当前策略提案（含置信与决策层级）
- Needs CEO（待 CEO 确认的结构性变化）
- 最近学习到了什么（策略增量）

# 5. Employee 需要展示什么

产品设计必须让用户能**查看某员工现在「怎么工作」**：

以信息收集员工为例：
- 当前关注：官方源 / 行业网站 / 平台热点 / 对标账号 / 用户评论
- 最近新增 / 降频 / 暂停的来源

> 默认工作面**不展示技术参数**（扫描间隔秒数、Token 计数、贡献度原始分）。 technical 细节进「高级 / 设置」层级，避免吓到普通用户。

# 6. Strategy Evolution 产品要求

设计必须支持区分三类：

1. **AI 自主微调**：规则内、留痕、可回滚（时段矩阵内微调、选题排序、活动期临时加源/加频、低值源临时降频）。
2. **AI 建议长期调整**：AI 提出超出当前规则的结构性变化 → 进策略提案流，待 CEO 确认。
3. **CEO 主动修改**：用户直接下命令。

**关键裁定：**
- CEO 主动明确下命令，例如「以后不要扫描这个网站」→ **不需要再次创建 CEO Decision**（这本身就是决策执行）。
- 只有 **AI 主动提出超出既有经营策略的结构性长期变化** → 才按 Frozen P7 进入 Decision（Needs CEO）。
- 边界原则：默认不静默永久修改重要策略；结构性变化须 CEO 可见、可确认、可驳回。

# 7. Source Strategy（信息雷达 → 产品必需能力）

收敛为以下产品能力：
- Source Portfolio（来源组合）
- 分层来源（官方/媒体/垂直/热点/对标/用户/内部/临时）
- 对话增删（§3）
- 列表管理（添加/删除/暂停/改频率）
- 扫描频率（分级）
- 暂停
- 来源贡献（跟踪有效信号/有效选题/表现）
- AI 建议加入 / 降频 / 删除
- Token 预算意识（结构化数据优先、先筛后读、去重、低值降频）

> **Reference Only（不进首版 Frozen 设计）**：贡献度公式、具体阈值、具体权重。研究中给出的 5 维加权分仅作 Reference，产品首版不写死，待实测校准。

# 8. Topic / Content Strategy

设计需要支持：
- 机会池（统一信号入口）
- 为什么值得做（业务适配说明）
- 信号来源（来自哪个源 / 哪个用户问题）
- 当前 Content Mix（比例可视化）
- 栏目（系列化）
- 平台活动 Opportunity（带适配度评估）
- AI 选题建议

> 不要暴露内部加权公式（选题业务适配分 w1..w8 等只在内部逻辑层，不进用户界面）。

# 9. Audience / Community

必须体现闭环：
```
评论 → User Signal → 用户洞察 → Content Opportunity
```
评论区**不只是自动回复工具**。

用户应能看到：
- 「大家最近最常问什么」（高频问题）
- 「哪些需求正在增长」（需求趋势）
- 「哪些问题已经变成下一轮内容」（闭环可见）

互动分级（常规自动 / 高价值认真回 / 内容机会提炼 / 风险升级 CEO）须在社区员工工作方式中可配置。

---

# 10. Publishing

设计需要支持演化路径：
```
初始行业经验 → 本账号实际数据 → 学习出自己的发布时间/频率
```

用户应能分辨两种建议的来源：
- 「平台通用建议」（行业经验初版）
- 「根据你自己的账号数据学习出的建议」（本账号时段×类型×星期矩阵）

> 不要把研究中的固定时间（如「晚 8 点」「日更 3 条」）写成默认真理；默认呈现应标注置信来源，并随本账号数据演化。

---

# 11. Analytics

指标必须跟经营目标挂钩；**不要默认 播放量 = 成功**。

设计需要支持链路：
```
目标 → 核心指标 → 观察 → 判断 → 策略建议
```

每条策略建议最好可见：
- 观察（什么数据/信号）
- 证据强度（单次 / 重复 / 实验验证）
- 建议（具体改什么）
- 影响（影响哪层策略）
- 是否可回滚

指标分层（供面板组织，非全量展示）：广度 / 互动 / 转化 / 质量 / 风险。

# 12. First Version Priority

给设计专家的明确分级：

**MUST DESIGN NOW（首版必做）：**
- 核心经营模型八步飞轮——*产品须承载其语义与能力*（目标驱动、情报→策略→执行→反馈→学习→进化闭环、可干预），不要求设计专家把八步飞轮机械画成流程图（§1）
- 五层策略归属——*产品须承载其配置语义与能力*（归属清晰、可分层配置、边界可见），不要求机械画成配置树 / Dashboard（§2）
- 对话驱动 + 列表编辑同一套方法（§3）

> **澄清（MUST 前两项的真实含义）**：上述「八步飞轮可视化」「五层策略归属配置结构」= 产品必须**承载这些语义与能力**——用户能感知目标 / 节奏 / 机会 / 异常、能干预策略与规则——**不要求**设计专家把经营架构机械画成流程图 / 配置树 / 数据看板。**用户不需要学习经营架构**：八步飞轮与五层模型是我们内部的经营分析视角，产品应以用户可理解的语言呈现能力，而非暴露架构图。
- Business Home 九项经营层信息（§4）
- Employee 工作方式查看（§5）
- Strategy Evolution 三类区分 + Frozen P7 边界（§6）
- Source Strategy 能力（§7，不含公式）
- Topic/Content 机会池与信号来源（§8）

**SHOULD DESIGN LATER（后续）：**
- 来源贡献度公式与阈值的实测校准
- 复杂实验框架（多变量长期 A/B）

- 完整合规规则库（各平台禁止项检查表）

# 13. Platform Fact 警告（最高优先级）

研究中出现的平台具体：
- 权重（如「收藏>复访>铁粉」「CES 1/1/4/4」）
- 频率（如「日更 3–5 条」「前 5 作品保护期」）
- 最佳时间（如「晚 8 点」「US 6–10pm EST」）
- 流量池（如「45% 推荐 / 25% 搜索」）
- 算法数值

**全部视为 REFERENCE / NEEDS VERIFICATION。**

设计专家只消费一条结论：
> **「Curis 需要一套动态的 Platform Facts 能力」**——按平台存储当前真实规则/活动/能力，带 VERIFIED/CONDITIONAL/UNKNOWN/UNAVAILABLE 四态，由官方来源实时验证，而非把具体数字写死到高保真。

任何高保真设计都不得硬编码上述具体数字。
