# Curis 产品与愿景资料库

## 这个库是做什么的

这是 Curis 内容制作部门长期使用的资料库，也是 CEO 自己阅读、理解和回顾产品的地方。

它要回答两个问题：

- 对用户：**「Curis 到底能帮我做什么？」**
- 对内容制作者：**「Curis 有什么值得讲给别人听？」**

以后 Curis 自己的内容团队，会直接读取这里的资料，制作抖音视频、小红书内容、B站视频、YouTube 视频、产品介绍、演示视频、官网内容、教程、产品故事、推广内容。

所以这套资料既要求**真实**，也要求有**可读性和传播价值**。

## 这个库不是什么

- 不是开发文档
- 不是架构文档
- 不是 Product Spec
- 不是 ADR
- 不是给工程师看的技术资料

上面这些（Product Blueprint、Frozen Contract、Runtime、ADR、Review、实现结果等）是**事实来源**。本库用自然语言重新把它们讲出来，供传播和回顾使用。

## 三个子目录

- **01_产品事实库**：Curis 现在是什么、已经确认的产品逻辑、已经实现 / 已批准的能力、用户现在或明确可以怎么用。未来可演变成产品使用说明、帮助中心、教程、FAQ、功能介绍、产品演示说明。以已经实现 / 已批准事实为主，事实必须准确，不能把未来写成当前。
- **02_产品愿景库**：Curis 未来想成长成什么、当前产品设计背后的长期方向、正在建设的能力、尚未实现但思路清晰的产品形态、未来一人公司可能怎样工作。允许大胆谈未来，但必须保持时间语义真实。
- **03_内容选题库**：从事实库和愿景库里提取——值得传播的故事、用户容易产生兴趣的问题、产品卖点、反常识观点、真实使用场景、产品成长故事。这里只记录「题」和传播角度，不直接生产最终抖音脚本或小红书文案。

## 资料状态约定（重要）

每篇资料允许同时包含三种时间语义，但必须让读者知道它属于哪个阶段：

- **NOW**：已经实现 / 已经验证
- **NEXT**：已经确定、正在建设
- **VISION**：长期愿景

三种都可以传播，但不要把 NEXT 或 VISION 伪装成 NOW。

不要在每段都贴标签。在文章开头或相关段落里自然说明即可，例如：「目前……」「接下来……」「未来我们希望……」。

## 长期维护原则

每当 Curis 出现重要的 **IMPLEMENTED / APPROVED / FROZEN / 重大产品方向变化**，都检查本库是否需要更新。

例如：某个原本属于 VISION 的能力真正上线以后，应该把相关内容逐渐从「未来我们希望……」更新成「现在 Curis 已经可以……」。

保留产品成长的历史，但当前产品事实必须同步。

## 写作约定（给内容制作者）

- 尽量用自然中文，产品名 / 技术名词（Curis、Workspace、Agent、API 等）才保留英文。
- 少用工程化语言（Contract、ADR、Schema、Runtime Spec、字段定义表等）。
- 用具体场景和真实问题说话，避免空泛的「赋能」「闭环」「核心价值在于」。
- 句子可以有长有短，可以解释原因、举例子、讲故事。
