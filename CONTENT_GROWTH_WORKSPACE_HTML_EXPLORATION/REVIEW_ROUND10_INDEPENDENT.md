## 一、结论（先看这段）

## 二、功能性结构问题

### P0-1 渲染期全局中英替换会改写用户内容（`workspace-r7.js:47`）

```js
C.polishText=()=>{ for(const root of ['main','aside','modal','crumb']){
  const walk=document.createTreeWalker(node,NodeFilter.SHOW_TEXT);
  ... for(const [a,b] of words) s=s.replace(new RegExp('\\b'+a+'\\b','g'), b); ...}}
```
词表 113 条，每次 `render()` 后对 `#main/#aside/#modal/#crumb` 的**全部文本节点**做词边界替换。

**实测证据**（`_rvF.js`）：把一个 Work 标题设为
`Team Review：Content Model 与 Scope 的 Status Source`

| 位置 | 实际渲染 |
|---|---|
| Work 工作台标题 / 面包屑 | `团队 审核：内容 模型 与 范围 的 状态 来源` |
| 弹窗正文 | 同样被替换 |
| 与数据库值 | 不再一致（页面上无法按原词检索、复制回去也对不上） |

风险不止示例：`Content / Model / Status / Source / Scope / Team / Review / Brief / Package / Result / Stage / Goal / Format / Owner / Stage / Provider / Capability / Unknown` 等 113 个词，都可能在用户写的选题标题、备注、研究结论、内容标题里出现，被静默改写成中文。同时该替换**不覆盖属性**（placeholder/title/aria-label），所以"中文化"本身也不彻底。

**建议**：不要在渲染后扫全量文本节点。把术语中文化收敛到渲染源（组件里的标签、列头、胶囊），或给替换函数加白名单容器（只作用于 `data-term` 标记的槽位），跳过内容字段。

### P1-1 复盘右栏「相关工作」3 行点击后完全无反应（`pages.js:913`）

**实测**（`_rvJ.js`，`_rvI.js`）：在复盘区点击右栏三条工作行

| 观察点 | 点击前 | 点击后 |
|---|---|---|
| `CG.S.route` | `{"area":"analytics"}` | `{"area":"analytics"}`（不变） |
| 主区文本长度 | 194 | 194（不变） |
| 提示消息 | — | 空 |
| `S.tabs.analytics` | `{}` | `{"analytics":"judge"}` |

**根因**：`openWork` 的 analytics 分支写的是
```js
if(w.area==='analytics'){ S.tabs.analytics='judge'; CG.go({area:'analytics'}); return; }
```
但复盘页读的是 `CG.S.an.tab`（`analytics-r5.js:225` 的 `TABS`），**`S.tabs.analytics` 从未被任何渲染读取**。对照实验：把 `S.tabs.analytics` 设成 `judge`/`contents`，主区长度恒为 194；把 `S.an.tab` 设为 `next`，主区变 621。

**同一控件在其余 5 个区都能跳转**（research/production/publish/accounts/assets 实测有效），只有复盘命中这个分支。

**建议**：analytics 分支改成 `CG.S.an.tab = 'judge'`（一处即可修好 3 行）；更彻底的做法是跳到该实验/复盘 Work 的可查看位置，而不是原地换页签。

### P1-2 「已形成提案」的选题行内没有去向入口

**实测**（`_rvJ.js`）：研究 → 选题池，6 行选题的**操作列只有「讨论这条选题」**，而进展列显示「已形成提案」。提案只能在另一排 chip「已形成提案」里另找。

补充说明（避免误判）：
- 行内「讨论这条选题」**是正确的**——它携带 `data-obj="inspiration" data-obj-id="INS-2"`，会话 key = `team|research|e-shen|-|-|inspiration:INS-2|-`，对象上下文没有丢。
- 制作区 Work 的「讨论」同样正确（`work:W-201` + `xhs-brand`）。

**建议**：行内补一个二级动作「查看提案 PROP-x」，或让进展胶囊可点。

### P1-3 发布阻塞「进入相关制作」猜不中时静默兜底（`workspace-r8.js:49`）

```js
C.M['pub-work']=id=>{ ... const w=C.WORKS.find(w=>w.target===p.accountId &&
  ((p.next||'').includes(w.id) || (p.title&&w.title.includes(p.title))));
  C.closeModal(); C.go(w?{area:'production',view:'workbench',id:w.id}:{area:'production'}); };
```
**实测**（`_rvJ`/专项探针）：

| 发布记录 | 关联线索 | 结果 |
|---|---|---|
| PUB-310 | `W-205 被授权照片阻塞…` | 命中 W-205 ✅ |
| PUB-305 | `重出封面后重试，不重复提交同一版本` | **未命中 → 直接跳制作列表，无任何说明** ❌ |

PUB-305 实际对应「小红书｜创始人IP · 封面规格修复重试」这个 Work，只是关联靠字符串猜，猜不到就静默降级。

**建议**：发布记录里显式存 `workId`；缺失时明确说"未关联到具体制作，请选择"。

### P2-1 内部 ID 进文案 + 新对象 ID 体系不统一

| 位置 | 原文 |
|---|---|
| 发布队列 | `下一步：等待 W-201 完成把关`、`W-205 被授权照片阻塞，排期风险` |
| 素材右栏 | `影响：阻塞 W-205 与 PUB-310` |
| 素材名 | `REF-1 拆解片段（3 段）`、`创始人授权照片 2 张（AR-1）` |
| 建立实验的提示 | `实验研究工作已建立：EXP-1789663373057`（毫秒时间戳，且不在 W-xxx 体系内） |
| 另见 `workspace-r8.js:59` | 新建研究工作用 `RESEARCH-<id>` |

**建议**：面向用户统一显示可读短号；时间戳 ID 换成序号；`AR-/REF-` 改成"授权项 / 参考片段"表述。

### P2-2 术语与占位残留

- `发布授权 Envelope / 各账号`（右栏标题，中英混排；词表有 `Operating Envelope` 但没有裸 `Envelope`）
- `搜索账号 / handle / 定位`（输入框 placeholder 仍是 `handle`）
- 属性层（title / aria-label / placeholder）不参与中文化，本轮全量扫描共命中 2 处（上表两条）

### P2-3 「已启用」按钮仍可点（`pages2.js:1197`）

派生 Variant 全部已启用时，按钮文案仍是「已启用」但保持可点，点了只弹一句「该 Work 没有待启用的派生 Variant」（6 个状态命中）。应置灰或隐藏。

### P2-4 无历史时顶部返回按钮可点、无反馈

`disabled:false`、`opacity:1`、`cursor:pointer`，点击后路由与正文都不变，也没有提示。应置灰或隐藏。

### P2-5 存在一个不在页签集合里的复盘视图 `gap`

`analytics-r5.js:225` 的 `TABS` 只有 `overview/contents/trend/judge/next`，但多处入口写 `data-t="gap"`（「集中待补（3）」「补充数据」等）。

**实测**：点「集中待补（3）」→ `an().tab='gap'`，主区从 194 字变 730 字（视图**确实**切过去了，不是死按钮），但**页签栏没有任何高亮**（`document.querySelector('.chip.on')` 为 null）。用户会不知道自己现在在哪个视图，也无法从页签判断位置。

**建议**：把 `gap` 提升为正式页签，或让这些按钮回落到已有页签并说明。

## 三、排版与流程问题

### L1 (严重) ≤1180px 右栏整体消失，且没有任何入口

`styles.css:77`：`@media (max-width:1180px){ .aside{display:none} #rail{width:186px} ... }`

| 视口宽 | 右栏 display | 右栏文本 | 主区文本 | 侧栏宽 | 主区宽 |
|---|---|---|---|---|---|
| 1440 | block | 242 | 474 | 214 | 876 |
| 1180 | **none** | 242 | 474 | 186 | 966 |
| 1120 | none | 242 | 474 | 186 | 906 |
| 1024 | none | 242 | 474 | 186 | 810 |
| 900 / 768 / 430 / 390 | none | 242 | 474 | 186 | 686/554/216/176 |

右栏承载「相关工作 / 责任与团队 / 数据新鲜度 / 内容缺口 / 发布授权 / 产线分布」，内容**没有**下沉到主区（主区长度恒为 474），也**没有任何控件**能把它打开（`app.js:164` 只在 `page.aside===null` 时加 `.hide`，没有反向开关）。→ 1024–1180px 的笔记本/分屏用户，这些信息完全不可达。截图 `_shots-rv10/1120-operate-aside-gone.png`。

### L2 (严重) ≤430px 逐字竖排，移动端实际不可用

390px 实测：侧栏固定 186px（无汉堡/抽屉）→ 主区只剩 176px，主区内部还有 77px 横向滚动。

- 「当前重点」的值被折成**一字一行**：宽 **10px**、高 **484px**（同一卡片的高 562px 元素也是 10px 宽）
- 顶部「经营边界」→ `经营边/界`；「团队持续经营中」→ 3 行竖排
- 面包屑 `Content Growth / 经营 / 整体经营` 变 3 列竖排
- 证据截图：`_shots-rv10/390-operate.png`、`390-publish.png`

### L3 (中) 复盘概览页主区空转，决策信息全在右栏

1440×950 下复盘「数据概览」主区只有 3 个 KPI 卡 + 3 个按钮 + 1 行说明（主区文本 194 字），而「集中待补（3） / 数据新鲜度 / 内容缺口」都挤在右栏。首屏主区利用率约 1/3。截图 `_shots-rv10/1440-analytics.png`。

### L4 (中) 右栏「相关工作」标题截断过早

实测行高 72.9px、标题可用宽 **198px**：24 字的标题被截到约 20 字（`clipped` 20–30 字），34 字的标题也不例外。原因是状态胶囊与标题同行且占定宽。进度条（4px，top 174.9）位于副标题（bottom 169.9）**下方 5px**，**没有压字**——此处不是缺陷。

### L5 (轻) 复盘右栏「数据新鲜度」值折行

`最近采集 09-16` / `06:10（人工自报）` 在 83px 宽内被折成 2 行（1600/1440/1280 均如此）。

### L6 (轻) 研究区两排同构 chip，层级不可辨

「选题池 / 参考与灵感 / 持续研究」（主视图，有高亮）与紧邻下方「全部选题 / 已形成提案」（次状态筛选）**样式、尺寸完全一致**，且第二排没有高亮态（默认"全部"也看不出选中）。其它 6 个区只有一排 chip。截图 `_shots-rv10/1440-research.png`。

### L7 (轻) 发布队列行宽不一致

首行是整行横排卡（人工发布项），其余行是窄卡 + 右对齐按钮，中间留大片空白。截图 `_shots-rv10/1440-publish.png`。
