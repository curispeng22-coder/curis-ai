项目全景：这是什么、进度、重点 / 难点 + 8 张图

Curis Workspace 的终极产品目标是面向个人创业者的「AI 公司系统」（用户扮演 CEO，系统把业务目标拆成任务 / 工作流 / 工具 / 模型 / 执行 / 学习 / 持久化）。 但当前上线范围不是完整公司系统，而是它的第一块基石 —— AI Task Executor MVP：一个受控自演进的 AI 操作系统内核（Controlled Self-Evolving AI OS Kernel）。 它只实现经过 gate 批准的执行器能力，同时把 L0–L6 的分层框架预留好，避免未来返工。

这是什么

受控自演进 AI 执行内核：用户提交任务 → 自动生成工作流 → AI 员工协调工具执行 → 记录 trace/学习 → 元开发自检 → 演进治理（稳定性优先，可决定「不演进」）。技术栈 FastAPI + SQLite + Next.js。

目前进度

已走到 v0.1 本地/Demo 发布（2026-07-06 关闭）。Sprint 0–4 全部交付并验收，含 Tool System v1.6 元开发、v1.8 受控自演进内核、统一任务操作台、多入口 UI、中文控制台。后端 41 个回归测试全绿。

开发重点 / 难点

重点：在不越 gate 的前提下把「执行闭环 + 学习闭环 + 受控演进闭环」三层都跑通。难点：① 严格 gate / 禁止范围约束下增量交付；② 低 Token 角色协作工作流；③ 演进治理的稳定性优先与架构锁；④ 当前为本地/Demo，无外部服务、无 Mock。

④ 业务流程图（泳道图）

按执行闭环把活动分配到 7 条泳道：用户、前端操作台、Orchestrator、AI Employee、Tool Router/Executor、Learning & Evolution、Storage。展示一次任务从提交到复盘的全链路。

说明：泳道强调职责边界——前端只做输入/展示/轮询，真正的编排、执行、学习、演进都在后端；Storage 只负责持久化，不参与业务决策。

⑤ 页面流程图

当前前端为单页操作台（Next.js App Router）。核心入口是 page.js：任务输入区 + 历史列表 + 选中详情面板（多 tab）。/employees、/control 为占位路由（未来 L2/L5）。

说明：页面流是「输入 → 列表 → 详情」的单一主路径；多入口 Starter 仅预填 composer 内容，仍走同一 Task API；运行后前端轮询/重载详情。占位路由不参与当前 MVP。

⑥ 状态机图（Task 生命周期）

以 Task 为中心的状态流转：从 INIT 创建，RUNNING 后逐步 EXECUTING，最终 COMPLETED 或 FAILED；失败时若有 fallback 进入 ADAPTING 再裁决。执行结果另有复盘子状态。

说明：状态由 Orchestrator 统一推进（update_workflow / transition）。FAILED 不一定终止——存在 fallback 时进入 ADAPTING 重新选工具；稳定性优先，适配失败则保持 FAILED。

⑦ 原型图（统一任务操作台 Wireframe）

低 fidelity 线框，呈现 v0.1 操作台布局：顶部栏 + 左任务输入（含多入口 Starter）+ 中任务历史 + 右选中详情（多 tab）。移动端单列堆叠。

说明：线框对应 page.js 的真实结构（composer + starters + history + detail tabs）。所有数据来自真实 API，无 Mock / simulation；详情面板并行加载 5 类接口。
