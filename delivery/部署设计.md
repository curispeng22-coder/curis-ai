## 1. 引言

### 1.1 适用范围与部署形态

本文档适用于 **Curis AI 工作台 v1** 的部署与运行，部署形态为：

- **形态**：单机本地桌面应用，Tauri 壳 `Curis.app`（macOS 平台），v1 自用（AI 团队 5 常驻角色内部使用）。
- **运行模型**：Tauri 原生窗口加载 `http://127.0.0.1:3000`；壳内拉起两个 sidecar 进程——前端 `next start :3000` 与后端 `uvicorn :8000`。
- **构建产出**：`cd desktop && tauri build --bundles app` → `desktop/target/release/bundle/macos/Curis.app`。
- **网络边界**：仅本机 loopback（127.0.0.1），无公网监听端口、无 DMZ、无云 Region / AZ / VPC；唯一出网路径为 Tauri 命令白名单（仅受控外部域名，本期仅 E-04 埋点平台）。
- **不在本文范围**：资源规格的云端多实例部署、多租户服务端化、灰度发布平台——以上归未来演进（见各章节"演进触发条件"），本期不适用。

### 1.2 名词与缩写

| 名词 | 含义 |
| --- | --- |
| Tauri | 用于构建桌面应用的 Rust 框架，提供 WebView 壳与系统 API（E-03） |
| Sidecar | Tauri 随主进程拉起的子进程（本期为前端 next、后端 uvicorn） |
| Loopback | 本机回环网络 127.0.0.1，仅进程间通信，不触网 |
| NAV_MODEL | 导航唯一真相源，由 E-02（canonical-nav.js）定义，前端消费 |
| C-01 / C-02 | 本地状态库（C-01 持久化 SQLite / 文件；C-02 内存缓存落盘） |
| E-01 ~ E-04 | 外部依赖：E-01 后端 home/summary（本地 sidecar）、E-02 NAV_MODEL 模块、E-03 Tauri 运行时、E-04 埋点平台 |
| credential_ref / secret_digest | 密钥仅存引用与摘要，明文绝不入库 / 落盘 |
| OS Keyring | 操作系统密钥环（macOS Login Keychain），本期 KMS 选型 |
| U-05 | 性能时延口径 = 相对基线型，不设绝对毫秒阈值，待运营数据回填 |
| RTO / RPO | 恢复时间目标 / 恢复点目标 |

## 3. 部署拓扑与高可用设计

### 3.1 物理拓扑

#### 3.1.1 物理拓扑图

本期部署形态为**单机本地桌面应用（Tauri 壳 Curis.app，macOS）**，v1 自用，无多租户、无公网入站、无云 Region / AZ / VPC 概念。物理拓扑仅包含一台用户本机（macOS）及其上的进程边界：

```
┌──────────────────────────────────────────────────────────────────┐
│  用户本机 (macOS) · 单机本地 · 无公网入站                           │
│                                                                    │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  Curis.app (Tauri 壳)                                        │  │
│  │   ├─ Tauri WebView 窗口 ──► 加载 http://127.0.0.1:3000      │  │
│  │   ├─ Sidecar 1: 前端 next start  ── 127.0.0.1:3000           │  │
│  │   └─ Sidecar 2: 后端 uvicorn   ── 127.0.0.1:8000 (E-01)      │  │
│  └────────────────────────────────────────────────────────────┘  │
│           │ 本地 loopback (127.0.0.1) 仅进程间                      │
│           ▼                                                        │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  本地状态库 (C-01 / C-02) · 本地文件 / SQLite · 落盘持久化  │  │
│  └────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
        │ 仅经 Tauri 命令白名单出公网（无其他网络暴露）
        ▼
   E-04 埋点平台（公网 HTTPS，域名白名单）
   （E-01 = 本地后端 sidecar；E-02 = 打包内代码模块；E-03 = 本地 Tauri SDK/IPC，均不触网）
```

> 说明：本期不存在云 Region / AZ / VPC / 子网 / 负载均衡 / WAF / CDN。网络边界收敛为本机 loopback（127.0.0.1）+ Tauri 进程间通信（IPC）。所有"跨网络"仅指应用经 Tauri 命令白名单出公网访问受控外部域名（仅 E-04）。

#### 3.1.2 拓扑要素清单

- 跨 Region 部署：否（单机本地，无 Region 概念）
- 跨 AZ 部署：否（单机本地，无 AZ 概念）
- 流量入口路径：Tauri WebView → 加载 http://127.0.0.1:3000（前端）→ 前端经本地 REST 访问 http://127.0.0.1:8000（后端 E-01）
- 内部调用路径：
  - 前端 ↔ 后端：本地 loopback HTTP REST（端口 3000 ↔ 8000）
  - 前端模块间：routeRef 内存注册表（NAV_MODEL 消费），无独立服务网格
  - 前端 ↔ 本地状态库：本地文件 / SQLite（C-01 状态库、C-02 内存缓存落盘）
- 数据库访问路径：后端 / 前端 → 本地 SQLite / 本地文件（C-01 状态库），无远程数据库实例
- 进程拓扑（R-1）：v1 启动链路 = Tauri 壳 `com.curis.desktop` + 2 个 sidecar（前端 `next :3000`、后端 `uvicorn :8000`），共 3 进程；无第三个 sidecar，`deploy/new-api` 网关不进入启动链路（R-2 容器链路未启用）
- 端口 3001 去留（R-3）：运行期前端恒在 `:3000`，`:3001` 仅为开发态临时验证端口；运行期 CORS 白名单收敛为仅 `:3000`（移除 `:3001`）
- 监听绑定（SEC-R2）：全部 TCP 监听仅绑定 `127.0.0.1`，禁止 `0.0.0.0` / `::` / 局域网地址
- 回环 Token 启动时序（SEC-U-01 方案 B）：Curis.app 主进程启动即生成 128-bit 随机回环 Bearer Token 并写入 macOS Keychain（`keychain://com.curis.desktop`），**早于**前端/后端两个 sidecar 的 spawn；Token 经 **Tauri IPC 内存注入 WebView**、**后端 sidecar 启动后自行从同一 Keychain 条目读取**（服务名 `com.curis.desktop`）；**严禁经 argv / shell 插值 / 环境变量传入**（同机 `ps` 可读，T-T-01 / T-T-02）；后端 uvicorn 中间件启动即生效，对全部业务路由强制校验 Token + Host 头白名单，**仅 `/health` 健康检查路由豁免**

#### 3.1.3 端口与监听清单（安全侧强约束）

| 端口 | 绑定地址 | 归属进程 | 允许非回环 | 安全要求 |
| --- | --- | --- | --- | --- |
| 3000/tcp | `127.0.0.1` | Next.js 前端 sidecar | 否 | 仅静态与页面路由，不得直接访问数据域 / 凭据域 |
| 8000/tcp | `127.0.0.1` | FastAPI 后端 sidecar | 否 | 全部业务路由强制回环 Token + Host 头白名单（TB-2 / FW-03） |
| 3001/tcp | 当前未监听 | 备用前端端口 | 否 | 去留见 R-3（运行期移除） |
| 其他 | 不允许 | 无 | 否 | 未登记监听视为违规，由监听变更监控告警 |

#### 3.1.4 进程启动安全约束（SEC-R3 / T-D-02）

- **SEC-R3（P0 威胁 T-T-01 / T-T-02）**：sidecar 启动**禁止把环境变量插值进 shell 字符串**、**禁止使用登录 shell `-lc`**。当前 `desktop/src/lib.rs` 以 `/bin/bash -lc` 拉起且将 `root`/`PY`/`NODE` 插值进脚本字符串，属待修复项；须改为非登录 shell（`bash` 非 `-lc`）并以 argv 数组（非字符串插值）传参。
- **T-D-02（端口清理）**：端口清理逻辑**禁止无差别 `lsof -tiTCP:PORT | xargs kill -9`**，必须叠加**进程指纹校验**（如校验监听进程的二进制路径 / 命令行确属 Curis sidecar 后再生效）。当前 `lib.rs` 用 `lsof -tiTCP:PORT -sTCP:LISTEN` 仍属端口级判定，须补指纹校验。

#### 3.1.5 回环 Token 认证启动时序与续期（SEC-U-01 方案 B，对齐安全侧 §2.1.3）

- **生成与托管（壳生命周期）**：Curis.app 壳进程（`curis-desktop`）启动时，以 **`SecRandomCopyBytes` 生成 128-bit 不透明随机串**作为回环 Bearer Token，写入 macOS Keychain（`keychain://com.curis.desktop`，与 R-Sec-001 同实例，服务名 `com.curis.desktop`）；Token **与壳进程同生命周期**——壳启动即生成、壳退出即从 Keychain 删除，**无续期概念，重启（壳）即换新**。Token 明文仅存于壳进程内存 + Keychain，绝不落盘至 C-01 / 日志。
- **注入时机（早于任一 sidecar，禁止命令行/shell 插值）**：Token 生成须**早于前端（next :3000）与后端（uvicorn :8000）任一 sidecar 的 spawn**——否则存在后端已监听但无鉴权的窗口期。注入方式：① WebView 经 **Tauri IPC 内存注入**（不落盘）；② **后端 sidecar 启动后自行从同一 Keychain 条目读取该 Token**（同服务名 `com.curis.desktop`），**严禁经命令行参数（argv）或 shell 插值或环境变量传入**（同机 `ps` / `/proc` 可读到，即 T-T-01 / T-T-02 风险）。WebView 加载 `http://127.0.0.1:3000` 时前端请求头携带该 Token。
- **后端校验生效点**：后端 uvicorn 启动时认证中间件即挂载，**对所有业务路由强制校验**回环 Token + `Host: 127.0.0.1` 头白名单；**唯一豁免路由为 `/health`**（健康检查），否则 watchdog 5s 探活会循环 401 导致误判失活。
- **sidecar 崩溃重启的 Token 续期对齐（watchdog R-O-003 / §3.3.1）**：watchdog 5s 端口探活（R-O-003）拉起崩溃的 sidecar（进程级自愈，＜ 10s）时，**Token 生命周期与 sidecar 解耦**——重启的是 sidecar 不是壳，须**复用当前壳生命周期内的同一 Token**（后端重启后从 Keychain 重新读取，不重新生成）；因此后端重启后前端既有 Token 仍有效，**避免重启后全量 401**。仅当壳进程自身退出 / 应用重开才换新 Token。
- **M1~M5 接口契约零变更**：回环 Token 为进程内认证增强，不改对外 REST API 契约，M1~M5 集成测试不受影响。

### 3.3 高可用与故障容错

#### 3.3.1 故障域划分

| 故障域 | 影响范围 | 容错机制 | 预期 RTO |
| --- | --- | --- | --- |
| 单 sidecar 进程崩溃 | 该进程（前端或后端） | Tauri watchdog 探测端口 3000/8000 失活 → 自动拉起 → 进程级恢复 | ＜ 10s（瞬时，用户无感） |
| 单本机（整机 / 系统崩溃 / 断电） | 全部进程与本地数据访问 | 用户重启 Curis.app，从 C-01 本地持久化恢复；本地数据零丢失 | ≤ 5min（用户重开应用） |
| 单 AZ | 本期不适用（单机本地无 AZ） | — | — |
| 单 Region | 本期不适用（单机本地无 Region） | — | — |

> **可用性来源拆分**：本期可用性 ≥ 99.9% 由本机进程稳定性 + Tauri watchdog 自动重启（进程级自愈）兜底，无云厂商 IaaS/PaaS SLA 依赖（因无云端组件）。RPO ≤ 0min 由本地 SQLite 即时落盘（C-01）保障，无远程同步则无同步窗口丢失。

#### 3.3.2 负载均衡

本期不适用。单机单实例部署，无 4 层 / 7 层负载均衡组件；前端请求直接由本机 loopback 分发至后端 sidecar，无多副本流量分配需求。演进触发：多实例/服务端化时引入反向代理或云 LB。

#### 3.3.3 健康检查配置

- 检查对象：两个 sidecar 监听端口（3000 / 8000）
- 检查方式：Tauri watchdog 周期性 TCP/HTTP 探活（如 `GET /health` 或端口连通性）
- 频率：每 5s 一次
- 失败阈值：连续 3 次失败判定失活
- 连续成功阈值：恢复后连续 2 次成功判定健康
- 处置：失活即按 T-D-02 叠加进程指纹校验后 kill 残余进程（禁止无差别按端口 kill），并由 Tauri 重新拉起 sidecar

#### 3.3.4 弹性伸缩配置

本期不适用。单机固定资源，无 HPA / 加副本机制。触发未来演进：本机 CPU 持续 > 预警水位且无法本地优化时，进入服务端化评估。

#### 3.3.5 容灾切换配置

- 单 AZ / 多 AZ / 多 Region：本期均为 N/A（单机本地）。
- 故障切换 RTO：进程级 ＜ 10s；整机级 ≤ 5min（用户重开）。
- 数据容灾：依赖用户本机备份机制（Time Machine / 手动导出 C-01），本期不提供应用级异地容灾。演进触发：多用户协作需引入服务端数据同步与备份。

### 4.2 流水线（CI / CD）

本期 CI 运行于**开发者本机 / 内部构建机**（无云端 CI 集群），8 阶段对齐模板：

| 阶段 | 触发条件 | 关键动作 | 失败处理 |

> **pre-commit 密钥/DB 泄露门禁（P0，发布阻断项）**：仓库启用 `.githooks/pre-commit` 钩子，在提交阶段扫描暂存区——复用 `credential_vault.py` 的 `SECRET_FIELD_RE` 匹配密钥特征，并拦截超 1MB 二进制，命中即阻断提交；扫描对象扩展至数据库文件（*.sqlite* / *.bak* / *.dump）与 .env 类密钥文件（含 `deploy/new-api/.env`）。与 CI 安全扫描（§4.2 安全扫描阶段）双重拦截，并作为发布门禁阻断项（§4.5.4）。
>
> **同批次上线约束（风险放大器）**：现有 `.githooks/post-commit` 第 13 行含 `git push`（已核实自动推送，远程为 PRIVATE），在 pre-commit 落地前是**风险放大器**——pre-commit 未生效即推送会外传泄露。故 **pre-commit 与 post-commit 自动推送须同一批次发布**，不得先上其一。
>
> **历史清理判断（安全侧 §3.3.4 已裁定，本文引用，不再自行断言）**：git 历史已含 3 个业务库（如 `data/admin.sqlite.20260717.pre-split`、`data/curis.sqlite.20260717.pre-r2-orphan`、`data/migration-backups/curis.sqlite.before-s12-20260729T012034016195Z.bak`）。安全侧裁定为**接受现状 + 停止新增**，**不强制** `git filter-repo` / BFG 重写历史。依据：① 远程 `curispeng22-coder/curis-ai-workspace` 为 **PRIVATE 单人仓库**，泄露面仅限 Owner 自身；② 3 个库内**无明文密钥**——`database.py` 设计上无密钥列，仅存 `credential_ref` + `secret_digest`（见 §2.2.6 / R-Sec-001），"轮转其中任何凭据引用"前提不成立；③ 重写历史 + 强推在单人仓库虽可行，但存在丢提交、本地 clone 失步的实操风险，为消除仅 Owner 可见的低收益风险去承担真实操作风险，收支不划算。该结论须显式登记，并由 `.githooks/pre-commit` 扫描**持续阻断后续新增**（见 §4.1 / §7.1.16）。

### 4.6 应用启动序列与回环 Token 校验（SEC-U-01 方案 B，对齐安全侧 §2.1.3）

Curis.app 壳进程启动序列（部署侧强制顺序，与安全侧 §2.1.3 一致）：

1. **壳启动即生成 Token 并写入 Keychain**：壳进程启动 → 以 `SecRandomCopyBytes` 生成 128-bit 不透明随机 Token → 写入 Keychain（服务名 `com.curis.desktop`）；与壳同生命周期，壳退出即删、无续期。
2. **再拉起后端 sidecar（uvicorn）**：后端启动后**自行从 Keychain 读取同一 Token**（同服务名）；**严禁经命令行参数 / shell 插值 / 环境变量传入**（T-T-01 / T-T-02，避免被同机 `ps` 读到）。
3. **再拉起前端 sidecar（next）并经 Tauri IPC 下发 WebView**：前端经 IPC 内存注入获取 Token（不落盘），加载 `http://127.0.0.1:3000` 后请求头携带。
4. **Token 生成必须早于任一 sidecar 启动**：否则存在后端已监听但无鉴权的窗口期（顺序约束硬保证，不可颠倒）。
5. **watchdog 重启 sidecar 不得重新生成 Token（对齐 R-O-003 / §3.3.1）**：watchdog 5s 端口探活拉起崩溃 sidecar（进程级自愈 ＜ 10s）时，复用壳生命周期内的同一 Token，不重新生成；仅壳进程重启才换新。

> **自检顺序补充（先于 sidecar）**：步骤 1 之后、步骤 2 之前执行启动硬门禁——C-01 数据库文件权限 **0600** / 目录 **0700** 校验不符即**拒绝启动**（P0 T-T-03，§6.1 / §7.1.12）；监听绑定仅 `127.0.0.1`（SEC-R2）；prod 启动期检测 **FileVault 状态**并据 §7.5 处置。后端中间件（步骤 2 启动即挂载）对全部业务路由强制校验回环 Token + Host 头白名单，**仅 `/health` 豁免**。

## 6. 应急与回滚

### 6.1 回滚机制

> **启动硬门禁（先于 sidecar 拉起，P0 T-T-03）**：应用启动自检阶段须先校验 C-01 数据库文件权限 **0600** / 目录 **0700**，不符即**拒绝启动**（硬门禁），不进行运行期权限热修；该门禁与发布门禁（§4.5.4）、自检表（§7.1.12）一致。若启动自检失败，按 §6.2 RB 系列处置（重装上一版本 / 上报），不尝试运行期修复 DB 权限。FileVault 未开启（prod）同样拒绝启动（§7.5）。

#### 6.1.1 回滚触发条件

- 生产错误率（AL-01 / AL-02 触发）
- 单接口相对基线（U-05）严重退化（AL-06）
- 关键告警触发且缓解无效（§6.2）

#### 6.1.2 回滚决策人

- 用户 / On-call 可独立决定应用版本回滚（重装上一版 .app）
- 密钥 / 配置类由 Owner（平台）决定

#### 6.1.3 回滚执行 SOP

| 对象 | 回滚方式 | 预计耗时 | 有损风险 / 数据丢失 |
| --- | --- | --- | --- |
| 应用版本 | 重新安装上一版本 .app（保留 C-01 本地数据） | ≤ 5 min | 无（数据向后兼容） |
| 配置（L3） | 本地配置文件保留历史版本，覆盖回退 | ＜ 1 min | 无 |
| 本地状态库（C-01） | DDL 变更必须可回滚；不可回滚 DDL（如 DROP COLUMN）禁止与代码同发布，须前置变更并备份 | ＜ 30 min | 有（须备份还原） |
| 密钥（L4） | Keychain 中旧凭证保留，回退引用即可 | ＜ 1 min | 无 |

#### 6.2.2 Runbook 编写规范

每条 Runbook 按以下结构编写：

- **症状**：触发该 Runbook 的可观测特征（桌面提示 / 日志关键字 / 用户反馈）
- **诊断（按顺序执行）**：定位根因步骤，明确使用的工具（本地日志 R-O-001 / watchdog 事件 / 进程端口探活）
- **缓解**：分场景处置（与回滚 §6.1、降级、重启衔接）
- **升级**：缓解未生效的升级条件与路径

#### 6.2.3 RB-01：后端 sidecar 无法自愈

- **症状**：AL-01 触发，应用卡死或接口全失败，桌面强提示。
- **诊断**：
  1. 查本地日志 R-O-001 中 uvicorn(:8000) 退出栈；
  2. 查 watchdog 事件是否尝试拉起及失败原因（端口占用 / 依赖缺失）；
  3. 确认本机资源（CPU/内存）是否耗尽。
- **缓解**：
  - 场景 A（偶发崩溃）→ watchdog 已自愈，观察 5min；
  - 场景 B（持续失败）→ 用户退出重开 Curis.app；仍失败则重装上一版本 .app（§6.1.3）。
- **升级**：重装无效 → 上报开发者群，附日志。

#### 6.2.4 RB-02：首屏门禁 E-01 不可达

- **症状**：AL-02，首屏默认落 CEO 工作台（BD-02 兜底），功能受限。
- **诊断**：
  1. 查后端 sidecar 是否存活（端口 8000）；
  2. 查前端 → 后端 loopback 连通性；
  3. 查 `ai_readiness` 字段获取是否异常。
- **缓解**：
  - 后端存活但接口异常 → 按 RB-01 重启后端；
  - 后端不可达 → 兜底生效（默认 CEO 工作台），引导用户稍后重试或重开应用。
- **升级**：持续不可达 → 上报。

#### 6.2.5 RB-03：埋点 E-04 不可用

- **症状**：AL-03，动线数据缺失，应用功能不受影响。
- **诊断**：查出网白名单是否含 E-04 域名、本机出网是否正常。
- **缓解**：降级——归位裁定仍生效，仅缺埋点；无需中断业务。
- **升级**：影响分析决策时再上报数据团队。

#### 6.2.6 RB-04：本地库写入失败 / 磁盘满

- **症状**：AL-04，保存失败、卡顿。
- **诊断**：查磁盘水位（§8.1.4）、C-01 文件权限。
- **缓解**：清理本机空间 / 导出并重建 C-01（从备份还原）；DDL 变更按 §6.1.3 回滚。
- **升级**：数据损坏无法还原 → 上报并启动备份恢复。

#### 6.2.7 RB-05：密钥加载失败

- **症状**：AL-05，依赖外部 API 的功能不可用。
- **诊断**：查 `.env`（gitignored）是否存在、Keychain 是否可访问。
- **缓解**：确认 `_load_local_dotenv()` 加载路径；重建 Keychain 条目；回退至 `.env` 引用（L2）。
- **升级**：密钥源不可用 → 上报平台。

#### 6.2.8 RB-06：性能相对基线退化

- **症状**：AL-06，单接口相对基线（U-05）P95 退化。
- **诊断**：查性能大盘、慢请求采样、本机资源水位。
- **缓解**：本地资源紧张 → 关闭非必要进程；代码回归 → 回退上一版本。
- **升级**：持续退化 → 性能专项排查。

> - **accessibility 属性**：统一采用 **`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`**——仅设备解锁时可访问、不随 iCloud 钥匙串同步（ThisDeviceOnly，密钥不出本机，契合本地单用户无公网形态）、锁屏后不可读；最契合本期安全边界，直接影响安全侧 §6 密钥保管设计（我已据此结论，若与安全侧最终稿不符请回注）。

### 7.4 主机流量规则、信任域与安全组件登记（安全侧权威，原样落位）

#### 7.4.1 信任域与信任边界（与安全侧 TZ-0~TZ-5 / TB-1~TB-6 对齐）

- 本部署唯一**信任域 = loopback-only**（对应安全侧 TZ-0 本地回环信任域）；VPC / 子网 / CIDR 双方均判 N/A。
- 信任边界 TB-1~TB-6 中，本部署实际涉及 **TB-2（后端回环 Token 主控制点）**：对应 FW-03，后端 :8000 全部业务路由强制回环 Token + Host 头白名单。
- 其余信任边界（如跨进程 / 跨用户边界）在本期单机单用户形态下不涉及。

#### 7.4.2 主机流量规则 FW-01 ~ FW-09（安全侧权威，编号与命名不得自造）

| 规则号 | 方向 | 主体 | 目标 | 动作 | 说明 |
| --- | --- | --- | --- | --- | --- |
| FW-01 | 入站 | 任意非本机来源 | 本机全部端口 | 拒绝 | macOS 应用防火墙"阻止所有传入连接" |
| FW-02 | 入站 | 同机进程 | `127.0.0.1:3000` | 允许 | 回环层无法区分调用方，管控下沉应用层 |
| FW-03 | 入站 | 同机进程 | `127.0.0.1:8000` | 允许 + 应用层强制 Token | TB-2 主控制点 |
| FW-04 | 出站 | `curis-desktop` 壳进程 | 任意公网 | 拒绝 | 壳自身无出站业务需求 |
| FW-05 | 出站 | 后端 Python 进程 | 出站域名白名单 `:443` | 允许 | 仅模型 API 与身份提供方 |
| FW-06 | 出站 | 后端 Python 进程 | 白名单外任意目的地 | 拒绝 + 告警 | 防凭据外投与数据外传 |
| FW-07 | 出站 | 前端 Node 进程 | 任意公网 | 拒绝 | `next start` 运行期无出站需求 |
| FW-08 | 出站 | 构建期工具（pnpm/pip/cargo） | 依赖仓库域名白名单 `:443` | 仅构建期允许 | 运行期一律关闭 |
| FW-09 | 入站 | 任意 | `22`/`3306`/`5432`/`6379`/`27017` | 拒绝 | 本机不应监听，防误起 |

#### 7.4.3 端口与监听清单

> 同 §3.1.3；本部署仅登记 `3000/tcp`、`8000/tcp`（均绑定 `127.0.0.1`），`3001/tcp` 运行期未监听（R-3 移除），其余端口未登记即违规。

#### 7.4.4 安全组件不适用登记（与安全侧 §3.4 对齐）

| 安全组件 | 判定 | 演进触发条件 |
| --- | --- | --- |
| DDoS 高防 | 不适用 | 服务端化 / 公网暴露且面临 DDoS 风险时引入 |
| WAF | 不适用 | 同机攻击者可绕过任何位于网络路径上的 WAF，投入产出比为负；公网暴露且需七层防护时重新评估 |
| 云防火墙 | 不适用 | 多实例 / 多租户云化时引入 |
| NAT 网关 | 不适用 | 服务端出网统一管控需求时引入 |
| 堡垒机 | 不适用 | 多运维人员 / 远程运维时引入 |
| SOC | 不适用 | 多系统集中安全运营时引入 |
| 云 KMS | 等价替换 | 由 **macOS Keychain + Secure Enclave** 承接（实例 `keychain://com.curis.desktop`），无需独立云 KMS |

#### 7.5 部署前置条件（磁盘加密 / FileVault，SEC-U-02 方案 A 承接）

- **用户裁决原文（一字不改引用）**：「本机应用无需加密，但这个点需要记录，未来本机测用完拆分走商业化要做加密」
- **三层兜底方案 A（不做数据库层加密）**：由 ① FileVault 全盘加密 ② 文件权限 0600 / 目录 0700（§2.2.2 / §6.1）③ 启动期权限校验（§4.5.4 / §7.1.12）三层承接；存储引擎维持 **SQLite + rusqlite 0.31.0，不引入 SQLCipher**。
- **FileVault 启动期检测（prod，不阻断启动）**：应用**启动期检测 FileVault 状态**；未开启时给出**持续性安全告警**，**不阻断启动**（与安全侧 §2.1.2「锁屏策略关闭时显示持续性提示不阻断」口径一致，最终以安全侧 §5~§8 为准）。prod 分发文档须标注"运行前请确认 FileVault 已开启"提示。
- **dev / int**：未开启同样发出持续性告警，不阻断。
- **商业化前置项登记（演进触发）**：**SQLCipher 全库加密**列为商业化前置项，触发条件＝形态转多用户 / 服务端化、出现第二名使用者或数据离开本机、进入商业化分发、或 Owner 裁定「本机测用完拆分走商业化」节点到达；届时由服务端化方案引入库级透明加密（与 §8.1.3 演进路径一致）。
