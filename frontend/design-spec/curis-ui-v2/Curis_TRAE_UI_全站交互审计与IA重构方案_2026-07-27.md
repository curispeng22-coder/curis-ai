# Curis TRAE UI 全站交互审计与 IA 重构方案

Status: Deprecated

> 审计对象：`curis-ceo-office` 静态原型
>
> 审计时间：2026-07-27
>
> 结论：视觉主题已基本统一，但全站还不是完整交互产品；当前主要缺口是导航信息架构、真实入口关系、配置流和状态诚实性。

## 0. 上次已完成内容（本次不重复执行）

- 已有微信小程序研发项目详情页与小红书自动化 Workflow 详情页。
- 两个详情页均有“创建配置”原型流：填写信息后进入本地“已创建草稿”状态，未声称已写入后端。
- 两个详情页均有执行员工头像与对话框资源配置入口，可按范围切换模型、Skill、Tool；员工之间的选择互不覆盖。
- Workflow 详情页有“试运行预览”，只更新本地预览状态，不触发真实发布。
- 项目中心已有“新建项目（示例）”入口与两个具体项目示例入口。

## 0.1 本轮已落地的原型调整

- 全站统一导航脚本已覆盖 47 个页面：一级入口保留默认首页，项目对象不再进入侧栏；移动端使用抽屉导航。
- 项目中心部门入口改为“部门项目合集 + 搜索/状态筛选”，项目卡片再进入具体详情。
- 组织中心新增可见的系统内置“人事部”，标注“默认存在”，员工唯一创建入口位于人事部员工管理页。

- 能力中心的模型/Skill/Tool/Workflow 新增入口已改为可点击路径。

### 1.1 已发现的直接问题

1. 侧栏把中心、子域、维度页和对象详情全部作为链接暴露；虽然有折叠样式，DOM 和视觉仍然让用户误以为它们是同级入口。
2. 项目中心的“部门项目空间”仍直接展示项目名称，项目越多侧栏和页面越长；项目卡片中还出现同一项目重复出现在多个部门的示例数据。
3. 经营分析、知识中心、执行工作台等页面沿用相同的多层链接，但没有统一的默认首页、面包屑和返回语义。
4. `company-runtime.html` 和两个新项目详情页没有统一产品侧栏，用户进入后会失去当前产品位置。
5. 项目中心、组织中心和能力中心的筛选/新增控件有“看起来可操作、实际未接入”的情况；例如“新建部门”“新增能力”当前为 disabled，页面仍用正常业务数字和实时措辞。
6. 组织中心没有人事部作为员工唯一管理入口；员工头像是总览展示，不能自然进入员工详情，也没有“创建后分配部门/项目”的路径。
7. 能力中心已经有模型卡片和 `capability-model-list.html`，但模型没有被定义成独立能力域，用户无法像 WorkBuddy 一样进入模型目录、查看能力差异并在上下文中选择。
8. 现有页面大量固定宽度和大卡片布局；390 宽度必须改成抽屉导航、单列/两列卡片和可滚动分段，不能让桌面侧栏与内容同时占据屏幕。

## 2. 建议的信息架构

原则：一级导航只代表产品中心；二级只代表稳定子域；三级对象（具体项目、员工、Skill、运行记录）只能从列表、空间卡片或上下文入口进入。

### 2.1 固定一级导航

| 一级中心 | 默认首页 | 仅保留的二级 | 三级对象入口 |
|---|---|---|---|
| 总裁办公室 | 总部驾驶舱 | 决策中心、重要汇报、战略会议室 | 公司运行视图从驾驶舱入口进入 |
| 项目中心 | 全部项目总览 | 部门项目合集（研发部项目、内容增长部项目等） | 项目列表/搜索/筛选进入具体项目 |
| 组织中心 | 组织总览 | 部门空间；人事部员工管理 | 员工详情、部门详情、项目分配 |
| 能力中心 | 能力总览 | 模型、Skill、Tool、Workflow | 能力详情、安装/启用、绑定员工或项目 |
| 经营分析 | 经营总览 | 组织维度、项目维度、Workflow 维度 | 指标详情和来源说明 |
| 头脑风暴室 | 会话总览 | 进行中的会话、产出结果 | 会话详情 |
| 知识中心 | 知识总览 | 公司级、项目级、部门级知识 | 知识条目详情 |
| 执行工作台 | 执行总览 | 任务队列、运行记录 | 任务/运行详情 |
| 公司设置 | 设置总览 | 公司档案、品牌与视觉、通知设置 | 设置项详情 |

不再作为导航节点：具体项目名、具体员工名、具体 Skill/Tool 名、公司运行视图、项目详情、任务详情、运行详情。

### 2.2 项目中心导航规则

- 侧栏只显示“研发部项目”“内容增长部项目”等部门合集，不显示“微信小程序研发项目”“小红书自动化 Workflow”等对象名。
- 部门项目合集首屏提供搜索、状态、负责人、项目类型和更新时间筛选。
- 具体项目进入详情后用面包屑：`项目中心 / 研发部项目 / 微信小程序研发项目`。
- 项目数量增长时只增加列表数据，不增加导航节点。
- “新建项目”保留在项目中心首页与部门项目合集页；详情页只显示项目内操作。

### 2.3 组织中心导航规则

- 组织总览保留 AI 研发中心、AI 内容中心等空间模块。
- 人事部是系统管理部门，显示在部门空间中并带“员工管理”标识。
- 新员工只能从人事部员工管理页创建；部门页不再出现“新增员工”，改为“从人事部调配”。

## 3. 统一导航与页面壳

### 3.1 桌面端

- 所有页面使用同一个侧栏组件、同一品牌区、同一选中态和同一展开态。
- 一级字号/字重高于二级；二级缩进、低对比度、带 chevron；不使用裸 `+` 表达层级。
- 只展开当前一级；切换一级时自动收起上一组。
- 主内容固定包含：面包屑、页面标题、状态说明、主操作区。

### 3.2 1024 与 390

- 1024：侧栏收窄为图标+当前标题，二级在悬浮/展开面板显示。
- 390：侧栏变为抽屉；顶部保留当前一级标题和返回入口；禁止桌面侧栏与正文并排。
- 卡片从多列降为单列或两列；表格改为信息卡；筛选改为底部抽屉。
- 所有页面必须通过同一套 `overflow-x: hidden` 和断点规则，不能逐页临时修补。

## 4. 三个创建页

### 4.1 新建部门

推荐采用“模板优先，自定义可选”的四步流：

1. 选择模板：AI 研发中心、AI 内容中心、空白部门；模板卡明确“包含哪些空间、默认角色、默认能力”。
2. 部门身份：名称、目标、负责人、所属公司空间。
3. 运行配置：默认项目视图、可用能力范围、汇报规则；未知项显示“未配置”，不能填假值。
4. 确认创建：显示将创建的空间和默认权限；原型阶段按钮标注“创建本地草稿”。

### 4.2 创建项目

同样采用“业务模板优先，通用模板兜底，自定义补充”：

1. 选择模板：研发项目、内容增长 Workflow、通用业务项目、空白项目。
2. 基本信息：项目名称、所属部门、负责人、目标、时间范围。
3. 业务块：从 Admin 拆解好的固定业务块中选择；没有专属模板时使用通用业务块（目标、阶段、任务、产出、审批、复盘）。
4. 执行配置：员工、模型、Skill、Tool、Workflow 的默认绑定；允许在详情页按员工或对话覆盖。
5. 确认：列出“会创建的页面块”和“尚未接入的能力”，避免用户误以为已经接通运行时。

### 4.3 新增员工

入口只放在 `组织中心 / 人事部 / 员工管理`：

1. 选择员工模板或自定义：研发工程师、内容策划、审核员、通用执行员、空白员工。
2. 身份与职责：名称、岗位、职责描述、负责人/汇报关系。
3. 默认能力：模型、Skill、Tool；每项都显示来源（官方、公司自定义、项目覆盖）和未接入状态。
4. 分配关系：选择部门、一个或多个项目、项目内角色；默认先归属人事部，再挂载业务部门/项目。
5. 权限与确认：可见范围、可执行动作、状态；确认后进入“草稿员工”或真实创建状态。

部门详情页只允许“从人事部调配员工”或“编辑分配”，不提供第二套创建员工流。

## 5. 能力中心重规划

### 5.1 目录结构

能力中心保留四个稳定模块：`模型`、`Skill`、`Tool`、`Workflow`。

- Agent 不再作为与模型/Skill/Tool 并列的能力目录；它是员工的执行身份，在员工详情和执行配置中出现。
- 模型是独立模块，不只是能力总览中的一张卡片。
- 每个模块都有列表、详情、搜索、分类、状态和安装/绑定状态。

### 5.2 参考 WorkBuddy 的展示方式

- 顶部：模块切换、搜索、我的已安装/已启用、添加入口。
- 第二层：精选/推荐、公司自定义、按业务类别筛选。
- 卡片：图标、名称、类型、用途描述、来源、状态、适配对象、最后更新时间。
- 卡片操作：查看详情、安装/启用、加入员工默认配置；无接入能力时显示原因，不显示假按钮。

### 5.3 模型模块必须展示

每个模型卡片至少包含：提供方、模型 ID、文本/图像/代码等模态、上下文限制、可用状态、成本字段（未知则显示“未记录”）、适用场景、当前是否为公司默认模型。

模型选择器与当前已完成的对话/员工头像资源切换共用同一目录；选择结果只对当前对话、员工或项目范围生效，并显示覆盖层级。

## 6. 组织中心与人事部规则

- 组织总览首屏增加固定“人事部 · AI 员工管理”卡片，显示员工总数、未分配数、待配置数。
- 点击人事部进入员工合集，可搜索、按部门/项目/状态筛选，点击员工进入详情。
- 新建员工按钮只在该页面出现；其他部门页面显示“从人事部调配”。
- 员工创建后默认存在于人事部，再通过创建/编辑流程分配至业务部门和项目。
- AI 研发中心、AI 内容中心仍是部门空间模块，不改成后台树菜单。
- “实时”“运行正常”等措辞必须有数据来源；只有快照或示范数据时统一写“示例快照/未接入”。

## 7. 页面级交互验收清单

每页必须回答以下问题，缺一项即不能算完整：

1. 从统一侧栏进入后，一级默认首页是否明确？
2. 页面是否有面包屑、当前对象上下文和唯一主操作？
3. 所有看起来能点的筛选、卡片、按钮是否有结果？未接入是否明确禁用原因？
4. 列表、空态、正常态、异常态是否都存在，且没有把示范数据写成真实运行数据？
5. 创建、编辑、分配、返回、取消、保存后的状态是否可见？
6. 1440、1024、390 是否使用同一导航和同一信息顺序，且无横向溢出？
7. 三级对象是否只从列表/卡片进入，而不是污染侧栏？

## 8. 建议实施顺序

1. 先统一页面壳和导航树，移除对象级导航，补齐三个无侧栏页面。
2. 再重做项目中心部门合集与项目搜索入口。
3. 再补人事部员工管理和三个创建页。
4. 再把能力中心拆成模型/Skill/Tool/Workflow 四个目录，并复用现有资源选择器。
5. 最后逐页做 1440/1024/390 交互验收；未确认的页面不进入下一页实现。

## 已确认的产品决策

“人事部”作为组织中心的一员可见，但属于系统内置部门：首次进入即存在、不可在“新建部门”流程中重复创建；所有 AI 员工先归属人事部，再在创建/编辑流程中分配至业务部门和项目。其余重构按第 8 节顺序实施。
