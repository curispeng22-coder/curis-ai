## 0. 交付物

| 交付物 | 文件 | 用途 |
|---|---|---|
| Figma 高保真稿契约 | `figma/curis-ui-v2.frames.json`、`figma/curis-ui-v2.interactions.json` | 页面、组件、状态、原型连线的唯一清单；现有 HTML 路由是 frame source |
| Figma Dev Mode 标注 | `figma/curis-ui-v2.tokens.json` + 本文第 3 节 | 尺寸、颜色、字号、间距、响应式与组件标注，前端直读 |
| 可 diff 规格 Markdown | `curis-ui-v2-handoff.md` | 信息架构、页面结构、状态、数据映射、验收规则 |
| 逐页字段映射 | `curis-ui-v2-data-map.json` + `curis-ui-v2-secondary-page-contracts.json` | 47 个页面的字段、主操作、状态和数据事实命名；前者为 19 个核心面，后者补齐 28 个二级/三级面 |
| 本地高保真预览 | `exports/{1440,1024,390}/` | 47 页面 × 3 个尺寸；`states/catalog-{size}.png` 为状态目录 |

本地替代方案不依赖 Figma：前端直接以 HTML 原型、PNG 预览、Token JSON、交互 JSON、字段映射 JSON 和本 Markdown 为事实源。`exports/1440`、`exports/1024`、`exports/390` 各有 47 张页面截图；`figma/curis-ui-v2.all-pages.json` 是全量页面清单；`states/` 提供 Hover/Focus/Drawer/Empty/Partial/Error/Disabled/Success 的状态目录。若未来接入 Figma，JSON 可作为导入清单，但不阻塞前端实现。

## 1. 画布与页面骨架

### 1.1 三个基准 Frame

| Frame | 尺寸 | 左侧导航 | 内容区 |
|---|---:|---:|---|
| Desktop | 1440 × 900 | 220px 固定 | 24px 侧边内距，12 栏，gap 14px |
| Tablet | 1024 × 768 | 76px 图标态 | 20px 侧边内距，12px gap |
| Mobile | 390 × 844 | 关闭时不占位；打开为 286px 抽屉 | 16px 内距，单列优先 |

所有页面共享：`body → .canvas → .curis-nav-v2 → .main`。导航只保留稳定产品空间；三级对象从中心列表或卡片进入。

### 1.2 一级页面 Frame

1. 总裁办公室 / 总部驾驶舱（默认首页）
2. 项目中心 / 全部项目总览
3. 组织中心 / 组织总览
4. 能力中心 / Agent、Model、Skill、Tool、Workflow
5. 经营分析 / 组织、项目、Workflow 维度
6. 决策中心
7. 重要汇报
8. 战略会议室
9. 头脑风暴室
10. 知识中心
11. 执行工作台
12. 公司设置
13. 公司运行视图（由总部驾驶舱入口进入，不作为总裁办公室下级导航）

对象级 Frame：研发部项目合集、小红书项目详情、微信小程序项目详情、人事部员工管理、新建部门、新增员工。

## 2. 统一导航交互

### 2.1 层级

- 一级：14px / 600，主色背景，图标 + 文案 + chevron。
- 二级：12px / 500，左缩进 35px，低对比度；不使用裸 `+`。
- 一级点击：进入该一级默认首页；chevron 点击：仅展开/收起二级。
- 当前组默认展开；当前二级使用左侧 2px 指示条和浅色背景。
- 项目中心二级只展示“研发部项目、内容增长部项目、产品部项目、运营部项目”，不展示具体项目名称。
- 组织中心固定展示“人事部 · 员工管理”；人事部是系统内置部门，不能从新建部门流程重复创建。

### 2.2 状态

| 状态 | 视觉 | 行为 |
|---|---|---|
| 默认 | 透明背景、白色 72% | 可点击 |
| Hover | 白色 10% 背景、轻微右移 1px | 不改变布局 |
| 当前一级 | 白色 16% 背景、文字白色 | 默认首页链接可点击 |
| 当前二级 | 白色 7% 背景、左侧 2px 线 | 进入子域/维度 |
| Drawer open | 286px 抽屉 + 半透明遮罩 | 点击遮罩关闭 |
| Focus | 主色 2px focus ring | 键盘可达 |

## 3. Dev Mode 标注

### 3.1 Token

直接使用 `figma/curis-ui-v2.tokens.json`。禁止在页面内新造同义色或字号。

### 3.2 核心组件

| 组件 | 尺寸/样式 | Figma 标注 |
|---|---|---|
| Page title | 24px / 700 / Literata / line-height 1.1 | `Title/Page` |
| Card title | 15px / 600 / Literata / line-height 1.3 | `Title/Card` |
| Body | 14px / 400 / Nunito Sans / line-height 1.6 | `Text/Body` |
| Helper | 11px / 400 / Nunito Sans / line-height 1.45 | `Text/Helper` |
| Card | surface、1px line、16px radius、shadow-sm | `Surface/Card` |
| Primary button | 8px 16px padding、8px radius、12px / 700 | `Action/Primary` |
| Secondary button | 1px line、8px radius、same height | `Action/Secondary` |
| Empty state | 32px 内边距；图标、说明、唯一主操作 | `State/Empty` |
| Error state | errorSurface、错误原因、重试 | `State/Error` |

### 3.3 响应式

- 1440：导航 220px；所有主模块使用桌面信息顺序。
- 1024：导航收缩到 76px，只保留图标；二级隐藏，内容仍按原顺序。
- 390：导航改为左侧抽屉；页面单列；表格转为卡片或横向滚动容器；主按钮全宽；不允许横向溢出。
- 不因响应式改变信息层级、按钮文案或数据状态。

## 4. 逐页结构与交互

### 4.1 总裁办公室

- 首屏：公司状态、当前核心项目目标、待处理汇报、运行视图入口。
- 主操作：进入公司运行视图；未接入时显示原因，不显示绿色“运行正常”。
- 状态：Loading 骨架、空公司创建入口、局部失败重试、完整错误态。

### 4.2 项目中心与部门项目合集

- 项目中心：全部项目总览、状态筛选、搜索、新建项目。
- 部门合集：部门标题、项目搜索、状态筛选、项目卡片、空结果提示。
- 卡片点击进入具体项目详情；项目名称不进入导航。
- 新建项目进入项目详情创建流，提交只显示本地草稿成功，不伪造后端写入。

### 4.3 组织中心与人事部

- 组织总览：组织事实、部门空间、人事部固定卡片、AI 研发中心/AI 内容中心空间。
- 人事部卡片：`系统部门 / 默认存在 / 员工唯一管理入口`。
- 员工管理：搜索、部门/项目/状态筛选、员工详情入口、新增员工。
- 新增员工：初始归属锁定人事部；业务部门和项目为后续分配字段。

### 4.4 能力中心

- 顶部目录：Agent、模型 Model、Skill、Tool、Workflow。
- 新增入口：新增能力、新增 Skill、添加工具、新增工作流；每个入口有明确路由或未接入原因。
- 模型卡至少展示提供方、模型 ID、模态、上下文限制、成本（未知为“未记录”）、可用状态、适用场景、默认标识。
- 资源选择器与项目详情的对话框/员工头像共用目录；选择结果显示作用范围。

### 4.5 经营分析、决策中心、重要汇报、战略会议室

- 四页共用同一标题基线：24px Literata / 700，顶部对齐。
- 经营分析：组织、项目、Workflow 三个维度；指标无来源时显示“未记录”。
- 决策中心：待决事项、上下文、决策记录；批准/补充信息必须有结果态。
- 重要汇报：待审阅、已审阅、归档；点击列表项进入阅读上下文。
- 战略会议室：会议空间、当前上下文、时间线；发起会议后进入草稿/进行中状态。

### 4.6 头脑风暴、知识、执行、设置、运行视图

- 统一首屏标题、返回语义、卡片头、空态和错误态。
- 执行工作台是次级入口，不抢占 CEO Office 默认首页。
- 公司运行视图从驾驶舱进入；运行事实未读取时统一显示“未读取事实”，不填假数字。

## 5. 三类配置流

### 新建部门

1. 输入部门名称与目标。
2. 选择通用部门模板或自定义配置。
3. 预览部门边界。
4. 生成草稿；人事部系统部门不可在此创建。

### 创建项目

1. 输入项目名称、目标、类型。
2. 选择部门合集归属。
3. 配置负责人、员工、模型、Skill、Tool、Workflow。
4. 创建项目草稿并进入详情。

### 新增员工

1. 输入员工名称、岗位职责。
2. 初始归属锁定人事部。
3. 可选分配业务部门与项目。
4. 生成员工草稿；后续可在员工详情编辑分配。

三条流程的取消、返回、提交成功、校验错误都必须可见；原型提交不调用后端。

## 6. 数据与状态映射

| UI 字段 | 数据规则 | 无数据时 |
|---|---|---|
| 数量/状态 | 只渲染真实读取或明确快照 | `未记录` |
| 来源时间 | 显示读取时间/快照时间 | `尚未同步` |
| 负责人 | 对象 owner | `未分配负责人` |
| 项目/部门 | 关系字段 | `未分配` |
| 成本 | 后端成本字段 | `未记录`，不得写 `$0` |
| 运行状态 | execution/workflow 事实 | `未读取事实` |
| 示例数据 | 仅原型演示 | 必须标记 `示例快照 · 未接入真实数据` |

## 7. 前端验收清单

- [ ] 1440 / 1024 / 390 使用同一页面信息顺序。
- [ ] 所有一级标题均为 24px / Literata / 700。
- [ ] 所有页面导航宽度、颜色、层级和展开行为一致。
- [ ] Hover、点击、Focus、Drawer、Empty、Partial、Error、Disabled 均有明确状态。
- [ ] 点击一级导航进入默认首页；项目对象不污染导航。
- [ ] 人事部默认存在、不可重复创建；新增员工入口只在人事部员工管理出现。
- [ ] 所有按钮有结果、明确禁用原因或明确未接入状态。
- [ ] 不把示例数据写成真实运行事实，不出现假操作成功。
- [ ] 通过 `git diff --check`；截图与 Figma Frame 一一对应后才交系统交付席。

## 8. 交付边界

本套件只定义 UI、信息架构、状态和前端交互；不授权新增 API、数据库、Admin、凭证、计费或 Workflow Runtime。前端实现必须以本套件和现有原型为事实源，任何新增页面或改变导航层级需先回产品规划席。
