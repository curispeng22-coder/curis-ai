# 项目中心 vs 组织中心 职能划分 + Terra 协调扩展配色

> 依据：用户对 `Trae交互设计问题检查.md` 的三点澄清（2026-07-26）
> 配套：本文档修正了前次检查报告的 P1-1 / P1-3 / P2-2 三处判断，详见文末「对前次检查报告的勘误」。
> 适用范围：CEO Office 全站信息架构、配色 token、员工详情规范。

---

## 1. 核心结论：两个中心是"同一家公司"的两种镜头

我们的模型：**组织层 = 公司 → 部门 → 项目 → 员工**。项目与部门同时出现在两个中心，但语义不同：

| 镜头 | 中心 | 回答的问题 | 部门的角色 | 项目的角色 |
| --- | --- | --- | --- | --- |
| **结构镜头** | 组织中心 | 「公司现在由谁组成、归谁管」 | **结构实体**（有部门详情页） | 组织树上的**节点**，链接出去看详情 |
| **工作镜头** | 项目中心 | 「项目推进得怎样、怎么管」 | **分组导航**（仅用于查找，不另立结构页） | **主对象**（详情页承载全生命周期） |

一句话：**组织中心里部门是" owner "，项目中心里部门是" shelf label "**。两者都出现部门/项目，但一个是"它在哪"，一个是"怎么找/怎么推进"，不冲突。

```
组织中心:  公司 ─ 部门(实体) ─(部门详情)─ 项目(节点, 链接到项目中心) ─ 员工
项目中心:  [按部门分组] ─ 项目(主对象) ─(项目详情)─ 任务图 / 验收 / 返工 / 产出
知识中心:  [按部门分组] ─ 知识条目(主对象) ─(条目详情)            ← 同分组模式
```

## 2. 内容归属表（哪些进组织中心、哪些进项目中心）

### 组织中心 ——「公司组织全貌」（结构 / 目录视角）
- **一级**：组织总览
  - 组织事实：部门数 / 员工数 / 阻塞部门 + 新建部门
  - 组织空间总览：CEO → 部门 轨道图（自顶向下）
  - 部门空间：各部门卡（职责 / 当前项目**链接** / 工作状态 / 依赖 / 员工头像条）
  - AI 员工头像条
- **二级**：部门空间（`org-dept.html`）→ 部门详情（职责 / 成员 / 下属项目 / 资源 / **新增员工**主操作）；AI 员工（`org-employees.html`）
- **三级**：具体部门 / 具体员工

### 项目中心 ——「项目运作视图」（工作 / 生命周期视角）
- **一级**：项目总览
  - 项目组合事实：项目总数 / 运行中 / 阻塞 / 已完成 + 新建项目
  - 全部项目（**按部门分组导航**：部门作分组头/筛选维度，之下为项目卡；部门分组仅用于查找，不另立部门结构页）
  - 项目组合状态时间线
- **二级**：点击某部门分组 → 该部门项目列表（**筛选视图**，非新结构页）
- **三级**：具体项目详情（目标 / 范围 / 动态任务图 / 运行状态 / **验收** / **返工** / 产出 / 风险）

### 边界红线（避免重复入口）
- 组织中心里，项目**只**作为部门详情内的链接节点出现，绝不与「项目中心」并列成双入口。
- 项目中心里，部门**只**作为列表分组头出现，绝不开「部门详情」（那是组织中心的职责）。
- 知识中心同理：知识条目按部门分组（多一层归类），但部门详情仍归组织中心。

## 3. AI 员工头像：保留，且与「能力绑定」正交

**澄清**：AI 员工**需要头像**，未来还需增加「上传头像」功能做人员区分。我前次 P1-3 把"头像"与"固定 Agent 角色"混为一谈，是错误的。

正确的区分：
- **头像 / 角色名** = 员工的**视觉身份**（用于人员区分），应保留，未来支持上传。
- **可调用能力集**（该员工能调哪些 Skill / Tool / 模型 / 绑定哪些权限）= **数据驱动的动态绑定**，来自能力层，不写死。

所以员工详情页应**同时呈现**两者，而非二选一：
- 头像区（可上传）+ 角色名 + 所属部门 + 参与项目
- 「可调用能力」区块：列出当前绑定的能力（动态，随配置变化）

> 修正：Trae 给员工画头像是对的；需补的是"动态能力绑定"展示，而不是删头像。

## 4. Terra 协调扩展配色（状态色 + 5 能力类目色）

**澄清**：主题绿 `#4a7c59` + 暖琥珀 `#705c30` 是基调，没错。但状态与类目需要更多颜色增加视觉区分——只要气质统一（低饱和、暖调为主、和谐落在 `#faf6f0` 奶油底上），不突兀即可。

### 4.1 既有语义色（保留，已 earthy）
| 变量 | HEX | 用途 |
| --- | --- | --- |
| `--green` | `#15935a` | 成功 / 可用 |
| `--cyan` | `#3f7d6e` | 信息 / AI 内容 |
| `--amber` | `#a8742a` | 待决 / 阻塞 / 警告 |
| `--red` | `#b83230` | 错误 / 失败 |

### 4.2 新增能力类目协调色（earthy，对应 5 大类）
| 类目 | 变量 | HEX | 软背景 | 用途 |
| --- | --- | --- | --- | --- |
| Agent | `--cat-agent` | `#3f6b4a` | `--cat-agent-soft #eaf1eb` | Agent 类能力标识（深苔绿，区别于 success 绿） |
| 模型 Model | `--cat-model` | `#5a7a8a` | `--cat-model-soft #eaf0f3` | 模型类（灰蓝，冷但克制） |
| Skill | `--cat-skill` | `#b8893b` | `--cat-skill-soft #f7f0e3` | Skill 类（赭金，暖） |
| Tool | `--cat-tool` | `#b5563f` | `--cat-tool-soft #f7ede9` | Tool 类（陶土红，暖） |
| Workflow | `--cat-workflow` | `#7a6b8a` | `--cat-workflow-soft #f1eef3` | Workflow 类（灰紫，earthy） |

### 4.3 气质规则（硬约束）
1. 饱和度 ≤ 40%，无荧光 / 无霓虹；全部和谐落在 `#faf6f0` 奶油底。
2. **状态色优先于类目色**：一个「阻塞的 Skill」用 `--amber`（状态），不用 `--cat-skill` 金；类目色只在"正常/中性"时用于区分大类。
3. **部门不加独立彩虹色**：部门用中性 / 主绿，避免"颜色太多反而乱"；分组导航靠文字 + 主绿，不靠色块。
4. 能力卡 / 标签用「类目软背景 + 类目深字」，不用满铺高饱和实色。
5. 头像底色从以上 5 类目色取（区分人员），但同部门内不强制同色，避免误导"部门=某色"。

> 修正：Trae 的问题不是"用了其他颜色"，而是用了过饱和的青 `#2a9daa` / 蓝 `#3a6a9a` / 紫 `#7a5aaa`（突兀）。替换为上表 earthy 系列即可，而非退回纯两色。
