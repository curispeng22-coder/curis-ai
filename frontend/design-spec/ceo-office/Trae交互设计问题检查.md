# Trae CEO Office 交互设计 · 问题检查报告

> 检查基准（我们已确认的产品规划与架构）：
> - **三层模型**：组织层（公司→部门→项目→员工）/ 运行层（目标澄清→规划→动态任务图→队列→调度→执行→验收→返工→完成）/ 能力层（Agent / 模型 / Skill / Tool / Workflow，经适配器接入；MCP/API/CLI/Connector/Webhook 是 Tool 子类）
> - **四条不可动摇原则**：①全自动任务流是核心 ②能力可替换不写死具体产品 ③员工非固定 Agent、是动态调用能力的岗位 ④任何开发须让「目标→执行→验收→返工→完成」更自动
> - **9 一级导航**：总裁办公室 / 组织中心 / 项目中心 / 能力中心 / 经营分析 / 头脑风暴室 / 知识中心 / 执行工作台 / 公司设置
> - **Terra 调色板**：仅 主绿 `#4a7c59` + 暖琥珀 `#705c30` + 4 个状态色（绿/琥珀/红/青绿），禁止彩虹硬编码色（SPEC §9 色彩一致性）
> - 检查对象：Trae 交付 23 页（路径 `…/curis-ceo-office/pages/`），读全了 `capability-center.html` / `org-center.html` / `workbench.html` + `SPEC.md`

> ⚠️ **2026-07-26 勘误（用户澄清后修正）**：以下三处原判断需修正，详见 `项目中心与组织中心职能划分.md` §5：
> - **P1-1（部门双重归属）**：原判"项目中心不应有部门入口" → 修正为**两边部门语义不同（结构实体 vs 分组导航），属合理分工非重复入口**；红线仅限"并列的部门详情页"。
> - **P1-3（AI 员工固定 Agent）**：原判"不应画固定头像" → 修正为**头像/角色名=视觉身份应保留且未来可上传**；需补的是"动态能力绑定"展示，不是删头像。
> - **P2-2（彩虹硬编码色）**：原判"禁其他色" → 修正为**需扩展协调色（状态色+5类目色），气质统一即可**；禁的是过饱和突兀色，非禁多色。

## 总评

整体**信息架构（9 一级 + 树形子导航）正确、空态/错误态/边界组件齐全、能力中心 5 大类 + Tool 子类分类是对的**——骨架合格。但**在页面内的数据逻辑、色彩纪律、运行层完整性上有多处硬伤**，其中部分属于"看起来漂亮但数据/逻辑站不住"的隐患，不是纯视觉问题。按严重程度分三档：

- **P0（必须修，属渲染/数据错误）**：2 项
- **P1（架构/逻辑冲突，需重做局部）**：4 项
- **P2（排版/一致性漂移，建议统一）**：4 项

## P0 — 必须修（渲染与数据错误）

### P0-1 能力中心大量占位符未替换（`$5$6` 裸字符）
- 文件：`capability-center.html` 行 678 / 703 / 727 / 762 / 791
- 现象：卡片预览行出现字面量模板变量，例如
  - 678：`<span>Code Reviewer - 异常$5Code Reviewer - 异常$6</span>`
  - 703：`<span>Claude 3.5 - $0.04/1k</span>$5Whisper - 维护中$6</span>`
  - 762：`<span>PostgreSQL - 正常</span>$5Docker - 正常$6</div>`
- 问题：模板引擎未替换的占位符 + 多余的 `</span>`，**用户会直接看到乱码**。属交付质量硬伤。
- 修法：把 `$5…$6` 区间替换成真实预览文案（如 `Code Reviewer - 异常`），并修正标签闭合。

### P0-2 能力中心"接入状态"与"来源"两组计数自相矛盾
- 文件：`capability-center.html` 行 806–833
- 现象：
  - 能力接入状态：可用 **24** + 阻塞 **3** = **27**
  - 能力来源：官方 **18** + 自定义 **14** = **32**
  - 而 5 个模块卡徽标之和 = 6+4+12+8+2 = **32**（与"来源"一致，与"接入状态"不一致）
- 问题：同一套能力集合，按两个维度切分的总数（27 vs 32）对不上，说明数据是**拍脑袋填的、未从同一数据源派生**。前端接真实数据时此处必然对不齐。
- 修法：两组计数必须来自同一份后端聚合（可用/阻塞/官方/自定义 都基于同一集合求和，且四类加总 = 模块卡总和）。

## P1 — 架构 / 逻辑冲突（对照三层模型与四条原则）

### P1-1 "部门"双重归属，组织层 / 项目层边界模糊
- 文件：全站侧栏（`org-center.html` 行 514–521 vs `capability`？实际在 `project-center` 子导航 行 498–508）
- 现象：
  - 组织中心子导航：`部门空间`（org-dept.html）、`员工管理`
  - **项目中心子导航里也有** `部门项目空间`（project-dept.html）
- 问题：我们的模型**组织层 = 公司→部门→项目→员工**，"部门"是组织层节点，不应同时挂在"项目中心"下形成双入口。产品架构里"部门项目空间"应是"部门详情页内的一个区块"，不是与"部门空间"并列的独立入口。当前做法让用户搞不清"部门到底归组织还是归项目"。
- 修法：部门只归组织中心；项目中心下只保留"项目总览 / 项目详情"，部门视角通过"部门详情页"内的"部门项目"区块呈现。

### P1-2 组织中心数据自相矛盾（部门数、员工数、健康数都对不上）
- 文件：`org-center.html`
- 现象：
  - 顶部事实卡：**部门数 3**、员工数 24（行 642–653）
  - 轨道图 + 部门卡实际画了 **4 个部门**（研发 / 产品 / 市场 / 运营，行 713–842）
  - "AI 员工"条只列了 **8 个**（A1–A8，行 854–886）
  - "组织健康"三态计数 **全为 18**（运行正常 18 / 需关注 18 / 阻塞 18，行 747–762）
- 问题：部门数（3 vs 4）、员工数（24 vs 8 展示）、健康数（18/18/18 明显是占位复制）三处互相矛盾且明显未经推敲。**这是 P0-2 同源问题：示例数据没做一致性校验**。
- 修法：示例数据需内部自洽（部门数=轨道图节点数=部门卡数；员工数=员工条数或明确"仅展示前 N"；健康三态之和应等于某真实基数，且不为全等占位值）。

### P1-3 "AI 员工"把员工画成固定 Agent，违反原则③
- 文件：`org-center.html` 行 854–886
- 现象：把员工渲染成固定角色卡（分析师 / 策划师 / 研究员 / 顾问…），每人固定头像、固定颜色。
- 问题：我们的原则③明确——**员工非固定 Agent，是"动态调用能力的岗位"（职责+目标+权限+项目上下文+记忆+可用能力）**。当前 UI 把员工当"写死的 AI 角色"展示，既与架构冲突，也容易让人误以为"员工=Agent"。
- 修法：员工卡片应呈现"岗位 + 当前可用能力集 + 所属项目上下文"，而非固定人设头像；或直接对齐原则③改为"岗位（动态能力绑定）"的语义。

### P1-4 执行工作台缺"验收 / 返工"为一级状态，运行层不完整
- 文件：`workbench.html` 行 648–868
- 现象：页面只有「当前执行队列 / Workflow Runs / 最近 Tasks」，队列项状态是 `执行中 / 等待中 / 返工中`（行 669–704）。
- 问题：我们的运行层是 **目标澄清→规划→动态任务图→队列→调度→执行→验收→返工→完成**，且原则①说全自动任务流是核心、原则④要求「验收/返工/完成」可见。当前页：
  - **完全没有"目标澄清 / 规划 / 动态任务图"上游**和**"验收"环节**的呈现；
  - "返工"仅作为一个红 tag 埋在某行，不是流程的一级状态机。
- 修法：至少应在运行层视图里显式呈现"验收中 / 返工中 / 已完成"三态为对等的一级状态（而非 tag 附属），并补"目标→任务图"的入口/概览，让核心链路可见。

## P2 — 排版 / 一致性漂移（对照 SPEC & Terra）

### P2-1 主内容区内边距偏离 SPEC（28px vs 24px）
- 文件：所有页 `.main { padding: 24px 28px 20px }`（`capability-center.html` 行 1065、`org-center.html` 行 1029、`workbench.html` 行 974）
- SPEC §2.3 规定 `padding: 24px 24px 20px`。横向多了 4px，且 `workbench.html` 的 `.canvas` 有 `box-shadow` 而其它页没有——**画布外框处理不一致**。
- 修法：统一回 `24px 24px 20px`；canvas 投影全站统一加或不加。

### P2-2 彩虹硬编码色，突破 Terra 两色纪律
- 文件：`capability-center.html`（Agent 青 `#2a9daa`、API 蓝 `#3a6a9a`、Workflow 紫 `#7a5aaa`，行 1290–1313）；`org-center.html`（员工头像 `#5a8f9e / #6ba3b0 / #a8742a / #c08a3a / #8a7240` 等，行 791–886；轨道图青绿描边）
- 问题：SPEC §9 要求"所有颜色使用 CSS 变量、无硬编码色值"，Terra 体系本身只有绿+琥珀+状态色。能力卡用 5 种强调色、员工头像用一整条彩虹，是**为区分而区分**，破坏了 Terra 的克制气质，也绕过 token。
- 修法：类别区分优先用**图标形状 / 标签文字 / 状态色**，而非新增色相；如必须区分，新增色须先提为 token 并经设计确认，不能页内硬编码。

### P2-3 执行工作台大量行内 style，违反组件类纪律
- 文件：`workbench.html` 行 666–705、773–812、833–864
- 现象：队列/运行/任务列表行几乎全用 `style="display:flex;…"` 内联，未走 SPEC §3 的 `.card / .tag / 列表行` 组件类。
- 问题：不可维护、token 难统一、后续改间距要逐行改。其它页（如 capability-center）组件化程度更高，形成**页间不一致**。
- 修法：抽成 `.queue-row / .run-row` 等类，与 SPEC 组件层对齐。

### P2-4 侧栏品牌区 markup 各页不一致 + 项目中心"项目总览"自链
- 文件：`capability-center.html` 行 468–473 用 `<span>Curis</span>`；`org-center.html` 行 939–958 用 `<div class="sidebar-brand-name">`（多出 sub 文案）。
- 项目中心子导航"项目总览"链接到 `project-center.html` 自身（行 499），等于自己指向自己，冗余。
- 修法：侧栏品牌区统一一套 markup；删除"项目总览"自链或用"返回总览"语义。

## 结论与建议

**这版"排版好看"成立，但"作为产品交互原型"还不扎实**——主要风险不在视觉，而在：
1. 示例数据没做内部一致性校验（P0-2、P1-2），前端接真数据时会对不上；
2. 两处渲染硬伤（P0-1 占位符）会直接暴露给用户；
3. 运行层缺"验收/返工"、员工被画成固定 Agent，这两处与咱们已拍板的产品主轴**逻辑冲突**，不是改 CSS 能解决的。

**建议的修法顺序**：先修 P0（占位符 + 计数自洽）→ 再修 P1（部门归属、员工语义、运行层补验收/返工、组织数据自洽）→ 最后统一 P2（padding、token、组件化）。修完这版就能作为合格的交互原型，交给我们补 Figma 高保真 + Dev Mode 标注三件套。
