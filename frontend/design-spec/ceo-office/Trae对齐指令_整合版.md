## 3. 职能划分：组织中心 vs 项目中心（避免重复入口）

两个中心是**同一家公司的两种镜头**，都出现部门/项目但语义不同，不冲突：

| 镜头 | 中心 | 回答的问题 | 部门的角色 | 项目的角色 |
|---|---|---|---|---|
| 结构镜头 | 组织中心 | 公司现在由谁组成、归谁管 | **结构实体**（有部门详情页） | 组织树上的**节点**，链接出去看详情 |
| 工作镜头 | 项目中心 | 项目推进得怎样、怎么管 | **分组导航**（仅用于查找，不另立结构页） | **主对象**（详情页承载全生命周期） |

**边界红线（务必遵守）：**
- 组织中心里，项目**只**作为部门详情内的链接节点出现，绝不与「项目中心」并列成双入口。
- 项目中心里，部门**只**作为列表分组头/筛选维度出现，绝不开「部门详情」（那是组织中心的职责）。
- 知识中心同理：知识条目按部门分组（多一层归类），但部门详情仍归组织中心。

**内容归属速查：**
- **组织中心（结构/目录视角）**：组织总览（部门数/员工数/阻塞部门+新建部门）、CEO→部门轨道图、部门空间卡（职责/当前项目**链接**/工作状态/依赖/员工头像条）、AI 员工头像条；二级=部门空间→部门详情（含**新增员工**）、AI 员工列表；三级=具体部门/员工。
- **项目中心（工作/生命周期视角）**：项目总览（项目总数/运行中/阻塞/已完成+新建项目）、全部项目**按部门分组导航**、项目组合状态时间线；二级=点击部门分组→该部门项目列表（筛选视图）；三级=项目详情（目标/范围/动态任务图/运行/**验收**/**返工**/产出/风险）。

## 4. 配色气质规则（Terra 扩展，已对齐 DESIGN.md §3.1）

基调不变：**主绿 `#4a7c59` + 暖琥珀 `#705c30`**。状态色与 5 能力类目色允许扩展，但气质必须统一（低饱和、暖调为主、和谐落在 `#faf6f0` 奶油底）。

### 4.1 既有语义色（保留）
| 变量 | HEX | 用途 |
|---|---|---|
| `--green` | `#15935a` | 成功 / 可用 |
| `--cyan` | `#3f7d6e` | 信息 / AI 内容 |
| `--amber` | `#a8742a` | 待决 / 阻塞 / 警告 |
| `--red` | `#b83230` | 错误 / 失败 |

### 4.2 新增能力类目协调色（earthy，替换原来的过饱和青/蓝/紫）
| 类目 | 变量 | HEX | 软背景 | 用途 |
|---|---|---|---|---|
| Agent | `--cat-agent` | `#3f6b4a` | `#eaf1eb` | Agent 类（深苔绿，区别于 success 绿） |
| 模型 Model | `--cat-model` | `#5a7a8a` | `#eaf0f3` | 模型类（灰蓝，冷但克制） |
| Skill | `--cat-skill` | `#b8893b` | `#f7f0e3` | Skill 类（赭金，暖） |
| Tool | `--cat-tool` | `#b5563f` | `#f7ede9` | Tool 类（陶土红，暖） |
| Workflow | `--cat-workflow` | `#7a6b8a` | `#f1eef3` | Workflow 类（灰紫，earthy） |

### 4.3 气质硬约束（违反即打回）
1. 饱和度 ≤ 40%，**无荧光/无霓虹**；全部和谐落在 `#faf6f0` 奶油底。
2. **状态色优先于类目色**：一个「阻塞的 Skill」用 `--amber`（状态），不用 `--cat-skill` 金；类目色只在"正常/中性"时用于区分大类。
3. **部门不加独立彩虹色**：部门用中性/主绿，分组导航靠文字+主绿，不靠色块。
4. 能力卡/标签用「类目软背景 + 类目深字」，不铺满高饱和实色。
5. 头像底色可从 5 类目色取（区分人员），同部门内不强制同色（避免"部门=某色"误导）。
6. **禁止页内硬编码色值**：所有颜色走 CSS 变量（token）；新增色须先提为 token。原 `capability-center.html` 的青 `#2a9daa` / 蓝 `#3a6a9a` / 紫 `#7a5aaa`、员工头像彩虹色，统一换成上表 earthy 系列。

### P1 — 架构/逻辑冲突（对照三层模型与四条原则）
- **P1-2 组织中心数据自相矛盾**：`org-center.html` 部门数 3 vs 轨道图 4、员工数 24 vs 展示 8、「组织健康」三态全=18。→ 示例数据内部自洽（部门数=轨道节点数=部门卡数；员工数=员工条数或注明"仅展示前 N"；健康三态之和=真实基数且非全等占位）。
- **P1-4 执行工作台缺"验收/返工"一级状态**：`workbench.html` 运行层只有队列/运行/任务，"验收"缺失、"返工"仅埋红 tag。→ 显式呈现「验收中/返工中/已完成」为对等一级状态；补"目标→任务图"入口/概览，让核心链路可见（原则①④）。

### P2 — 排版/一致性漂移
- **P2-1 主内容区内边距**：`.main` 现 `24px 28px 20px`，应统一回 **`24px 24px 20px`**；canvas 投影全站统一加或不加。
- **P2-3 行内 style**：`workbench.html` 队列/运行/任务列表几乎全行内 style。→ 抽成 `.queue-row / .run-row` 等组件类，与 SPEC 组件层对齐。
- **P2-4 侧栏品牌区 markup 不一致 + 项目中心"项目总览"自链**：`capability-center.html` 用 `<span>Curis</span>`、`org-center.html` 用 `<div class="sidebar-brand-name">`（多 sub 文案）。→ 侧栏品牌区统一一套 markup；删除"项目总览"自链。

## 6. 已澄清 · Trae 原本就做对 · 无需改的点

以下三点经用户澄清，**Trae 当前做法正确，保持即可**（前次检查报告的对应判断已勘误）：

- **部门分组导航（P1-1 勘误）**：项目中心用部门作分组头/筛选维度是合理分工，**不是重复入口**；红线只限"并列的部门详情页"，分组导航不算。
- **AI 员工头像（P1-3 勘误）**：头像/角色名=视觉身份，**应保留且未来支持上传**；需补的是员工详情里"动态能力绑定"区块（见 §1.2 第 17 项），不是删头像。
- **多色协调（P2-2 勘误）**：允许扩展协调色，禁的是过饱和突兀色；把原过饱和青/蓝/紫换成 §4.2 的 earthy 系列即可，无需退回纯两色。

## 7. 数据自洽纪律（通用规则，所有页适用）

1. 同一对象集合的多个维度计数（状态/来源/类目）必须**同源派生**，加总一致。
2. 列表"总数"必须等于实际卡片数；若只展示前 N 项，须注明"仅显示前 N"。
3. 占位/示例数据不得出现 `$x$x` 类未替换模板变量；不得出现全等复制的占位数字（如 18/18/18）。
4. 状态/类目色必须从 token 取，不得页内硬编码。

## 8. 交付验收标准

补齐+修复后，交互原型应达到：
- **44 页全覆盖**（9 一级 + 30 二级 + 5 三级），全站内部链接（sidebar/面包屑/卡片跳转）**无 404**。

- 侧栏品牌区 markup 全站一致。
