### 2.3 侧栏导航交互规则（来源：确认稿 §3）

1. 点击一级名称：进入一级默认首页，并展开二级
2. 点击 chevron：只展开或收起，不跳转
3. 一级文字和图标权重大于二级
4. 二级缩进 28px，三级缩进 48px
5. 三级只显示真实对象；零数据不生成占位对象名
6. 当前一级收起时，二级与三级必须隐藏
7. 不在一级导航重复显示总裁办公室的三个二级模块
8. 不使用裸加号表达层级或创建

## 4. 通用页面骨架（来源：确认稿 §4）

**基准画布**：Desktop 1536 × 1024，body 居中于 `#e8e2d8` 背景，画布本身 `overflow:hidden`。

| 区域 | 规格 |
| --- | --- |
| 左侧产品导航 | 176px 固定宽度 |
| 主内容左右内边距 | 20px |
| 主内容布局 | 12 栏 |
| 栏间距 | 14px |
| 页面顶部安全距离 | 12px |
| 主区块纵向间距 | 14px |

**6 个通用区块**（按确认稿通用骨架）：
1. **页面身份**：页面标题、副标题、Company 状态
2. **事实条带**：三个事实单元 + 页面级主操作
3. **空间主视觉**：页面最大视觉区
4. **事实侧栏**：状态、缺失项、阻塞或来源
5. **对象空间**：部门、项目、能力或内容集合
6. **数据边界**：说明只展示真实已读取事实

**页面目的**：让 CEO 在一个首屏内确认 Company、当前核心项目目标、组织运行事实、待处理汇报和实时办公室。

**展示内容**：

**布局结构**（固定画布 1536×1024）：

### 6.2 项目中心

**页面目的**：一级点击后立即看到所有项目总览（按部门分组导航以便查找），三级进入具体项目详情。项目中心是「项目工作视图」——项目是主对象，承载全生命周期（目标→任务图→执行→验收→返工→完成）。

> **与组织中心的边界**（详见《项目中心与组织中心职能划分》）：项目中心里的「部门」仅作**分组导航 / 筛选维度**（项目太多时按部门归类查找），**不另立部门结构页**；部门详情归组织中心。组织中心里的项目只是部门树上的**链接节点**，点出去进项目中心。

**展示内容**：
- 页面身份：标题「项目中心」+ 状态 + 当前核心项目目标胶囊
- 项目组合事实：项目总数 / 运行中 / 阻塞 / 已完成 + **新建项目**按钮
- 全部项目（按部门分组导航）：部门作分组头，之下为项目卡（进度 / 状态 / 负责人 / 截止）；部门分组仅为查找，非结构页
- 项目组合状态：项目状态时间线
- 项目运行边界：底部边界说明（不允许伪造进度/阶段）

**布局结构**：
| 区域 | 栏宽 | 行高 |
| --- | --- | --- |
| 页面身份 + 项目事实 + 新建 | span4 + span8 | 280px |
| 全部项目（按部门分组）+ 项目组合状态 | span8 + span4 | 280px |
| 项目运行边界 | span12 | 110px |

**交互逻辑**：
- 点击一级 → 进入项目总览（按部门分组）
- 点击某部门分组头 → 该部门项目列表（筛选视图，非新结构页）
- 点击项目 → 项目详情（三级，含验收 / 返工一级状态）
- 新建项目入口：必须等写 Contract 通过，未授权时按钮不渲染

### 6.3 组织中心

**页面目的**：一级点击后进入组织总览，以部门空间展示公司组织全貌（结构 / 目录视角）。组织中心是「结构镜头」——部门是结构实体（有部门详情页），项目只是部门树上的链接节点。

> **与项目中心的边界**（详见《项目中心与组织中心职能划分》）：组织中心里项目只作为部门详情内的**链接节点**出现（点出去进项目中心看全生命周期），绝不与项目中心并列成双入口；部门在此是**结构实体**，项目中心里的部门只是分组导航。

**展示内容**：
- 页面身份：标题「组织中心」+ 状态
- 组织事实：部门数 / 员工数 / 阻塞部门 + **新建部门**按钮
- 组织空间总览：3D 轨道舞台（中心 = CEO 办公室，发光；轨道 = 部门节点）
- 组织健康事实：部门运行健康数字
- 部门空间（两列）：每个部门卡片含当前项目（**链接到项目中心**）/ 工作状态 / 依赖关系 / AI 员工头像
- AI 员工：员工头像条
- 组织运行边界：边界说明

**布局结构**：
| 区域 | 栏宽 | 行高 |
| --- | --- | --- |
| 页面身份 + 组织事实 + 新建 | span4 + span8 | 280px |
| 组织空间总览 + 组织健康 | span8 + span4 | 280px |
| 部门空间（两列）+ AI 员工 | span7 + span5 | 280px |
| 组织运行边界 | span12 | 110px |

**交互逻辑**：
- 点击一级 → 组织总览
- 二级：部门空间、AI 员工
- 三级：具体部门 / 具体员工
- 点击部门 → 部门详情（必含「新增员工」主操作）
- 部门节点（轨道上）可点击进入

### 6.4 能力中心

**页面目的**：统一展示 5 大类能力资产（Agent / 模型 / Skill / Tool / Workflow）和真实组合关系。Tool 大类下含 MCP / API / CLI / Connector / Webhook 子分类。

**能力分类体系**：
```
大类（5 个，各自独立模块入口 + 二级列表页）：
  ① Agent        — 智能体适配器（外部/内部 Agent）
  ② 模型 Model   — LLM / 多模态模型注册
  ③ 技能 Skill    — 推理技能、Agent 行为封装
  ④ 工具 Tool     — 工具调用（含子分类：MCP / API / CLI / Connector / Webhook）
  ⑤ 工作流 Workflow — 步骤编排、决策节点
```

> 设计理由：MCP / API / CLI / Connector / Webhook 本质都是「被调用的外部能力接入方式」，归入 Tool 大类下做子分类；而 Agent / 模型 / Skill / Tool / Workflow 是真正不同的能力类型，各自单列大类。

**展示内容**：
- 页面身份：标题「能力中心」+ 状态
- 能力资产事实：Agent / 模型 / Skill / Tool / Workflow 五类数量 + 搜索框 + **新增能力**按钮
- 能力模块入口：**五列大卡片**（Agent / 模型 / Skill / Tool / Workflow），每张含：图标 + 模块名 + 描述 + 数量 + 状态 + Top 3 能力预览 + 进入列表
- 能力接入状态：可用 / 阻塞 / 官方 / 自定义 四类说明
- Tool 子分类说明：MCP / API / CLI / Connector / Webhook 五类接入方式（在 Tool 卡片底部或能力池区块展示）

**布局结构**：
| 区域 | 栏宽 | 行高 |
| --- | --- | --- |
| 页面身份 + 能力事实 + 搜索 + 新增 | span12 | 72px |

## 9. 状态规范

| 状态 | 视觉与行为 |
| --- | --- |
| Loading | 保持最终布局尺寸；使用骨架；不显示 0 |
| Empty | 保留完整空间构图；显示明确下一步 |
| Normal | 只绑定真实事实 |
| Partial Data | 成功区域正常；失败区域局部错误 |
| Error | 脱敏错误和局部重试 |
| Permission Denied | 不显示无权限数据；操作隐藏或明确禁用 |
| Offline | 显示最后快照时间；不标成实时 |
| Mutation Loading | 主操作锁定；防重复提交 |
| Mutation Success | 返回来源页并一次性高亮新对象 |
| Mutation Error | 保留输入；字段错误就近显示 |

**禁止**：
- 缺失数据显示为 0
- 等待 Contract 显示为可操作功能
- 使用 Mock 项目 / 部门 / 员工 / 能力名称
- 用综合评分替代事实
- 用 Task 入口替代 Company 或 Project 空态

## 13. 状态矩阵（空 → 填充 的最终形态约定）

> 目的：当前 39 页只落地了**空状态（Empty）**。前端 1:1 还原时，必须同时知道「内容填充后」的精确形态。下表是每个核心列表/卡片模块的**状态机**：前端按表中规则随数据量自适应，不靠猜。
> 所有数值基于 §3 间距基数（8px）与 §4 固定画布 1536×1024。列数指 `.grid12`（12 栏）内的实际占用，不是 CSS grid 列数。

### 13.1 通用状态定义

| 状态 | 触发 | 布局行为 |
| --- | --- | --- |
| **Empty** | 0 条数据 | 保留完整空间构图；显示 `.empty-box` + 明确下一步；不显示 0（事实条数字符串显示"—"或留空，但 Empty 阶段事实条可显示 0，见 §9 禁止项例外：事实条 0 表示真实计数） |
| **Single** | 1 条 | 与少量态同布局，单卡片/单行占满其栅格单元格，不强制拉伸 |
| **Few** | 2–8 条 | 按模块默认列数铺排（见下表），行高固定，卡片/行之间 8px 间距 |
| **Full** | 占满首屏可见区（约 9–12 张卡片 / 8–10 行） | 默认列数满铺；超过可见区内容进入滚动区（`.scroll` overflow-y:auto），不压缩卡片 |
| **Overflow** | 超过 Full 阈值 | 分页 / 「加载更多」 / 虚拟滚动三选一，由后端返回总数决定；分页器固定在卡片网格底部，与 `.boundary` 边界说明之间留 14px |

### 13.2 核心模块状态矩阵

| 模块 | 组件 | Empty | Few（≤8） | Full（≈9–12） | Overflow（>12） | 截断规则 |
| --- | --- | --- | --- | --- | --- | --- |
| 能力模块入口 | `.mod-grid` 5 列 | 5 张空卡（"0 个能力"） | 5 列满铺 | 5 列满铺（固定 5 大类，不会更多） | 不适用（大类恒定 5） | 模块名不截断；描述 `flex:1` 内 `line-clamp:2`；Top3 预览最多 3 行，超出省略号 |
| 能力卡片网格 | `.cap-grid` 3 列 | 空态提示 | 3 列 × N 行 | 3 列满铺，约 3 行=9 张卡可见 | 分页（每页 12 张） | 名称 `line-clamp:1`；描述 `line-clamp:3`；分类标签 `white-space:nowrap` 省略；操作区固定底部 |
| 部门空间 | `.dept2` 两列 | 空态 | 两列卡片流 | 两列持续堆叠，滚动 | 同 Full（滚动） | 卡片标题 `line-clamp:1`；当前项目/状态单行省略 |
| 项目轨道 | 阶段轨道行 | 空态 | 每条轨道 1–N 项目胶囊 | 轨道横向排布，纵向阶段行 | 轨道内横向滚动 / 收起为「+N」 | 项目名 `line-clamp:1`；状态点语义色 |
| 执行队列 / 列表 | `.row` 列表 | 空态 | 单行堆叠 8px 间距 | 约 9 行可见 | 分页（每页 20 行）或滚动 | 主标题 `line-clamp:1`；副标题 `line-clamp:1`；meta 右对齐 `nowrap` |
| 知识条目列表 | `.row` 列表 | 空态 | 同执行队列 | 同执行队列 | 分页或搜索过滤 | 同执行队列 |
| 三级详情 7 段骨架 | 段落块 | 每段显示空占位 | 按真实字段填充 | 段落自然延伸，滚动 | 长日志/运行记录用「展开更多」折叠 | 正文 `line-clamp` 依字段；代码/日志等宽字体 `overflow-x:auto` |

### 13.3 截断与密度硬规则（前端必守）

1. **卡片描述**：`.cap-card .cc-desc` 固定 `line-clamp:3`，超出隐藏不撑高。
2. **卡片标题**：`.cc-name` / `.mc-n` 固定 `line-clamp:1`，不换行改两行。
3. **列表副标题**：`.r-s` 单行 `text-overflow:ellipsis`，不折行。
4. **栅格不塌**：任何数据量下 `.cap-grid` 恒 3 列、`.mod-grid` 恒 5 列、`.dept2` 恒 2 列；不允许因数据少而变 1 列（Empty 态也保持列数，仅内容为虚线空卡）。
5. **间距恒定**：卡片间距恒 14px（`.cap-grid`/`.mod-grid` gap）、列表行间距恒 8px（`.row` margin-bottom），不随密度缩放。
6. **分页器**：仅当后端 `total > 单页上限` 时渲染，位置在网格/列表底部 + 14px，样式复用 `.cat-bar` 圆角与 `--line` 边框。
7. **事实条数字**：0 表示真实计数为零（允许显示 0）；列表/卡片内的「暂无」一律用 `.empty-box`，不显示 0。
